# Notifications owner capabilities

This package defines language-neutral Notifications contracts and bounded PostgreSQL capabilities. It does not start an HTTP service. API requests keep preference reads, notification inserts, and caller-owned changes in the same PostgreSQL transaction; the API remains the transaction coordinator.

The preference contract in `preferences.schema.json` covers reads, partial updates, and in-app mute checks. Migration `0311` installs `aap_notifications_v1.preference_command(jsonb)`. The policy JSON and owner SQL carry the same known types and toast defaults.

The append contract in `append.schema.json` carries a caller-generated notification UUID and returns the inserted row snapshot. Migration `0314` installs the persistence-only `aap_notifications_v1.append_notification(jsonb)` function. Callers must compose the existing preference-owner mute check before append; the append function does not apply product policy. It inserts with PostgreSQL's transaction timestamp, returns `read_at` and `created_at`, and never commits. The API rehydrates that snapshot into its existing SQLAlchemy identity map and preserves `notify`/`notify_many` return behavior.

`infra/docker/module-data-grants.sql` gives `notifications_code` the columns needed for notifications and preferences. The preference grant script gives the existing API LOGIN and a function-only peer access to `preference_command(jsonb)`, then revokes direct preference-table access. The append grant script gives the API LOGIN `append_notification(jsonb)`; the function-only `notification_append_client` gets only that append function plus `preference_command(jsonb)` to compose policy in one transaction. It revokes direct notification INSERT from the API LOGIN and leaves notification reads and update/delete flows on their existing consumers. Apply the strict grants only after the API and worker artifacts use both owner paths; old API images that directly insert notifications will fail after INSERT is revoked.

The bounded acceptance covers package contracts, a Node peer that composes preference and append functions over one borrowed transaction, and focused API transaction tests. `scripts/verify_module_data_boundary.py` exercises the function-only roles and API grants against owned disposable PostgreSQL resources. This capability closes the general insert path only; it does not qualify complete Notifications delivery, WebSocket, inbox, channel, or outbox deployment.
