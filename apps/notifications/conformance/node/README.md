# Notifications protocol peers

These small Node clients call the versioned PostgreSQL preference, append, and read-state functions directly. The append client composes the existing preference check with the persistence-only append function on one function-only connection and in one transaction. The read-state client checks current-user row scoping, no-op results, bulk counts, and rollback on the same borrowed connection. These are local interoperability checks, not a separate Notifications HTTP service.

Run `pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts`, then `pnpm run check` for the schema self-check. The owned database verifier supplies `NOTIFICATION_PREFERENCES_DATABASE_URL` and `NOTIFICATION_PREFERENCE_USER_ID` for the preference client, `NOTIFICATION_APPEND_DATABASE_URL` plus `NOTIFICATION_APPEND_USER_ID` for the append client, and `NOTIFICATION_READ_STATE_DATABASE_URL` plus `NOTIFICATION_READ_STATE_USER_ID` for the read-state client. The append peer checks preference policy before insert; the read-state peer verifies that only owner functions can update notification state. The function-only role has no direct table privileges.
