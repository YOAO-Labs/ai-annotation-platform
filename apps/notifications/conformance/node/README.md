# Notifications protocol peers

These small Node clients call the versioned PostgreSQL preference, append, read-state, and deletion functions directly. The append client composes the existing preference check with the persistence-only append function on one function-only connection and in one transaction. The read-state client checks current-user row scoping, no-op results, bulk counts, and rollback. The deletion client checks single-row scope, clear-read counts, invalid requests, rollback, and direct-delete denial on the same borrowed connection. These are local interoperability checks, not a separate Notifications HTTP service.

Run `pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts`, then `pnpm run check` for the schema self-checks. The owned database verifier supplies `NOTIFICATION_PREFERENCES_DATABASE_URL` and `NOTIFICATION_PREFERENCE_USER_ID` for the preference client, `NOTIFICATION_APPEND_DATABASE_URL` plus `NOTIFICATION_APPEND_USER_ID` for the append client, `NOTIFICATION_READ_STATE_DATABASE_URL` plus `NOTIFICATION_READ_STATE_USER_ID` for the read-state client, and `NOTIFICATION_DELETE_DATABASE_URL` plus `NOTIFICATION_DELETE_USER_ID` for the deletion client. The function-only role has no direct table privileges.
