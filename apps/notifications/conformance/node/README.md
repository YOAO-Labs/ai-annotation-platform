# Notifications protocol peers

These small Node clients call the versioned PostgreSQL preference and append functions directly. The append client composes the existing preference check with the persistence-only append function on one function-only connection and in one transaction, matching the API adapter. This is a local interoperability check for borrowed transactions, not a separate Notifications HTTP service.

Run `pnpm install --ignore-workspace --frozen-lockfile --ignore-scripts`, then `pnpm run check` for the schema self-check. The owned database verifier supplies `NOTIFICATION_PREFERENCES_DATABASE_URL` and `NOTIFICATION_PREFERENCE_USER_ID` for the preference client, and `NOTIFICATION_APPEND_DATABASE_URL` plus `NOTIFICATION_APPEND_USER_ID` for the append client. It sets `task.rejected` muted before the append peer checks and skips it in the same transaction; the append function itself persists the row only after the caller policy check passes. The append peer can execute only `preference_command(jsonb)` and `append_notification(jsonb)` and has no table privileges.
