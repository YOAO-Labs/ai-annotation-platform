# Capture requested evidence on demand

Follow the [maintainer guide](../../../../docs-site/dev/how-to/update-screenshots.md) for browser commands, media paths, and publication checks.

1. Identify the requested role, target page, starting state, and expected result. Verify the serving revision and the Web/API URL, and for writes verify the isolated database, storage, and any needed worker and broker. Use disposable records and licensed or redacted samples. Start a fresh named `agent-browser` session, not the shared default session or someone else's tab.
2. Use `snapshot -i` and the real controls for the requested interaction. Take fresh references after navigation or rendering changes. Wait for actual media and page readiness, align canvas input to rendered content rather than letterboxing, check requests and save/readback when relevant, and report failures rather than simulating success.
3. For a requested recording, finish authentication and private setup before using `agent-browser record start <temporary-file.mp4>` in that same session. Operate the real flow and run `agent-browser record stop` after the result. Review the actual file separately: play the beginning, core action and ending and inspect any poster. Check legibility, real geometry and outcome, glitches, and absence of credentials, signed URLs, personal data and private notifications. Do not confuse successful encoding or an isolated frame with a validated interaction.
4. Keep temporary evidence outside the repository; close only your session and retire only your resources. For an explicitly requested publication update, keep the existing destination and embedding, preserve meaningful alt text, poster and written steps or transcript as appropriate, and check the changed media in its final location. Leave unrelated published files untouched.
