# 已接受作业的媒体输入

媒体控制服务已经能核对当前来源并交付图片、视频引用。已接受的推理和训练作业还需要固定自己的输入；随后读取“这个 Task 现在使用哪个文件”，会改变原操作的含义。本页记录当前实现和继续提取所需的边界，不把持久作业 ID、模型快照或当前来源 URL 当成已冻结的媒体。

## 当前输入如何固定

| 消费路径                          | 已固定的事实                                                                                     | 仍依赖当前来源的部分                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 工作台单张图片预标                | 作业及幂等身份、Task 受理版本与来源绑定、Assets 代次／快照、对象身份；副本 VersionId、SHA 和大小 | 整图、ROI、失败项重试及候选证据已通过本地联调；后续写入继续核对当前来源及权限              |
| 普通单图批量预标（含 Scene 模式） | 同事务固定完整成员与逻辑来源、输入清单摘要；封存后固定逐题 Input／失败结果、版本化副本及摘要     | 本地已覆盖整图、ROI、部分失败和原输入重试；完整 Jobs 执行恢复及推理协议继续提取            |
| 场景单位、文字及跟踪等批量路径    | 原执行参数与 Task 范围；受控模型另有权重与类别身份                                               | 继续按各自消费事实迁移，尚未接入普通图片清单                                               |
| 视频逐帧预标注                    | 原 Job 固定成员、来源与采样；版本化原视频、完整选中时间表、计划及帧摘要                          | 逐帧执行、覆盖、失败重试与采纳已接入；容器链路已验收，代表性负载和执行交接继续             |
| 视频跟踪与修正                    | 提示、种子、标注版本和跟踪参数                                                                   | API 读到的来源快照没有存入跟踪作业；执行方重新取得当前摘要与 URL                           |
| 训练数据版本准备                  | Task、标注、类别、Scene 分组、源路径、S3 ETag、字节数和可选 VersionId                            | 首次复制尚需读取原对象；未记录 Assets 来源代次和快照，Scene 与 Labeling 事实来自分开的读取 |
| 训练执行与冻结逐样本评估          | 已就绪训练包摘要、保留媒体的 SHA、标签和类别                                                     | 消费 Learning 自己的保留副本，不需要再次解析当前 Task 来源                                 |
| 评估页面的“当前源”比较            | 原评估证据保持不变                                                                               | 这是有意读取当前 Task、标注和对象的比较功能，应继续与冻结评估输入分开                      |

整图请求与 ROI 裁剪可能发生在不同时间。迁移后的图片路径使用同一版本化副本；其他路径仍需逐项固定自己的输入。`Task.version` 和标注版本只约束各自事实，不能替代对象 ETag、VersionId 或内容摘要。

逐帧视频受理使用独立的视频输入清单，捕获与原始 `batch_predict` Job 一起提交。待执行请求重放继续使用清单内的采样参数，服务器后续调整帧数上限不会重建已接受的选择。缺少清单身份的旧消息和不匹配的重放明确拒绝，不按当前 Task 补造来源。逐帧入口目前只接受单个检测阶段。

## 最终写入的 Task 来源检查

进入推理前，`LabelingWriteScope` 记录 Task 的来源代次、素材关联、路径和文件类型。最终 Labeling 写入持有当前 Task 行锁后重新核对这些事实；即使 `Task.version` 没有变化，换源或路径从 A 改为 B 再改回 A 也会以 `prediction_source_changed` 拒绝迟到结果。

逐帧持久化遇到锁竞争时，把原来源事实随推理结果一起序列化到重试消息。恢复后仍使用原作用域，不以当前 Task 重建来源；真实换源属于非重试冲突。旧消息若没有记录来源绑定，则以 `labeling_write_scope_unknown` 拒绝，需要在部署前排空或明确处理，不能补造历史身份。

这层检查约束 Task 绑定。单张 Workbench、普通图片批量及视频逐帧输入现由 Assets 输入合同补充素材代次、快照及版本化副本；跨帧场景、整段跟踪等消费方仍需逐项迁移。

## 训练副本的既有保证

训练版本受理时记录源对象 ETag、大小和可选 VersionId。首次物化使用条件 GET，验证尺寸并计算 SHA，随后保存 Learning 自己的媒体副本。重试会核对并复用该副本；原对象在首次复制前被覆盖或删除时，准备失败，不会切换到新图片。训练 ZIP 位于独立 attempt 路径，保留媒体和包的清理由 Learning 持有。

这两种身份需要分别保留：Assets 决定原始来源及其代次，Learning 决定训练版本及保留副本。已经就绪的训练包、评估样本和模型试用不应为了统一接口而重新读取 Assets 当前源。

训练准备仍需补齐跨 owner 的受理快照。Labeling 当前读取 Task、标注和工具配置，再组合 Assets 的尺寸及 Scene 事实；Scene 影响训练与验证分组。新的输入引用必须保留这些关联及原 Task 版本，不能只替换文件 URL。

## 输入合同需要承担的职责

输入合同使用 `aap-assets-inputs/v1`，与图片派生合同共用现有 Assets Media 进程，分别持有收据和生命周期。输入副本进入独立的版本化桶，模型 URL 绑定具体 VersionId，ROI 读取同一版本并核对 SHA 和大小。共享缓存桶继续承担派生媒体的生命周期。详细取舍见 [ADR-0107](../adr/0107-versioned-accepted-media-inputs)。工作台单张图片及普通图片批量路径（含 Scene 模式中的单图 Task）已接入；其余输入路径继续迁移。

控制进程具有 49 项视频／图片／输入／清单 SQL 能力；图片 Worker 具有 6 项图片及 4 项输入能力，清理进程具有 8 项 outbox／垃圾能力。输入物化只做对象 I/O 与其租约操作，最终来源检查由 native 函数承担；不把图片控制端的 system 能力授予 Worker。Labeling 在原写事务中检查来源并登记标注 pin，派生标注继承该证据；仍有预测、标注或可重试失败项引用时，原 Job 历史清理不使输入失效。无引用后开始 30 天保留期；清理回执继续保留并定期扫描迟到版本。

输入、attempt、垃圾账本及标注 pin 的四张表由 native SQL 迁移管理，未映射为 API ORM 模型。Alembic autogenerate 通过 `app/db/native_schema.py` 排除这些表；协议升降级继续执行各自的显式迁移及保留责任检查，避免未来的 ORM 自动迁移误建议删除证据表。

## 普通图片批量清单

`aap-assets-input-manifest/v1` 增加 header／member 两张 native 表。workflow 通过捕获能力与 Job 同事务固定完整选择；四个控制 HTTP 操作负责读取、分页、准备与封存。`candidate_count` 保留跳过已有预测前的合格数量，`selected_count` 是实际成员数量。全项目／批次不增加总量上限，显式选择保持 200 项限制；控制页最多 100 项且不超过 2 MiB，达到字节预算时提前返回继续游标。范围、摘要和 Task 身份由严格值模型验证，队列中只传清单身份和摘要。

准备与复制在 Job 认领前完成，每次交付最多尝试 100 个未完成成员；已有结果直接重放。已知对象身份必须匹配，未知身份以准备时首次成功 HEAD 为字节受理时点。永久源错误登记为成员失败；临时繁忙保留原 pending 作业。只有所有成员已有可用 Input 或固定失败才封存，后续输入过期不会改写历史封存结果。

Scene 模式图片项目中的普通单图 Task 使用同一清单及最终写入围栏。Scene、帧序号和相机上下文不属于这条单图推理输入；需要这些上下文的场景执行单位和点云多相机操作不使用此清单。升级时先排空缺少清单身份的旧 Scene 图片批量作业；旧 payload 缺少完整配方，无法分类的 pending 作业也保守纳入排空。Scene 模式项目仍保留清单时拒绝回退，不通过删除证据恢复旧实现。

执行逐页读取，逐题下载并校验原图后再清理该题旧预测；固定失败的成员保留旧预测。每条失败保留清单来源及可用的原 Input；缺少原始字节的失败项明确拒绝重试。最终写入还核对实际 Input 所属原 Job，整组结果在回滚后整体重试，所有 Mask 内容预验证先于业务锁。后续页读取失败会记录失败作业、已处理位置与未处理数量，已保存候选保留；这不构成完整进程恢复协议。

本地受限 SQL/S3 验收覆盖真实独立控制和图片执行进程、丢响应后的同输入重放、源替换、整图及 ROI 的真实版本字节、覆盖顺序、部分失败、原 Job 删除及 Task 工作流版本推进后的原输入重试。Node 消费四个清单接口并读取 1503 个冻结成员；另有 native 验收覆盖原用户删除后的证据保留。进程从安装后的 wheel 启动，不导入 API、ORM、Celery 或 Redis。详细字段和切换规则见[媒体接口](/api/guides/assets-media)及 [ADR-0108](../adr/0108-bulk-image-input-manifests)。

本地已在受限 SQL/S3 身份下通过独立控制、图片执行和清理进程验收：丢失受理响应后的同身份重放，整图模型拉取摘要与 ROI 来源一致，最新输入 key 被覆盖后仍读取原版本，来源变化与原版本缺失拒绝读取，以及未完成 multipart 和迟到版本清理。Node 消费端覆盖五项 HTTP 操作，真实候选采纳覆盖原 Job 删除、原发起者停用和 Task 工作流版本推进后的证据保留。临时输入故障会继续等待同一输入；永久失败保留明确错误。候选、人工 Mask 更新和切片恢复在对象读取前检查权限、开关与版本条件，最终持锁复核来源及当前权威；预验证内容缺失时拒绝写入，不在锁内补读。

原 Job 取消与输入副本 ready 转换之间不是原子操作。读取引用与最终 Labeling 写入继续检查作业／证据保留和当前来源，阻止失效结果写入业务状态。素材转换、Mask 修复批处理及部分视频跟踪路径仍有持业务锁的对象 I/O，属于其余 Labeling 边界工作；不据此声明全部 Mask 或全模块独立部署已经完成。

## 视频帧证据与恢复

保留帧预测使用有类型的 `extra.accepted_video_input`，记录原输入 Job、计划及时间表摘要、原视频 SHA、选中序号与源帧时间、帧 ID 和帧 SHA。当前写入 Job 另由 `accepted_video_execution_job_id` 记录；重试 Job 可以不同于原输入 Job。最终 Labeling 写入先核验当前调用人、任务和实际作业，再在同一事务内 pin 原生帧证据。空结果也保存 Prediction 与证据；同一执行、输入、计划和选中序号的重复提交返回原回执。

带视频证据的失败项先验证原视频来源、保留副本及精确帧版本，再创建重试 Job。输入暂时繁忙时保留失败项并延后；缺少证据的旧逐帧失败项明确拒绝，不切换到当前 Task URL。推理完成后再次在锁外校验来源，写入时分别检查历史输入和当前重试 Job。候选采纳先验证来源及帧副本，再将每条 Annotation 的 pin 与标注同事务提交；切片和 Mask 派生继承已有证据。

逐帧主执行链路按封存清单和固定帧序号分段，不读取当前视频元数据重建计划。外部准备、来源及完整时间表核验完成前，Job 保持 pending；随后在一个事务内认领、复核原计划、清理可运行题目的旧预测并保存派发事实。没有可用原视频的成员保留旧预测。每帧推理后在业务锁外再次核验原始来源与副本，写入事务继续执行当前权限、Task 和实际 Job 围栏。

持久化繁忙时，消息保留推理结果和精确帧证据，恢复时不重新推理。每段首次统计与进度计数由同一个 Redis 操作记录；重复交付返回原统计，避免 Celery 把不同返回值当成额外完成的段。仍有段等待时会续期全部段回执和 chord 状态。API、两个 Celery Worker、独立 Media 控制／执行及 Cleanup 容器已完成本地真实 SQL/S3 链路验收，覆盖固定帧字节、证据、重复段投递和停止退出；代表性负载、在途交接及完整模块部署资格继续验证。

Media 原始输入和帧执行的初始及周期心跳会在原执行期限内重试临时繁忙，始终使用相同 generation 和 token；确认初始租约前不开始对象读取。真实租约丢失、未知心跳错误及取消会停止当前 I/O，持续繁忙超过原期限则按超时结束，不把一次锁竞争当成失去租约。

1. 受理操作先有持久身份，再固定完整选择与输入。无幂等键的操作也需要稳定作业 ID；响应中断后的重放与一次新的提交必须区分。
2. 每项输入绑定 Task 身份与版本、linked/legacy 来源归属、来源代次和快照、对象 ETag/VersionId/大小，以及已知的内容摘要。类别、标注、Scene、帧序号和时间表等影响计算含义的事实由其 owner 一并固定。
3. 对象 I/O 在数据库业务锁之外执行，随后以捕获的事实复核。引用、页游标、attempt 和 generation 都必须能重放；失败或丢失响应不能静默换成当前源。
4. 支持条件读取的消费方必须传递原 ETag 和 VersionId。仅向后端提供普通 URL 时，要交付固定版本或不可变输入副本；先 HEAD 再签发未版本化对象的普通 URL 仍有读取竞态。
5. 推理各阶段、ROI、逐帧提取、跟踪和失败重试消费同一受理输入。裁剪缓存属于派生结果，不能证明根输入已经冻结；重试也不能重新解析当前文件并覆盖原输入身份。
6. 捕获输入不授予标注写权限。最终写入继续复核当前账号、项目、Task/批次/编辑锁、标注版本和真实作业状态，并核对结果对应的来源。沿用各操作现有撤权、取消和终态语义。
7. 原始来源、保留副本、临时派生对象和未确认输出分别由其 owner 管理。删除保护、租约排空、迟到写入和回退需要真实存储与数据库证据；历史记录不能通过读取当前状态补造原输入身份。

这些职责要覆盖普通批量、工作台单题、受控模型、幂等重放、视频 fan-out、跟踪修正和失败项重试。训练自动选样也复用同一冻结入口。只替换其中一个签名 URL helper，不能构成完整迁移。

## 提取顺序与验收

先统一批量预标注的持久受理，再建立 Assets 的冻结来源引用、条件传输和必要的不可变交付；随后迁移推理与 Learning 消费方，保留各自最终写入和副本所有权。当前选用的 Python 图像、视频和存储实现可以继续复用；公开合同必须是可独立消费的值与字节协议，不能要求调用者导入 API、ORM 或 Celery。

验收需要实际覆盖：受理后尚未启动就能查询作业、提交后派发失败、重复投递、同键覆盖、路径或关联变化、首个模型响应与 ROI 读取之间的替换、帧任务延后执行、失败重试、输入缺失、取消、进程接管及旧副本保留。迁移中的旧在途作业需要排空或明确拒绝，不能推断它们从未记录的来源身份。

完整目标和其余模块缺口见[模块部署状态](./module-deployment)。本页不构成新的部署、语言替换或生产容量资格。
