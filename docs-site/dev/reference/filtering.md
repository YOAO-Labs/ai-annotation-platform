# 筛选状态与结果范围

应用共用筛选控件、值校验和 URL 状态机制。每个业务页面继续负责字段、默认值、权限、请求参数和分页规则；Data Manager 的表达式树不用于替代普通列表的 API 参数。

## 前端职责

| 层                                     | 职责                                                                       |
| -------------------------------------- | -------------------------------------------------------------------------- |
| `components/filters/FilterBar`         | 字段搜索、条件芯片、快捷条件和清除入口；清除的具体范围由调用方决定         |
| `components/filters/FilterValueEditor` | 编辑文本草稿，仅提交完整、合法的值；数字 `0` 和布尔 `false` 是有效值       |
| `lib/filters/filterValues`             | 有限数字、数组、布尔和区间的解析；保留值本身的类型                         |
| `hooks/useDebouncedValue`              | 服务端列表文本默认等待 250ms；外部导航恢复可立即更新                       |
| `hooks/useUrlFilterState`              | 从当前 URL 解码，按页面 codec 原子更新或重置；不发请求、不替业务选择默认值 |
| 页面 codec 和查询 hook                 | 参数白名单、默认值、依赖重置、查询身份、AbortSignal 和结果范围             |

输入中的 `1.`、缺少一个端点的区间或未闭合的引号属于草稿，不应触发查询或保存。恢复的无效条件需要可见的错误提示，不能通过丢弃条件扩大结果范围。枚举建议值不必是完整白名单；已经保存但不在当前建议中的值应保留并可移除。

## 筛选呈现层

`components/filters/FilterTrigger` 固定使用项目页的漏斗图标；`FilterPanel` 提供按钮旁的非模态 Popover 与窄屏底部 Sheet，标题、正文滚动和底部操作区共用布局。它们只管理展示，不拥有业务草稿或请求参数。

项目页通过 `ProjectFilterControl` 保持入口同步显示，首次展开时才加载 `ProjectFilterPanel` 及其浮层依赖；已应用摘要由独立的 `ProjectFilterSummary` 同步渲染，不能从重型面板模块反向导入。首次加载后保留面板组件，关闭和重新打开仍由 Radix 管理动画与焦点。生产构建后还需运行 `pnpm --filter @anno/web size`；仅构建成功不代表满足主包预算。

`FilterGroup`、`FilterToggle` 和 `FilterSelect` 统一常驻筛选的标识与控件样式，保留原生按钮/选择框语义。`ActiveFilterChip` 把编辑与移除拆成并列操作，并以可访问名称和可见文字标识无效条件。筛选组不用缺少 tabpanel 的 tablist 语义；真正的导航页签不受影响。

项目高级筛选仍使用草稿与应用；成员、邀请、审计和模型目录的附加面板标明即时生效。徽标由页面按实际负责的条件维度计算，不把已加载结果数、默认范围或已单独显示的状态重复计数。移动字段到面板不能移动 URL、输入草稿、分页和选择状态的所有者。工作台筛选留在原位，来源复选框和置信度滑块保留输入焦点隔离。

使用说明见 [使用筛选](../../user-guide/reference/filtering.md)。

## URL 与请求

URL 是页面级已应用条件的状态来源。输入框和 Apply/Cancel 对话框可以有本地草稿；浏览器前进、后退、刷新及同组件内导航都需要重新读取 URL。文本编辑替换当前历史记录，显式视图导航保留导航语义。

导航恢复使用的草稿同步标记必须在用户重新输入时清除，不能一直等待用户已经改写的草稿等于旧 URL。写回前还需确认防抖值对应当前输入草稿，避免切换其他筛选项或按 Enter 时把未完成防抖的旧值写回；审计详情值按原文比较，保留空字符串和空白字符。多字段草稿分别维护恢复标记，只更新 URL 中确实变化的字段，避免一个字段的导航恢复暂停另一个字段仍在防抖的编辑。

codec 只改自己拥有的键，保留布局、创建向导、跳转来源等其他参数。成员与邀请分别使用自己的键空间。缺少某个键和明确的空值不能混为一谈，例如审计的 `detail_key` 存在时，`detail_value=` 表示一个有效的空字符串条件。

条件变化时，查询不能先携带旧页码或 cursor 请求一遍，再通过 effect 回到首页。将依赖重置放在同一次状态变化中，或在构造查询时用条件身份确定有效页码。无限列表的页集合由 TanStack Query 的 query key 管理；改变条件即进入新的查询集合。

query key 包含业务和账号身份及规范化后的条件。将 TanStack Query 提供的 `AbortSignal` 传到现有 API client；取消旧请求不显示加载失败提示。取消与 query key 隔离分别解决资源浪费和旧结果覆盖，不能只依赖其中一种。

## Data Manager 表达式

任务、对象和轨迹沿用 `filter_json`，接受空对象、根规则及嵌套 AND/OR。前端编辑不改变条件次序或分组：同一个 AND 中的对象条件要求同一对象满足，而不同嵌套组可以由不同对象解释命中。不能使用普通布尔代数把这些组展平。

独立关键词 `q` 作为顶层 AND 条件加入。只有独立的 `task.keyword contains` 或无歧义的直接合取项可以转为关键词输入框；OR 内关键词继续保留在原树中。快捷条件和图表点击添加合取项，不重写已保存的 OR。

URL 的 `filter`、`sort`、`columns` 继续使用 `{ "v": 1, "value": ... }`。短视图链接恢复保存条件；已有完整 filter envelope 且省略 q 时，外部关键词为空。清除条件保留独立关键词、排序和列，并让当前保存视图进入未保存状态。

结构上限、字段能力、同对象 SQL 和证据规则见 [Data Manager 查询与聚合](./data-manager-query.md)。前端控件校验不能替代服务端校验和权限条件。

## 数量与操作范围

业务列表使用 `components/ui/ListPagination`，默认每页 20 行，容量选项为 10／20／50／100。每个列表独立拥有页码和容量；容量进入查询身份，并与页码归零一起更新。服务端分页按所选容量计算 offset，游标分页保存已访问游标以支持上一页；只有已取得完整、已筛选排序的数组才使用 `useListPagination` 在客户端切页。不能对服务端的一页结果再次切页并将其视为完整集合。

空列表仍显示分页栏；读取中禁用翻页与容量控件。API 没有提供总数时显示页码与当前页数量，不推算全部记录数。删除末页记录后校正到有效页；跨页选择和批量操作继续遵循原业务范围。

| 数量       | 含义                                       |
| ---------- | ------------------------------------------ |
| 可见总量   | 权限允许访问的完整集合                     |
| 匹配总量   | 当前已应用条件匹配的完整集合，未被分页截断 |
| 已加载量   | 浏览器已经取得的分页或本地快照             |
| 当前显示量 | 帧、来源或面板显示条件进一步限制后的集合   |

同一业务的列表、计数和支持的导出复用已应用参数及授权关系。全局概览卡片、忽略本字段自身条件的 facet 和本地快照可以保留独立口径，但标签需要说明范围。不能把当前页长度展示为筛选结果总量。

工作台候选依次经过置信度、已接受/忽略状态、来源可见性和帧显示条件。批量采纳仍针对当前任务已经加载、符合来源/置信度/去重条件的候选，可包含其他帧；按钮数量与文案说明实际操作范围。只切换显示筛选不会触发采纳、删除或几何修改。

持久化 `annotation.is_hidden` 控制画布可见性，列表保留恢复入口。帧筛选和来源可见性是任务级临时状态；置信度阈值和审阅模式继续由已有会话偏好负责。重置筛选状态不重新挂载拥有未完成写操作的组件。

## 保留的业务差异

- 用户列表改条件后清空选择，翻页保留跨页选择；预标历史队列保留用户显式累积的选择，并显示已选数量。
- 选项搜索不清除已选 ID；角色、项目或模型变化只重置原业务定义的依赖。
- 通知分类只筛选已加载通知；全局搜索保留 200ms，Python TUI 保留 300ms。
- 工作台队列保留批次、未分批和退回重做范围；当前任务不存在时，“当前任务”的离线操作不能变成“全部任务”。
- 管理分析保留 7/30/90 天和默认 30 天，各聚合请求使用同一范围。

这些差异属于业务契约，不需要增加通用筛选插件、动态表单运行时或新服务。
