# 训练准备与重复传输资源基线

本工具测量从已登记托管图片到固定训练包的现有链路：JWT HTTP预检、同摘要创建、普通账号Celery物化和打包至ready，再完整读取同一个训练包两次。它为数据集与存储的训练准备成本提供本地证据，不执行模型训练，也不部署新Executor或实现节点缓存。

## 复现

先核对[工作树环境](/dev/how-to/worktree-environments)的本机依赖和归属。只能使用当前checkout拥有、业务表及九桶均为空的独立`test`模式；拒绝已有业务、对象、删除标记或未完成上传。工具不接受生产目标，不重置已有数据。

```sh
mkdir -m 700 /tmp/training-benchmark-private
pnpm dev:worktree -- exec --mode test -- env DEBUG=false LOG_LEVEL=WARNING \
  PYTHONDONTWRITEBYTECODE=1 apps/api/.venv/bin/python \
  scripts/benchmark_dataset_training.py \
  --output /tmp/training-benchmark-private/report.json
```

默认依次测量1,000和10,000个样本。`--sizes 8`仅用于小规模链路校准，不能代替两档基线；自定义档位须在2–10,000内且不重复。协调器、独立API和Worker使用当前API虚拟环境，读取同一份现有业务代码；子进程不接收迁移／测试owner DSN，另核对实际连接不是数据库、schema或业务表owner。

每个测量阶段默认最多等待14,400秒，可用`--phase-timeout-seconds`调整。该值仅控制工具等待及HTTP客户端，不修改生产任务、来源读取或鉴权预算；超时会取消并等待协调操作收尾、停止所属进程，结果保持失败。

报告以`0600`原子更新，含明确运行／完成／失败状态、当前阶段、已完成观测、启动代码提交及工具／业务源码指纹。运行期间源码变化会拒绝完成结果。观测超时不代表进程已结束：先检查原进程句柄和报告，不为恢复状态重启同一测量。

工具结束时关闭其API、Worker及临时文件。若失败，最多保留各64KiB私有进程日志供诊断，不覆盖已有诊断文件；处理完毕应删除。启动器仍拥有test数据库、Redis和九桶，须在确认所有客户端退出后按该模式精确confirmation销毁，并独立确认不存在；不要删除其他模式或长期人工环境。

## 夹具与正确性

每档在独立Project／Dataset中写入真实PNG，按现有`register_item_asset`登记可信SHA和实际定位，并建立已标注图片任务。准备这些夹具的时间单列，不计入预检或打包。三个图像档为32×24、256×192和1024×768，各自使用重复颜色／内容；虽保留全部逻辑成员，仅形成三个内容分组，因此按内容分组后的train／val比例不保证正好80／20。结果不代表自然图像、多类别、复杂标注或大图片的全量训练准备。

预检、创建和Worker使用正式权限、来源读取、完整核验、冻结、manifest与打包实现，未替换返回值、来源字节或业务依赖。最终核对精确Task成员、split、图片SHA／大小／尺寸、独立已知bbox标签及其摘要、ZIP全部成员和包摘要；原Dataset／Item／Task／Annotation及项目关联行保持，逐对象核对原件字节不变。测量不重建既有冻结、血缘或实际加载器成员合同。

## 指标口径

| 阶段／指标     | 实际测量范围                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP预检、创建 | 独立请求的服务端wall／CPU、SQL成败／耗时、图片检查及S3观测；另记客户端完整响应时间。                                                        |
| Worker构建     | 真实训练打包Task从prerun至postrun，等待版本ready、Job完成及指标落盘；包含物化、保留副本与打包核验。                                         |
| RSS、临时空间  | 每0.5秒采样API／Worker进程和test临时目录，记录峰值／收尾；采样可能漏过瞬时峰值。创建响应前已发生的Worker活动包含在创建阶段采样中。          |
| SQL            | 已激活请求／Task上下文及已传播线程的实际执行成败与耗时，不保存SQL或参数。                                                                   |
| S3             | 该上下文内的API操作与实际响应正文read／close；不以ContentLength冒充已读取字节。独立SDK Transfer线程不继承上下文，因此不计其上传操作／字节。 |
| 两次包读取     | 独立HTTP客户端直连本机S3签名地址，记录完整传输字节、摘要与耗时；每次实际传输，未假设存在节点缓存。                                          |

S3范围写在每份指标的`s3_observation_scope`中，关闭、在途SQL／S3及未知读取情况反映在`complete_observation`；它只描述已声明上下文范围，不表示覆盖所有SDK线程。最终ZIP与对象核验独立于操作计数。进程CPU包含该进程的线程，外部采样与服务端观测分别呈现，不能把局部S3计数当作总网络流量。

资源采样的`wall_seconds`是观测窗口，包含0.5秒轮询等待；短阶段应查看`client_response_seconds`或服务端`elapsed_seconds`。包读取是直连本地MinIO的完整HTTP读取，不代表Vite代理、跨站点、冷盘或完整Executor下载／解包及训练运行的耗时。

本机共享PostgreSQL／MinIO、其他独立模式及暖缓存可能影响结果；源端底层磁盘和生产网络没有在本工具中取得资格。此基线不自动新增性能达标门槛，也不单凭两次包读取直接启动缓存工程；先依据具体资源和重复传输成本，按原方案评审缓存是否值得实施。

## 当前结果

33个不同辅助检查通过，8样本真实校准已完成，原件与五类业务行保持，全部观测上下文收尾；其test资源已清理。校准预检约1.043秒、创建约1.271秒、Worker约5.371秒，两次完整读取相同5,802字节包，核对19个ZIP成员。小规模数据不用于推断千张／万张性能。

两档规模测量尚未完成，结果以当前报告的实际终态为准，失败或预算拒绝不写作通过。

目录遍历、原图读取和增量同步分别见[扫描基线](/dev/reference/dataset-scan-benchmark)、[原图读取基线](/dev/reference/dataset-read-benchmark)和[增量同步基线](/dev/reference/dataset-sync-benchmark)，不能相互替代。
