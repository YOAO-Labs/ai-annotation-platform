# 审阅 AI 候选

AI 预标和外部预测先生成 **Prediction（候选）**，不会直接替代人工标注。进入工作台后，先核对候选，再决定接受、拒绝或继续编辑。

## 哪些结果需要审阅

- [批量 AI 预标](../projects/ai-preannotate)生成的图片候选。
- [外部预测导入](../datasets/prediction-import-export)写入的候选。
- 图片交互式 AI 工具生成、等待确认的候选；不同工具的确认方式见[图片交互式 AI](../workbench/sam-tool)。
- 视频 AI 追踪的结果也需要审阅，它以 job 保存候选，但可按目标与帧窗口接受 / 拒绝，见[视频关键帧传播与 AI 追踪](../workbench/video-propagate)。

## 图片候选的审阅步骤

1. 打开包含 AI 预标结果的任务。在「标注详情」的「AI 待审」列表查看候选；「单图 AI」面板用于运行推理。
2. 选中一个候选，检查几何、类别和属性；需要时先在工作台调整。
3. 按 `A` 接受，或按 `D` 拒绝当前选中的候选。也可以使用「标注详情」中的对应操作。
4. 接受后，候选成为正式 Annotation，仍可继续编辑、改类或删除；拒绝后，该候选不再作为待审结果出现。

`Tab` / `Shift+Tab` 可在同类对象之间切换；需要暂时跳过当前候选时，只切换焦点而不执行接受或拒绝，该候选会继续留在待审列表。开启“决策后自动前进”后，接受或拒绝成功才会选中下一个待审对象；按钮与快捷键使用同一流程。请求失败或等待补选项目类别时保留当前候选，可重试。完整的键盘审阅流转见[工作台概览](../workbench/#审阅键盘流转)。

图片的原生 Mask 候选显示真实像素，保留孔洞与不相连区域；点击有色像素选中，孔洞不会命中候选。详情与待审列表显示加载状态和像素统计，加载失败可点“重试加载”。读取被关闭时不请求像素，详情显示尚未加载。来源或置信度筛选、接受和拒绝会同步更新候选层；切题后不会沿用上一题的像素。

原地引用图片可审阅已发布受控实例分割模型生成的整图原生 Mask；失败项可保留原模型和原图重试。来源离线时，仍可查看平台已经保存的候选像素；接受时继续严格核验原图、候选和当前权限，查看成功不代表可以接受。

整组接受只处理尚未驳回的对象；已经驳回或被重试结果替代的候选不能再次采纳。

## 数据边界

| 操作                | 会发生什么                                                       | 不会发生什么                                          |
| ------------------- | ---------------------------------------------------------------- | ----------------------------------------------------- |
| 接受候选            | 写入一条可编辑的正式 Annotation                                  | 不会覆盖已有人工标注                                  |
| 接受交互式原生 Mask | 原子保存像素内容、AI 来源和正式 Annotation；网络重试沿用同一决策 | 不会先留下半个 Prediction，也不会把 Mask 转成 polygon |
| 拒绝候选            | 放弃当前候选                                                     | 不会删除其它候选或人工标注                            |
| 清理预测            | 按来源删除尚未接受的 Prediction                                  | 不会删除已经接受的 Annotation                         |
| 视频追踪“拒绝所选”  | 清除当前追踪 job 选中目标与帧窗口的暂存候选                      | 不会改写原轨迹或人工关键帧                            |

需要按来源批量清理候选时，使用[外部预测导入 / 导出](../datasets/prediction-import-export#清理预测)。选择“ML Backend 预标”或“全部预测”前，先核对范围；这两种操作会清除未接受候选，之后需要重新运行或重新导入才能恢复。

交互式原生 Mask 在接受前只存在于当前工作台会话，不属于可跨页面恢复的批量 Prediction。请求失败时候选仍留在画布，可直接重试；成功后才从候选层移除。切题、切帧、切模型、取消或会话过期会释放尚未接受的候选。

AAP JSON 导入的视频 Prediction 与图片候选一样逐 shape 审阅，不走追踪 job 审阅条。视频工作台只显示当前帧可见的 bbox、polygon、polyline 和真实像素 Mask；关键帧之间按轨迹规则解析，outside 帧隐藏。选中当前帧的普通待决候选后可用 `A` 采纳、`D` 忽略，成功后只在当前帧内自动前进；「全部」列表的显式按钮保留对应候选的操作范围。接受或忽略只处理当前候选的整个 shape，刷新后决定仍保留；接受后生成同类型的正式视频 Annotation，并保留轨迹身份和候选溯源。

## 视频追踪的不同之处

视频追踪完成或取消后，已算出的帧会显示在“AI 追踪候选”审阅条中。bbox 候选显示为框，Mask 候选按真实像素显示为紫色半透明区域；预览与接受后使用同一份 RLE，不会因接受而变成外接框。候选仍归属于同一个 job，但可以勾选目标并填写起止帧分批决定：接受后回填源轨迹并为额外目标创建新轨迹，拒绝只清除选区，未决范围刷新后仍可继续审阅。人工关键帧默认受保护，显式确认覆盖会留下审计记录。不要把图片候选的逐条 `A` / `D` 操作当作视频追踪的审阅方式。

Mask 纠错传播的审阅条会额外显示人工种子帧、实际传播窗口、方向、原生 Mask 或 bbox 降级 lineage，以及人工帧保护状态。纠错帧不作为候选被再次接受；只有传播出的目标帧进入局部决定。取消后候选立即移除，人工种子帧保留。

## 候选没有出现或无法恢复

- 批量预标后没有候选：到 `/ai-pre/jobs` 查看任务状态和错误；项目管理员可从 job 详情重试可恢复项。
- 刷新视频任务后没有审阅条：确认仍有该任务的可见权限、候选尚未被其他有权限用户处理，再查看 `/ai-pre/jobs?tab=video`。
- 需要处理失败或卡住的预标：按[失败预测恢复](../workflows/failed-prediction-recovery)先在 Jobs 页面定位；服务和容器诊断交给对应 runbook。
