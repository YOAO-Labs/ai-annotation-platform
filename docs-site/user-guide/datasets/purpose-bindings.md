# 九用途映射与受控切换

> 适用角色：超级管理员

超级管理员可在 **存储管理 → 用途映射**（`/storage?tab=purposes`）查看并管理平台全部 9 类托管存储用途。即使部署环境中多个用途共用同一个物理存储桶，界面也会逐行展示每项用途的用途代次（generation）、位置修订（revision）与读写策略。

这里的**托管用途写策略**与**外部数据集来源的只读能力**相互独立：外部目录或外部 S3 来源保持只读，不代表平台无法向已登记的全局 S3 托管目标保存文件；反之，修改用途映射也只改变后续新分配的写入位置，不等于已完成历史对象迁移。需要将当前默认源的九用途整组原子切换到新对象存储实例时，请使用[对象存储迁移准备 · 九用途整组切换与回滚](./storage-migration#九用途整组切换与回滚)。

## 通用五分钟预览与受控切换流程

单用途受控切换统一遵循**实时探针验证 → 维护影响预览 → 五分钟内显式确认**的三步流程：

1. **选择候选目标位置**：在 **用途映射** 对应行点击切换按钮，从默认托管位置或已登记的全局 S3 位置中选择目标（`bug_reports` 要求选择已登记的全局 S3 位置）。只读来源不能作为托管写入目标，连接器“测试连接”成功也不能代替此处的托管写入验证。
2. **实时探针验证与影响预览**：点击 **验证并预览**。后端在目标位置的受控前缀下真实执行条件写入、完整读回、列举与准确清理探针，并汇总当前用途下的历史责任记录数。若探针失败或测试对象收尾无法确认，系统直接拒绝切换。
3. **五分钟内确认切换**：核对旧/新位置、桶与前缀、现有记录统计后，在 **5 分钟有效期内**点击确认。若确认前目标配置、位置维护状态、用途代次、影响数量或管理员权限发生变化，旧预览令牌即失效，需重新验证并预览。

### 为什么历史对象与在途上传留在原位置

- **零隐式搬迁**：用途切换只更新后续新分配使用的绑定代次，**不会自动搬迁、复制或删除历史对象**，也不会中断切换前已分配、正在进行的上传或打包任务。
- **按保存目标精确读取**：已落库记录始终携带自身的物理定位（Saved Target）。即使将来把用途再次切回默认位置，期间写入新位置的对象仍保留在新位置并按保存记录读取，系统绝不根据“今天的绑定”去猜读旧文件。
- **位置保护与备份责任**：只要某个存储位置仍被任何历史原件、缓存、归档或待清理责任引用，该位置就不能改址或删除（常规密钥轮换除外，轮换后按当前凭据访问原地址）。切往外部全局 S3 的对象不会自动纳入平台默认本地九桶的盘点与备份恢复范围，需由运维按实际目标位置安排独立备份。

## 各用途切换规则与隔离边界

以下列出全部 9 项用途在探针要求、网络可达性与历史兼容上的具体规则：

## 切换数据集原件的新写入位置

在 **数据集原件** 行选择默认托管位置或已登记全局 S3 并执行 **验证并预览**，系统核验条件写入、完整读回与测试对象清理，并展示原件、创建责任、辅助原件和退役记录数量。

- **覆盖范围**：仅后续新分配的浏览器直传、ZIP 导入、连接器复制、目录复制及同用途原始 LiDAR/地图辅助原件采用新位置。在途上传无需排空，导入暂存与最终原件位置彼此独立，数据集改名也不移动原件。
- **读取与密钥轮换**：读取严格校验保存的 endpoint、桶、对象键与完整内容摘要。正常轮换连接密钥使用当前凭据，已冻结内容身份不变；若凭据失效、位置停用或内容变化则明确报错，不从其他桶猜读。

## 切换媒体缓存的新分配位置

在 **派生媒体缓存** 行选择默认托管位置或已登记全局 S3，验证条件写入、完整读回、准确删除与前缀列举，并分别预览目录预览、原图缓存、图片金字塔、视频派生、缩略图输出与旧缩略图六类记录（不同类型记录不可直接相加为对象总数）。

- **同源短期能力链接**：浏览器通过平台同源短期链接读取新分配的普通缩略图、图片金字塔和视频派生输出（支持视频 Range 请求），**无需配置外部 S3 桶 CORS 或向浏览器暴露内部 S3 地址**。链接仅在有效期内授权读取该单文件，不是登录凭据。
- **目录预览与原图缓存隔离**：目录预览继续走认证入口；按需完整原图缓存继续由原件读取入口校验权限、内容与来源策略（保留原有配额、TTL 和读租约），不生成公开下载链接。网格高并发加载图片时按传输名额排队交付。

## 切换导入暂存的新写入位置

在 **导入暂存** 行选择默认托管位置或已登记全局 S3。目标必须支持**版本控制、条件写入、完整读回、准确版本删除及受控前缀列举**。

- **在途隔离**：已有 AI 预标输入、已签发的 Dataset/Task 直传上传、Mask 格式上传和已建导入批次继续使用原保存位置。即使临时文件写在新暂存位置，完成导入时仍按 `datasets` 或 `annotations` 用途的绑定封存最终原件。
- **网络可达性与清理**：若选择外部 S3，其 endpoint 必须同时供**浏览器上传**和**模型推理服务读取**（直接按该 endpoint 签名）。AI 预标临时输入沿用固定版本清理；直传和 Mask 导入暂存不设远端自动删除，切换不会新增桶级生命周期回收。

## 切换导出的新写入位置

在 **导出** 行选择默认托管位置或已登记全局 S3，预览分别列出 ZIP 与独立媒体包数量，并验证条件写入、完整读回、对象/版本列举及测试对象删除。

- **配套位置与缓存复用**：在途导出留在原位置，配套 ZIP 自动继承独立媒体包分配时的位置；若导出请求命中已有导出缓存，直接复用旧包而不因位置切换重做。首次 7 天下载期限与格式权限保持不变。
- **签名端点与旧链接**：外部 S3 的 endpoint 须供浏览器及下载脚本访问；默认托管位置继续走平台下载代理。轮换密钥后平台按新凭据签发新下载链接，但已下载 ZIP 内冻结的旧媒体链接仍受原到期时间与存储方凭据规则约束。

## 切换标注文件的新分配位置

在 **标注文件** 行选择默认托管位置或已登记全局 S3。验证探针实际执行**空文件条件 PUT、非空分段上传（Multipart Upload）、完整读回与准确收尾**，并预览任务原件、任务写入分配、RLE 对象、评论附件和指南图片五类责任记录。

- **覆盖与保留**：仅后续新分配的独立任务原件、持久 RLE 掩码对象、评论附件（保持首次 90 天期限）和指南图片使用新位置。普通几何标注仍保存在数据库；Mask 导入暂存与缩略图分别归属 `import` 和 `media_cache`。未知归属的历史记录沿原规则拒绝读取，无需在切换前全库扫描补认。

## 切换训练文件的新分配位置

在 **冻结训练数据** 行选择默认托管位置或已登记全局 S3。验证探针实际执行**微小普通写入、非空分段上传、完整读回、精确前缀列举与批量删除**，并预览训练版本、实验、预览、逐样本评估、主动学习轮次和删除意图六类责任记录。

- **跨位置血缘与可达性**：在途对象留在原位置；重试、续训、模型权重及初始化来源按各自保存的 owner 读取，输入数据版本与输出实验可位于不同目标位置。目标 endpoint 须供训练执行器和下载方直接访问。若初始化权重带有新受控根，训练执行器需声明对应地址能力。未固定归属的旧对象仍须由项目管理员显式核验原位置保留副本，不按当前绑定猜测。

## 更换头像存储位置

在 **头像** 行选择默认托管位置或已登记全局 S3，预览现有头像数量并验证写入、完整读回与删除。

- **历史头像定位检查**：切换仅影响后续新上传头像。若系统提示存在缺少独立定位的历史头像，请相关用户重新上传头像或切换为内置头像后再执行用途切换，平台不会猜测未定位旧头像的存储桶。

## 切换报告附件的新上传位置

在 **报告附件** 行从**已登记的全局 S3 位置**中选择目标，在受控前缀下验证条件写入、完整读回与准确删除后于 5 分钟内确认。

- **附件隔离与清理**：已保存和正在上传的附件留在原位置，报告中的逻辑附件键、下载期限与权限不变。缺少独立归属的旧附件保持原不可读提示，但不会阻塞新上传位置切换。目标上的附件仍由原清理责任负责，存有任何状态附件的位置不可改向或删除。

## 切换审计归档的新写入位置

在 **审计归档** 行选择默认托管位置或已登记全局 S3，预览已分配与已发布归档数量，并验证条件写入、完整读回与准确清理探针。

- **在途完成与永久保留**：切换前已分配、正在写入的月度归档继续写入原位置，后续新分配才写入新目标；历史月份与公开归档键不变。审计归档永久保留，切换不搬迁或删除旧归档，旧位置受归档责任持续保护不可删除。
