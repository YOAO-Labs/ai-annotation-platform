# 图像数据集导入

本页讲**图像文件怎么进数据集**:四种上传方式、ZIP 目录结构、支持的格式与上限、去重规则,以及导入后如何自动生成任务。

- 点云 / 多模态(lidar + 相机)导入见 [点云 / 多模态数据集导入格式](../datasets/import-formats)。
- 把**外部预测 / 标注**(COCO / YOLO / AAP JSON)导进项目、或清理已导入预测,见 [预测导入 / 导出](./prediction-import-export)——本页不展开这条链路。
- 导出标注成果见 [导出格式](../reference/export-formats)。

> **两条不同的链路,别混淆**:
> 本页的「图像导入」把**图片文件本身**灌进数据集(`dataset_items` + 对象存储);「预测导入」是另一条链路,往**已有 task** 上写标注 / 预测。先有数据集和图片,才谈得上导预测。

集成程序若直接使用独立Task上传接口，仍按初始化、PUT、完成三步调用，单文件最多5GiB。上传地址只指向暂存区；完成时由服务端核验并创建原件，重复使用旧地址不会改变已接受文件。两个写接口要求项目管理权限，且由原发起者完成；无创建证明的历史上传需重新初始化。接口与错误处理见[独立任务原件上传](../../api/guides/tasks-and-annotations.md#独立任务原件上传)。本页导入向导继续使用数据集上传流程。

## 打开导入向导

进入顶部菜单「数据集」,在数据集列表里点「上传」(已有数据集在独立详情点「上传」继续追加文件),打开导入向导。新建数据集时,第一步「选择来源」里选多文件、ZIP 包或连接器并配置来源;第二步「基本信息」里填写数据集名称、说明并选择数据类型(本页选图像)。已有数据集继续上传时直接从来源步开始,不经过新建信息步。

- **多文件** — 浏览器里直接选 / 拖入若干图片文件。
- **ZIP 包 (≤200MB)** — 上传一个 ZIP,后端解压并保留子目录结构。
- **连接器导入** — 从已配好的 S3 / OSS / SFTP 连接器按路径 + 通配符批量拉取。

![图像数据集导入向导](../images/datasets/import-images-wizard.png)

第四种是命令行的「扫描导入」(对已建好、对象存储里已有文件的数据集补建 item),见下文。

## 方式 A · 浏览器多文件上传

「多文件」标签里拖入或点击选择图片。每个文件走**预签名直传**:前端逐个向后端申请上传地址(`uploadInit`),直接 PUT 到对象存储,再回调 `uploadComplete` 入库;默认并发 3。

- **支持图像 / 视频 / 任意二进制**,单文件 ≤ 5 GiB（完成上传时由后端核验实际字节；文件类型按 MIME 推断:`image/*` → image、`video/*` → video、其余 → other）。
- 适合几十到几百个文件的零散上传。文件很多时改用 ZIP 或连接器导入。

## 方式 B · ZIP 上传(向导)

把一批图片打成 ZIP 上传,后端解压、逐个写对象存储并入库。这是图像数据集最常用的方式。

### 目录结构:顶层即图片,或保留子目录

ZIP 上传**保留 ZIP 内的子目录结构**；图片列表与导出沿用这些相对目录。同一逻辑路径已有不同内容时，文件名追加序号，避免遮盖旧样本。数据集改名不移动原图。两种布局都行:

顶层平铺:

```
images.zip
├── 001.jpg
├── 002.jpg
└── 003.png
```

按类别 / 来源分子目录(相对路径会保留):

```
animals.zip
├── cat/
│   ├── 001.jpg
│   └── 002.jpg
├── dog/
│   ├── 001.jpg          # 与 cat/001.jpg 同名,不冲突(见去重)
│   └── 003.jpg
└── bird/
    └── 010.png
```

解压时自动跳过:macOS 元数据目录 `__MACOSX/`、任意以 `.` 开头的隐藏文件(如 `.DS_Store`);拒绝绝对路径和含 `..` 的路径(zip-slip 防护)。这些被跳过的条目计入响应里的 `skipped`。

### 上限

| 限制项       | 值       |
| ------------ | -------- |
| 整个 ZIP 包  | ≤ 200 MB |
| 单个文件     | ≤ 100 MB |
| ZIP 内条目数 | ≤ 5000   |

超过整包上限返回 `413`,超过条目数也返回 `413`;单文件超限不阻断整包,该文件计入 `errors`(其余照常入库)。需要更大批量(数万文件 / 几百 GB)走**连接器导入**。

### 去重:按内容,不按文件名

去重以实际文件内容的校验结果为准，**不以文件名、路径或存储 ETag 认定重复**。因此:

- 跨子目录的**同名**文件(`cat/001.jpg` 与 `dog/001.jpg`)只要内容不同,都会入库——同名不冲突。
- **内容相同**的文件(无论文件名是否相同、是否在不同子目录)只保留第一个,其余计入 `deduped`。
- 已核验的同数据集文件支持重复内容识别；旧 hash 只作为候选，读取原件确认相同内容后才跳过。旧原件无法读取或证据不足时会保留新文件，不冒险丢弃。

### 看懂响应

上传完成后向导汇总后端响应,字段含义:

```json
{
  "added": 142, // 新入库的文件数
  "deduped": 6, // 内容重复、被跳过的文件数
  "skipped": 2, // 隐藏文件 / __MACOSX 等被规范化跳过的数
  "errors": [
    // 逐条失败明细
    { "name": "huge.tiff", "error": "超过单文件 100MB 上限" }
  ],
  "total_in_zip": 150, // ZIP 内非目录条目总数
  "linked_tasks": 142, // 若数据集已关联项目,本次顺带建的 task 数
  "scene_inference_notes": [] // scene 识别提示(图像普通导入一般为空)
}
```

判断成功:`added` 是真正入库数;`total_in_zip = added + deduped + skipped + errors.length`。`errors` 非空时逐条看 `name` / `error` 定位(常见是单文件超 100MB)。`scene_inference_notes` 只在识别 scene 时有内容(时序 / 多场景目录),纯图像平铺导入通常为空。

## 方式 C · 连接器导入(大批量)

数据量大(数万文件 / 几百 GB)或图片已在云存储 / SFTP 上时,用「连接器导入」:

1. 选一个可见连接器(普通项目管理员可用全局连接器 + 本人创建的个人连接器,超管可用全部)。
2. 填 `source_path`(连接器内的起始路径),勾选**递归扫描**(默认开),可用逗号分隔填 `include_globs` 过滤(如 `*.jpg, *.png`)。
3. 提交后导入作为**后台任务**运行,向导显示进度、成功数、跳过数和失败明细。

连接器导入使用独立的枚举预算，代码默认值如下：

| 限制项     | 默认值  | 覆盖用环境变量                   |
| ---------- | ------- | -------------------------------- |
| 最大文件数 | 50000   | `DATASET_IMPORT_MAX_FILES`       |
| 最大总字节 | 200 GiB | `DATASET_IMPORT_MAX_TOTAL_BYTES` |

超级管理员可在「设置 → 系统设置 → 数据导入」查看部署有效值并保存覆盖。作业受理时固定预算，枚举超限会**整体失败，不产生本次部分导入**；修改设置不会改变已排队或重试作业的预算。连接器的创建、主机白名单、密钥加密等配置见 [数据源连接器](./storage-connections)。

## 方式 D · 扫描导入(命令行 / 已有对象)

如果文件已经在对象存储里(例如外部流程直接写进了桶),对该数据集触发 `POST /api/v1/datasets/{id}/items/scan`,后端在固定扫描根中为缺失的文件补建 item。升级前数据集保留升级时的名称根；新建数据集使用独立存储根，具体写入约定见[数据集 API](/api/guides/datasets#扫描)。改名不改变扫描范围，重复扫描不重复登记。扫描只建立索引，不将 ETag 当作已核验内容。适合「对象先到、item 后补」的场景,日常 UI 导入用不到。

## 支持的图片格式

ZIP / 多文件路径不维护一份硬编码扩展名白名单,而是按 MIME 推断类型:`image/*` 归为 image、`video/*` 归为 video、其余归为 other。因此浏览器和操作系统能识别为图片 MIME 的常见格式都能进——`.jpg` / `.jpeg` / `.png` / `.bmp` / `.gif` / `.webp` / `.tiff` 等。能否在工作台正常**渲染标注**取决于浏览器对该格式的支持(JPEG / PNG / WebP 最稳;TIFF 等部分浏览器不直接显示)。入库时会为图像读取宽高并异步生成缩略图。

## 导入后:自动建任务

数据集**关联到项目后**,每个数据条目自动生成一个 task(初始状态 `pending`),进入该项目工作台待标注。两种触发时机:

- **首次关联**(`link`):按条目数决定快慢路径——条目数 ≤ `TASK_CREATE_SYNC_THRESHOLD`(默认 **2000**)在关联请求里**同步**建 task;**超过**阈值改为**后台异步**建 task,关联界面显示进度条,**建完之前这批任务在工作台还看不到**。
- **关联后继续追加**:已关联的数据集再上传文件、上传 ZIP、扫描导入或连接器导入,**新增文件同步建 task**,无需先取消关联再重新关联。

超级管理员可在「系统设置 → 数据导入」修改首次关联的同步阈值。数量等于阈值时仍同步，设为 0 时所有非空数据集首次关联都转后台；已排队的作业保持原执行方式。

> 首次关联转入后台后若工作台暂时空着，需等待关联界面的建任务进度完成，不必重新关联。

## 服务器目录原地引用

超级管理员先在**存储管理 → 受控目录位置**登记部署者已挂载的根内相对目录，并选择“仅指定的数据管理员”或“所有数据管理员”；指定人员支持按姓名、邮箱搜索。超级管理员及获位置授权的项目管理员可在**数据集 → 接入服务器目录**创建普通图片数据集。项目管理员仅管理自己创建的数据集。已有非时序图片数据集可在“来源与同步”页签管理目录来源：先选择来源、扫描，再核对预检差异；“新增来源”“来源设置”“周期计划”和历史记录按需展开。尚未配置来源时，新增表单自动展开。本机文件夹、多文件、ZIP 和连接器复制导入继续使用原入口。

1. 输入数据集名称，创建空图片数据集。
2. 选择已登记且启用的存储位置，填写位置下相对目录，或用“浏览目录”选择。根句柄由运维配置，不能输入任意宿主机绝对路径。
3. 填写负责扫描的完整 worker hostname，按需包含子目录，设置逗号分隔的图片匹配规则和排除规则，点击“配置目录来源”。规则区分大小写、相对来源根匹配；例如 `excluded` 排除整个同名子目录，`temp/*` 排除其中文件。该节点必须挂载同一目录并通过探测。
4. 原图策略选择“原地引用”（默认，不复制原图）或“托管复制”；缓存独立选择“仅预览”（默认）、“无持久缓存”或“按需原图”，位置的缓存上限优先；“来源设置”显示服务端计算的当前生效策略。托管复制从只读来源读取，经 SHA 核验后写入平台独立对象。点击“只读预扫描”。扫描在后台运行；完成后按页查看文件的相对路径和观测字节。失败或取消时可恢复，目录发生变化时需重扫。
5. 点击“运行接入预检”。后台读取图片，核验 SHA-256、格式和尺寸，分别展示已索引、待核验、已核验待登记、原已登记路径、预计新增、异常和排除数。预检不创建样本。完整预检后，在“本轮增量差异”核对新增、内容与观测相同、已变化、本轮未见、本轮排除和核验失败，支持类型筛选和分页。勾选确认后点击“确认仅登记新增”；没有新增时按钮不可用。旧账本仍使用“确认批量登记”。实际服务请求的 API 节点也必须能读到该目录；正式登记逐项重新读取固定摘要，支持 PNG、JPEG、WebP 单帧图片，每张最多64MiB、3200万像素。少量图片也可继续逐条“核验并登记”。
6. 进入数据集详情，在样本检查器点击“核验预览”。通过既有“关联项目”接入普通图片项目，生成任务；后续新增登记也会给已关联项目补任务。

“预检统计与体量”汇总本轮数量、原图复制与预览估算；“预检与登记明细”提供逐项结果、异常筛选和修复重试。“扫描条目”保留逐条登记与缓存预览；“扫描历史”按页查看保留记录，从历史扫描链接进入时自动展开。“来源设置”集中管理缓存、扫描规则及停用/注销。

目录发生增量变化时，再点“只读预扫描”和“运行接入预检”，与预检开始时已登记的来源路径比较，只有通过完整内容核验的新路径可在本轮新增。相同路径不会重复建样本或任务；同摘要但文件身份观测改变也会列为变化。变化项不会替换原图绑定，未见项不等于文件已删除，可能是未遍历到；旧样本、任务和标注保留。取消或中断的预检不发布差异，恢复完成后再核对。差异是本轮历史记录，原图使用时仍重新严格校验。不同摘要的内容变化可通过下文的“接受为新修订”逐项确认；同摘要观测变化可通过下文“重新核验并保留样本”处理；同来源内移动可明确选择目标；普通重试不能接纳这些变化。周期扫描见下文。

已有目录来源的普通图片数据集仍可混合上传文件、ZIP 或复制导入。ZIP 不自动创建 Scene，以便继续登记原地图片；这些写入在耗时读写后复查账号和初始凭据，撤权后保留已提交部分。

撤回位置使用权后，项目管理员不能再浏览、扫描、登记或管理预览；既有任务仍按分派和成员权限读图。若要停止所有任务读图，应停用来源或位置。修改使用范围会更新位置修订，旧扫描与登记不能继续写入，已登记样本和外部原图保留。

原地引用不创建独立托管原件；可选预览和完整原图缓存分别计量，完整缓存可重建并受额度/到期限制。托管复制新增平台独立原图副本。每次核验产生有界临时快照并及时清理。预检实际编码测量预览估算，未测或编码失败显示未知；登记分别列出新增原图字节、本轮路径已存预览和失败数，来源影响预览提供该来源当前账本合计及观测时间。预览失败不撤销已成功登记的原图，可重新核验并生成预览。关闭页面会保留已提交条目，重开可继续查看；预检和正式登记均可取消、继续，取消不会撤销已登记样本。单文件损坏或不可读会记录异常并继续处理其余图片，可按“仅显示异常”分页查看，修复后重试单项。尚未核验的文件允许显式重试读取当前内容；已有核验回执的文件始终校验原摘要，替换后的图片需重新扫描，不能通过重试改写旧身份。同来源、同相对路径重复操作返回已有样本；原地引用的不同来源保留独立业务身份；托管复制可复用同一数据集内已核验且实际可读的相同托管内容，来源路径映射仍分别保留。

工作台通过登录权限读取完整核验原图，加载完成前禁止编辑。按需策略下，同一内容的完整副本仍可用于来源自然离线或同名文件覆盖后的旧任务；缓存缺失或失效时须重新读取来源，原图无法核验则阻止保存。来源/位置停用和权限撤回仍拒绝读取及保存，已有标注保留。恢复来源后使用“重读原图”重试。标注员只获分配任务的读图权限，不获得整个目录浏览权限。删除样本或数据集、解除项目关联均不删除外部原图。

超级管理员可在**存储管理 → 位置详情 → 完整原图缓存**设置“按需原图”、额度和保留时间。默认额度为零，启用按需必须设置正额度；来源也选择按需策略后，首次成功读取并完整核验原图才尝试保留。额度只包含完整原图缓存，预览、托管原件与磁盘容量另计。用量分别显示上传中、已登记、待删除；满额优先淘汰未在读取中的旧副本，无法保留时仍可使用本次已核验的源快照。单图大于额度时不淘汰其他副本。

“请求清理原图缓存”会二次展示清理范围，确认后提交最多100份副本回收。正在读取或上传的副本不强清，实际删除前继续计费，失败由后台重试；新生成副本不属于旧观测的清理范围。保存缓存设置会更新位置修订，旧修订副本退出读取并逐步回收，因此来源离线前应完成所需配置并确认读图。样本检查器将来源历史状态、完整缓存记录与预览分开显示；“有完整缓存记录”不代表源已在线或对象此刻可读，仍需点击“核验读取原图”。

目录面板的“只读缓存预览”通过实时鉴权读取固定摘要派生，原图自然离线时仍可浏览；它不能用于标注或证明原图可读。无缓存策略不新增派生，旧回填及金字塔入口也不会另为目录独占样本生成缓存。关闭缓存策略立即停止该来源预览读取；已有缓存保留并单独计量，共享旧托管样本的既有缓存不归该来源删除。

来源的缓存修改、停用或恢复会更新修订；旧扫描与登记历史保留，继续登记需重新扫描和预检。停用可恢复，注销不可恢复。点击“查看停用/注销影响”，检查关联样本、任务、标注和缓存占用后确认；活动尝试会被取消，已有样本、任务与标注均保留。原地引用停止新读与后续标注，已经核验的在途标注事务先结束再完成停用；托管复制原图不依赖外部来源，停用或注销后继续可用。所有操作都不删除外部文件。删除平台样本/数据集只按精确对象键清理其预览。若存储清理失败、进程崩溃或提交结果未知，日志会保留对象键，需要运维核对数据库与该键后处理残留；当前没有自动垃圾回收器。

当前支持后台批量登记、逐条登记、普通图片预览、手工几何标注，以及[后台图片预标](../projects/ai-preannotate.md)的单阶段和 geometry/ROI 多阶段执行。预标按固定内容核验，输入临时副本在处理结束后回收；候选仍不等于人工标注。失败项可按原模型与原内容重试，普通几何候选及已发布受控实例分割模型的整图原生 Mask，经当前内容、生成记录和权限核验后可采纳；Mask 保留原始孔洞与断连区域，项目和部署须允许原生 Mask 编辑。旧记录缺少可信内容溯源时需重新预标。工作台也支持交互式提示、原生掩码创建/精修及采纳，模型设置中可运行预测测试；每次操作核验原图，旧掩码会话不能用于另一份内容。确定性批量掩码修复和局部 SAM 重跑也支持引用图片，执行、恢复、回滚及候选采纳均复核当前权限和固定原图；候选可驳回。引用视频/Tracker 重跑、跨任务传播、时序 scene、大图金字塔尚未接入引用内容，相关操作会拒绝或使后台任务明确失败。后台图片导出会严格核验并打包原图，详见[导出格式](../reference/export-formats.md#原地引用图片)。使用上传或复制托管数据可继续走已有能力。周期扫描需显式配置，默认人工接纳；后台扫描完成不表示全目录已登记或原图持续在线。

新增已挂载根内子目录，以及在 UI 登记该目录，都无需重启容器。新宿主机目录尚未映射进 API/worker 时，应由运维先补只读挂载；修改 Compose volumes 通常需要重建受影响容器，无需重建镜像。详见[受控位置](./storage-connections#已挂载目录的存储位置)。

## 外部 S3 原地引用

先在数据源连接器中配置允许使用的 S3 endpoint、桶、base_prefix 和只读凭据，再在数据集的“来源与同步 → 新增来源”选择该位置。填写位置下的相对前缀或浏览前缀，其余扫描、预检、确认登记及项目关联步骤与目录相同。API 和指定 worker 都须能连接该服务；不需要挂载宿主机目录或重建镜像。

S3 前缀和对象键按原始字符匹配，保留空格、中文、连续斜线、反斜杠和点段；服务本身可能拒绝某些键名，平台不会将其改写为其他键。扫描逐页保存检查点，取消或中断保留已提交页；完成只表示约定范围已枚举，不代表全桶同一时刻快照。预检读取完整内容后才能成为可登记图片。

平台使用服务返回的不可变版本读取原图；没有不可变版本时使用 ETag 条件请求，再完整校验 SHA。ETag 不作为内容摘要。若版本仍在，最新对象被覆盖不会改变已登记版本；没有固定版本时，源对象被替换将拒绝旧任务读图和保存。版本或对象被删除也不会删除已有索引、任务或标注。兼容服务不支持条件读取、返回部分原图或重定向到其他 endpoint 时会拒绝接入；不能用缓存替代原件继续标注。

原地引用不向平台写入原图；可选预览独立计量。选择托管复制时，平台使用安全的内部名称写入副本，精确源键仍保存在来源登记关系中，后续读取不依赖外部连接。外部来源操作始终不提供写入、改名或删除功能。

## SFTP 原地引用

先请运维配置专用只读 SFTP jail，并将精确服务器、账号及主机公钥登记为部署资格。连接器 Base path 填 `/`；整个账号可读范围都将作为该位置的授权范围，不能用来源子目录代替服务器隔离。只有符合当前部署资格的位置会出现在接入面板；普通 SFTP 连接器仍可用于原有复制导入。

在“来源与同步 → 新增来源”选择 SFTP 位置，浏览或填写相对目录，指定扫描 worker，之后按相同流程扫描、预检、确认登记和关联项目。中文、空格及字面加号/百分号可保留；父级跳转、绝对路径、符号链接与特殊文件不接入。每目录最多5000项，超限会明确失败。

每次使用原图仍会读取完整图片并核对摘要。来源变化或离线时保留样本和旧标注，拒绝继续使用原图标注；已有预览独立显示。停止或注销来源不会修改外部文件。更换服务器或主机公钥须由运维先禁用位置并协调各节点，历史样本不会自动指向新服务器。详见[部署说明](/ops/deploy/docker-compose#只读-sftp-引用)。

## 周期扫描与差异核对

在数据集“来源与同步”中选择已有来源，展开“周期计划”，填写15–10080分钟的间隔并启用。默认60分钟；后台按分钟检查，到期后由来源绑定的节点重新探测、扫描并预检。页面显示当前阶段、最近检查、下次计划和异常。目录、外部 S3 和合格只读 SFTP 沿用各自的部署与读取条件。

周期计划默认“人工确认”。也可在启用前选择“纯新增轮次自动登记”：只有整轮预检完整、无错误且仅含新增与未变化时，才自动登记新增路径，沿用来源指定节点读取与当前授权。任何变化、未见、排除或核验失败都会让整轮等待核对，不会先接纳其中的新增。策略在轮次开始时固定，后启用自动策略不会接管已开始的人工轮次。

人工策略下，发现新增、变化、未见、排除或核验失败后，会等待核对本轮差异，保留旧样本、任务和标注。可以在下方预检中确认仅登记新增；登记结束后继续下一周期。若此次不接纳，勾选“已核对本轮差异”，点击“跳过本轮差异，继续周期”；不会创建样本，也不会删除差异记录。只有相同项时自动等待下一周期。

“暂停周期扫描”停止后续触发，当前扫描或登记仍可完成；需要停止当前任务时，在任务面板单独取消。取消的任务不会被周期计划恢复，下一轮按间隔另建。停用整个来源会影响原地引用和在途任务，操作前应查看来源影响预览。

计划使用本次启用账号的当前管理权限；权限、凭据、来源配置或存储根身份变化后会停用并显示原因，核对后需重新启用。活动扫描或预检期间不能换执行账号或凭据，先完成或取消当前任务后重新启用。已完成的差异仍等待核对，重新授权不会跳过它；人工正式登记继续由确认人执行。节点繁忙或离线会延后，不补跑错过的周期；本功能采用固定间隔，可填写 IANA 显示时区，例如 Asia/Shanghai；计划与最近检查按此时区显示。间隔按实际分钟计算，1440分钟始终为24小时，不随夏令时调整，不支持日历定时或自动接受变化内容。

## 接受内容为新修订

同路径图片的实际内容变化后，在完整预检的“本轮增量差异”中点击该项“接受为新修订”。核对路径、旧样本、前后摘要和候选图片，勾选确认后接纳。一次只处理选中的一项；需要同时登记新增路径时，请先处理内容修订，再点“确认仅登记新增”。开始新增登记后，未处理的内容变化需重新扫描和预检。

接纳后，新样本在文件列表显示修订号；悬停可查看前驱样本。已关联的普通图片项目会获得空白任务，旧任务及标注保留，不自动继承。托管复制也创建独立业务样本。后续新关联项目会为数据集中保留的新旧样本都创建任务。

旧目录原图已经被覆盖时，旧任务可能无法读取，系统不会把新图配给旧标注。保留了不可变对象版本的外部 S3 或有合格完整缓存时，可以继续核验旧版本；管理预览缓存不代替旧任务原图。原预检分类与异常计数是历史记录，接纳结果另列；周期计划仍需核对并继续。

只有不同摘要的内容变化开放此操作。相同内容的观测变化可按下文重新核验；未见、排除和核验失败继续保留旧绑定；移动可按下文明确选择目标。候选或当前修订过期、来源暂停、权限撤回、文件再次改变会拒绝接纳，需要处理原因后重新扫描。

## 重新核验并保留样本

同一图片被按原字节重新写入、替换 inode 或修改时间后，严格读取可能拒绝旧观测。在完整预检的差异列表点击该项“重新核验并保留样本”，核对路径、前后相同的 SHA 和候选图片，勾选确认。

成功后仍使用原样本、原任务和原标注，只追加核验记录；不会新增空白任务或复制原图。已打开且读图失败的任务需要重新读取或重开页面。普通重扫和重试不会自动更新旧引用；来源资格变化仍需处理部署原因。需要登记新增文件时，请先完成重新核验，再确认仅登记新增。

## 移动后继续原任务

文件移到同一来源的其他目录后，重新扫描并完成预检。在旧路径的“本轮未见”行点击“选择移动目标”，从相同 SHA 的新增路径中明确选择目标，核对候选图片并勾选确认。可能存在多个同内容候选，平台不会自动选择。没有目标时保留原样本，可检查规则与路径后重扫。

成功后仍是原样本、任务和标注，读取改用已核验目标。界面在旧、新路径两行显示重定位结果；该目标不会再被新增登记重复接纳。请先处理移动再登记其他新增。旧目录路径日后重新出现时会作为新增候选，不自动改变已移动样本。跨来源或存储位置的搬迁不适用此操作；平台不会移动或删除源目录文件。

## 调整扫描范围

选择已有来源，在“调整扫描规则”修改是否包含子目录、图片匹配和排除规则，然后点击“预览规则影响”。预览只展示已接纳路径哪些仍在范围、将移出或重新纳入；扩大范围后的新文件数量要等重新扫描确定。活动任务须先结束或取消，再重新预览。

核对列表并勾选确认后保存。位置、来源相对路径、节点和所有权不能在此改向。保存后重新扫描、预检，已有周期计划须重新启用；旧检查点不能沿用。移出扫描范围不会删除样本、任务或标注，旧任务仍按原内容身份读取。新预检将这些旧路径列为“本轮排除”。

服务器目录和 SFTP 排除目录名会排除整个子树；外部 S3 规则按完整相对对象键匹配，例如排除 `dir/*` 才覆盖其下对象。规则区分大小写，每个输入框对应一条完整规则；逗号和首尾空格会原样保留。

## 扫描历史与存储位置入口

选择来源后，“扫描历史”分别显示最近完整扫描、当前执行任务和分页历史。最新一次失败或取消不会遮住以前的完整扫描；点击“查看最近完整扫描”可查看保留的条目和增量差异，历史页每页20次。历史详情、停用或注销来源仅供查看；继续处理请返回当前来源的最新有效轮次。任务入口复用后台任务详情，取消保留已提交结果。

在存储页“位置关联来源与后台任务”选择位置，可查看当前账号可见的来源数量和相关扫描、预检及登记任务。位置、来源与任务分别分页；点击来源进入对应数据集并自动选中该来源。其他数据集的管理权限不会因位置可见而开放。后台任务过期清理后，其扫描和差异历史仍保留。

已托管数据冻结出的训练版本保存独立快照、标注、媒体和打包文件。后续重扫、源文件变化或移除、接纳新修订及取消同步均不改变旧冻结版本；原地引用图片也可从关联项目创建训练版本：预检展示预计复制体量，构建时按固定 Asset 和 SHA 保存独立训练副本。源图片变化、移除或来源停用后，已就绪训练版本仍读取原有内容。详见[训练数据版本](../online-learning/data-versions.md#原地引用图片)。
