# 图像数据集导入

本页讲**图像文件怎么进数据集**:四种上传方式、ZIP 目录结构、支持的格式与上限、去重规则,以及导入后如何自动生成任务。

- 点云 / 多模态(lidar + 相机)导入见 [点云 / 多模态数据集导入格式](../datasets/import-formats)。
- 把**外部预测 / 标注**(COCO / YOLO / AAP JSON)导进项目、或清理已导入预测,见 [预测导入 / 导出](./prediction-import-export)——本页不展开这条链路。
- 导出标注成果见 [导出格式](../reference/export-formats)。

> **两条不同的链路,别混淆**:
> 本页的「图像导入」把**图片文件本身**灌进数据集(`dataset_items` + 对象存储);「预测导入」是另一条链路,往**已有 task** 上写标注 / 预测。先有数据集和图片,才谈得上导预测。

## 打开导入向导

进入顶部菜单「数据集」,在数据集列表里点「上传」(已有数据集在展开行点「上传」继续追加文件),打开导入向导。新建数据集时,第一步「选择来源」里选多文件、ZIP 包或连接器并配置来源;第二步「基本信息」里填写数据集名称、说明并选择数据类型(本页选图像)。已有数据集继续上传时直接从来源步开始,不经过新建信息步。

- **多文件** — 浏览器里直接选 / 拖入若干图片文件。
- **ZIP 包 (≤200MB)** — 上传一个 ZIP,后端解压并保留子目录结构。
- **连接器导入** — 从已配好的 S3 / OSS / SFTP 连接器按路径 + 通配符批量拉取。

![图像数据集导入向导](../images/datasets/import-images-wizard.png)

第四种是命令行的「扫描导入」(对已建好、对象存储里已有文件的数据集补建 item),见下文。

## 方式 A · 浏览器多文件上传

「多文件」标签里拖入或点击选择图片。每个文件走**预签名直传**:前端逐个向后端申请上传地址(`uploadInit`),直接 PUT 到对象存储,再回调 `uploadComplete` 入库;默认并发 3。

- **支持图像 / 视频 / 任意二进制**,单文件 ≤ 5 GiB（完成上传时由后端核验实际字节；文件类型按 MIME 推断:`image/*` → image、`video/*` → video、其余 → other）。
- 适合几十到几百个文件的零散上传。文件很多时改用 ZIP 或连接器导入。

## 方式 B · ZIP 上传(向导)

把一批图片打成 ZIP 上传,后端解压、逐个写对象存储并入库。这是图像数据集最常用的方式。

### 目录结构:顶层即图片,或保留子目录

ZIP 上传**保留 ZIP 内的子目录结构**；图片列表与导出沿用这些相对目录。同一逻辑路径已有不同内容时，文件名追加序号，避免遮盖旧样本。数据集改名不移动原图。两种布局都行:

顶层平铺:

```
images.zip
├── 001.jpg
├── 002.jpg
└── 003.png
```

按类别 / 来源分子目录(相对路径会保留):

```
animals.zip
├── cat/
│   ├── 001.jpg
│   └── 002.jpg
├── dog/
│   ├── 001.jpg          # 与 cat/001.jpg 同名,不冲突(见去重)
│   └── 003.jpg
└── bird/
    └── 010.png
```

解压时自动跳过:macOS 元数据目录 `__MACOSX/`、任意以 `.` 开头的隐藏文件(如 `.DS_Store`);拒绝绝对路径和含 `..` 的路径(zip-slip 防护)。这些被跳过的条目计入响应里的 `skipped`。

### 上限

| 限制项       | 值       |
| ------------ | -------- |
| 整个 ZIP 包  | ≤ 200 MB |
| 单个文件     | ≤ 100 MB |
| ZIP 内条目数 | ≤ 5000   |

超过整包上限返回 `413`,超过条目数也返回 `413`;单文件超限不阻断整包,该文件计入 `errors`(其余照常入库)。需要更大批量(数万文件 / 几百 GB)走**连接器导入**。

### 去重:按内容,不按文件名

去重以实际文件内容的校验结果为准，**不以文件名、路径或存储 ETag 认定重复**。因此:

- 跨子目录的**同名**文件(`cat/001.jpg` 与 `dog/001.jpg`)只要内容不同,都会入库——同名不冲突。
- **内容相同**的文件(无论文件名是否相同、是否在不同子目录)只保留第一个,其余计入 `deduped`。
- 已核验的同数据集文件支持重复内容识别；旧 hash 只作为候选，读取原件确认相同内容后才跳过。旧原件无法读取或证据不足时会保留新文件，不冒险丢弃。

### 看懂响应

上传完成后向导汇总后端响应,字段含义:

```json
{
  "added": 142, // 新入库的文件数
  "deduped": 6, // 内容重复、被跳过的文件数
  "skipped": 2, // 隐藏文件 / __MACOSX 等被规范化跳过的数
  "errors": [
    // 逐条失败明细
    { "name": "huge.tiff", "error": "超过单文件 100MB 上限" }
  ],
  "total_in_zip": 150, // ZIP 内非目录条目总数
  "linked_tasks": 142, // 若数据集已关联项目,本次顺带建的 task 数
  "scene_inference_notes": [] // scene 识别提示(图像普通导入一般为空)
}
```

判断成功:`added` 是真正入库数;`total_in_zip = added + deduped + skipped + errors.length`。`errors` 非空时逐条看 `name` / `error` 定位(常见是单文件超 100MB)。`scene_inference_notes` 只在识别 scene 时有内容(时序 / 多场景目录),纯图像平铺导入通常为空。

## 方式 C · 连接器导入(大批量)

数据量大(数万文件 / 几百 GB)或图片已在云存储 / SFTP 上时,用「连接器导入」:

1. 选一个可见连接器(普通项目管理员可用全局连接器 + 本人创建的个人连接器,超管可用全部)。
2. 填 `source_path`(连接器内的起始路径),勾选**递归扫描**(默认开),可用逗号分隔填 `include_globs` 过滤(如 `*.jpg, *.png`)。
3. 提交后导入作为**后台任务**运行,向导显示进度、成功数、跳过数和失败明细。

连接器导入使用独立的枚举预算，代码默认值如下：

| 限制项     | 默认值  | 覆盖用环境变量                   |
| ---------- | ------- | -------------------------------- |
| 最大文件数 | 50000   | `DATASET_IMPORT_MAX_FILES`       |
| 最大总字节 | 200 GiB | `DATASET_IMPORT_MAX_TOTAL_BYTES` |

超级管理员可在「设置 → 系统设置 → 数据导入」查看部署有效值并保存覆盖。作业受理时固定预算，枚举超限会**整体失败，不产生本次部分导入**；修改设置不会改变已排队或重试作业的预算。连接器的创建、主机白名单、密钥加密等配置见 [数据源连接器](./storage-connections)。

## 方式 D · 扫描导入(命令行 / 已有对象)

如果文件已经在对象存储里(例如外部流程直接写进了桶),对该数据集触发 `POST /api/v1/datasets/{id}/items/scan`,后端在固定扫描根中为缺失的文件补建 item。升级前数据集保留升级时的名称根；新建数据集使用独立存储根，具体写入约定见[数据集 API](/api/guides/datasets#扫描)。改名不改变扫描范围，重复扫描不重复登记。扫描只建立索引，不将 ETag 当作已核验内容。适合「对象先到、item 后补」的场景,日常 UI 导入用不到。

## 支持的图片格式

ZIP / 多文件路径不维护一份硬编码扩展名白名单,而是按 MIME 推断类型:`image/*` 归为 image、`video/*` 归为 video、其余归为 other。因此浏览器和操作系统能识别为图片 MIME 的常见格式都能进——`.jpg` / `.jpeg` / `.png` / `.bmp` / `.gif` / `.webp` / `.tiff` 等。能否在工作台正常**渲染标注**取决于浏览器对该格式的支持(JPEG / PNG / WebP 最稳;TIFF 等部分浏览器不直接显示)。入库时会为图像读取宽高并异步生成缩略图。

## 导入后:自动建任务

数据集**关联到项目后**,每个数据条目自动生成一个 task(初始状态 `pending`),进入该项目工作台待标注。两种触发时机:

- **首次关联**(`link`):按条目数决定快慢路径——条目数 ≤ `TASK_CREATE_SYNC_THRESHOLD`(默认 **2000**)在关联请求里**同步**建 task;**超过**阈值改为**后台异步**建 task,关联界面显示进度条,**建完之前这批任务在工作台还看不到**。
- **关联后继续追加**:已关联的数据集再上传文件、上传 ZIP、扫描导入或连接器导入,**新增文件同步建 task**,无需先取消关联再重新关联。

超级管理员可在「系统设置 → 数据导入」修改首次关联的同步阈值。数量等于阈值时仍同步，设为 0 时所有非空数据集首次关联都转后台；已排队的作业保持原执行方式。

> 首次关联转入后台后若工作台暂时空着，需等待关联界面的建任务进度完成，不必重新关联。

## 服务器目录原地引用

超级管理员先在**存储管理 → 受控目录位置**登记部署者已挂载的根内相对目录，并选择“仅指定的数据管理员”或“所有数据管理员”；指定人员支持按姓名、邮箱搜索。超级管理员及获位置授权的项目管理员可在**数据集 → 接入服务器目录**创建普通图片数据集。项目管理员仅管理自己创建的数据集。已有非时序图片数据集展开后也有“服务器目录 · 登记与复制”面板。本机文件夹、多文件、ZIP 和连接器复制导入继续使用原入口。

1. 输入数据集名称，创建空图片数据集。
2. 选择已登记且启用的存储位置，填写位置下相对目录，或用“浏览目录”选择。根句柄由运维配置，不能输入任意宿主机绝对路径。
3. 填写负责扫描的完整 worker hostname，按需包含子目录，设置逗号分隔的图片匹配规则和排除规则，点击“配置目录来源”。规则区分大小写、相对来源根匹配；例如 `excluded` 排除整个同名子目录，`temp/*` 排除其中文件。该节点必须挂载同一目录并通过探测。
4. 原图策略选择“原地引用”（默认，不复制原图）或“托管复制”；缓存独立选择“预览缓存”（默认）或“无缓存”，位置的缓存上限优先。托管复制从只读来源读取，经 SHA 核验后写入平台独立对象。点击“只读预扫描”。扫描在后台运行；完成后按页查看文件的相对路径和观测字节。失败或取消时可恢复，目录发生变化时需重扫。
5. 点击“运行接入预检”。后台读取图片，核验 SHA-256、格式和尺寸，分别展示已索引、待核验、已核验待登记、原已登记路径、预计新增、异常和排除数。预检不创建样本。检查结果及体量后勾选确认，点击“确认批量登记”。实际服务请求的 API 节点也必须能读到该目录；正式登记逐项重新读取固定摘要，支持 PNG、JPEG、WebP 单帧图片，每张最多64MiB、3200万像素。少量图片也可继续逐条“核验并登记”。
6. 返回列表展开数据集，在文件列表点击“核验预览”。通过既有“关联项目”接入普通图片项目，生成任务；后续新增登记也会给已关联项目补任务。

已有目录来源的普通图片数据集仍可混合上传文件、ZIP 或复制导入。ZIP 不自动创建 Scene，以便继续登记原地图片；这些写入在耗时读写后复查账号和初始凭据，撤权后保留已提交部分。

撤回位置使用权后，项目管理员不能再浏览、扫描、登记或管理预览；既有任务仍按分派和成员权限读图。若要停止所有任务读图，应停用来源或位置。修改使用范围会更新位置修订，旧扫描与登记不能继续写入，已登记样本和外部原图保留。

原地引用只增加元数据及明确选择的派生预览，原图持久复制量为0；托管复制新增平台原图副本。每次核验产生有界临时快照并及时清理。预检实际编码测量预览估算，未测或编码失败显示未知；登记分别列出新增原图字节、本轮路径已存预览和失败数，来源影响预览提供该来源当前账本合计及观测时间。预览失败不撤销已成功登记的原图，可重新核验并生成预览。关闭页面会保留已提交条目，重开可继续查看；预检和正式登记均可取消、继续，取消不会撤销已登记样本。单文件损坏或不可读会记录异常并继续处理其余图片，可按“仅显示异常”分页查看，修复后重试单项。尚未核验的文件允许显式重试读取当前内容；已有核验回执的文件始终校验原摘要，替换后的图片需重新扫描，不能通过重试改写旧身份。同来源、同相对路径重复操作返回已有样本；原地引用的不同来源保留独立业务身份；托管复制可复用同一数据集内已核验且实际可读的相同托管内容，来源路径映射仍分别保留。

工作台通过登录权限读取完整核验原图，加载完成前禁止编辑；源文件变化、来源停用、挂载不可达或权限撤回时显示错误并阻止保存，已有标注保留。恢复来源后使用“重读原图”重试。标注员只获分配任务的读图权限，不获得整个目录浏览权限。删除样本或数据集、解除项目关联均不删除外部原图。

目录面板的“只读缓存预览”通过实时鉴权读取固定摘要派生，原图自然离线时仍可浏览；它不能用于标注或证明原图可读。无缓存策略不新增派生，旧回填及金字塔入口也不会另为目录独占样本生成缓存。关闭缓存策略立即停止该来源预览读取；已有缓存保留并单独计量，共享旧托管样本的既有缓存不归该来源删除。

来源的缓存修改、停用或恢复会更新修订；旧扫描与登记历史保留，继续登记需重新扫描和预检。停用可恢复，注销不可恢复。点击“查看停用/注销影响”，检查关联样本、任务、标注和缓存占用后确认；活动尝试会被取消，已有样本、任务与标注均保留。原地引用停止新读与后续标注，已经核验的在途标注事务先结束再完成停用；托管复制原图不依赖外部来源，停用或注销后继续可用。所有操作都不删除外部文件。删除平台样本/数据集只按精确对象键清理其预览。若存储清理失败、进程崩溃或提交结果未知，日志会保留对象键，需要运维核对数据库与该键后处理残留；当前没有自动垃圾回收器。

当前支持后台批量登记、逐条登记、普通图片预览与手工几何标注。原生掩码处理、预测与采纳、跨任务传播、时序 scene、大图金字塔、训练冻结和后台导出尚未接入引用内容，相关操作会拒绝或使后台任务明确失败。使用上传或复制托管数据可继续走已有能力。周期同步尚未提供；后台扫描完成不表示全目录已登记或原图持续在线。

新增已挂载根内子目录，以及在 UI 登记该目录，都无需重启容器。新宿主机目录尚未映射进 API/worker 时，应由运维先补只读挂载；修改 Compose volumes 通常需要重建受影响容器，无需重建镜像。详见[受控位置](./storage-connections#已挂载目录的存储位置)。
