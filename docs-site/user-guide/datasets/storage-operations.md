# 存储诊断与容量账目

> 适用角色：项目管理员（查看所管来源的诊断、故障观测与存储任务进展） / 超级管理员（查看全平台诊断、对象占用盘点、增量账目对账与视频派生重试）

本页介绍如何在 **存储管理**（`/storage`）中查看位置内的来源诊断、当日原图不可读率与预览失败率、去重故障观测、后台存储任务的已提交进展，以及平台九用途对象存储的容量盘点与净变化增量账目。

## 位置内的来源诊断

在 **存储管理 → 位置** 打开任意存储位置的居中详情，展开 **来源诊断**。点击 **刷新诊断** 仅重新读取数据库中的持久记录，**不会访问外部原件、不会扫描目录，也不会触发预览生成**。

- **当前已采纳源索引规模**：覆盖本位置内当前用户有权查看的全部已采纳来源文件（含原地引用与复制接入），不随下方来源列表翻页而变化。同一文件跨多个数据集或父子来源重叠时只计 1 次；不同路径的文件即使 SHA-256 相同也分别计量，不同 S3 对象版本分别计量。若缺少一致证据、存在同址内容冲突或节点不可比较，则显示已确认部分与“总量未知”。注意：这是外部源文件的逻辑规模，**不能与平台对象存储字节相加**，也不代表磁盘物理占用或原件此刻实时可读。
- **每个来源的三维观测明细**：
  1. **原件最近观测**：统计已登记的原地引用业务样本（含保留的历史修订，不含托管复制与未登记文件），区分为**已验证、待验证、失踪、内容变化、不可读**并附最近观测时间。
  2. **预览生成记录**：区分为**已有记录、生成失败、未生成或记录失效、未启用、已停用**。“没有预览”不代表原件损坏；“已有记录”也不保证预览对象此刻仍在桶内。
  3. **扫描与预检**：展示当前活动轮次（或恢复中的旧轮次）及最近完成轮次的时间、完整性与“配置匹配 / 历史配置”标记。点击 **查看轮次** 可跳回数据集来源页，点击 **任务详情** 居中查看后台任务；页面同时展示该来源已声明的[来源原件保护责任](./sources#来源原件保护责任)。

## 原图不可读率与预览失败率

在位置详情的 **来源故障观测** 面板顶部，系统汇总展示当日（**UTC 零点至当前服务器观测时刻**）的两项核心健康指标，筛选下方故障状态或翻页不会改变这两项汇总：

| 指标名称         | 分子 / 分母统计口径                                                                 | 排除范围（不计入尝试分母）                                                   | 零分母或缺失处理                                |
| ---------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------- |
| **原图不可读率** | 已记录的授权完整回源读取中，失败次数 / 尝试总数（预检登记时的两次安全复读分别计数） | 按需完整原图缓存命中、目录列举、位置短探针、因撤权/取消/配置变化未收尾的操作 | 显示为 **未知**（绝不将无尝试分母当作“零失败”） |
| **预览失败率**   | 实际新生成并最终发布预览的尝试中，失败次数 / 尝试总数                               | 复用已有预览、未开启缓存策略、最终事务回滚的操作                             | 显示为 **未知**                                 |

> **指标解读边界**：这两项比率是基于已记录尝试的当日窗口观测值，用于发现回源读取或编码异常趋势，不能直接等同于底层文件损坏比例、全量请求成功率或位置的实时在线证明。

## 来源故障观测

在 **来源诊断 → 来源故障观测** 中，管理员可按 **未恢复**、**已恢复** 或 **全部** 筛选并独立翻页（点击 **刷新故障观测** 仅查询数据库状态）：

- **同行持续失败合并**：每条记录展示故障类别、所属来源、操作类型、首次/最近失败时间及累计失败观测次数。同一来源与内容范围的重复失败会自动合并计数，避免刷屏堆叠。
- **严格的“已恢复”判定**：仅当**相同目标、相同操作与相同内容范围**后续实际执行成功并通过完整性核验时，记录才转为“已恢复”。命中原图缓存、邻近文件读取成功或采纳了不同内容的新版本，均不会清除原故障；配置或内容已变更的旧范围会标为“历史”。
- **角色分工与审计联动**：根目录不可用、存储访问被拒绝默认提示由**平台管理员**处置；原件内容变化、预览生成失败默认提示由**数据集管理员**处置（任务发起者或备份责任声明人不自动成为故障认领人）。项目管理员仅可见所管来源，超级管理员可见全部（含孤立保留来源），并可点击 **查看此来源故障记录** 跳转至[审计日志 · 存储故障关联](../superadmin/audit-logs#存储故障关联)。

## 存储任务的已提交进展

从右上角任务铃、来源扫描轮次、容量盘点或迁移记录打开居中 **任务详情**，可查看扫描、预检/登记、容量盘点、迁移清单及复制任务的 **已提交进展（Committed Progress）**：

- **真实持久化推进**：界面展示的阶段、已处理单位计数和最后记录时间均来自 Worker 实际完成并提交落库的处理批次（即使总百分比尚未跳动，也可能已推进了新目录或新分页）。排队等待时长与执行时长分开展示；**纯心跳、刷新弹窗、续租或权限检查不会刷新“最后推进时间”**。
- **15 分钟无进展核实提示**：当运行中的任务超过 **15 分钟**未提交任何新的持久化进展时，详情弹窗会显示处置角色核实提示（排队等待阶段不触发该提示）。此提示**不代表任务已死锁**，系统也不会因此自动取消任务、重试、删除数据或恢复位置访问。管理员应先核对当前阶段、队列与执行 Worker 节点，再按[Celery Worker 卡住排查手册](/ops/runbooks/celery-worker-stuck#存储任务的无进展提示)检查底层存储访问与未收尾责任。

## 平台对象占用与后台盘点

超级管理员可在 **存储管理 → 平台对象占用** 查看当前部署配置的九用途存储桶容量快照，点击 **查看各桶统计与时间** 展开各桶对象数、字节数与采样时间窗口（多个用途共用同一物理桶时合并显示并只计 1 次；已单独切往外部位置的用途会明确提示未纳入默认九桶小计）。

### 六类平台对象归属拆解

盘点任务按数据库保存的地址或受控归属前缀，将桶内实际列举到的当前可见对象拆分为以下 6 类（已包含在对象总量内，不可重复相加；外部源索引规模单独展示）：

| 对象分类            | 覆盖内容与计量规则                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------- |
| **1. 托管原件**     | 数据集托管原件、独立任务原件与原始 LiDAR/地图辅助文件（同一物理对象被多样本引用只计 1 次）。 |
| **2. 预览与缓存**   | 按需完整原图缓存、目录预览、普通缩略图、高清图片金字塔与视频派生资产。                       |
| **3. 训练版本文件** | 训练数据版本归属下准备中与已保留的全部实际文件（含冻结快照、清单与最终 ZIP）。               |
| **4. 临时产物**     | 导入暂存、AI 预标临时输入等受控暂存对象。                                                    |
| **5. 其他平台对象** | 导出产物、头像、报告附件、评论附件、指南图片、持久 RLE 掩码、压缩审计归档等。                |
| **6. 未归类**       | 桶内实际存在但缺少可信数据库归属或出现跨分类冲突的对象（保留字节计数，绝不隐式丢弃）。       |

### 盘点状态与操作说明

- **只读刷新 vs 后台重新盘点**：点击 **刷新状态** 仅读取已保存快照；点击 **重新盘点** 才创建后台分页列举任务（按页保存检查点，中断后由后台租约自动续跑，重复点击返回同一活动任务）。
- **四种快照状态**：区分 **尚未统计**（未知）、**成功为零**（确认空桶 `0 B`）、**过期或失败**（距上次采样超 24 小时或最近失败，保留旧值并标过期）与 **部分覆盖**（仅部分桶完成时合计保持未知，全部配置桶均有成功快照后才计算总计）。盘点仅统计采样窗口内 S3 当前可见对象（不含历史版本、删除标记、未完成分片或底层副本开销）。

## 容量净变化增量账目与周期对账

展开 **增量账目与周期对账**，超级管理员可查看自上次盘点基准以来，平台各受控写入（Producer）与受控清理（Deleter）产生的已确认容量净变化（`confirmed_added_bytes` / `confirmed_removed_bytes`）及未决操作（`unknown`）。

### 受控写入与清理记账覆盖表

只有当存储端返回明确的单次条件写入或准确版本删除回执、完整内容与前后当前对象状态核验一致，且底层流与许可真正收尾后，系统才将字节变化记入“已确认”；凡遇 SDK 重试、无版本/`null` 版本、回执丢失、并发覆盖或收尾不明，一律保守记入 **`unknown`（未知）**，绝不靠业务任务成功或预约大小去臆测物理字节变化：

| 业务域与对象类别                                                   | 受控新增记账（`confirmed_added_bytes`）                                                                                          | 受控移除/覆盖净变化（`confirmed_removed_bytes` / 净差值）                                                                       | 记为 `unknown` 或不计入的边界情况                                                    |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **AI 预标临时输入**                                                | 单次条件写入并核验完成后确认新增字节                                                                                             | 按固定版本删除并核实前后状态后确认移除字节                                                                                      | 重试、回执缺失或未执行删除的提前返回                                                 |
| **托管原件**（直传、ZIP、连接器/目录复制、Task、辅助原件）         | 仅计最终受控创建的原件字节（核验不可变版本与完整内容后确认）                                                                     | 通过[受控回收准确版本](./lifecycle-and-retention#受控回收准确版本)物理删除且无旧版本回露时确认移除                              | 浏览器暂存、准备中分片、逻辑删除/退役记录本身不产生移除确认                          |
| **派生媒体缓存**（缩略图、完整原图缓存、金字塔、视频派生）         | 每个实际写入并核验收尾的缓存对象独立记录新增                                                                                     | 缩略图按准确版本删除确认净变化；完整缓存、金字塔、视频派生按键级删除标记（delete marker）及前后状态核验确认当前内容减少或零变化 | 若删除当前版本后显露旧版本，净变化可能增加或为零；缓存到期退休记录本身不等于物理删除 |
| **独立导出媒体包**（图片、视频、点云复制）                         | 每个复制写入的对象独立记账（多对象部分失败或后续业务拒绝不抹去已发生写入）                                                       | 按准确版本删除且前后当前内容证据完整、资源收尾后确认净变化（删非当前版本净变化为 `0`）                                          | 版本不固定、回执丢失或清理任务中途未收尾                                             |
| **导出 ZIP 包**                                                    | 保留分段上传；核验准确版本、完整内容与前后状态后，按新旧当前可见字节计净变化（同键等长覆盖为 `0`）                               | 按键级清理（含独立与关联媒体两种入口）核验唯一删除标记与前后状态后确认当前内容减少                                              | 分段上传临时分片、历史版本占用及 SDK 重试导致的回执不明均记为 `unknown`              |
| **问题报告附件**                                                   | 单次条件写入、准确版本与完整内容核验收尾后确认新增（后续发布失败不抹去物理写入）                                                 | 按准确版本删除、核验引用/租约/缺失并收尾后确认净变化                                                                            | 重复提交条件失败不否定早先写入；附件退休状态不等于已确认移除                         |
| **头像、评论附件、指南图片、持久 RLE 掩码、审计归档**              | 按实际保存文件字节计量（压缩 RLE/归档按压缩后字节计）；已有对象直接复用计为 `0`                                                  | 头像按准确版本删除确认净变化；其余保留类对象业务行删除或退休不补算移除量                                                        | 无版本、重试或回执不明记为 `unknown`                                                 |
| **服务端训练文件**（冻结训练包、主动学习图片、评估报告、脱敏日志） | 核验完整回执、准确版本与前后状态后，计新旧当前对象大小之差（覆盖缩小可为负，直接复用为 `0`；冻结文件需等整轮临时目录与许可收尾） | 当前仅计覆盖引起的可见大小差值，历史清理尚未计入增量移除账目                                                                    | 训练执行器预签名直传与浏览器暂存未纳入；缺版本历史读取权限或发生重试时记为 `unknown` |

### 周期对账调度（1–168 小时）

增量账目为部分覆盖观测，不能直接替代全桶盘点（未接入的生产者、云厂商自动生命周期规则或外部直接写入会形成未解释差异）。因此超级管理员可配置**周期盘点对账**：

- **开启与间隔配置**：周期盘点默认关闭。超级管理员可显式开启并设置 **1 至 168 小时**（默认 **24 小时**）的调度间隔；开启后尽快触发首轮盘点以建立对象级基准，后续完整成功轮次即可与增量账目比对。若已有盘点任务正在运行，调度器不会重叠启动第二轮。
- **暂停与关闭**：点击关闭仅停止后续定时调度（在途任务可在任务详情单独取消）。当管理员权限或存储配置发生变化时，周期计划会自动暂停，核对修正后需显式重新开启。

## 视频派生资产失败重试

在 **存储管理** 页的 **视频资产失败** 区域，管理员可查看生成失败的视频派生记录并点击 **重试**：

- **共享任务详情与分项结果**：点击重试后自动打开居中任务详情，实时展示当前处理阶段及最终成功/失败计数；关闭弹窗后自动刷新失败列表（也可从右上角任务铃或完成通知重新打开）。视频海报（poster）与时间表/元数据分别独立展示重试结果——元数据生成成功不代表海报已恢复；若元数据尚未就绪，视频分块与帧缓存继续保持等待提示。
- **投递确认与不可取消约束**：若队列投递尚未确认，可返回失败列表重新点击重试；一旦任务进入执行，界面不提供取消按钮。若执行端状态未知，任务会保留等待提示，需核实原媒体输出的处理状态后再处置。
