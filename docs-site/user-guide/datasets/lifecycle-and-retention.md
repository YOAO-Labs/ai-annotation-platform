# 原件访问、归档与保留回收

> 适用角色：项目管理员（数据集归档与恢复、认证原件下载） / 超级管理员（托管原件保留预演、期限与保留要求设置、完整内容核验与准确版本回收）

本页介绍数据集生命周期（归档与恢复）、托管原件的受控创建与认证读取，以及业务删除数据集或样本后，平台如何通过独立保留账本保护托管原件并执行可审计的准确版本回收。

## 数据集归档与恢复 {#归档与恢复}

数据集列表默认展示活动数据集，可通过 **数据集状态** 筛选器切换到“已归档”或“全部”（筛选、分页与返回上下文保存在 URL 中）。归档数据集的详情深链仍可打开，样本、来源历史、项目任务、标注与关联训练版本均完整保留。

- **五分钟预览与确认归档**：数据集创建者或超级管理员可在数据集详情点击归档预览，核对样本、来源、项目/任务、活动作业及已记录的冻结训练版本依赖后，在 **5 分钟内**确认归档（权限、配置、关系或生命周期变化后需重新预览）。统计中的冻结版本仅覆盖已保存数据集归属的样本，计数为 `0` 不代表没有历史冻结内容。
- **归档后的读写边界**：归档后禁止继续上传/导入、修改成员或配置、关联/解绑项目、运行来源写操作、创建质量检测/复核委托，或将归档样本加入新训练版本。**已有项目任务仍按当前项目权限正常读取与标注**；已创建的冻结训练版本继续打包、下载和用于训练。平台绝不删除或改写外部原件，个人阅读视图仍可保存。
- **恢复活动状态**：恢复操作仅将数据集重新设为活动状态，**不会自动恢复**已撤销的人员/位置/项目权限、API Key 或同步委托。归档前排队的导入、建任务、扫描/登记、质量作业和自动同步不会随恢复自动续跑，需在当前权限下显式发起新一轮操作。归档数据集若需执行业务删除，必须先显式恢复为活动状态。

## 按已核验身份下载托管原件

面向集成程序与评测脚本的[认证原件下载接口](/api/guides/verified-content#认证通用原件下载)支持先查询 `DatasetItem`、`TaskOriginal`（独立任务原件）或相机关联文件的内容身份，再按已核验身份下载完整原始字节。

- **按保存定位完整核验**：下载始终读取原件记录自身保存的物理位置并校验全部字节，后续调整用途映射不会改变已有原件的读取目标。查询内容身份返回“可用性未检查”仅代表元数据存在，若权限撤销、文件内容变化或位置处于维护停止状态，实际下载会明确失败。
- **单文件上限与媒体分流**：通用认证下载单文件上限为 **512 MiB**，原样交付点云、视频及其他已核验文件的原始字节（不用于原生视频流式拖动播放）。标注工作台的图片预览（单张严格图片读取上限 64 MiB）与原生视频播放租约各自沿独立合同运行；外部原地引用图片继续走严格图片读取，不会自动转换成托管原件。
- **浏览器与模型服务签名域名隔离**：若浏览器能正常看图而模型推理报下载失败，请管理员分别检查浏览器公共访问地址与模型容器可达的对象存储 Host。两者在签名前按调用方角色独立选择，切勿手工篡改已签名 URL 的域名；详见[部署签名契约](/ops/deploy/docker-compose#对象存储访问与签名契约)。

## 新托管原件的创建与直传隔离

无论是数据集导入还是独立任务上传，平台对所有新创建的托管原件均实行**暂存隔离 + 条件创建 + 完整回读核验**：

1. **浏览器直传暂存隔离**：浏览器获取的预签名上传 URL 仅指向导入暂存区（`import` 用途）。前端上传完成并回调后，后端先完整读取暂存对象计算 SHA-256 摘要，再向最终原件位置执行**条件创建（Conditional PUT）**并完整回读确认。重复向旧上传 URL 发送请求只会修改暂存区，绝不可能覆盖已接受的最终原件。
2. **多渠道统一回执**：ZIP 解压、远端连接器复制和受控目录托管复制均走同一受控创建流程。每次创建持久保存存储服务端返回的成功回执（含不可变 `version_id`）与内容证据，核验通过后才关联业务样本。
3. **未决创建责任保护**：若遇内容去重、业务事务回滚或提交结果不明，已创建的物理对象由独立持久账本继续记录，不会立即盲目删除，也不会对结果不明的同一最终键自动重试覆盖（连接器导入已消费的源字节仍计入本轮预算）。历史存量原件与只读扫描登记没有创建回执，系统不会因内容相同而伪造回执，真实版本号与缺失版本分别保存。

## 托管原件保留与回收预演

删除托管数据集或单个样本时，平台在**同一个数据库事务**中捕获已登记托管原件的物理位置记录，写入独立的保留账本。因此，业务层的逻辑删除**不会立即删除底层对象存储中的原件**；未指定保留期限时默认按**无限期保护**（`retain_until = null`）处理。

超级管理员可在 **存储管理 → 平台对象占用** 展开 **托管原件保留与回收预演**（只读查询数据库，不扫描桶、不探测原件、也不提交删除任务）。每条位置记录按保护状态分为三类：

| 状态分类         | 判定规则与阻断说明                                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **仍有保护要求** | 发现当前样本、内容位置、任务、任务数据集关联、保留训练快照（含失败/取消快照）、主动学习历史或同组记录上存在有效保留要求（`declared_holds`）。 |
| **保留中**       | 无上述活动引用或显式保留要求，但本条或同组相关记录的共同保留期限（`retain_until`）尚未到期，或仍为无限期保护。                                |
| **资格待核实**   | 保留期限已过且无引用阻断，但仍需核实创建回执、完整内容证据或位置维护排空状态。仅满足策略期限不等于可以直接物理删除。                          |

> **统计口径说明**：保留预演以“位置记录”为单位（仅覆盖删除数据集或样本时捕获的已登记托管原件，不回填升级前已丢失的未知旧位置）。同一物理对象若对应多条位置记录会重复累计字节；未知大小单列展示，不换算为“可释放磁盘容量”。

## 显式保留期限与声明要求

在保留原件的居中详情展开 **保留设置与要求**，超级管理员可管理保留期限（`retain_until`）与显式保留要求（`declared_holds`）。平台按**同桶同键（Same Bucket + Same Key）**将相关记录保守归组（可能跨不同 endpoint）：组内任一记录设为无限期则整组无限期，否则共同保护至最晚到期时间。

- **调整本条期限（`retain_until`）**：可设为无限期或未来截止时间（按界面注明的浏览器时区输入并保存为带时区时间戳）。填写原因后先预览再确认；若缩短无限期或既有期限，系统会明确提示风险。确认时若时间已过或同组策略已变，须刷新后重新预览。
- **登记与解除保留要求（`declared_holds`）**：用于登记备份保留或迁移观察责任。填写内部引用编号（仅限字母、数字及 `. _ : -`，禁止填写路径、URL 或密钥）与原因后生效，持续保护同组全部记录，不会随时间自动解除。只有原登记记录可执行解除（其他同组记录提供“打开登记记录”跳转），解除前同样需填写独立原因并预览确认。
- **保护边界**：引用编号只是管理声明，不证明外部备份已存在或可恢复；这些设置也不是底层 S3 Object Lock，不涵盖外部只读源、媒体缓存或训练副本。

## 核验原件完整内容

在原件详情展开 **完整核验** 区域，超级管理员可显式发起后台完整内容核验并查看分页历史（展开或刷新历史仅查数据库）：

- **后台全字节校验**：Worker 重新读取完整对象（单次上限 **5 GiB**，协作读取预算 **60 秒**），将实际读取的 SHA-256 与字节大小同该记录的可信历史内容比对。若缺少可信历史摘要、存储身份不匹配或超出预算，界面直接显示阻断原因而不读取对象。
- **不可变核验历史**：结果区分为**本次相符（`matched`）**、**对象或内容变化（`changed`）**、**对象缺失（`missing`）**、**无法核验（`incomplete`）**、失败及取消。“本次相符”仅代表该观测时刻一致，不保证此后同名键未被外部替换。
- **并发与中断保护**：等待中的任务可显式重派；运行中取消会等待底层读流与客户端真正收尾后才进入终态。若 Worker 进程异常退出导致流关闭状态不明，未收尾责任将持久保留并阻止重复核验，须由运维核实执行端，严禁通过手工删表绕过。

## 受控回收准确版本

仅当托管原件需要物理销毁时，超级管理员可在原件详情展开 **受控回收**，填写原因并执行预览。平台仅允许对满足以下**全部前置条件**的准确对象版本（Exact Version）执行物理删除：

1. **具备可信创建与版本证据**：必须拥有条件创建回执、完整内容核验记录及明确的不可变 `version_id`。无创建证据、未开启桶版本控制或 `null` 版本的历史对象一律阻断回收并继续保留。
2. **零活动引用与期限届满**：同桶同键整组记录的保留期限必须全部到期，且不存在任何样本、任务、训练快照、主动学习记录、原地引用别名、有效保留要求（`declared_holds`）或未完成迁移保护。
3. **所在位置已停止访问并排空**：原件所在的存储位置必须已关闭新访问且在途读取排空为 `0`——已登记外部位置使用[位置访问维护](./storage-connections#位置访问维护)，默认平台托管位置使用[迁移维护窗口](./storage-migration#迁移维护窗口)。

确认回收后，后台任务会**先最后一次完整回读并核验该版本的 SHA-256 与大小**，确认无误后才调用精确 `version_id` 删除并验证该版本已缺失（同名键下的其他版本不受影响）。回收任务一旦认领即拒绝新的同址引用；在删除回执与流关闭责任完全结清前，禁止恢复位置访问或关闭维护窗口。

## 周期引用核对 {#周期引用核对}

系统每天自动运行一次**周期引用核对**（`reconcile`），超级管理员也可在界面点击 **立即核对**。

- **只读数据库对账**：核对任务仅扫描数据库中的业务引用与保留账本关系，汇总最近成功时间、实际引用数、保留计数、未知覆盖范围及有界变化摘要。
- **不自动触发写删**：周期引用核对不会扫描底层对象存储桶，不会自动修改保留期限，更不会自动删除任何物理对象。每次执行[受控回收准确版本](#受控回收准确版本)前，系统始终实时重新检查全部保护条件，绝不直接拿上次周期核对的快照代替实时准入检查。
