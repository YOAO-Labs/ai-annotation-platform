# 存储位置与连接器

S3 endpoint 只填写服务地址，用户名和密码放入密钥字段；地址内嵌凭据会被拒绝，历史读回会移除该部分。配置拼写错误也会直接报错。SFTP 密码与私钥二选一，须匹配所选认证方式。超级管理员保存显式空主机白名单将拒绝所有连接目标，恢复部署默认应删除覆盖。

> 管理连接器：项目管理员 / 超级管理员。所有活跃账号都可使用 `global` 连接器；`owner` 连接器仅创建者和超级管理员可使用。`owner` 创建者即使后来变为 employee 或 viewer，仍可编辑或删除自己创建的连接器。

左侧导航 **存储管理**（`/storage`）提供统一的存储控制台，集中管理受控目录、远端连接器、跨网络站点、用途映射、容量账目与迁移准备。进入具体操作前，先区分四个核心概念：

| 概念                                 | 职责与边界                                                                                                                                       | 典型入口                                                                |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| **存储位置（Storage Location）**     | 登记平台可控访问的物理或逻辑根（服务器受控目录、Agent 受控根、全局对象存储位置），记录分节点探测健康、人员授权、原图缓存配额与维护状态。         | **存储管理 → 位置**                                                     |
| **存储连接器（Storage Connection）** | 保存外部对象存储（`s3`：AWS S3 / 阿里云 OSS / MinIO / 腾讯云 COS 等）或 `sftp` 服务器的端点与加密凭据，用于按路径复制导入或挂载只读来源。        | **存储管理 → 位置 → 新建远端连接**                                      |
| **九用途映射（Purpose Binding）**    | 定义平台 9 类托管数据（数据集原件、媒体缓存、导入暂存、导出、标注文件、训练文件、头像、报告附件、审计归档）后续**新分配写入**的目标位置。        | **存储管理 → 用途映射**（见[九用途映射与受控切换](./purpose-bindings)） |
| **已保存目标（Saved Target）**       | 每个已创建对象或业务记录自身持久保存的物理定位（endpoint、bucket、key、version）。读取和清理始终按已保存目标执行，不会因当前用途映射切换而改向。 | 位置详情 → **维护影响**                                                 |

## 存储位置列表与持久健康

进入 **存储管理 → 位置**，S3 / SFTP 连接器与已挂载目录在同一全宽列表中按名称、类型和状态展示。旧数据连接器链接会自动跳转到存储页。点击名称或“查看详情”在居中弹窗查看能力、配置和关联来源。

- **节点健康与启用状态分离**：列表直接展示分节点探测结果（未探测、过期、通过、失败、部分节点失败）及最近探测时间。“已启用”只是配置开关，不能代替节点实时健康。记录超过有效期后提示刷新摘要，打开或刷新列表只读取数据库持久记录，不会自动向存储发起实时探测。
- **去重已采纳源规模**：按本位置当前可见的已采纳来源文件去重，多个数据集或父子来源引用同一文件只计一份；证据不足或存在同址冲突时显示已确认部分与“总量未知”，无采纳记录显示 `0`。不同位置规模不能直接相加，也不与平台对象存储字节相加。
- **权限隔离**：连接配置仅供项目管理员（可见全局连接与本人创建的个人连接）和超级管理员（可见全部）读取。全局连接供业务使用不等于向普通成员公开端点、桶、用户名或目录；密码、密钥与私钥永不回显。

## 已挂载目录的存储位置

服务器本地目录、CephFS 和 NFS 由运维统一只读挂载为受控根（`STORAGE_FILESYSTEM_ROOTS`），再由超级管理员在 **存储管理 → 位置**（或通过[存储位置 API](/api/guides/storage-locations)）登记名称、根句柄、相对目录和使用人员。例如根句柄 `ceph` 对应 `/mnt/cephfs`，位置登记 `traffic`，目录浏览再选其下的 `vehicle_detection`。

- **免重启扩展子目录**：在已挂载根内新建子目录或在界面登记已有子目录无需重启容器；新增未挂载的宿主机路径仍需运维先补挂载。
- **指定节点探测**：不能仅凭 API 节点可读就认定扫描 Worker 可用。超级管理员及获授权的项目管理员须在位置详情探测指定的扫描 Worker 节点，通过后再从数据集页[接入目录来源](./sources)。外部目录仅作只读引用或复制源，不接受平台写入或删除。

## 从数据集往返存储位置

数据集接入向导只选择已有位置或连接；需要新建时点击 **管理存储位置** 跳转到存储页，完成后返回原数据集向导。平台按当前登录会话与数据集保留非机密的文本草稿，本地文件选择和密钥不会持久保存。

从位置详情点击 **查看数据集** 可按该位置筛选受影响的数据集（同一数据集多个来源按当前权限去重计为 1 个）；从数据集来源页也可一键定位到对应存储位置详情，关闭后保留原页码与扫描上下文。

## 远端存储连接器（S3 / OSS / SFTP）

平台后端内置两种远端连接器类型（`StorageKind`）：

- **`s3`（界面显示 S3 / OSS）**：覆盖 AWS S3、阿里云 OSS、MinIO、腾讯云 COS 等所有 S3 兼容服务，统一使用 `s3` 类型并填写各自 `endpoint`。
- **`sftp`**：SFTP / SSH 文件服务器。

### 新建、测试与编辑连接器

1. 在 **存储管理 → 位置** 点击 **新建远端连接**，填写名称、类型（`S3 / OSS` 或 `SFTP`，创建后不可改）与范围（`owner` 个人可见，或仅超级管理员可建的 `global` 全局连接）。
2. **填写参数与加密凭据**：
   - **S3 / OSS**：必填 `endpoint`、`bucket`、`access_key`、`secret_key`；可选 `region`、`base_prefix`（导入起始前缀，后续 `source_path` 限制在其内部）、`use_ssl`。
   - **SFTP**：必填 `host`、`username` 及 `password` 或 `private_key`（支持 RSA / Ed25519 / ECDSA，可选 `passphrase`）；可选 `port`（默认 22）与 `base_path`。
3. **SFTP 主机指纹前置条件**：连接器测试与复制导入使用服务端系统 `known_hosts` + `RejectPolicy`（拒绝未知主机，不自动 TOFU）。运维须预先在 API 与 Worker 容器/主机登记目标指纹（如 `ssh-keyscan`）。独立 Assets Source 可用 `ASSETS_SOURCE_SFTP_KNOWN_HOSTS_FILE` 指定可读文件，独立导入进程可用 `ASSETS_IMPORT_SFTP_KNOWN_HOSTS`；未指定时读取对应进程的系统 known_hosts。注意：[SFTP 原地引用](./sources)使用独立的 `STORAGE_SFTP_ROOTS` 与固定主机公钥，不混用系统 `known_hosts`。
4. **测试、编辑与并发保护**：点击列表的 **测试** 会真实连接并采样列举最多 20 条记录（仅验证 API 节点认证与列举，不代表 Worker 原图读取、Range 或写入已就绪）。编辑参数或轮换密钥（留空表示保持原密钥）时，系统先对候选配置执行认证与列举验证，通过后才落库；保存时校验修订版本（`expected_revision`），防止多人并发覆盖。删除连接器不影响已复制入库的文件。`owner` 连接器仅创建者或超级管理员可以编辑／删除；创建者后来变为 employee 或 viewer 时仍保留这项管理权限。`global` 连接器仅超级管理员可以编辑／删除。

### 主机白名单（超级管理员）

连接器在**创建、测试、导入**三处均强制校验 SSRF 主机白名单（DNS 解析为真实 IP 后比对）。超级管理员在 **设置 → 系统设置 → 连接器主机白名单** 管理条目（支持 CIDR 网段、单 IP、精确域名、带前导点的后缀域名如 `.aliyuncs.com`）：

- **默认拒绝**：白名单为空时所有创建、测试和导入均被拦截。
- **永久硬拒绝**：回环（`127.0.0.1`）、链路本地（含云元数据 `169.254.169.254`）、组播、未指定（`0.0.0.0`）和保留网段即使写入白名单也一律拒绝。容器内访问宿主机请走 Docker 网关 IP。
- 若运维配置了部署主机 SFTP 地址，超管可点击 **添加部署主机** 预填 host 与端口，但仍须手工填写专用只读 staging 账号并将其加入白名单。

### 从连接器复制导入数据集

单次导入受文件数（默认 `50000`，`DATASET_IMPORT_MAX_FILES`）和总字节（默认 `200 GiB`，`DATASET_IMPORT_MAX_TOTAL_BYTES`）预算约束，超限时在枚举阶段整体拒绝，不产生部分导入。任务受理时固定本轮预算；导入保留 `source_path` 内部子目录层级，重复导入按内容自动去重跳过。

实际有效值由本部署默认与超级管理员在「设置 → 系统设置 → 数据导入」保存的覆盖决定。每次导入受理时固定两项预算；修改设置只影响之后新建的导入，已经排队、运行或重试的作业继续使用原预算。恰好等于预算仍可导入。文件数和总字节预算同时约束枚举与实际传输；源文件在枚举后增大或变化会拒绝该文件，不会绕过预算。这不改变浏览器上传限额。

### 中断、取消与重试

导入请求受理后会保留后台作业，即使执行进程尚未启动也能在任务列表中找回。请求响应中断时，客户端使用原 UUID 再次确认同一作业；更改导入参数需要新 UUID。

运行进度逐文件持久保存。执行进程异常退出后，新的进程在原租约到期后接续；已经导入的文件和建题计数不会重复。枚举超限时不开始复制，个别文件失败继续记录失败数及有限的明细。内容相同的文件按内容跳过，原始文件保留。

取消会保留已提交的文件，并阻止正在复制的迟到结果继续登记。待处理或运行中的导入会阻止删除数据集；完成取消后，仍被项目任务或其他功能引用的素材继续按引用规则保护。受理时作业会保存连接器配置和加密凭据快照，之后编辑或删除连接器不会改写或删除该快照；已受理作业仍按原快照执行。取消、作业终态、数据集和当前租约围栏仍阻止后续写入。要用新连接配置或凭据，请创建新的导入作业。

## 按需完整原图缓存

超级管理员可在 **存储管理 → 位置详情 → 完整原图缓存** 配置“按需原图”策略、位置配额（默认 `0`，启用按需须设正整数额度）和保留时间（TTL）。

- **生效条件与计量范围**：仅当存储位置和数据集来源同时开启按需策略时，首次成功读取并完整核验的引用原图才会写入缓存。额度仅计量完整原图缓存（分列上传中、已登记、待删除），预览缩略图、托管原件与磁盘总容量另计。满额时优先淘汰无活跃读租约的旧副本；无法缓存时本次已核验源快照仍可交付使用。
- **受控清理**：点击 **请求清理原图缓存** 会二次预览范围，确认后单次提交最多 100 份副本回收。正在读取或上传的副本受读租约保护不强清，清理仅回收平台缓存副本，绝不删除外部来源文件。

## 保存位置配置与位置维护

### 保存位置配置

修改受控目录使用范围或原图缓存配置时，先点击 **预览使用范围变更** 或 **预览缓存配置变更**。居中弹窗展示字段差异、已保存关系与 5 分钟有效的确认令牌（`impact_token`）；若确认前配置、权限或盘点关系发生变化，须刷新后重新预览。

保存来源位置配置会递增位置修订（revision）：依赖旧修订的完整原图缓存将失配并逐步回收，旧扫描、预检登记与自动同步在各自后续检查点阻塞。撤回目录使用权仅限制来源管理与新接入，已有任务仍按项目权限读取；停用位置则拒绝新的引用原图读取（含完整缓存）。

### 位置维护影响

超级管理员可在外部存储位置或默认托管位置详情展开 **维护影响**（只读查询数据库，不访问源目录或对象存储）：

- **保存目标（Saved Targets）**：按物理位置统计九种业务用途的 27 类持久责任记录（含在途、失败、退休及待清理记录）、关联的数据集/项目/任务、保存在此的训练版本与实验，以及当前用途绑定数。当前绑定只决定新分配，责任数不等于物理对象数。
- **来源关系（Source Lineage）**：覆盖该位置全部保留来源（含暂停、注销及已解绑历史），去重展示样本、数据集和项目数，以及持久扫描轮次、预览/完整缓存账本、可关联临时输入和带位置血缘的冻结版本。
- **未定位历史责任**：全平台尚不能归属到具体位置的旧记录单列展示，系统不按当前绑定猜测，也不阻碍当前位置的维护确认。

### 位置访问维护

当部署已启用位置访问维护协议（`STORAGE_MAINTENANCE_PROTOCOL_ENABLED=true`）时，超级管理员可在外部来源位置详情展开 **位置访问维护**，按四步安全排空访问：

1. **开始维护**：预览关系并确认后，关闭该逻辑位置的新受控访问；在途操作继续收尾。
2. **刷新维护状态**：查看未收尾操作总数及前 50 条明细。平台不把作业取消、超时或失联当作物理 I/O 结束，不提供强制清零。
3. **停止访问**：仅当未收尾操作降为 `0` 时可预览并确认停止，记录“受控访问已停止”。
4. **恢复访问**：递增维护修订并恢复新读取；维护前排队的旧扫描、登记、同步或预测授权不会自动复活，需重新发起。
