# 对象存储迁移准备

> 适用角色：超级管理员（控制台清单、复制批次与维护窗口管理） / 可信部署运维（最终停写绑定、读取映射发布与九用途整组切换）

当需要将平台默认配置的九用途对象存储整体迁移至新的已登记全局 S3 实例时，可通过 **存储管理 → 迁移准备**（`/storage?tab=migration`）配合运维工具完成可核验、可回滚的在线与窗口迁移。

## 控制台与可信运维的分工

平台将对象存储迁移划分为“超级管理员控制台操作”与“可信部署运维 CLI 操作”两条职责链，避免在浏览器页面直接暴露底层存储管理凭据或绕过进程级停写栅栏：

| 阶段                              | 执行角色与入口                          | 核心职责与产出                                                                                                                       |
| --------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **1. 在线迁移清单与初次复制**     | 超级管理员（`/storage` → **迁移准备**） | 建立配置源九桶清单（JSONL 报告），指定九用途策略（`migrate` / `retain` / `rebuild`），向目标全局 S3 执行初次条件创建与完整回读核验。 |
| **2. 在线增量批次追赶**           | 超级管理员（`/storage` → **迁移准备**） | 在不停机状态下链式建立后续清单与增量复制批次，复用已核验不可变版本映射，仅补传新增或可变对象。                                       |
| **3. 开启迁移维护窗口与排空**     | 超级管理员（`/storage` → **迁移准备**） | 开启持久迁移维护窗口，关闭默认来源的普通受控访问，等待在途登记操作排空归零并确认停止。                                               |
| **4. 原生停写栅栏与最终封存**     | 可信部署运维（运维 CLI）                | 验证底层存储原生停写栅栏（native fence），将其绑定到已停止的维护窗口，完成最终增量清单与目标完整核验封存。                           |
| **5. 发布封存副本读取与整组切换** | 可信部署运维（运维 CLI）                | 显式发布各用途封存副本读取映射，预览并一次确认九用途原子切换（或受控回滚），开展切换后观察与旧实例退役。                             |

运维侧详细命令与参数请参见[对象存储迁移清单与封存运维指南](/ops/deploy/storage-migration-inventory)。

## 建立配置源迁移清单

超级管理员进入 **存储管理 → 迁移准备**，点击 **建立迁移清单**。后台任务会自动读取当前部署配置的九种用途桶（多个用途共用同一物理桶时自动按实际桶合并），无需也不会让你手工输入宿主机路径、任意端点或目标凭据：

- **盘点内容与完整性预算**：任务记录桶级版本控制规则、全部对象版本（versions）、删除标记（delete markers）和未完成分段上传（multipart uploads），并对预算范围内的对象完整读取核验 SHA-256。高级预算可限制最大页数、条目数、单对象字节、总读取字节与超时；若因预算耗尽或源端报错提前停止，未检测部分不会冒充为 `0`，已封存的部分清单仍可供审阅。
- **私密报告下载**：清单完成后，当前超级管理员可下载私密 JSONL 报告（包含真实对象键、版本与元数据，不提供公共匿名链接，随终态后台任务保留 **30 天**）。已经单独切往外部位置的用途会在报告中标明未纳入默认源盘点。建立清单仅作只读观测，不会复制对象、修改绑定或停止源端写入。

## 准备并执行初次复制

在封存清单行点击 **准备初次复制**，在居中弹窗选择已登记的全局 S3 存储位置作为目标（直接使用该连接的加密凭据），并逐项为九种用途指定处理策略：

- **`migrate`（复制）**：本批次将源对象按版本复制到目标位置并完整回读核验。
- **`retain`（保留源端）** / **`rebuild`（后续重建）**：本批次不复制、也不清理源对象。若共用同一物理桶的多个用途选择了相互冲突的处理策略，计划会将其列为“歧义跳过”，防止重复上传或误处理。

提交后后台先生成配对的业务定位目录并冻结复制映射与检查点（此步不写目标）。审阅计划统计后点击 **开始初次复制**：

1. **条件创建与回读回执**：目标位置必须已启用版本控制（Bucket Versioning）。Worker 按源版本与冻结映射向目标执行条件创建，随后完整读回校验 SHA-256 与大小，将目标 `version_id`、nonce 与核验回执持久写入私密 SQLite 检查点。
2. **断点续跑与选择性重试**：
   - **继续未完成项**：仅处理待复制与未确认项，已成功项跳过，失败项默认保留。
   - **续跑并重试全部失败项**：将待复制项与全部失败项一并加入本轮执行。
   - **仅重试已选失败项**：在计划详情展开失败对象分页列表（按安全身份摘要、大小和错误码展示），仅勾选特定失败对象重试，其余状态不变。
   - **重新核验**：仅重新读取目标端已保存的准确版本校验完整性，不重新上传。
3. **中断恢复与检查点保管**：若旧任务因进程退出状态不明，系统保留未决责任而不按时间强行接管；可在高级操作点击 **检查并恢复中断执行**，确认底层结束后沿原范围恢复。复制计划独立于 30 天后台任务保留，超管可随时下载私密 SQLite 检查点（含真实源/目标地址与回执，请按机密运维资料保管）。

## 准备后续增量批次

初次复制完成后，源端在业务运行期间可能继续产生新对象。在已准备且无活动任务的父批次详情点击 **准备后续批次**，选择同一配置源的新封存清单（自动继承目标位置、九用途策略与执行预算）：

- **单链父子批次**：每个父批次最多派生一个直接后续批次，建立后父批次自动转为只读，界面支持在父子批次间跳转。
- **复用映射与差异核验**：
  - **复用映射**：对已拥有准确目标创建回执的不可变源版本，直接沿用原目标地址，经本批次完整读回核验后计入“已核验”，无需再次读源或重传。
  - **可变版本与身份冲突**：`null` 版本或未固定版本保守重新复制；若同一显式源版本的摘要、大小或 ETag 发生变化，则列为“身份冲突”并拒绝覆盖旧目标。
  - **本次未观察到与删除标记**：与父批次对比未出现的对象仅标为“本次未观察到”（不等于源端已物理删除，历史回执继续保留）；源端删除标记单列记录，不会在目标端复制成空文件。

## 迁移维护窗口

在线增量追赶接近尾声后，超级管理员在 **迁移准备** 页点击 **开启迁移窗口**，选择一个已就绪、无活动任务且尚无后续批次的父复制计划（前提：部署已启用 `STORAGE_MAINTENANCE_PROTOCOL_ENABLED=true`）：

1. **关闭普通登记访问并排空**：窗口开启后立即锁定父批次、默认来源与目标位置，首先关闭默认来源的普通受控访问。查看窗口详情等待未收尾登记操作降为 `0` 后，点击 **确认停止登记访问**。
2. **窗口绑定只读盘点与复制**：仅当登记访问确认停止后，才允许建立绑定该窗口的源清单与后续增量复制批次。窗口许可仅放行冻结桶内的只读列表、`HEAD` 与 `GET`，严禁上传或删除源对象；普通业务读取与其他旧任务不会获得例外放行。
3. **排空边界说明**：“登记访问已排空”仅代表接入位置维护协议的受控操作已结束；此前已签发的浏览器预签名上传、共享同一物理桶的其他位置或存储端生命周期规则仍可能产生写入。因此控制台仍显示“全源停写未证明”，需配合下节的运维最终核验。

## 最终核验记录

可信部署运维在底层确认源端原生停写栅栏（native fence）并将其绑定到已停止的维护窗口后，窗口修订更新；随后完成绑定窗口的最终清单、增量复制与目标完整核验。

- **查看已封存证据**：窗口详情展示最终核验状态、原生观测时间，以及复制（`migrate`）、保留源端（`retain`）和待重建（`rebuild`）的对象计数，点击 **查看最终复制批次** 可直接打开对应后继批次。“已封存”代表该窗口下的清单与目标准确版本已完成闭环核验。
- **关窗锁定保护**：只要运维绑定的最终核验责任仍在生效，控制台上的 **关闭窗口** 按钮即保持锁定不可用。必须先由运维显式解除绑定并等待在途窗口操作完全收尾后，才能在控制台关闭维护窗口（解除绑定本身也不会自动放开底层源端写入）。详见[最终增量封存](/ops/deploy/storage-migration-inventory#绑定窗口并封存最终增量)。

## 已封存副本的读取范围

最终封存完成后，运维可按用途显式发布封存副本读取映射（无需先修改新写入用途绑定）。发布后，平台各读取入口按业务记录原本保存的完整地址、SHA-256 与字节大小，精确路由到目标位置已核验的**准确对象版本（Exact Version）**——即使目标端同名键后续新增了其他版本或删除标记，读取也不会漂移：

### 托管原件的已封存副本读取 {#托管原件的已封存副本读取}

已有 `Task`、`DatasetItem` 和辅助原件保持原身份与逻辑地址不变；认证图片读取、通用认证原件下载与后台原件读取自动从目标端已核验的准确版本交付字节。未纳入映射的保留源端（`retain`）对象、待重建（`rebuild`）对象及无准确映射的历史记录继续按原规则处理。

### 训练产物和导出 ZIP 的迁移读取 {#训练产物和导出-zip-的迁移读取}

训练数据版本包下载、冻结图片/掩码、训练执行器输入、已有实验产物的纯读取，以及导出 ZIP 的缓存核验与新签发下载链接，均可直接读取目标端的封存副本（原训练 snapshot/manifest 与包摘要不变）。注意：此前已发出的直接 S3 预签名链接及旧 ZIP 内冻结的媒体链接不会自动改写，运维在旧链接自然过期前应保持原存储入口只读。

### 其他保留文件的迁移读取 {#其他保留文件的迁移读取}

- **头像、报告附件、压缩审计归档、持久 RLE 掩码、评论附件与指南图片**：均按原保存地址与内容证据读取目标端封存副本，原有访问权限、附件有效期、评论关联与月度审计校验规则完全保持。
- **独立导出媒体**：缓存复用时逐件核验完整内容并比对冻结文件清单（集合不完整或变化时拒绝复用）。新签发链接指向目标准确版本且不延长首次 7 天到期时间；正在读取的文件受原 owner 租约保护，关闭前不可被回收。

### 媒体缓存副本与 Range 读取 {#媒体缓存副本与-range-读取}

已有缩略图、高清图片金字塔、视频派生文件与按需完整原图缓存，只要存在准确封存副本即可直接读取（含视频与缓存的 `Range` 区间读取）。金字塔与视频派生按单次请求的成员逐个检查，无需等待整个缓存目录全部迁完；流式响应过程中若运维撤回映射，系统立即停止后续分块交付并等待连接安全关闭。

### 导入暂存、日志与在途写入 {#导入暂存日志与在途写入}

- **Mask 导入暂存与脱敏训练日志**：具备内容摘要的原生 Mask 导入暂存可直接从封存副本执行预检和后台读取；已结束训练实验的终端日志可直接从封存副本完整核验并在内存脱敏后供管理员认证下载，无需再向已停写的旧位置写入脱敏副本。
- **在途写入处置要求**：读取映射绝不授权向已停止的旧位置继续写入或删除。切换前必须妥善处置旧位置上的在途直传、AI 预标输入、训练产物生成与导出打包（等待实际收尾，或保留责任记录后取消并在切换后显式重建）。

## 九用途整组切换与回滚

完成最终封存与封存副本读取验证后，可信部署运维可执行**九用途整组原子切换**：

- **整组原子切换**：一次确认同时更新全部 9 项用途的新分配绑定。校验期间若任何一项用途的代次（generation）或目标配置发生变化，整组切换即原子拒绝（不同于控制台单用途独立切换）。
- **受控回滚（保留新写入只读）**：切换后若需回滚，运维先停止新目标位置的写入并等待在途操作实际收尾，再将后续新分配整组切回原端。**切换期间已写入新目标的原件、缩略图等对象保留在新目标的原保存地址与业务引用中，新目标转为受控只读**，原端恢复新写入分配。回滚绝不回退数据库快照或丢弃已生成的新对象；切回前已分配给新目标但尚未完成的在途写入，需显式取消并在原端重建。详见[九用途原子切换与新写入回滚](/ops/deploy/storage-migration-inventory#九用途原子切换与新写入回滚)。

## 正常切换后的观察与旧实例退役

整组切换完成后，系统进入**正向观察期（Forward Observation）**：

1. **观察记录与读取连续性**：在观察期内，新分配写入全部落入新目标位置，而历史对象通过已发布的封存副本读取映射（或 `retain` 策略下的原端只读入口）提供服务。超级管理员可通过[存储诊断与容量账目](./storage-operations)持续核对新目标的受控新增账目、周期盘点与故障观测。
2. **旧实例退役前置条件**：完成切换**不等于**可以立即销毁或下线旧对象存储实例。仅当确认以下条件全部满足后，运维才可按退役规程下线旧实例：
   - 切换前签发的所有指向旧实例的外部预签名 URL 及导出 ZIP 内冻结链接均已自然过期；
   - 标记为 `retain`（保留源端）或未纳入迁移副本的历史对象已全部完成归档、重建或业务到期回收；
   - 旧位置上的所有未决访问账本、清理责任与保留要求（`declared_holds`）均已核实结清。
