# 训练模型回流与发布

训练完成后，从项目「在线学习 → 模型与发布」将结果添加为候选，加载到推理服务试用，再人工发布为本项目的预标注模型。权重直接在平台与服务之间传递，不需要下载后重新上传。

当前支持 Ultralytics 图片检测和通过资格检查的 LibreYOLO YOLO9 t/s/m/c 原生检测权重。能够训练或下载权重，不表示该模型已经具备回流资格；分割训练和其他未开放规格以实验详情的原因提示为准。

## 操作由谁完成

| 操作                     | 入口                                | 负责人                 |
| ------------------------ | ----------------------------------- | ---------------------- |
| 注册或编辑推理服务       | 模型市场 → 注册管理 → 实例          | 超级管理员             |
| 初始化默认凭据           | 设置 → 系统设置 → ML 服务认证与维护 | 超级管理员             |
| 为项目启用服务           | 项目设置 → ML 模型 → 管理 backend   | 项目负责人或超级管理员 |
| 添加候选、加载试用与发布 | 项目在线学习 → 模型与发布           | 项目负责人或超级管理员 |

注册服务只建立一个可调用的地址；添加候选只固定训练产物与类别；发布才决定本项目后续预标注使用哪个模型。服务凭据准备完成也不会自动创建候选或发布。

## 从训练结果添加候选

模型回流有两个操作入口：

- **从训练结果进入**：打开「训练实验」中的来源实验，选择其中成功的执行记录，点击「回流到项目模型」。平台会打开添加面板，并带入该实验和执行记录。未通过回流资格检查时，详情展示具体原因，仍可下载原生权重。
- **从模型列表进入**：切换到「模型与发布」，点击右上角「从训练结果添加模型」，选择来源训练实验和成功执行记录。

回流直接读取平台内的训练权重，无需先下载再上传。名称会预填当前本地时间，例如 `2026-0909-1125`，可继续补充或修改。为每个原生输出类别明确选择当前项目的矩形框类别，再点击「从训练结果添加模型」。模型保存权重摘要、类别顺序、绑定、实验、数据版本与评估来源；注册后这些信息固定，被模型引用的实验不能删除。

类别绑定列表每页显示 10 项，并在列表内滚动；可按类别名称、原生序号或已选项目类别搜索，也可勾选「仅未绑定」。顶部显示整体绑定进度。点击「按同名绑定」会为全部未绑定项填入完全同名的项目类别，保留已有手动选择，不受当前搜索或分页限制。切换分页与筛选不会丢失选择，全部原生类别均已绑定后才能注册。

## 准备推理服务

模型详情会直接显示加载试用是否就绪，区分服务列表读取失败、项目未启用、未配置有效认证及服务不可用。下拉框保留已注册服务，并标注不能选择的原因；「配置推理服务」列出各服务状态并提供现有实例的直达入口。只有一个已启用、已配置系统托管或手动 Token 认证且在线的服务时会自动选中；多个服务时需要手动选择。

选择「用于加载模型的推理服务」，点击「加载模型并试用」。服务列表读取失败时可点击「重试」。服务尚未就绪时，按两步操作：

1. **超级管理员配置服务认证**：进入「模型市场 → 注册管理 → 实例」，编辑已有 YOLO 服务，选择「系统托管（YOLO）」并保存。平台自动生成或复用私有凭据，在部署指定的 YOLO 地址验证后同步保存，无需生成、复制 Token 或修改 `.env`。尚无实例时才注册；已有实例无需重复注册。
2. **项目负责人启用实例**：在「项目设置 → ML 模型 → 管理 backend」启用该服务，再返回本页选择并加载。

内置服务的默认凭据分别持久保存在部署的私有共享目录，各容器只读自己的凭据。旧容器首次升级需要重建镜像并应用新的目录挂载；之后初始化或同步凭据无需再次重建容器。普通 `/health` 成功只表示进程可达，系统托管会额外验证受认证端点；保存后执行实例健康检查更新服务状态。

远程或已自行配置 `YOLO_MANAGED_MODELS_TOKEN` 的服务继续使用手动 `token`，填写与服务端一致且至少 32 个字符的令牌。手动配置优先，不会被系统托管覆盖。已使用手动 Token 的实例留空编辑保留原值；从系统托管切回手动 Token 必须明确填写服务端令牌。`none` 不发送认证凭据，不能用于加载训练权重。

需要批量初始化时，超管可使用「设置 → 系统设置 → ML 服务认证与维护」。这个入口准备和同步服务访问凭据，不会自动启用项目、安装候选或发布模型。服务与模型的关系、请求路由以及 Token 为什么还保护普通推理，见[模型服务接入、路由与认证](../../dev/concepts/ml-backend-routing-and-auth)。

## 加载、确认并发布

平台校验权重后安装到该实例，检查原生任务和类别，并在一张固定验证图片上推理。页面展示试用图片、预测框和耗时；负责人检查误检、漏检及人工修正成本，勾选「已查看固定验证样本，确认用于后续人工试用」，点击「发布此模型」并在确认框中确认发布。训练完成或试用成功都不代表精度已经提升。

候选对比要求相同的验证摘要、类别、绑定、框架及评估配置。页面只展示原生报告实际提供的指标；LibreYOLO 暂无分类别结果，不将其原生 precision／recall 别名当作常规精确率／召回率。不同框架候选分别展示，不能直接比较分数。

## 用当前发布预标注

发布后，返回「模型与发布」列表，在当前发布下选择待标注图片，设置置信度与追加／覆盖方式，点击「使用当前发布预标注」。每个任务固定创建时的模型和类别绑定，并保留权重、实验、数据版本与发布来源。后来发布其他模型不会改变已排队任务；网络重试沿用原任务身份。结果仍需在工作台接受、修正、提交并审核，之后才能进入下一训练数据版本。

工作台按自己的置信度阈值筛选候选。若模型已返回结果但列表为空，可在「当前题 AI → 高级配置 → 候选筛选与批量采纳」降低显示阈值，再审阅候选。点击对象行「更多操作」可固定展开采纳、改类别等操作，触屏也可使用。

Ultralytics 图片检测模型发布后，也可在「模型市场 → 模型目录」、普通 AI 预标和工作台「当前题 AI → 高级配置」选择。它能作整图源阶段，也能在父框裁剪图上检测子物体；同一 YOLO 实例可承载多个阶段。LibreYOLO 保留已验证的单阶段检测路径。视频和点／框／文本交互提示仍不属于训练模型回流范围。任务只会进入完成该版本部署检查的确切实例；实例不可用时任务报错，不会换用其他权重。重新点击加载检查可恢复该实例丢失或损坏的副本。

## 在预标注和管线中选择

在项目配置的「项目检测模型」下拉中选择「项目当前发布」或明确的历史发布版本。保留当前后端配置时继续使用原有内置模型设置；选择目录中的具体规格后，其权重规格固定，参数预设单独保存，不会改写原后端的偏好。

添加检测子阶段后，分别选择该阶段的模型、置信度、原生类别索引和 ROI 扩展。**父框类别过滤使用项目绑定后的名称**，例如原生 `person` 绑定「行人」后，下游筛选「行人」。保存包含项目模型的管线时，只能保存为所属项目的私有管线；不能发布为组织或公共模板。

失败重试按原始快照重跑失败的那道题的完整管线。下游失败时保留失败策略允许的候选和错误记录；只有完整重试成功才替换旧候选的显示状态，已采纳的人工标注保持不变。

## 回退或停用发布

发布历史可回退到此前模型与实例组合，也可清除当前发布。回退先验证旧部署可用，再更新项目选择；已有任务和历史结果保留原版本。其他负责人同时发布时，页面会要求刷新，避免覆盖对方的更新。

## 「加载模型并试用」为何不可用

先读按钮附近的原因，再从「配置推理服务」进入对应位置。不要通过重复添加候选解决服务配置问题。

| 页面提示或现象                 | 处理方式                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 服务列表读取失败               | 点击「重试」；持续失败时请管理员核对 API 错误与当前账号权限                  |
| 项目未启用                     | 在项目设置中启用已有实例，无需重新全局注册                                   |
| 未配置推理认证                 | 超管编辑目标实例，内置服务选择对应系统托管认证；自建服务填写匹配的手动 Token |
| 服务当前不可用                 | 超管执行实例健康检查；若认证已保存仍不可用，核对服务运行与模型能力           |
| 本地凭据已初始化，但仍不能调用 | 本地文件可用不等于容器已升级或认证已验证，按系统设置中的结果继续排查         |
| 加载失败或副本损坏             | 保留错误信息，修复目标服务后重新点击加载试用，不更改已冻结权重               |
| 发布时提示配置已变化           | 刷新后核对最新发布与部署，再明确确认本次操作                                 |

## Token 要自己生成吗

内置服务选择「系统托管」时不需要。平台生成或复用独立凭据，服务从私有目录读取；认证方式仍是系统托管，不能选 `None` 来代替。`None` 表示调用时不发送凭据，无法加载受保护的训练权重。

Token 用于证明平台有权调用服务，除了模型安装也保护能力查询、推理和控制入口。它不是个人登录密码，也不是训练质量证明。初始化不会轮换已有 Token；通常也不需要为同步凭据重建镜像。旧部署首次升级和容器维护由部署管理员按[维护指南](../../ops/deploy/ml-backend-maintenance)处理。
