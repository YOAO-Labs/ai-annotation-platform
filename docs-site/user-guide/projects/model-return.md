# 训练模型回流与发布

训练完成后，从项目「在线学习 → 模型与发布」将结果添加为候选，加载到推理服务试用，再按任务类型设置默认预标模型。权重直接在平台与服务之间传递，不需要下载后重新上传。

当前支持 Ultralytics 图片检测、受控的 Ultralytics `yolo11n-seg` 图片实例分割，以及通过资格检查的 LibreYOLO YOLO9 t/s/m/c 原生检测权重。其他分割规格与 LibreYOLO 分割尚未开放回流。能够训练或下载权重，不表示已经具备回流资格，以实验详情的原因提示和目标实例检查结果为准。

在「模型与发布」列表工具栏选择检测或实例分割任务。表格逐行显示型号、类型、状态和来源指标；型号来自注册时冻结的基础模型规格，历史记录缺失时显示「—」。默认模型在自己的行内标记「默认预标」，也可在该行停用默认选择。模型筛选、预标注及切换记录集中在同一个列表区域。

同一项目、同一任务可以保存并部署多个模型；检测与实例分割各自维护默认预标选择。设置默认模型只决定默认预标入口使用哪个模型，不会停用其他已部署模型，也不代表项目只有一个模型在用。显式选择具体模型的管线继续使用自己的配置，已排队任务继续使用创建时冻结的模型。分割需要项目启用区域工具和原生栅格掩码编辑，并通过部署侧的掩码读写开关检查。

## 操作由谁完成

| 操作                     | 入口                                | 负责人                 |
| ------------------------ | ----------------------------------- | ---------------------- |
| 注册或编辑推理服务       | 模型市场 → 注册管理 → 实例          | 超级管理员             |
| 初始化默认凭据           | 设置 → 系统设置 → ML 服务认证与维护 | 超级管理员             |
| 为项目启用服务           | 项目设置 → ML 模型 → 管理 backend   | 项目负责人或超级管理员 |
| 添加候选、加载试用与发布 | 项目在线学习 → 模型与发布           | 项目负责人或超级管理员 |

注册服务只建立一个可调用的地址；添加候选只固定训练产物与类别；默认预标设置只决定该任务类型的默认入口使用哪个模型。服务凭据准备完成也不会自动创建候选或发布。

## 从训练结果添加候选

模型回流有两个操作入口：

- **从训练结果进入**：打开「训练实验」中的来源实验，选择其中成功的执行记录，点击「回流到项目模型」。平台会打开添加面板，并带入该实验和执行记录。未通过回流资格检查时，详情展示具体原因，仍可下载原生权重。
- **从模型列表进入**：切换到「模型与发布」，点击右上角「从训练结果添加模型」，选择来源训练实验和成功执行记录。

回流直接读取平台内的训练权重，无需先下载再上传。名称会预填当前本地时间，例如 `2026-0909-1125`，可继续补充或修改。为每个原生输出类别明确选择当前项目对应工具的类别：检测绑定矩形框类别，实例分割绑定区域类别。再点击「从训练结果添加模型」。模型保存权重摘要、类别顺序、绑定、实验、数据版本与评估来源；注册后这些信息固定，被模型引用的实验不能删除。

类别绑定列表每页显示 10 项，并在列表内滚动；可按类别名称、原生序号或已选项目类别搜索，也可勾选「仅未绑定」。顶部显示整体绑定进度。点击「按同名绑定」会为全部未绑定项填入完全同名的项目类别，保留已有手动选择，不受当前搜索或分页限制。切换分页与筛选不会丢失选择，全部原生类别均已绑定后才能注册。

## 查看模型详情与操作

在「模型与发布」列表点击模型名称或「详情与操作」，进入该模型的统一页面。顶部「评估与发布」用于查看指标、下载模型、加载试用和发布；「来源与使用」查看训练来源及部署、发布、预标注记录；「标记与备注」保存人工建议或归档模型。切换分区不离开模型页面，刷新后仍停留在原分区，返回列表时保留筛选与页码。

## 准备推理服务

模型详情会直接显示加载试用是否就绪，区分服务列表读取失败、项目未启用、未配置有效认证及服务不可用。下拉框保留已注册服务，并标注不能选择的原因；「配置推理服务」列出各服务状态并提供现有实例的直达入口。只有一个已启用、已配置系统托管或手动 Token 认证且在线的服务时会自动选中；多个服务时需要手动选择。

选择「用于加载模型的推理服务」，点击「加载模型并试用」。服务列表读取失败时可点击「重试」。服务尚未就绪时，按两步操作：

1. **超级管理员配置服务认证**：进入「模型市场 → 注册管理 → 实例」，编辑已有 YOLO 服务，选择「系统托管（YOLO）」并保存。平台自动生成或复用私有凭据，在部署指定的 YOLO 地址验证后同步保存，无需生成、复制 Token 或修改 `.env`。尚无实例时才注册；已有实例无需重复注册。
2. **项目负责人启用实例**：在「项目设置 → ML 模型 → 管理 backend」启用该服务，再返回本页选择并加载。

内置服务的默认凭据分别持久保存在部署的私有共享目录，各容器只读自己的凭据。旧容器首次升级需要重建镜像并应用新的目录挂载；之后初始化或同步凭据无需再次重建容器。普通 `/health` 成功只表示进程可达，系统托管会额外验证受认证端点；保存后执行实例健康检查更新服务状态。

远程或已自行配置 `YOLO_MANAGED_MODELS_TOKEN` 的服务继续使用手动 `token`，填写与服务端一致且至少 32 个字符的令牌。手动配置优先，不会被系统托管覆盖。已使用手动 Token 的实例留空编辑保留原值；从系统托管切回手动 Token 必须明确填写服务端令牌。`none` 不发送认证凭据，不能用于加载训练权重。

需要批量初始化时，超管可使用「设置 → 系统设置 → ML 服务认证与维护」。这个入口准备和同步服务访问凭据，不会自动启用项目、安装候选或发布模型。服务与模型的关系、请求路由以及 Token 为什么还保护普通推理，见[模型服务接入、路由与认证](../../dev/concepts/ml-backend-routing-and-auth)。

## 加载、确认并设置默认预标

平台校验权重后安装到该实例，检查原生任务和类别，并在一张固定验证图片上推理。检测展示预测框；实例分割展示原图上的逐实例掩码，保留孔洞、断连部件和实例重叠，并显示耗时。负责人检查误检、漏检及人工修正成本，勾选「已查看固定验证样本，确认用于后续人工试用」，点击「设为默认预标模型」并在确认框中确认。训练完成或试用成功都不代表精度已经提升。

同一模型版本与同一部署已是该类型的默认预标选择时，按钮显示「已设为默认预标」。切换次数记录该类型默认选择的变化，不是模型自身的版本号：切换模型、切换推理部署及恢复历史选择都会新增记录；重复设置、重复停用或恢复到相同组合不会增加记录。已有历史记录继续保留。

候选对比要求相同的验证摘要、类别、绑定、框架及评估配置。页面只展示原生报告实际提供的指标；LibreYOLO 暂无分类别结果，不将其原生 precision／recall 别名当作常规精确率／召回率。不同框架候选分别展示，不能直接比较分数。

## 分割试用与正式逐样本评估

固定样本试用检查的是一张验证图上的安装、类别和掩码输出，成功后部署才会标记为就绪。它不产生完整验证集精度结论，也不会自动发布。

需要量化比较时，另建「逐样本评估」，明确选择同任务冻结数据版本中的验证成员。真值、图片方向、类别绑定、阈值和实际推理环境会固定保存；后续修改工作台标注不会改写已有报告。原生实例掩码直接参与像素比较；旧多边形分割版本会按固定的像素中心规则显式栅格化，并记录转换身份。

分割报告按置信度排序，进行同类一对一掩码匹配，展示 TP、FP、FN、精确率、召回率和 F1，以及**已匹配实例**的平均 Mask IoU、Dice。漏检另计 FN，不会被高 Dice 掩盖；这些固定阈值指标不是 AP/mAP。面积组按原图前景像素划分：小于 1,024 为小实例，1,024–9,215 为中实例，至少 9,216 为大实例；TP/FN 使用真值面积，FP 使用预测面积。逐样本页面可分别显示真值与预测掩码，再核对当前标注任务。

当前分割评估每次最多 32 张图、每图 200 个真值和 100 个预测，总真值最多 2,000 个；原图最多 1,280,000 像素，单边不超过 4,096。掩码还受证据字节数与匹配计算预算限制，超过上限会明确拒绝或报告失败。只有冻结基准、类别、用途、阈值、预处理和推理环境身份一致的两个完整成功报告才能比较。

受控分割固定核验运行时和掩码解码路径。训练、推理与人工回流的流程验收不替代每个目标部署的 GPU 准入和受管生命周期验收，也不代表业务精度达标。变更镜像、权重或设备后，须按对应部署规则重新核验。

## 用默认模型预标注

设置默认模型后，返回「模型与发布」列表，在「使用默认预标模型」中核对任务类型和模型名称，选择待标注图片，设置置信度与追加／覆盖方式，点击「用默认模型预标注」。每个任务固定创建时的模型和类别绑定，并保留权重、实验、数据版本与发布来源。后来发布其他模型不会改变已排队任务；网络重试沿用原任务身份。结果仍需在工作台接受、修正、提交并审核，之后才能进入下一训练数据版本。

分割结果以逐实例栅格掩码进入候选，人工在工作台采纳、改类别或修正像素后，仍须提交并审核。冻结下一数据版本时，可在「分割训练桥接」选择「原生实例掩码训练」；执行器须先通过对应桥接资格检查，画笔或 SAM 修正后的孔洞与多部件才能直接保留为训练真值。只运行试用或逐样本评估不会写入人工标注，也不会自动创建下一轮训练。

工作台按自己的置信度阈值筛选候选。若模型已返回结果但列表为空，可在「单图 AI → 高级配置 → 候选筛选与批量采纳」降低显示阈值，再审阅候选。点击对象行「更多操作」可固定展开采纳、改类别等操作，触屏也可使用。

Ultralytics 图片检测模型发布后，也可在「模型市场 → 模型目录」、普通 AI 预标和工作台「单图 AI → 高级配置」选择。它能作整图源阶段，也能在父框裁剪图上检测子物体；同一 YOLO 实例可承载多个阶段。LibreYOLO 保留已验证的单阶段检测路径。视频和点／框／文本交互提示仍不属于训练模型回流范围。任务只会进入完成该版本部署检查的确切实例；实例不可用时任务报错，不会换用其他权重。重新点击加载检查可恢复该实例丢失或损坏的副本。

受控 `yolo11n-seg` 仅支持图片整图源阶段，不支持父框裁剪、视频或点／框／文本交互提示。使用实例分割类型对应的默认模型，检测与分割的默认选择不能互相替代。

## 在预标注和管线中选择

在项目配置的「项目检测模型」下拉中选择「项目当前发布」或明确的历史发布版本。保留当前后端配置时继续使用原有内置模型设置；选择目录中的具体规格后，其权重规格固定，参数预设单独保存，不会改写原后端的偏好。

添加检测子阶段后，分别选择该阶段的模型、置信度、原生类别索引和 ROI 扩展。**父框类别过滤使用项目绑定后的名称**，例如原生 `person` 绑定「行人」后，下游筛选「行人」。保存包含项目模型的管线时，只能保存为所属项目的私有管线；不能发布为组织或公共模板。

失败重试按原始快照重跑失败的那道题的完整管线。下游失败时保留失败策略允许的候选和错误记录；只有完整重试成功才替换旧候选的显示状态，已采纳的人工标注保持不变。

## 恢复或停用默认选择

在列表底部展开「默认预标切换记录」，可恢复此前的模型与实例组合；在默认模型所在行点击「停用默认预标」，可清除该类型的默认选择。恢复前先验证旧部署可用，再更新选择；其他已部署模型、已有任务和历史结果保留。其他负责人同时修改时，页面会要求刷新，避免覆盖对方的更新。

## 「加载模型并试用」为何不可用

先读按钮附近的原因，再从「配置推理服务」进入对应位置。不要通过重复添加候选解决服务配置问题。

| 页面提示或现象                 | 处理方式                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------- |
| 服务列表读取失败               | 点击「重试」；持续失败时请管理员核对 API 错误与当前账号权限                  |
| 项目未启用                     | 在项目设置中启用已有实例，无需重新全局注册                                   |
| 未配置推理认证                 | 超管编辑目标实例，内置服务选择对应系统托管认证；自建服务填写匹配的手动 Token |
| 服务当前不可用                 | 超管执行实例健康检查；若认证已保存仍不可用，核对服务运行与模型能力           |
| 本地凭据已初始化，但仍不能调用 | 本地文件可用不等于容器已升级或认证已验证，按系统设置中的结果继续排查         |
| 加载失败或副本损坏             | 保留错误信息，修复目标服务后重新点击加载试用，不更改已冻结权重               |
| 发布时提示配置已变化           | 刷新后核对最新发布与部署，再明确确认本次操作                                 |

## Token 要自己生成吗

内置服务选择「系统托管」时不需要。平台生成或复用独立凭据，服务从私有目录读取；认证方式仍是系统托管，不能选 `None` 来代替。`None` 表示调用时不发送凭据，无法加载受保护的训练权重。

Token 用于证明平台有权调用服务，除了模型安装也保护能力查询、推理和控制入口。它不是个人登录密码，也不是训练质量证明。初始化不会轮换已有 Token；通常也不需要为同步凭据重建镜像。旧部署首次升级和容器维护由部署管理员按[维护指南](../../ops/deploy/ml-backend-maintenance)处理。
