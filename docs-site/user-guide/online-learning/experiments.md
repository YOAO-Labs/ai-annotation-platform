# 创建与管理实验

每个实验固定一份数据、基础模型、模型初始化来源和训练配置。先明确任务，再选择兼容选项；想换数据或参数继续尝试时创建新实验，中断后继续原训练则使用断点续训。

实验列表的「训练框架」同时显示框架名称与该实验冻结的版本，与「模型与发布」列表的展示方式一致，便于核对不同实验的训练环境。

## 按三步创建实验

管理员启用独立训练执行器后，在「训练实验」点击「新建实验」，打开居中的配置面板，项目实验列表保留在背景。按「数据与模型」「配置参数」「核对并开始」三步完成配置，步骤条在滚动时保持置顶。先选择目标检测或实例分割任务，默认名称自动加上 `detect-` 或 `segment-` 前缀与时间戳，可自行修改。训练数据只列出该任务的就绪版本，训练器和「基础模型」只列出支持该任务的选项；初始化候选再按任务、训练器和模型型号过滤。切换任务会清除原数据、基础模型和初始化来源，保留已设置参数以便在选择新模型时核对兼容性；自定义名称保持不变。

未选择任务前，数据、训练器与基础模型选择暂不可用。未选择数据或模型时显示灰色占位提示，提示不作为下拉选项；较早的就绪数据可通过「加载更早的数据版本」继续选择。关闭面板后保留当前账号与项目的任务选择和本地草稿，再次打开可继续编辑；创建链接也可直接访问或刷新。

也可在就绪数据详情点击「使用此版本新建实验」。系统先核对精确冻结版本与兼容训练器／基础权重，展示确认面板，只有点击「确认采用数据版本」才更新草稿。兼容的当前模型与参数会保留；需要换模型时会明确说明采用受控默认参数并移除原参数覆盖、配方来源及项目权重初始化。取消保持原草稿。已有尚未确认的实验或参数搜索请求时不能替换数据，关闭面板也不丢弃原请求身份；采用后仍须检查配置并提交，后续新数据版本不会自动替换此选择。关闭实验面板可返回原数据任务和版本。

图片实例分割可选择受控 Ultralytics YOLOv8、YOLO11、YOLO26 的 n/s/m/l/x 基础模型；实际选项由管理员目录与节点就绪状态决定。数据任务、家族、基础模型和参数定义须一致。支持普通实验、配方、克隆、停止、断点续训、原生权重下载、兼容项目候选初始化、受控回流、掩码逐样本评估、自动训练与主动选样。参数搜索与原生增强预览仍未开放；已有选择不会被静默换成检测配置。

参数设置、变化项核对与分割增强约束见[训练配置与复用](./configuration)。

## 选择模型初始化方式

Ultralytics 的「模型初始化」区域中，「初始化权重」可选择「预训练基础权重」「从零训练（随机初始化）」或同项目候选模型。从零训练仅使用所选模型架构创建随机权重，不加载预训练参数；它与项目模型权重初始化互斥。对应参数 `pretrained` 默认为 `true`，关闭后从零开始。配置会随实验、配方和克隆保存；断点续训仍恢复该实验自己的完整检查点，不重新随机初始化。

选择项目候选作为初始化权重时，只会列出符合任务、训练器和型号的同项目候选。预训练基础权重使用上方所选基础模型，由管理员预先配置并校验，无需选择本地文件夹。候选可分页查找，已归档候选也可选择；无需先部署或发布。当前支持受控 Ultralytics 三个家族的检测与实例分割，目标框架版本、家族、规格、任务、原生类别及顺序须与来源完全一致，不提供跨版本隐式升级、类别头重映射或任意检查点上传。

页面显示来源候选、训练数据、验证摘要、权重 SHA256 与大小。这里的资格检查只读取固定身份和对象元信息；「检查训练配置」会完整验证权重与评估对象。核对页显示实际固定的模型、实验和执行尝试。来源失效、规格不匹配或对象损坏时保留当前选择并显示原因，需要明确重新选择后再检查。

项目权重仅用于初始化：新实验从第 0 轮开始，优化器、调度器、缩放器、EMA 和最佳成绩均重新创建。后续停止或中断时，断点续训使用本实验自己的完整检查点，不会重新加载父模型。改变初始化来源会清除旧检查结果并轮换创建请求；尚未确认的创建请求保持原内容，刷新后仍可原样重试。模型谱系提供独立的「初始化权重来源」关系。

| 方式           | 从哪里开始                                 | 适合什么情况                                            |
| -------------- | ------------------------------------------ | ------------------------------------------------------- |
| 预训练基础权重 | 管理员配置并校验的基础权重                 | 使用通用预训练能力开始新实验                            |
| 从零训练       | 所选模型架构的随机权重                     | 需要比较随机初始化；当前在支持的 Ultralytics 配置中选择 |
| 项目候选初始化 | 同项目、同规格、同原生类别及顺序的保留候选 | 用上一轮模型启动新一轮实验                              |
| 断点续训       | 当前实验的合格完整检查点                   | 恢复中断实验，沿用其冻结配置与训练状态                  |

## 检查并提交

在最后一步点击「检查训练配置」，逐项核对服务端返回的最终生效值、依赖调整和当前不生效项，再点击「开始训练」。同时可查看冻结数据、类别、权重、镜像与配置摘要。修改任何输入或受控目录发生变化后，都需重新检查。

页面按当前账号和项目保存本地草稿，刷新后会重新核验数据、目录与权限。创建响应中断时，会锁定原请求并提供「重试并确认创建」，重试沿用相同请求身份。也可返回实验列表检查结果；只有明确放弃尚未确认的请求后才能继续编辑，重新提交可能产生另一个实验。

实验固定数据包、类别顺序、验证集、基础模型和运行环境。GPU 正忙或执行器离线时保持排队；训练使用指定的一张 GPU，同一物理资源一次执行一个实验。显存不足会报告失败，不会自动改小批大小或图片尺寸。

参数、增强预览与配置复用见[训练配置与复用](./configuration)。

## 产物位置与历史实验

新实验创建时固定权重、检查点、报告与日志所在的整个产物前缀，各次执行和断点续训共用同一位置。之后修改当前训练桶，不会把已有实验指向新桶。训练输入的数据版本、项目候选初始化的来源权重与本实验输出各自解析保留位置，可以位于不同桶。

升级前尚未固定位置的实验仍可查看列表、配置和已有元数据；读取或下载文件、上传产物、续训及回流模型前，需要项目管理员通过 [storage-pin API](/api/guides/training-datasets#实验产物归属与历史核验) 显式核验当前保留副本。实验和全部执行须已成功、失败或取消，且资源租约已释放；失联不表示已停止。停止和资源收尾仍可完成。

核验会完整读取保留产物，并与已保存的独立摘要、大小及执行身份比较；缺失、冲突或无法解释的额外文件会拒绝。此时保留记录与文件，先由管理员核对，不通过修改当前桶或直接补数据库值绕过。已有位置但端点身份不符时也会明确拒绝，运维步骤见[存储恢复说明](/ops/deploy/storage-recovery#训练实验产物归属的部署顺序)。

## 停止与断点续训

「停止训练」会先请求退出。看到「已取消」才表示训练进程已停止。失败或取消后，页面核对当前执行已释放资源、正轮次的未完成检查点、冻结配置与已知兼容环境，才提供「从检查点续训」。兼容执行器离线时可以排队；历史执行的检查点不会替代当前执行。续训沿用原配置并新增记录，当前进度重新开始记录；没有合格检查点时需创建新实验。

显存不足依据原生异常类型显示说明，信号终止不会被推断成显存不足。完整配置实验可使用原始基础权重新建草稿，明确检查批大小 `batch` 与尺寸 `imgsz`；不会自动改参数、选数据或采用检查点。旧六参数实验需在配置工作区明确迁移。执行器失联时保留 GPU 租约，等待确认旧进程退出；遥测中断本身不会释放资源。

训练已经退出后，产物发布遇到永久性校验拒绝会回报失败并显示原因，避免一直占着队列重试。临时网络、存储或锁繁忙会继续上传；完成响应丢失时确认原结果，不会重新训练。

新生成的 Ultralytics 检查点会一并保留历史最佳权重，续训期间没有更佳指标也能完成最终评估。旧检查点若缺少这一恢复凭据，仍按原配置尝试恢复；无法取得历史最佳时会明确失败，不会将最后一轮权重冒充最佳。扩展配置实验要求完整恢复凭据。续训保留最佳模型选择，但不承诺与不中断训练逐位一致。

## 删除与来源保护

打开具体实验，点击详情页顶部的「删除实验」，确认后删除；「新建实验」保留在训练实验列表页。训练尚未结束，或实验已被项目模型引用时，删除按钮禁用并说明原因。模型归档仍保留来源引用，不会解除实验保护。

终态实验未被其他记录引用时可以删除，被搜索、策略等引用时也会阻止删除并说明原因。删除未被引用的数据版本或终态实验后，记录立即移出列表；存储暂时不可用时后台继续清理文件，不会把已完成的删除显示为失败。

删除前须已固定存储归属，清理责任会保留同一位置，不随当前训练桶变化。历史未核实的清理意图保持待核对，不执行物理删除。

选择具体执行后，继续查看[训练监控与指标](./metrics)。
