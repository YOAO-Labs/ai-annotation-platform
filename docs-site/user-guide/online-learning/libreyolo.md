# LibreYOLO 训练容器

选择「LibreYOLO」训练仓库，可以用项目的冻结矩形框数据训练 YOLO9 检测模型，保存原生权重与完整检查点，并对通过资格检查的规格进行模型回流。本页逐项对照原生参数和平台配置。

## 容器与仓库的关系

当前 `training-executor` 镜像同时安装 LibreYOLO 和 Ultralytics，由框架适配器选择训练入口。两个仓库可以共用同一个容器与 GPU，同一物理资源串行执行。LibreYOLO 不是经由 Ultralytics 的训练回调或检查点格式来训练。

训练镜像固定安装 `libreyolo==1.6.0`，使用 PyTorch `2.14.1+cu132`、torchvision `0.29.1+cu132`。管理员还需为受控型号配置镜像摘要、权重文件与校验值；可选模型由实际目录决定。推理使用独立 LibreYOLO 原生插件，不依赖 Ultralytics；默认 YOLO9 t，另支持 s/m/c。

上游仓库覆盖更多模型和任务，也提供多 GPU、从零训练、LoRA、蒸馏等训练能力，参见[容器依赖对应的仓库说明](https://github.com/LibreYOLO/libreyolo/blob/809009bc294daa6e75e0976ab7cfdd0057d17d79/README.md)。平台当前开放范围见下表，参数对照以其[通用与 YOLO9 配置源](https://github.com/LibreYOLO/libreyolo/blob/809009bc294daa6e75e0976ab7cfdd0057d17d79/libreyolo/training/config.py)为基准。

## 支持的模型与任务

| 基础模型 ID              | 任务         | 平台训练与下载 | 平台回流                                    |
| ------------------------ | ------------ | -------------- | ------------------------------------------- |
| `libreyolo9t`            | 图片目标检测 | 支持           | 资格核验后支持原生插件推理、试用和默认预标 |
| `libreyolo9s`            | 图片目标检测 | 支持           | 同上                                        |
| `libreyolo9m`            | 图片目标检测 | 支持           | 同上                                        |
| `libreyolo9c`            | 图片目标检测 | 支持           | 同上                                        |
| `libreyolo9e`            | 图片目标检测 | 不支持原生执行 | 历史记录与已有产物仍可读取、下载            |
| 其他家族、规格或量化格式 | 对应原生任务 | 尚未开放       | 尚未开放                                    |

当前固定的 LibreYOLO 原生 YOLO9 实现仅提供 t/s/m/c。E 不属于该原生实现，不能通过添加目录项、改文件名或切换到 C 来启动训练；历史 E 记录与产物保持原身份。

表中的型号是受控适配器允许的范围，页面只展示管理员已经配置的条目。原生权重命名可能使用 `LibreYOLO9t.pt` 等文件名，平台基础模型 ID 则使用上表的小写形式。

| 能力范围                           | 上游仓库                              | 当前在线学习                                                   |
| ---------------------------------- | ------------------------------------- | -------------------------------------------------------------- |
| 图片检测                           | 提供 YOLO9、YOLOX、RF-DETR 等多种家族 | 仅受控 YOLO9 t/s/m/c                                           |
| 实例、语义或交互式分割             | 有对应家族与任务，需匹配原生实现      | 未开放 LibreYOLO 训练与回流；项目分割使用受控 Ultralytics 路径 |
| 分类、姿态、旋转框及其他视觉任务   | 有对应模型入口                        | 未开放本章的训练与回流流程                                     |
| 配方、实验克隆与断点续训           | 原生训练提供配置与状态                | 平台固定配置与完整检查点后提供对应入口                         |
| 增强预览、共享逐样本评估、主动选样 | 各自需要特定实现                      | 当前未开放此适配器资格                                         |

## 平台增加或管理的实验参数

| 平台参数或选项          | 原生对应                       | 默认或选择规则                                                 |
| ----------------------- | ------------------------------ | -------------------------------------------------------------- |
| 实验任务 `task`         | 模型与原生检查点任务           | 当前只允许图片检测 `detect`                                    |
| 训练器 `framework`      | LibreYOLO 适配器               | 本页为 `libreyolo`                                             |
| 基础模型 `base_model`   | 模型权重与原生 `size`          | 只允许目录中的 YOLO9 t/s/m/c                                   |
| 数据版本 `dataset_id`   | 执行时生成的 `data`            | 同项目就绪检测版本；固定图片与原生类别顺序                     |
| 实验名称 `name`         | 平台显示名称                   | 默认带 `detect-` 前缀；原生输出子目录固定为 `framework`        |
| 模型初始化              | 管理员配置的基础权重           | 新实验使用受控基础权重，暂不开放项目候选初始化或随机初始化选项 |
| 旧参数对象 `parameters` | 原六个训练参数                 | 兼容历史提交；与完整配置互斥                                   |
| 配置 `configuration`    | 生效的原生参数                 | 可编辑项使用受控默认值，平台处理依赖与固定项                   |
| 配方／克隆 `origin`     | 平台配置来源                   | 固定来源，仍需明确选择本轮数据                                 |
| 从检查点续训            | 完整原生状态与平台最佳权重凭据 | 由平台检查当前执行资格，不接受任意 `resume` 路径               |
| 训练集逐轮 PR／mAP      | 没有本适配器对应的平台选项     | 不提供 `evaluate_train`，不能借用 Ultralytics 配置             |
| 预检与创建请求标识      | 平台预检、重复请求确认         | 界面生成，不传入原生训练                                       |

旧六参数实验仍沿用其冻结配置，新建完整配置支持更多受控原生参数。配置使用方式见[训练配置与复用](./configuration)。

## 参数名称、依赖与默认值差异

平台使用 LibreYOLO 的原生键：优化器为小写 `sgd`、`adam`、`adamw`；增强概率为 `mosaic_prob`、`mixup_prob` 和 `flip_prob`，不照搬 Ultralytics 的同类键。平台只为 `mixup_prob` 开放 `mixup` 别名，二者不能同时提交。参数表中另列出的原生 `mixup` 字段属于其他路径，不是当前 YOLO9 检测的可编辑项。

与原生默认相比，平台把 `epochs` 改为 `50`、`batch` 改为 `8`、`seed` 改为 `42`，并把新训练的 `letterbox_pad` 明确设为 `center`。设备、AMP、加载进程、验证频率与产物配置由平台固定，不能通过 YAML 覆盖。

| 条件                               | 生效或校验规则                                                        |
| ---------------------------------- | --------------------------------------------------------------------- |
| 优化器不是 `sgd`                   | 动量、Nesterov 与动量预热不生效，显式提交会拒绝                       |
| 使用 `sgd` 且启用 Nesterov         | `momentum` 必须大于 0                                                 |
| `warmup_epochs=0`                  | 起始预热学习率与动量预热不生效                                        |
| 学习率计划不是 `linear`            | `warmup_momentum` 不生效                                              |
| 关闭 `ema`                         | `ema_decay` 不生效                                                    |
| 预热开启且 `warmup_lr_start > lr0` | 默认值随 `lr0` 调整；显式越界覆盖会拒绝                               |
| `mosaic_prob=0`                    | YOLO9 Mosaic 分支的旋转、平移、缩放、剪切、透视和 MixUp 不生效        |
| 默认 `no_aug_epochs` 覆盖全程      | 随短训练缩短为至多 `epochs - 1`；显式覆盖全程时，相关增强会标为不生效 |

## 指标、检查点与回流

训练过程提供原生总损失 `train/loss`，`val_loss` 可选择是否计算原生验证损失。当前没有训练集逐轮 Precision、Recall 或 mAP 表现，也没有分类别最终指标。

最终报告保存 mAP50-95、mAP50、mAP75 和 AR100。原生 `precision`／`recall` 别名分别对应 mAP50-95／AR100，平台不把它们当作常规 Precision／Recall。没有预测时可能没有执行 COCO 评估后端，零指标仍保留，但缺少评估身份时不能参与同口径排名。

断点续训要求当前实验的完整检查点，核对原生任务、模型家族、类别顺序、优化器、随机状态及历史最佳权重。缺失或不匹配的状态会明确失败；不把最后权重冒充最佳权重，也不承诺恢复后与连续训练逐位一致。

YOLO9 t/s/m/c 回流时再次核对格式、原始类别与权重字节。独立插件的 CUDA 配置固定 LibreYOLO 1.6.0、PyTorch `2.14.1+cu132`、torchvision `0.29.1+cu132` 和 CUDA 13.2，使用 FP32 并关闭 half、AMP、TF32；显式 CPU 开发或历史配置不是 GPU 失败时的回退。实际运行时及资格独立固定，不修改原始训练收据。负责人仍须完成类别绑定、固定样本试用，并明确发布默认预标选择。YOLO9 e 以及其他家族未开放回流，见[模型回流](./models)。

## 目前的局限性

- 训练限受控 YOLO9 图片检测；仓库支持其他模型和任务，不会自动扩大平台目录。
- 新实验暂不开放项目候选初始化、从零训练、任意权重上传、LoRA、层冻结、蒸馏、CUDA Graph、编译或外部实验跟踪器注入。
- 训练固定使用单张 GPU，AMP、同步 BN、缓存与下载脚本均关闭，未开放 DDP、自动批大小或 CPU 训练。执行器另固定 CPU 线程，显存不足不会自动改小参数。
- 原生增强预览、共享逐样本评估和主动选样尚未开放；已有原生试用与默认预标流程可以继续使用。
- 缺少常规 Precision／Recall、训练集表现和分类别报告时保持缺失；跨框架不能直接对比分数。训练参数表与[逐样本固定阈值评估](./sample-evaluation)的设置用途不同。
- YOLO9 e 不支持原生执行，历史记录与产物仍可读取、下载；回流限 t/s/m/c。训练产物不自动安装或激活插件、启用项目或改变默认预标模型。

需要实例分割或逐轮训练集表现时，查看 [Ultralytics 训练容器](./ultralytics)的对应能力与参数。
