# 训练监控与指标

打开实验详情，在「查看执行」中选定一次执行记录，再查看「指标曲线」「资源与耗时」「产物与记录」「训练配置」和「实时日志」。续训会新增执行记录，阅读曲线前先核对当前选择。

## 对照阅读四张曲线

选择实验后，详情显示训练阶段、实际轮次与执行耗时。「指标曲线」上排展示「训练表现」「训练损失」，下排对应「验证表现」「验证损失」。两张表现图使用 Precision、Recall、mAP50 和 mAP50-95；实例分割分别保留框和掩码指标。两张损失图对应框、分类、DFL／L1、掩码及原生语义损失，按执行器实际提供的分项展示。YOLO26 使用原生 L1 分项，不会补造 DFL 为零；未上报的指标保持缺失。

训练时每 3 秒增量刷新；可切换各次执行记录，续训曲线不会与前一次混合。逐轮指标表保留可查询的数值，缺失或不可用指标显示为空，不会补成零。

## 训练表现、训练损失分别回答什么

| 图表     | 数据来自哪里                       | 用来观察什么                                  |
| -------- | ---------------------------------- | --------------------------------------------- |
| 训练表现 | 可选的冻结训练集原生评估，关闭增强 | 模型在训练集上的 Precision、Recall 与 mAP     |
| 训练损失 | 实际优化过程中的逐轮平均值         | box、cls、dfl、seg 等实际提供的损失分项       |
| 验证表现 | 原生验证流程                       | 模型在冻结验证集上的 Precision、Recall 与 mAP |
| 验证损失 | 原生验证流程                       | 相同任务的验证损失分项                        |

## 是否开启逐轮训练集评估

Ultralytics 的「逐轮评估训练集」（`evaluate_train`）默认关闭，可在创建实验的「配置参数」常用项中开启。每轮结束后，平台使用与验证集相同的原生评估器，关闭增强，额外评估冻结训练集。这会增加执行耗时；结果只用于监控，不参与最佳权重选择，选择会随实验、配方、克隆及续训保留。

这一选项由平台额外调度评估调用，相当于对训练分区执行 `model.val(split="train")`，并非给 `model.train()` 增加一个同名原生参数。训练损失无须开启它，始终采集；LibreYOLO 只提供训练总损失，未提供训练集表现。历史执行未上报的指标保持为空，不补算，也不会用验证结果代替。

## 怎样理解表现与损失

| 指标                | 阅读方式                                                                   |
| ------------------- | -------------------------------------------------------------------------- |
| Precision（精确率） | 关注预测出的目标有多少是正确的，误检多时通常需要重点检查                   |
| Recall（召回率）    | 关注真实目标找回了多少，漏检多时通常需要重点检查                           |
| mAP50               | 在 IoU 阈值 0.50 下汇总各类别 AP，结合置信度排序评价结果                   |
| mAP50-95            | 在 0.50 至 0.95 的多个 IoU 阈值下平均，更严格地考察定位或掩码重合          |
| loss（损失）        | 原生训练目标的分项或总值，用来观察优化过程；量纲与权重不同的分项不直接互比 |

Precision 和 Recall 与评估阈值及框架语义有关，mAP 也不是某个固定阈值下的准确率。类别不均衡时，结合分类别结果和具体样本阅读，避免只看整体均值。

训练损失来自带训练增强的优化过程，而训练集评估关闭增强，因此损失下降与 mAP 变化不一定同步。训练和验证损失还受各自数据组成影响，不宜只凭绝对值大小判断质量。训练表现持续提高、验证表现停滞或下降时，可以检查过拟合、样本覆盖和划分泄漏，再用冻结样本复查错误。

实例分割的表现图分别展示框和掩码。阅读掩码质量时选择掩码指标，并同时检查漏检与实际像素结果。Ultralytics 分割原生最佳权重选择分数是框与掩码 mAP50-95 之和，可能大于 1，不能解读成百分比或单独的掩码准确率。

## 最近轮次与最终最佳权重

曲线记录所选执行逐轮上报的结果。最终最佳权重可能来自更早的轮次；续训时也可能保留前一次执行的历史最佳权重。要判断最终交付模型，查看[实验比较](./comparison)中的 Best 最终评估或下载对应评估文件，不能用曲线最后一点替代。

指标按训练框架语义显示，重复别名会合并。缺失值、未上报分项或未知停止原因保持未知；提前完成不自动等于耐心早停。停止和检查点资格见[停止与断点续训](./experiments#停止与断点续训)。

## 资源、耗时与剩余时间

「资源与耗时」中的所选执行资源卡片约每 5 秒刷新，显示训练进程组的 CPU 核数、RSS 总和、原生批次吞吐，以及整张 GPU 的利用率和显存。整卡数值可能包含其他进程；PyTorch 已分配／保留显存来自训练子进程分配器，不能当作全部进程显存。无法确认归属或读取失败时显示不可用，真实零值仍显示为零。可展开近期资源趋势；峰值只涵盖实际收到的采样。

执行耗时持续更新，已结束的历史记录保持固定。观测阶段与执行状态分别显示，不会从低利用率推断等待数据。至少收到 3 个可比较的完整训练周期后，才估算训练剩余时间范围；首个预热／恢复周期不计入。尚未观测过的增强尾段、过期采样、停止或失联会暂停估算。评估和保存耗时保持未知，提前停止也不会被当作保证完成时间。

## 实时日志与历史产物

「实时日志」显示已脱敏的近期内容，可加载更早日志或关闭「跟随最新日志」继续阅读。点击「复制当前日志」可原样复制当前已加载的全部日志块；需要完整历史时下载日志产物。实验、评估、数据版本和模型发布的错误信息旁均提供复制入口，保留完整原文和换行。连接中断后保留已显示内容并继续重连；保留窗口造成的缺口会明确提示。每次执行最多保留 720 条近期采样与 512 个日志块，原始观测在 7 天后分批清理；历史摘要和已发布产物继续保留。切换执行、项目或登录会话后不会混入迟到结果。

「产物与记录」按执行次数下载权重、完整续训检查点、脱敏日志、配置、资源与阶段观测摘要和产物清单；「训练配置」查看本次冻结的数据与参数。产物通过大小与 SHA-256 校验后才可下载。日志下载返回再次脱敏的副本，原始产物与摘要不改写；超出 8 MiB 或校验失败的历史日志明确不可用。URL、凭据和主机路径在新日志保存前脱敏，超长行整体省略。上传中断会继续上传已完成结果，无需重新训练。
