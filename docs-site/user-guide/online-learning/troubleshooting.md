# 常见问题与能力边界

先核对当前项目、任务类型、数据版本、实验执行和目标部署，再处理对应问题。不同执行或部署的状态可能不同；页面显示未知时，不用其他记录的结果代替。

## 从训练队列定位问题

「训练队列 → 开始训练」列出可管理项目，支持按名称或编号搜索；没有就绪版本时先点击「准备数据」。类别未配置或媒体类型不支持时，页面会列出原因，结构配置通过后仍需检查实际训练样本。

「队列与历史」集中显示执行、排队、完成和失败数量，可按进行中、已结束、异常及训练器筛选。点击实验进入详情，查看所选执行记录；页面约每 3 秒刷新，筛选与视图保存在链接中。

「训练仓库」显示执行器最近心跳，按系列与任务统一列出基础模型规格、参数数量、兼容状态和回流能力。版本旁可复制容器镜像摘要，规格旁可复制对应基础权重校验值，用于向管理员核对环境。不同框架仓库可能共用同一容器和 GPU，不能按仓库数量推断并发能力。

## 数据准备与训练问题

| 现象                               | 先核对什么                                                 | 下一步                                                                   |
| ---------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------ |
| 未标注图片没有进入负样本           | 是否已审核确认无目标，或负责人逐项确认                     | 完成人工检查后重新预检；不要用空白状态推断无目标                         |
| 父版本或比较基线不可选             | 项目、任务、就绪状态及数据桥接是否兼容                     | 选同任务兼容版本；检测与分割、简单多边形与原生掩码不能混作父版本         |
| 数据构建后，当前标注已修正但包没变 | 数据版本保存的是冻结快照                                   | 用修正后的标注创建新版本；重试失败构建仍沿用原快照                       |
| 创建响应中断，不确定是否成功       | 页面是否保留未确认请求，列表是否已有记录                   | 使用页面的确认原请求入口；不要换一组内容反复创建                         |
| 新建实验没有数据或模型可选         | 是否先选任务，是否存在同任务就绪数据和可用训练器           | 先准备数据，再检查仓库能力与基础模型；未选择的灰色提示不是业务选项       |
| 项目模型不能用来初始化             | 同项目、任务、框架、基础型号、原生类别与顺序是否一致       | 读资格原因并重新选择；不支持任意检查点上传或类别头重映射                 |
| 实验持续排队                       | 执行器心跳、GPU 上的实验及停止／失联状态                   | 查看队列与仓库，必要时请管理员确认旧进程；失联不代表资源已释放           |
| 显存不足                           | 当前执行日志及原生异常                                     | 以原基础配置新建草稿，明确调整 `batch` 或 `imgsz` 并重新检查             |
| 点停止后仍未取消                   | 是否还在退出、上传或确认旧进程                             | 等待后端确认；看到已取消才代表训练进程停止                               |
| 没有续训按钮                       | 当前执行是否已释放资源、是否有合格完整检查点、环境是否兼容 | 读资格原因；没有合格检查点时创建新实验                                   |
| 分割小目标在训练前被拒绝           | 所选训练尺寸缩放后是否仍有实例前景像素                     | 核对冻结掩码与 `imgsz`；训练消失和验证器缩小掩码的 tiny 目标损失分别报告 |

具体操作见[训练数据版本](./data-versions)和[创建与管理实验](./experiments)。数据版本、实验和模型的删除会检查来源引用；先处理页面指出的引用，归档模型不会解除引用保护。

## 指标与比较问题

| 现象                              | 如何理解                                                                                                                 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 有训练损失，没有训练表现          | 训练损失始终采集；Ultralytics 训练集 Precision／Recall／mAP 需要创建时开启「逐轮评估训练集」。LibreYOLO 未提供训练集表现 |
| 训练曲线最后一点与 Best 表不同    | Last 是所选执行最近轮次；Best 是已发布最佳权重的最终评估，可能来自更早轮次                                               |
| 两个实验都有分数，却没有差值      | 冻结验证基准、类别、评估器、参数或指标语义可能不同，也可能缺少身份记录；只有完整且同口径的结果参与差值计算               |
| 分割最佳选择分数大于 1            | 原生 fitness 使用框与掩码 mAP50-95 之和，不能当百分比                                                                    |
| 逐样本 F1／Dice 与训练 mAP 不一致 | 前者使用固定置信度与匹配阈值，后者来自原生评估；匹配实例 Dice 还不包含漏检，不能互相替代                                 |
| 图中断线或显示空值                | 缺失、不可用或轮次间断会保留，不补零；先核对执行和实际上报能力                                                           |
| GPU 显存高于 PyTorch 分配值       | 前者是整卡数值，可能含其他进程；后者来自训练子进程分配器                                                                 |

详细解释见[训练监控与指标](./metrics)、[实验比较](./comparison)和[逐样本评估](./sample-evaluation)。

## 加载与默认预标问题

| 页面提示或现象                   | 处理方式                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------- |
| 服务列表读取失败                 | 点击重试；持续失败时请管理员核对 API 错误与账号权限                                       |
| 项目未启用服务                   | 在「项目设置 → ML 模型 → 管理 backend」启用已有实例                                       |
| 未配置推理认证                   | 超管编辑目标实例；内置服务选择对应系统托管认证，自建服务填写匹配的手动 Token              |
| 服务当前不可用                   | 超管执行实例健康检查，核对服务运行与模型能力；普通 `/health` 成功不等于受保护端点认证通过 |
| 本地凭据已初始化，仍无法调用     | 本地文件存在不代表旧容器已经升级或认证验证成功，按系统设置中的结果继续排查                |
| 推理环境已变化                   | 在模型详情重新加载并试用，再创建评估；训练版本保留原值，推理版本按目标部署记录            |
| 不支持的评估协议                 | 管理员核对平台与推理服务的协议支持，不能通过改写训练版本解决                              |
| 加载失败或副本损坏               | 复制错误信息，修复目标服务后重新加载试用，沿用已冻结权重                                  |
| 设置默认时提示配置变化           | 刷新后核对最新模型和部署，再确认本次选择，避免覆盖其他负责人的修改                        |
| 模型有输出，但工作台候选列表为空 | 检查「单图 AI → 高级配置 → 候选筛选与批量采纳」的显示阈值，再审阅候选                     |
| 切换默认后，旧任务仍使用旧模型   | 任务在创建时固定模型；切换默认只影响以后解析默认选择的新任务                              |

设置与恢复步骤见[模型回流与默认预标](./models)。每种任务可以保留多个部署，默认预标选择不等于全项目只使用一个模型。

## 自动训练与主动选样问题

| 现象                           | 检查方向                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| 策略已启用，却没有新实验       | 是否有已审核训练分区的实际变化、达到门槛并结束冷却；检查触发记录与定时调度                 |
| 验证集变了，变化样本数没有增加 | 验证变化形成新评估基准，不计入训练样本增长                                                 |
| 检测策略在等待分割任务         | 同项目自动训练串行；构建、排队、运行或失联待确认会阻止另一任务重复触发                     |
| 同一份失败数据没有反复自动重试 | 失败不推进成功基线，同一策略修订不会重复启动相同失败训练内容；处理原因后明确保存新修订     |
| 主动选样候选被排除             | 检查是否与历史训练、验证、测试成员同内容或同场景，以及是否有标注、草稿、锁、分派或历史记录 |
| 主动建议中没有预测实例         | 这是缺少模型信号，会使用标记的随机补位，不能据此认定背景                                   |
| 选样预览成功，接纳却失败       | 接纳前会重新核对媒体、资格与历史成员；发生变化后需重新选样                                 |

配置细节见[自动训练策略](./automation)和[主动学习选样](./active-learning)。

## 能力速查

| 能力                     | Ultralytics 检测                 | 受控 Ultralytics 实例分割        | LibreYOLO 检测                 |
| ------------------------ | -------------------------------- | -------------------------------- | ------------------------------ |
| 基础模型                 | YOLOv8／11／26 n/s/m/l/x         | YOLOv8／11／26 n/s/m/l/x         | YOLO9 t/s/m/c                  |
| 训练数据                 | 矩形框                           | 简单多边形或原生实例 RLE         | 矩形框                         |
| 配方、克隆与检查点续训   | 支持，需资格检查                 | 支持，保持任务与桥接一致         | 支持，需资格检查               |
| 逐轮训练损失             | 原生分项                         | 原生分项，包含实际提供的掩码损失 | 原生总损失                     |
| 逐轮训练集 PR／mAP       | 可选，默认关闭                   | 可选，框／掩码分别展示           | 未提供                         |
| 从零随机初始化           | 可选                             | 可选                             | 未提供本章所述选项             |
| 项目候选初始化           | 受控同版本、家族、规格与类别顺序 | 受控同版本、家族、规格与类别顺序 | 未开放                         |
| 原生增强预览             | YOLO11 检测                      | 未开放                           | 未开放                         |
| 参数搜索                 | 已开放的受控检测配置             | 未开放                           | 已开放的受控检测配置           |
| 模型回流                 | 需资格检查                       | 受控原图掩码路径                 | YOLO9 t/s/m/c，已验证 CPU 路径 |
| 共享逐样本评估与主动选样 | 支持                             | 支持，另有像素与计算上限         | 未开放                         |

当前训练抽取限图片项目。分割回流仅支持图片整图源阶段，暂不用于父框裁剪、视频或点／框／文本交互提示；检测和分割的默认选择互不替代。其他任务、模型规格、量化格式与运行时以服务端能力声明和资格检查为准。

## 目标部署的独立验收

用户流程跑通只能说明所用环境的这条流程成功。目标部署的 GPU 故障处理和模型生命周期仍由部署管理员单独验收，不能用普通 YOLO 模型的验收结果代替受控分割模型路径。

管理员按[实例分割在线学习验收](../../dev/how-to/validate-segmentation-online-learning)准备真实受控分割权重、冻结来源和代表原图，执行两轮冷加载、同池卸载等生命周期检查；GPU 故障与租约恢复按 [GPU 仲裁验收](../../ops/runbooks/gpu-arbitration-acceptance)执行。保留与实际镜像、权重、设备相匹配的证据。业务是否接受误检、漏检与修正成本，由项目负责人结合验证集和人工试用决定。

## 反馈问题时保留哪些信息

复制当前项目、任务类型、数据版本、实验及精确执行、模型与部署的 ID，并附错误原文、发生时间和操作步骤。页面的复制图标可复制完整 ID 或哈希；悬浮或键盘聚焦可查看含义。列表中的任务序号、部署序号用于当前显示集合，排查时以完整 ID 为准。

实验日志可复制当前已加载内容，完整历史通过产物下载。浏览器剪贴板失败时检查权限或使用 HTTPS；局域网 HTTP 仍可打开训练页面、准备数据与配置实验。更深入的模型安装和路由诊断交给管理员参考[模型回流链路排查](../../dev/how-to/debug-model-return)。
