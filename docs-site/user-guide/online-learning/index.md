# 在线学习

把项目中已经检查的标注用于训练，再把新模型交给标注员试用，是在线学习的主要工作。本章从第一轮训练讲到后续迭代，覆盖图片目标检测和图片实例分割。

平台按轮次冻结数据、训练和保存模型。人工接纳、修正、提交与审核后的标注，才会进入下一轮数据准备；预标候选、加载试用和评估结果不会自动成为训练真值。可以先手动完成一轮，再根据项目节奏开启自动训练。

## 从哪里进入

项目负责人和超级管理员可从左侧「训练队列」查看可管理项目、训练仓库、队列与历史。点击「进入项目」打开项目在线学习页；项目列表卡片或行菜单中的「在线学习」也通向同一入口。

「开始训练」侧栏显示仓库名称、版本和可用状态。「训练仓库」页将基础模型、参数数量和兼容状态统一按系列与任务分组，不同规格在同一行展示。规格旁的复制按钮可复制对应基础权重校验值，悬停规格可查看完整型号与权重文件名；仓库版本旁可复制容器镜像摘要。

项目页有四个标签：

| 标签       | 在这里完成什么                                               |
| ---------- | ------------------------------------------------------------ |
| 训练数据   | 检查标注、冻结版本、查看样本与分布、比较版本、下载训练包     |
| 训练实验   | 选择任务、数据与模型，配置训练，跟踪执行并比较实验           |
| 模型与发布 | 注册候选、绑定类别、加载试用、评估、设置各任务的默认预标模型 |
| 自动训练   | 按已审核数据的变化门槛和冷却时间触发下一轮训练               |

列表筛选、页码和详情视图通常保存在地址中，返回或刷新后可以继续查看。创建日期筛选按 UTC 日界计算，结束日期包含整天；自动填写的名称使用本地时间。

需要脚本或终端操作时，可以使用 [Python SDK](../../dev/sdk/python-client#在线学习命名空间) 与 [aap learning CLI](../../dev/sdk/cli#aap-learning)。它们沿用相同的项目权限、预检摘要和版本冲突保护；TUI 提供训练队列、执行详情和日志监控，配置、发布与人工决策仍需明确操作。

## 一轮迭代会留下什么

| 对象         | 保存的内容                                 | 下一步                           |
| ------------ | ------------------------------------------ | -------------------------------- |
| 数据版本     | 当时的图片、标注、类别顺序、训练／验证划分 | 用就绪版本创建实验               |
| 训练实验     | 所选数据、模型初始化、生效参数与运行环境   | 等待执行，查看指标和产物         |
| 执行记录     | 一次运行的曲线、日志、检查点与结果         | 比较结果，或在合格时续训         |
| 候选模型     | 成功执行的最佳权重及项目类别绑定           | 在具体服务上加载并试用           |
| 模型部署     | 某候选在某推理服务上的安装和试用记录       | 评估，或设为该任务的默认预标模型 |
| 默认预标选择 | 检测或分割默认入口使用的模型与部署         | 生成候选，交给人工审阅           |

同一个项目可以保留多个模型，也可以同时有多个部署。检测和实例分割各自维护默认预标选择；默认选择只服务于对应任务的默认入口。管线明确指定的模型、已有部署和已排队任务各自保留固定来源，详见[模型回流与默认预标](./models)。

## 开始前确认分工

项目负责人负责检查数据、创建实验、核对类别绑定、组织人工试用，并决定默认预标选择。标注员和审核员按原有项目流程完成候选接管、修正、提交和复核，操作见[候选审阅](../ai/candidate-review)和[审核流程](../review/)。

超级管理员负责训练执行器与推理服务的准备。训练仓库用于执行训练，ML Backend 用于模型推理，两者可以位于不同服务。全局注册一个推理服务后，还需要在项目中启用；训练成功也不会自动完成这些配置。

## 当前支持范围

| 任务与训练器             | 数据与训练                                                                 | 模型回流与使用                                                                            |
| ------------------------ | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Ultralytics 图片目标检测 | 矩形框；目录中受控型号；支持训练集逐轮评估、从零训练、增强预览与参数搜索   | 通过资格检查后可回流、试用、默认预标、逐样本评估和主动选样                                |
| Ultralytics 图片实例分割 | 受控 `yolo11n-seg`；简单多边形或原生实例掩码；支持训练集逐轮评估和从零训练 | 受控原图实例掩码回流；整图预标、掩码逐样本评估和主动选样；暂不支持参数搜索或增强预览      |
| LibreYOLO 图片目标检测   | 目录中受控模型；原生训练、检查点与最终评估                                 | YOLO9 t/s/m/c 可在独立插件上按 CPU 或 CUDA 运行时资格回流；共享逐样本评估与主动选样尚未开放 |

页面以当前执行器和服务端的资格检查为准。能下载权重、能训练某型号，不代表该型号已经开放平台回流。视频、点云、分类、关键点与旋转框尚未开放本章同样的训练流程；完整边界见[能力速查](./troubleshooting#能力速查)。

## 数据来源、谱系与存储边界

- **来源谱系与冻结副本**：训练数据版本同时支持托管原件与原地引用目录（详见[训练数据版本](./data-versions)）。冻结时平台按完整 SHA-256 核验原图并写入独立训练存储，保存原件身份或来源修订证据，后续源目录变更不会改写已就绪版本。
- **实际训练成员回执（`input_membership`）**：实验执行时由训练执行器核对原生加载器实际接纳的训练/验证成员，并在成功产物的 `manifest.json` 中记录 `input_membership` 回执，防止静默漏项或分区漂移（详见[创建与管理实验](./experiments#实际训练成员回执（input_membership）)）。
- **存储归属与新分配切换**：训练文件的新分配位置由超级管理员在[九用途映射与受控切换](/user-guide/datasets/purpose-bindings#切换训练文件的新分配位置)中验证并确认。已有数据版本、实验、预览、评估和主动学习文件继续按保存位置使用；重试和续训不搬迁历史对象，未知旧归属仍需显式核验。此设置只调整文件目标，不改变模型、参数或训练资格。
