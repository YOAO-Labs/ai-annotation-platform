# Ultralytics 训练容器

选择「Ultralytics」训练仓库，可以用项目的冻结标注训练 YOLOv8、YOLO11 和 YOLO26 的目标检测或实例分割模型。三个家族均登记 n/s/m/l/x 规格；实际可选项以管理员已准备、校验并启用的目录为准。本页列出使用的仓库、支持范围，以及原生配置和平台配置的完整对照。

## 容器与仓库的关系

当前部署使用共享的 `training-executor` 镜像，其中同时安装 Ultralytics 和 LibreYOLO。界面中的两个训练仓库分别表示两套框架适配器；它们可以由同一个容器执行，并共用同一张 GPU。同一物理资源一次执行一个实验，仓库数量不代表并行训练数量。

镜像固定安装 `ultralytics==8.4.183`，使用 PyTorch `2.14.1+cu132`、torchvision `0.29.1+cu132`。管理员配置镜像摘要和每个基础权重的校验值后，平台才把相应型号列为可选项。执行器核对依赖、权重、数据与参数身份，不能通过填写其他模型文件名绕过目录。

上游仓库还提供其他模型家族和任务。查看原生功能时，以[容器依赖对应的仓库说明](https://github.com/ultralytics/ultralytics/blob/v8.4.183/README.md)及[配置源文件](https://github.com/ultralytics/ultralytics/blob/v8.4.183/ultralytics/cfg/default.yaml)为依据；下面的平台支持表决定哪些能力可以在在线学习中使用。

## 支持的模型与任务

| 家族   | 检测基础模型 ID                                       | 实例分割基础模型 ID   | 规格      |
| ------ | ----------------------------------------------------- | --------------------- | --------- |
| YOLOv8 | `yolov8n`、`yolov8s`、`yolov8m`、`yolov8l`、`yolov8x` | 对应检测 ID 加 `-seg` | n/s/m/l/x |
| YOLO11 | `yolo11n`、`yolo11s`、`yolo11m`、`yolo11l`、`yolo11x` | 对应检测 ID 加 `-seg` | n/s/m/l/x |
| YOLO26 | `yolo26n`、`yolo26s`、`yolo26m`、`yolo26l`、`yolo26x` | 对应检测 ID 加 `-seg` | n/s/m/l/x |

共 30 个型号与任务组合。检测模型通过相应资格检查后可回流、试用与预标；分割模型使用简单多边形或独立实例 RLE，回流用于原图掩码、整图预标和掩码评估。目录登记、节点权重就绪、原生训练和目标部署资格分别核验，不能把检测型号的数据或参数定义改名后用于分割。未登记的家族、规格及任务仍不可选。

| 任务                               | 上游仓库能力                       | 当前在线学习入口                               |
| ---------------------------------- | ---------------------------------- | ---------------------------------------------- |
| 图片目标检测                       | 提供对应模型与流程                 | YOLOv8、YOLO11、YOLO26 的 n/s/m/l/x            |
| 图片实例分割                       | 提供对应模型与流程                 | 三个家族的 n/s/m/l/x，项目区域类别             |
| 语义分割、深度、分类、姿态、旋转框 | 仓库有对应任务入口，具体型号须匹配 | 尚未开放本章的训练与回流流程                   |
| 视频追踪、预测、导出、基准测试     | 原生运行模式                       | 不作为在线学习实验任务；使用平台各自的功能入口 |

## 平台增加或管理的实验参数

新建实验先选择任务，再选择就绪数据、训练器与基础模型。「模型初始化」决定加载预训练权重、随机初始化，或使用合格的项目候选。下表说明实验层参数如何对应原生调用；不需要把这些标识手工写入原生参数 YAML。

| 平台参数或选项                  | 原生对应                   | 默认或选择规则                                                          |
| ------------------------------- | -------------------------- | ----------------------------------------------------------------------- |
| 实验任务 `task`                 | 固定原生 `task`            | 新建界面先明确选择 `detect` 或 `segment`                                |
| 训练器 `framework`              | 选择框架适配器             | 本页为 `ultralytics`                                                    |
| 基础模型 `base_model`           | 原生模型架构／权重来源     | 只允许上表受控目录中的型号                                              |
| 数据版本 `dataset_id`           | 执行时生成的 `data` 路径   | 固定一个同任务就绪版本，保留类别与划分                                  |
| 实验名称 `name`                 | 平台显示名称               | 默认带 `detect-` 或 `segment-` 前缀；原生输出子目录另固定为 `framework` |
| 使用预训练权重 `pretrained`     | 受控原生开关与模型构建路径 | 默认 `true`；`false` 从受控 YAML 架构随机初始化                         |
| 项目候选 `initialization`       | 加载固定候选权重           | 可选；同项目、同规格、同原生类别与顺序；与随机初始化互斥                |
| 逐轮训练集评估 `evaluate_train` | 平台额外调用原生评估器     | 默认 `false`；不作为 `model.train()` 参数传入                           |
| 旧参数对象 `parameters`         | 原六个训练参数             | `epochs`、`batch`、`imgsz`、`seed`、`lr0`、`patience`；与完整配置互斥   |
| 配置 `configuration`            | 解析后的可编辑原生参数     | 省略覆盖项时使用受控默认值，并计算依赖调整                              |
| 配方／克隆 `origin`             | 配置来源记录               | 固定来源修订或实验，不代替本轮数据选择                                  |
| 从检查点续训                    | 当前实验的完整原生检查点   | 由平台检查资格，不在新建实验中手填 `resume`                             |
| 预检与创建请求标识              | 平台预检、重复请求确认     | 界面生成；不会作为原生训练参数发送                                      |

平台仍能读取旧六参数实验；新建完整配置与旧参数对象使用各自的提交格式，不能在一次创建中混用。配方、YAML 和参数页的操作见[训练配置与复用](./configuration)。

## 参数依赖与分割差异

优化器默认使用 `SGD`，覆盖原生的 `auto`，使显式学习率和优化器参数有可核对的含义。选择 Adam／AdamW 后，SGD 动量预热不生效；显式提交不生效参数会被拒绝。SGD 的动量必须大于零。

默认预热轮次超过 `epochs - 1` 时会随短实验调整，显式填写越界值则拒绝。默认 `close_mosaic` 覆盖全部训练时会缩短；显式设置覆盖全程时，相关增强会被标为不生效。开启 `rect` 会关闭 Mosaic、MixUp 和 CutMix。检查页同时显示这些依赖调整。

## 指标、初始化与产物

训练损失始终按原生分项采集。开启 `evaluate_train` 后，每轮关闭增强并额外评估冻结训练集，产生 Precision、Recall、mAP50 和 mAP50-95；它会增加耗时，计入执行预算，不参与最佳权重选择。分割分别保存框和掩码指标。原生分割最佳选择分数是框与掩码 mAP50-95 之和，可能大于 1。

`pretrained=false` 创建随机权重的新实验。项目候选初始化只导入权重，新实验重新建立优化器、调度器、EMA 与最佳成绩；断点续训则恢复当前实验自己的完整检查点。两者的区别见[模型初始化方式](./experiments#选择模型初始化方式)。

成功执行保留最佳权重、完整续训检查点、最终评估、日志和实际原生配置等产物。指标解释见[训练监控与指标](./metrics)，注册、类别绑定和试用见[模型回流](./models)。

## YOLO26 的参数差异

YOLO26 固定使用原生端到端分支，最终验证、训练集额外评估、模型试用和预标保持相同分支。平台固定 `nms=false`，`iou` 不代表正在执行的普通 NMS 阈值；`reg_max=1` 时 DFL 损失增益不可编辑。曲线按原生实际记录展示 L1、分割及语义辅助等损失，缺失项保持缺失。

实例分割会从变换后的独立实例掩码生成语义辅助目标，重叠处使用面积最小的覆盖实例，等面积按冻结实例顺序选择，原始实例仍独立保留。该家族的分割批大小默认 1；`batch × 类别数 × imgsz²` 超过 6,400 万元素会在原生训练前拒绝。这个上限不代表特定 GPU 一定能容纳该配置，大规格需分别测量显存。

历史实验保留原有框架、参数摘要和镜像身份；升级不自动授予跨框架版本续训资格。项目候选初始化同样要求框架版本、家族、规格、任务和原生类别顺序一致。

## 目前的局限性

- 训练固定使用所分配的单张 GPU；未开放 DDP、多 GPU、自动批大小、CPU 训练、AMP、缓存和任意回调／外部配置注入。显存不足直接报告，不自动改参数。
- 从零训练仍使用受控基础型号，不能上传任意模型 YAML 或检查点。项目候选初始化要求规格与原生类别顺序完全一致，不提供类别头重映射。
- 分割几何增强按差异表固定，暂不提供增强预览和参数搜索。细小目标仍受缩放影响，训练前消失会阻断；原生验证器的缩小掩码另有 tiny 目标损失说明。
- 原生实例 RLE 训练受单图 1,600 万像素、300 个实例、原图掩码元素和批次掩码元素等预算约束，超限会拒绝；普通 YOLO 多边形加载器不能直接替代平台适配器。
- 分割模型回流只用于图片整图源阶段，暂不用于父框裁剪、视频或点／框／文本提示。目标 GPU 故障和受控模型生命周期仍需[独立验收](./troubleshooting#目标部署的独立验收)。
- 历史缺失指标不补算，续训不承诺与连续训练逐位一致；跨框架、跨验证基准的分数不直接排名。

另一训练仓库的参数和能力见 [LibreYOLO 训练容器](./libreyolo)。
