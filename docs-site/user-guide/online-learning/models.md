# 模型回流与默认预标

训练完成后，从项目「在线学习 → 模型与发布」将结果添加为候选，加载到推理服务试用，再按任务类型设置默认预标模型。权重直接在平台与服务之间传递，不需要下载后重新上传。

当前受控路径覆盖 Ultralytics YOLOv8、YOLO11、YOLO26 的 n/s/m/l/x 图片检测与实例分割，以及 LibreYOLO9 t/s/m/c 原生检测权重。LibreYOLO 分割尚未开放回流。能够训练或下载权重，不表示目标实例已就绪；须逐项核对精确框架版本、原生模型结构、类别顺序和安装收据，以实验详情与目标实例检查结果为准。CPU 原生链路验收不能替代目标 GPU 的容量、故障与生命周期验收。

在「模型与发布」列表工具栏选择「全部类型」、目标检测或实例分割。全部类型汇总展示两类模型，并保留各自的「默认预标」标记；选择具体类型后，可在默认模型行停用该类型的默认选择、使用默认模型预标注或查看切换记录。表格逐行显示型号、类型、状态和来源指标；型号来自注册时冻结的基础模型规格，历史记录缺失时显示`—`。切换类型会返回第一页；查看模型详情后返回列表，仍保留原类型筛选。

同一项目、同一任务可以保存并部署多个模型；检测与实例分割各自维护默认预标选择。设置默认模型只决定默认预标入口使用哪个模型，不会停用其他已部署模型，也不代表项目只有一个模型在用。显式选择具体模型的管线继续使用自己的配置，已排队任务继续使用创建时冻结的模型。分割需要项目启用区域工具和原生栅格掩码编辑，并通过部署侧的掩码读写开关检查。

## 操作由谁完成

| 操作                     | 入口                                | 负责人                 |
| ------------------------ | ----------------------------------- | ---------------------- |
| 注册或编辑推理服务       | 模型市场 → 注册管理 → 实例          | 超级管理员             |
| 初始化默认凭据           | 设置 → 系统设置 → ML 服务认证与维护 | 超级管理员             |
| 为项目启用服务           | 项目设置 → ML 模型 → 管理 backend   | 项目负责人或超级管理员 |
| 添加候选、加载试用与发布 | 项目在线学习 → 模型与发布           | 项目负责人或超级管理员 |

注册服务只建立一个可调用的地址；添加候选只固定训练产物与类别；默认预标设置只决定该任务类型的默认入口使用哪个模型。服务凭据准备完成也不会自动创建候选或发布。

## 从训练结果添加候选

模型回流有两个操作入口：

- **从训练结果进入**：打开「训练实验」中的来源实验，选择其中成功的执行记录，点击「回流到项目模型」。平台会打开添加面板，并带入该实验和执行记录。未通过回流资格检查时，详情展示具体原因，仍可下载原生权重。
- **从模型列表进入**：切换到「模型与发布」，点击右上角「从训练结果添加模型」，选择来源训练实验和成功执行记录。

回流直接读取平台内的训练权重，无需先下载再上传。名称会预填当前本地时间，例如 `2026-0909-1125`，可继续补充或修改。为每个原生输出类别明确选择当前项目对应工具的类别：检测绑定矩形框类别，实例分割绑定区域类别。再点击「从训练结果添加模型」。模型保存权重摘要、类别顺序、绑定、实验、数据版本与评估来源；注册后这些信息固定，被模型引用的实验不能删除。

候选权重始终沿同项目来源实验和精确执行记录读取，下载、加载试用和用作新实验初始化都使用来源实验固定的位置。输入图片则使用数据版本自己的位置；更换当前训练桶不会改写这些来源。历史来源实验尚未固定位置时，先由项目管理员[显式核验保留产物](./experiments#产物位置与历史实验)，再继续注册或使用。

同一次成功执行只回流一次。已回流时，实验详情的按钮显示「已回流到项目模型」并禁用，同时提示对应模型名称；从旧链接或添加面板选择该执行也不能重复添加。模型归档后仍保留这一限制。续训产生的另一条成功执行可独立回流。

类别绑定列表每页显示 10 项，并在列表内滚动；可按类别名称、原生序号或已选项目类别搜索，也可勾选「仅未绑定」。顶部显示整体绑定进度。点击「按同名绑定」会为全部未绑定项填入完全同名的项目类别，保留已有手动选择，不受当前搜索或分页限制。切换分页与筛选不会丢失选择，全部原生类别均已绑定后才能注册。

## 查看模型详情与操作

在「模型与发布」列表点击模型名称，进入该模型的统一页面。顶部「评估与发布」用于查看指标、下载模型、加载试用和发布；「来源与使用」查看训练来源及部署、发布、预标注记录；「标记与备注」保存人工建议或归档模型。切换分区不离开模型页面，刷新后仍停留在原分区，返回列表时保留筛选与页码。

列表状态旁提供「设为默认预标」快捷入口，在弹窗中核对模型、推理服务与固定样本；尚未就绪时，先完成加载试用，再勾选样本确认并设置默认模型。设置成功后自动关闭弹窗并刷新列表，筛选和页码保持不变。「全部类型」下也按模型实际任务设置默认选择；选择具体类型后，已是默认模型的行保留「停用默认预标」入口。

类别绑定可通过每行的「清除」取消，包括项目类别已删除的旧映射；清除后需重新完成绑定才能注册。模型详情选择另一候选后，可点击「取消模型对比」返回单个模型报告。

## 准备推理服务

模型详情会直接显示加载试用是否就绪，区分服务列表读取失败、项目未启用、未配置有效认证及服务不可用。下拉框保留已注册服务，并标注不能选择的原因；「配置推理服务」列出各服务状态并提供现有实例的直达入口。只有一个已启用、已配置系统托管或手动 Token 认证且在线的服务时会自动选中；多个服务时需要手动选择。

选择「用于加载模型的推理服务」，点击「加载模型并试用」。服务列表读取失败时可点击「重试」。服务尚未就绪时，按两步操作：

1. **超级管理员配置服务认证**：进入「模型市场 → 注册管理 → 实例」，编辑已有 YOLO 服务，选择「系统托管（YOLO）」并保存。平台自动生成或复用私有凭据，在部署指定的 YOLO 地址验证后同步保存，无需生成、复制 Token 或修改 `.env`。尚无实例时才注册；已有实例无需重复注册。
2. **项目负责人启用实例**：在「项目设置 → ML 模型 → 管理 backend」启用该服务，再返回本页选择并加载。

内置服务的默认凭据分别持久保存在部署的私有共享目录，各容器只读自己的凭据。旧容器首次升级需要重建镜像并应用新的目录挂载；之后初始化或同步凭据无需再次重建容器。普通 `/health` 成功只表示进程可达，系统托管会额外验证受认证端点；保存后执行实例健康检查更新服务状态。

远程或已自行配置 `YOLO_MANAGED_MODELS_TOKEN` 的服务继续使用手动 `token`，填写与服务端一致且至少 32 个字符的令牌。手动配置优先，不会被系统托管覆盖。已使用手动 Token 的实例留空编辑保留原值；从系统托管切回手动 Token 必须明确填写服务端令牌。`none` 不发送认证凭据，不能用于加载训练权重。

LibreYOLO 原生检测应选择管理员安装并启用的受控插件实例，使用该实例的手动 Token，而不是冒用内置 YOLO 的系统托管身份。插件的安装许可和实际能力均须声明匹配的训练框架、原生格式与 CPU 或 CUDA 运行时；项目还须启用对应服务池。停用或退役的插件不能加载、发布或接收新请求。

需要批量初始化时，超管可使用「设置 → 系统设置 → ML 服务认证与维护」。这个入口准备和同步服务访问凭据，不会自动启用项目、安装候选或发布模型。服务与模型的关系、请求路由以及 Token 为什么还保护普通推理，见[模型服务接入、路由与认证](../../dev/concepts/ml-backend-routing-and-auth)。

## 加载、确认并设置默认预标

平台校验权重后安装到该实例，检查原生任务和类别，并在一张固定验证图片上推理。检测展示预测框；实例分割展示原图上的逐实例掩码，保留孔洞、断连部件和实例重叠，并显示耗时。负责人检查误检、漏检及人工修正成本，勾选「已查看固定验证样本，确认用于后续人工试用」，点击「设为默认预标模型」并在确认框中确认。训练完成或试用成功都不代表精度已经提升。

同一模型版本与同一部署已是该类型的默认预标选择时，按钮显示「已设为默认预标」。切换次数记录该类型默认选择的变化，不是模型自身的版本号：切换模型、切换推理部署及恢复历史选择都会新增记录；重复设置、重复停用或恢复到相同组合不会增加记录。已有历史记录继续保留。

候选对比要求相同的验证摘要、类别、绑定、框架及评估配置。页面只展示原生报告实际提供的指标；LibreYOLO 暂无分类别结果，不将其原生 precision／recall 别名当作常规精确率／召回率。不同框架候选分别展示，不能直接比较分数。

## 训练版本与推理版本

模型详情保留创建权重时的「训练版本」，每个部署独立记录完成加载试用的「推理版本」。升级推理容器不会修改训练版本、权重摘要或安装文件收据。样本评估页面同时展示两个版本，报告和预标来源冻结实际推理环境及其资格摘要。

已登记的旧 Ultralytics 训练权重可在新版推理服务重新加载试用；跨版本仅开放旧 YOLO11 检测和 YOLO11n 实例分割，仍须通过网络结构、检测头、类别顺序和运行时源码校验。不支持任意版本互换或降级推理。一次固定图片试用用于确认部署可用，模型质量还需通过完整验证集评估。

新的 LibreYOLO 部署必须在安装收据中明确返回合格的 CPU 或 CUDA 执行配置，并在固定样本试用中固定该配置。发布前平台重新读取现场收据并逐项比较试用时的运行时；不同设备或配置必须使用新的实例与部署重新试用，不能原地切换。旧的无运行时引用仍表示原有 CPU 语义，不会因版本相同而接受 CUDA 结果。训练来源资格、权重摘要、旧收据和发布快照均不会改写。

升级后，若运行时身份变化，请选择新的推理实例重新加载并试用，再发布新部署。旧排队任务继续使用原来冻结的推理身份，环境不匹配时明确失败；历史发布快照和评估结果不会被重写。

## 进一步评估模型

固定样本试用用于检查安装、类别和输出是否可用。需要量化判断检测或掩码质量时，创建[逐样本评估](./sample-evaluation)，选择同任务冻结数据中的验证成员，并固定匹配阈值与推理环境。

分割流程验证与业务精度、目标 GPU 部署准入是不同的验收工作。镜像、权重或设备发生变化时，管理员还需按[目标部署验收](./troubleshooting#目标部署的独立验收)核验。

## 用默认模型预标注

设置默认模型后，返回「模型与发布」列表，在「使用默认预标模型」中核对任务类型和模型名称，选择待标注图片，设置置信度与追加／覆盖方式，点击「用默认模型预标注」。每个任务固定创建时的模型和类别绑定，并保留权重、实验、数据版本与发布来源。后来发布其他模型不会改变已排队任务；网络重试沿用原任务身份。结果仍需在工作台接受、修正、提交并审核，之后才能进入下一训练数据版本。

分割结果以逐实例栅格掩码进入候选，人工在工作台采纳、改类别或修正像素后，仍须提交并审核。冻结下一数据版本时，可在「分割训练桥接」选择「原生实例掩码训练」；执行器须先通过对应桥接资格检查，画笔或 SAM 修正后的孔洞与多部件才能直接保留为训练真值。只运行试用或逐样本评估不会写入人工标注，也不会自动创建下一轮训练。

工作台按自己的置信度阈值筛选候选。若模型已返回结果但列表为空，可在「单图 AI → 高级配置 → 候选筛选与批量采纳」降低显示阈值，再审阅候选。点击对象行「更多操作」可固定展开采纳、改类别等操作，触屏也可使用。

受控图片检测模型发布后，也可在「模型市场 → 模型目录」、普通 AI 预标和工作台「单图 AI → 高级配置」选择。它能作整图源阶段，也能在父框裁剪图上检测子物体。视频和点／框／文本交互提示仍不属于训练模型回流范围。任务只会进入完成该版本部署检查的确切实例；实例不可用时任务报错，不会换用其他权重。

受控实例分割仅支持图片整图源阶段，不支持父框裁剪、视频或点／框／文本交互提示。使用实例分割类型对应的默认模型，检测与分割的默认选择不能互相替代。

## 在预标注和管线中选择

在项目配置的「项目检测模型」下拉中选择「项目当前发布」或明确的历史发布版本。这里的「项目当前发布」指检测任务的默认预标选择；其他任务和显式指定的模型仍各自独立。保留当前后端配置时继续使用原有内置模型设置；选择目录中的具体规格后，其权重规格固定，参数预设单独保存，不会改写原后端的偏好。

添加检测子阶段后，分别选择该阶段的模型、置信度、原生类别索引和 ROI 扩展。**父框类别过滤使用项目绑定后的名称**，例如原生 `person` 绑定「行人」后，下游筛选「行人」。保存包含项目模型的管线时，只能保存为所属项目的私有管线；不能发布为组织或公共模板。

失败重试按原始快照重跑失败的那道题的完整管线。下游失败时保留失败策略允许的候选和错误记录；只有完整重试成功才替换旧候选的显示状态，已采纳的人工标注保持不变。

## 恢复或停用默认选择

在列表底部展开「默认预标切换记录」，可恢复此前的模型与实例组合；在默认模型所在行点击「停用默认预标」，可清除该类型的默认选择。恢复前先验证旧部署可用，再更新选择；其他已部署模型、已有任务和历史结果保留。其他负责人同时修改时，页面会要求刷新，避免覆盖对方的更新。

### 安全退出旧 LibreYOLO 部署

先在新插件实例重新加载相同权重并确认固定样本，切换当前发布；已冻结的任务不会自动迁移。项目负责人可调用 `POST /api/v1/projects/{project_id}/trained-models/{version_id}/deployments/{deployment_id}/stop-references`，将旧部署置为 `draining`：禁止新冻结、重新部署和发布回滚，但已冻结任务仍可按原身份完成。确认当前发布已切换，并完成或明确处置排队、运行和未放弃的失败重试后，调用同一路径下的 `retire` 将其置为 `retired`；仍有依赖时返回冲突和计数。操作保留历史部署、收据和发布，不影响同一旧实例上的 Ultralytics 部署。

任务终态不是原生 GPU 工作已退出的证明。管理员还须通过推理实例的实际排空和资源释放确认完成执行，再按插件安装管理流程停用或卸载运行时；不要删除历史 Registry 来绕过依赖。

## 加载试用不可用时

先读按钮附近的原因，再从「配置推理服务」进入已有实例。按[服务问题速查](./troubleshooting#加载与默认预标问题)处理服务未启用、认证缺失、不可用或副本损坏等情况；无需通过重复添加候选解决服务配置问题。

## 来源、使用记录与备注

在模型详情切换「来源与使用」，查看权重和冻结来源摘要，再沿「来源记录」进入准确的实验、执行尝试和数据版本。「相关记录」一次加载一类后续记录，每页最多 20 条。其他记录的「查看详情」进入对应的实验或数据详情，模型记录直接进入统一模型页。原候选列表的归档范围、页码和当前分区保存在链接中，刷新后可以继续查看，旧模型来源链接也会打开统一页面。

配置克隆表示沿用配置，断点续训表示恢复对应检查点；两者不会混为同一来源。部署页面显示最近一次加载与试用检查，发布页面显示当时保存的冻结身份。历史记录缺失、不一致或无权访问时显示来源缺口，不会改用最新尝试。路径再次经过同一节点时会提示可能存在历史循环。

切换顶部「标记与备注」，选择模型标记，填写「标记说明」，点击「保存标记与说明」。每次保存保留操作人、时间与序号，后续修改不会覆盖旧说明：

- **普通候选**：取消其他标记，恢复在默认列表中显示。
- **待进一步评估**：记录需要继续测试或评估，仍显示在默认列表，不自动创建评估任务。
- **暂不采用**：记录当前不采用的意见，仍显示在默认列表；这是人工备注，不会阻止发布或停用当前模型。
- **已归档**：从默认列表隐藏，可在「全部模型，包含归档」或「仅已归档模型」中查看；默认预标模型仍显示，权重不会删除。

这些操作只保存标记和说明。发布在同页「评估与发布」中完成，各任务类型的默认预标停用与历史恢复保留在「模型与发布」列表中。

默认候选列表隐藏已归档模型，但默认预标模型仍保留并标明归档。可切换为包含归档或仅已归档；已有模型详情、部署和历史证据继续可用。归档不删除权重，也不解除数据与实验的来源保护。

「使用此模型的预标注」按需统计匹配完整冻结候选身份的现存记录，最多读取 1,000 条并明确上限。旧格式、已删除和无法核对的记录不在范围内；候选身份不完整时显示无法计数，零也不表示从未使用。该计数不是累计调用量或模型质量评分。

## Token 要自己生成吗

内置服务选择「系统托管」时不需要。平台生成或复用独立凭据，服务从私有目录读取；认证方式仍是系统托管，不能选 `None` 来代替。`None` 表示调用时不发送凭据，无法加载受保护的训练权重。

Token 用于证明平台有权调用服务，除了模型安装也保护能力查询、推理和控制入口。它不是个人登录密码，也不是训练质量证明。初始化不会轮换已有 Token；通常也不需要为同步凭据重建镜像。旧部署首次升级和容器维护由部署管理员按[维护指南](../../ops/deploy/ml-backend-maintenance)处理。
