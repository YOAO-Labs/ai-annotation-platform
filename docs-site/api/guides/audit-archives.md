# 审计归档

基路径为 `/api/v1/audit-logs`。归档列表和内容读取均要求 `Authorization: Bearer <token>`，仅允许当前超级管理员访问；沿用账号和 API Key 的角色权限，不增加 scope。

## 查询已发布归档

```http
GET /api/v1/audit-logs/archives
Authorization: Bearer <token>
```

返回按月份倒序排列的数组，每项包含 `year`、`month`、`object_key`、`size_bytes` 和 `archived_at`。列表来自数据库中已完成发布的独立归档记录，`archived_at` 是发布时间；未确认或未完成发布的记录不会出现在列表中。查询列表不扫描对象存储，也不受新写入 bucket 配置变更影响。

## 分页读取归档

```http
GET /api/v1/audit-logs/archives/2024/1?limit=100&offset=0
Authorization: Bearer <token>
```

路径年份范围为 `2000..9999`，月份为 `1..12`；`limit` 默认 `100`，范围 `1..1000`；`offset` 默认 `0`，不得为负数。响应形状保持为：

```json
{
  "items": [],
  "total": 3,
  "limit": 100,
  "offset": 0,
  "year": 2024,
  "month": 1
}
```

服务端按照创建归档时保存的端点身份、bucket、对象键及内容摘要读取。切换新归档的写入 bucket 不会让历史读取转向新 bucket 中的同名对象。

超级管理员可通过[审计归档用途切换](./storage-locations#审计归档用途切换)预览确认后改变后续分配位置。已分配但尚未发布的归档也保留原位置；公开 `object_key` 始终是逻辑归档键，不暴露外部完整物理前缀。全局 S3 位置的历史读取使用该连接的当前凭据，正常轮换不要求旧配置修订等于当前修订，物理地址仍不可改向。列表只查询数据库，目标离线时仍可查看已发布元数据。

每次请求先完整核验压缩文件、全部 JSONL 行、月份、顺序、行数、源内容摘要和末尾元数据，核验完成后才返回指定页。即使只请求第一页，后续内容损坏也会使整个请求失败。分页控制响应大小，无法降低每次完整核验所需的存储读取量。

`items` 中保留最后一行的字面 `_partition_meta` 对象，`total` 为审计行数加一。该对象包含归档和作业标识、月份、归档时的源分区身份、行数及源内容摘要。源分区 OID 是历史记录，读取不要求原数据库分区仍然存在。超出最后一行的 `offset` 返回空 `items`，仍返回相同 `total`。

核验预算为压缩内容最多 64 GiB、源内容最多 256 GiB、单行最多 16 MiB、审计行最多 1000 万条、总核验时间最多 600 秒。超出预算返回冲突，不返回部分内容。

## 权限变化与错误

归档读取在存储准入后、物理读取完成后，以及返回前重新检查原账号、原 API Key、当前超级管理员角色、归档归属和存储维护状态。API Key 被撤销、轮换、改 scope、到期，或账号停用、降权时，请求可能在存储已读取后失败。JWT 到期和现有登录撤销规则同样适用。

| 状态码 | 含义                                                             |
| ------ | ---------------------------------------------------------------- |
| `403`  | 当前角色不足，或原账号、原凭据已失效                             |
| `404`  | 已有归属记录指向的物理归档不存在                                 |
| `409`  | 缺少已发布归属、内容或归属不符、超过核验预算，或存储维护状态变化 |
| `422`  | 路径或分页参数不合法                                             |
| `503`  | 存储暂不可用，或无法确认物理读取已收尾                           |

错误使用 `{"detail":{"code":"固定错误分类"}}`。没有独立归属记录的旧归档返回 `409 audit_archive_storage_unpinned`，不会尝试从当前 bucket 猜测读取。未知归属、尚未发布和物理对象缺失是不同情况：只有已有已发布归属的物理对象确认缺失时才返回 `404`。

接口返回已核验的行数据，不返回对象存储 URL。取消客户端请求会等待已启动的物理读取和关闭收尾；无法确认关闭时保留维护责任记录，由运维核对，不因业务请求结束而推断 I/O 已结束。
