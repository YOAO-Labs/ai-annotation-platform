# 一致备份与隔离恢复演练

数据库记录和对象文件属于同一个恢复点。独立完成一次 `pg_dump` 和一次对象镜像，仍需核对二者是否对应：冻结版本可能尚未发布，文件可能正在删除，数据库中也可能保留旧桶绑定。

仓库提供本地离线演练，使用两套全新随机资源验证备份代次、恢复映射和业务完整性。它复用本机 PostgreSQL/MinIO 服务，各自拥有独立数据库、Redis 和九用途桶。演练不接收既有源或目标参数，不读取人工或生产业务数据；只写入合成夹具，不启动 API、Web、Worker 或 Beat。

## 执行演练

先完成[独立工作树环境](/dev/how-to/worktree-environments)的本机依赖和凭据配置。使用当前 checkout 的 API 虚拟环境；数据库迁移账号须能创建并删除自己的演练库，已有运行账号保持原权限。`pg_dump/pg_restore` 优先使用宿主机工具，缺少时使用当前本机 PostgreSQL 容器内的工具。

```sh
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py

# 可选：保存不含凭据的私有报告
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --report /tmp/recovery-report.json
```

退出码 `0` 表示本次演练和清理均通过。报告含统一 `backup_generation`、迁移头、对象与字节数、阶段用时、应用对账及清理状态。它说明本次合成规模和已知停写窗口，不代表生产 RPO、RTO 或性能承诺。报告用完后自行删除。

源、目标都有数据库 comment、桶 tag 和 Redis label。脚本拒绝既有资源、错误归属、未知数据库客户端和非空恢复目标；不强断连接，不创建或修改共享 PostgreSQL roles。正常结束和注入失败均校验并销毁本次随机资源。清理失败时退出码为 `1`，报告保留私有恢复目录与准确 owner；先核对归属再处理，不能通过删清单或强断连接绕过保护。

## 备份代次保存什么

备份使用私有目录和文件，最后原子发布完成标记。没有有效完成标记的目录不可用于恢复。

| 内容                   | 校验与用途                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| PostgreSQL custom dump | 保存完整 schema 与数据，记录 SHA-256；不恢复源角色所有权或全局授权。                     |
| 九用途映射             | 保留全部用途，按物理桶去重；空桶也是明确范围。                                           |
| 逐对象清单与内容       | 分页列举、流式完整 SHA、字节数和必要 metadata，包含冻结媒体与 ZIP。ETag 仅检查读中变化。 |
| 配置与迁移身份         | 保存代码提交、迁移头和非敏感物理映射，不复制真实 `.env`。                                |
| 数据库对账证据         | 保存表行数及内容指纹，明确冻结版本和未完成作业。                                         |
| 外部原件责任           | 记录未备份的外部来源及责任，不把引用索引当作原图备份。                                   |
| 独立密钥材料           | 仅生成演练专用 Fernet key，独立受限保存；公共清单只含其校验身份。                        |

默认预算为一万对象、单对象64 MiB、对象合计512 MiB、dump128 MiB。读前后复核对象集合、大小及 ETag，发布前再次核对数据库指纹和零客户端。遇版本化桶、历史版本、删除标记、未完成分片、超预算、缺对象或读中变化会拒绝发布。当前范围是离线的当前对象，不包含供应商副本、文件系统快照或 PITR。

## 训练版本存储归属的部署顺序

训练数据版本将 ZIP、保留图片和掩码的整个前缀固定到内部 `storage_ref`。升级使用 additive 迁移 0220；迁移只增列和约束，不从当前环境变量补写旧版本归属。

1. 暂停新版本创建、重试及相关自动触发，盘点归属为空的旧构建。对仍在排队或运行的旧版本先取消，等待所属 export Worker 实际退出该构建；不能以 API 已返回取消或账本暂时为空替代收尾证据。
2. 先应用增量迁移，再更新所属 API 和全部可能构建训练版本的 Worker，确认旧进程已退出。Celery 不会热加载源码；本机挂载代码的刷新不需要重建镜像。不同部署若使用烘焙代码，仍须按其部署方式更新运行代码，不能将未刷新 Worker 当作新协议消费者。
3. 新版本在创建事务固定归属后才派发。旧 `ready`、`failed`、`cancelled` 版本由有项目管理权限的人员显式调用[storage-pin 接口](/api/guides/training-datasets#固定存储归属与历史版本核验)；普通读取、重试和升级脚本都不能默默接管。候选来自已持久登记的平台 training 绑定，先核对其配置与实际保留副本，不用改当前桶来绕过检查。
4. 确认固定成功或明确记录无法核实的历史项后，再恢复相关入口。旧部分版本若没有独立输入 SHA，即使对象元信息摘要与当前字节相符也会拒绝；保留原记录与对象，不能直接 SQL 填入当前桶后继续重试或删除。

显式核验只读当前副本，最多盘点 100000 对象、实际读取 64 GiB、协作截止 600 秒；每个 API 进程一个核验名额，多进程需累计评估。核验可能完整读取 ZIP 和独立媒体/掩码，须安排相应 I/O 窗口；超时或取消仍要等实际关闭，收尾不确定时保留访问责任和占位。成功只保存归属与观察证据，不改冻结 snapshot、manifest、包内容或摘要。

已有 pin 不能通过普通更新改写；代码回退应保留新列和固定事实。存在任一固定版本或固定清理意图时，迁移拒绝破坏性降级。当前用途桶变化不会影响旧 pin 的位置，实际端点改变则明确阻断；此能力不允许直接切换整个 training 用途，也不替代真实后端迁移、独占权限或执行器最终输入集合对账。

## 训练实验产物归属的部署顺序

实验产物使用 `TrainingRun.storage_ref` 固定整个 `projects/{project_id}/runs/{run_id}/`，所有 attempt 和续训共用该位置。增量迁移 0221 只增加可空字段与约束，不按环境配置回填旧实验。

1. 暂停实验创建、续训、自动策略及参数搜索派生。盘点旧实验与执行器，先请求停止活跃执行，确认实际训练进程组退出并按原 fence 完成资源收尾；`lost`、API 已收到停止请求或单次没有观测，都不是可核验的终态证据。归属未知仍允许停止、失败回报和资源结算。
2. 应用迁移，刷新 API 和可能创建实验或清理产物的 Worker，确认旧代码进程已退出。执行器与 ML 服务 wire 合同不变，此项不要求重建后端镜像；挂载代码仍须刷新相应进程，烘焙代码按部署方式更新。盘点尚未过期的旧上传 URL，停止发新 URL 不会撤销已签发 URL。
3. 对实验及全部执行都为成功、失败或取消、且所有执行均无资源租约的历史实验，由当前有项目管理权限的人员显式调用 [Run storage-pin](/api/guides/training-datasets#实验产物归属与历史核验)。API Key 另需 `datasets:write` 及既有读取 scopes。候选来自持久 training 绑定；不修改当前桶来猜位置，也不直接 SQL 填入归属。
4. 核验完整读取保留产物，与数据库独立上传及发布清单的 SHA、大小和执行元信息核对。已发布产物缺失、独立凭据不足、未知额外文件或无法解释的脱敏副本均拒绝，保持原记录与对象。当前实验、全部执行、权限/API Key、绑定或维护代次在最终复核前变化，也不保存归属。

该核验最多 10000 次执行、100000 个对象、实际读取 64 GiB，协作截止 600 秒，与训练数据版本核验共用每个 API 进程的一个名额。取消与超时须等待物理收尾，未确认关闭则保留责任和占位。证据只说明本次当前副本通过核验，不保证历史位置、独占权限或已签发 URL 此后不会写入；仍须安排受控停写窗口。

归属为空的旧实验可看元数据，不能读取或签名产物、上传、派发、续训、注册模型或开始删除。模型权重通过同项目来源实验及精确执行解析，输入数据版本独立解析；模型下载、安装、初始化和评估不能以当前桶代替旧来源。新删除意图携带完整归属；旧 NULL 实验清理意图保留待核对，不物理删除。固定事实须随代码回退保留，含固定事实时拒绝破坏性降级。

此部署不开放整个 training 用途切换；辅助输出另按下一节部署。CPU 或合成存储核验不替代真实 GPU 输入、故障和生命周期验收。

## 预览、评估与选样归属的部署顺序

增量迁移 0222 给 TrainingPreview、SampleEvaluationRun、ActiveLearningRound 增加可空固定归属，不回填旧记录。暂停三类新建／重试和相关清理，确认原执行器、Worker 与远程推理请求的实际收尾，应用迁移后刷新所属 API 及执行／清理 Worker。挂载源码不需重建镜像，执行器／ML wire 未改变；烘焙源码按原部署方式更新。

新建入口在首次派发前分配。旧记录通过三个[辅助 storage-pin 接口](/api/guides/training-datasets#辅助产物归属与历史核验)显式核验；预览无任何 CPU 租约且 PUT 窗口到期，评估／选样当前尝试终态。重试已封存的旧 lost 仅在非当前、较旧代际、claim 为空并保存完成时间时兼容；这些 DB 围栏不证明旧物理线程停机。正常评估终态残留 claim 不等于正在执行，仍须独立确认停写。

核验使用持久 training 绑定，完整读取全部现存前缀对象，不回源补证或修复。独立发布／上传回执、冻结派生 SHA、metadata 和有界语义不能解释的对象均保留并拒绝接管；没有独立派生大小时，只按实际 PNG 字节预算与冻结 SHA／尺寸核验。旧评估报告不借重试后的当前 Sample 行声称旧推理已重新核验。

预览和评估原行分别保留清理责任，未知归属不物理删除；主动学习未增加删除入口。已有任一新 owner 时拒绝破坏性降级，回退代码须保留字段和事实。核验名额、关闭不确定和维护代次沿用上节，共享每个 API 进程一个名额。此项不开放整个用途切换，也不代表真实模型执行资格。

## 上传头像归属的部署顺序

增量迁移0223增加独立 `avatar_uploads` 表，不根据当前桶回填旧token。升级前暂停头像变更，盘点 `users.avatar_ref` 中的历史上传引用并通知用户重新上传或改用内置头像。没有独立归属的旧token升级后返回404，原文件继续保留，不能按当前桶批量推测删除；当前部署若没有上传引用，无需额外迁移头像字节。

应用迁移后刷新所属API、cleanup Worker及Beat，确认新退休清理任务与队列已注册，再恢复上传。挂载代码不要求重建镜像。上传先提交pending事实，只有真实写入/完整回读结束且发布围栏通过才变ready；进程崩溃或提交应答不确定留下的pending不按年龄自动删除。人工对账须同时确认无活动或迟到写入、无用户引用、保存位置和独立内容回执，不能仅依据创建时间清桶。

替换或清除后的retired行保存清理责任，失败可重试；维护排空或未知端点拒绝物理删除并保留行。不要删除账本来消除错误。存在任何上传记录时迁移拒绝破坏性降级，回退应用仍须保留表、归属和状态。该部署不开放用途切换，也不把匿名token头像授权扩大到其他对象。

## 异步导出产物归属的部署顺序

增量迁移0224增加独立 `export_outputs` 表和缓存到产物的可空关联。升级前暂停项目、批次和选中任务的异步导出，等待旧 export Worker 实际收尾；应用迁移并刷新所属API、export/cleanup Worker与Beat，再恢复入口。挂载源码不需要重建镜像。历史未完成Job没有原请求输出授权证明，须重新发起导出；旧完成Job和通知中的URL继续按原值展示，过期后重新导出，不从当前桶重签。

新ZIP先保存独立SHA/字节数、精确位置和固定七天期限，再上传、完整回读并发布ready。每次候选有独立键，重复投递不会覆盖旧文件。失败、取消或提交应答不确定保留pending与字节，不能仅按年龄自动删除；人工核对须证明无活动或迟到写入、保存位置和独立内容回执。原请求API Key撤销、轮换或scope/期限变化后，Worker拒绝发布新下载链接。

缓存只复用关联ready且完整内容核对通过的产物，签名仅使用原期限剩余窗口。旧NULL关联缓存不做物理探测，按miss重新构建。缺失或损坏只失效缓存索引，旧产物责任继续保留。过期清理先排除同产物未收尾读取、提交retired，再按保存桶精确删除；失败保留重试。Job或Project消失不会丢失独立产物责任，清理不能删访问账本来绕过未知关闭。有任何产物时拒绝破坏性降级；回退应用仍须保留归属、期限和状态。完整export用途切换仍未开放。

## 报告附件归属的部署顺序

增量迁移0225增加独立 `bug_attachment_uploads` 表，保存上传者、内容回执、180天固定期限、状态及首次报告绑定，不回填旧附件。升级前暂停附件写入，盘点并等待旧直传请求实际收尾；旧upload-init不再签发PUT链接，改为返回409并指向认证的原始图片上传接口。前端和API须一起更新，旧客户端需刷新。

应用迁移后刷新所属API、消费cleanup队列的Worker及Beat，确认附件清理任务和定时调度已注册。启动时移除bug桶原有的整桶180天lifecycle，并独立检查该规则已消失，再恢复附件写入；其他用途规则保持。挂载源码不需要重建镜像。不能让对象存储的整桶过期规则绕过应用的读取许可和退休流程。

新附件先提交pending归属，条件创建后完整回读SHA，发布时重核原账号/API Key、保存期限和维护门禁。报告只能首次绑定本人ready且未过期的附件；下载通过认证接口返回完整核对后的图片字节，不暴露可重放的PUT或匿名下载地址。历史无归属的附件元数据保留，下载返回409；用户需在新反馈中重新上传，不能用当前桶或同名前缀推断历史归属。

删除报告先在同事务退休已知附件，再提交清理；账号或报告消失不会丢失独立责任。清理排除未收尾读取许可，按保存桶精确删除，失败保留重试。pending和未知历史不按年龄自动删除，人工对账须独立证明旧写入已结束及内容、位置和引用。存在附件归属时拒绝破坏性降级；回退应用保留表、回执和绑定，可暂停新上传，不能恢复按当前桶猜读。

## 恢复顺序与物理映射

合成夹具另覆盖ready、pending和retired三类头像、导出产物和报告附件及其实际WebP/ZIP/PNG。完整回读、用户引用、缓存和报告关联对账确认恢复未把pending发布或丢失退休责任；导出夹具没有对应源Job，退休附件没有对应账号或报告，验证责任独立保存。另有无归属的历史报告附件及字节，恢复后仍保持未知，不自动生成归属。

脚本先验证完整备份和独立密钥，再销毁演练源库、源桶与外部合成原件，随后恢复到另一组空资源，证明目标不借读源数据。

目标库先创建为空库，再执行 full restore；恢复前不会运行迁移覆盖已有 schema。实际迁移头匹配后才授予已有运行账号权限。对象先完整验证备份，再检查所有目标桶为空，逐项复制并回读完整 SHA 和 metadata。目标桶保留自己的归属标签。

数据库内有持久物理引用，改环境变量不足以完成恢复。本演练只在恢复目标库显式映射平台桶绑定、平台 Asset 副本、来源预览、完整原图缓存、临时输入租约、训练数据版本、实验、预览、评估、选样、头像、导出产物和报告附件归属及删除账本和托管原件保留账本，并记录变换账本。旧存储身份或未知映射会拒绝通过，不会静默“修复”为当前位置。原始 dump、业务ID、内容身份、采纳修订、冻结 snapshot、manifest 和 ZIP 均不改写；容量观测仍属于原位置和原采集时间。

训练数据版本、实验、预览、评估、选样、头像、导出产物、报告附件及已有删除意图的固定归属先核对源 endpoint、bucket、精确前缀或对象键和物理身份。恢复工具须具有表 owner 权限，在显式 `aap.restore_training_storage=on` 事务标记下，仅映射嵌套 `storage_ref.bucket/storage_identity`；删除意图自身的 bucket 同步映射，并记录变换账本。前缀/精确键、端点、绑定与配置代次、接管来源及核验证据均保持，不能把源证据改成目标现场新核验。已保存但身份无法核实的归属拒绝映射；归属仍为空的旧记录不因恢复而自动接管，其旧清理意图保持待核对且不执行物理删除。

Run 配置、Preview 的 request/spec/input 与上传发布回执及期限、Evaluation/AL 的冻结 spec、attempt/report、候选 request/media/evidence、完成回执、初始化 pin、模型权重 artifact/provenance 及摘要不在物理映射白名单内，均逐字段保持。头像的token、账号快照、SHA/字节数、pending/ready/retired状态、退休时间和用户引用同样保持。导出产物的项目/Job快照、媒体/格式、SHA/大小、文件数、固定期限、状态/退休时间及缓存关联同样保持。报告附件的上传者/报告UUID快照、实际SHA/大小/MIME/文件名、固定期限、状态及退休时间保持，已删除账号或报告不重建，历史无归属附件不接管。模型仍通过原同项目 Run/Attempt 外键找到映射后的归属；不能重写这些冻结证据来制造目标已重新训练或重新核验的结论。

托管原件保留记录只在初始平台位置/绑定及保存的存储身份与演练源一致时映射bucket/storage_identity；未知身份需要独立恢复合同，不能静默采用目标配置。原始assertion_digest、历史Dataset/Item/Asset及保留策略保持不变，恢复后回读原件摘要验证。该映射仍不授予物理回收权限，也不代表生产恢复点已成为在线保留锁。

声明保留要求不保存第二份locator，以RESTRICT关联稳定退休锚点。有效及已解除hold的ID、锚点、类别/编号、原因、历史操作者、时间和修订均逐字段对账；它们没有允许映射的列。相同locator的多条断言与不同期限一并恢复，恢复后的预演仍须看到相关记录的无限期和有效备份/迁移要求。不能丢弃已解除历史，或因换桶就将声明改成已验证恢复证明。

核验历史不加入物理映射白名单：期望内容、原定位/配置指纹、对象观测和未完成责任均完整保留。目标恢复导致锚点定位变化后，旧匹配只作历史，context不再匹配；不自动重派未完成核验。确认执行端与未收尾责任后再对目标显式创建新核验，不能通过改写历史指纹制造目标已验证的结论。

原件创建账本也不映射任何列：源最终键、配置、预算、真实成功响应、版本观察和完整回读事实全部保持。AssetLocation 与退休断言保留原 creation_id；该关联表达历史来源，不把目标桶恢复写入冒充源回执。目标物理定位按既有白名单变换并另记账，新配置下不能继续旧创建或将旧回执重新关联为当前创建。未完成创建保持待核对，不自动重放。

恢复验证调用既有业务校验器，核对标注—样本—Asset/修订、所有保留冻结图片和标签、清单及包 SHA、来源证据和 Native Executor 输入。部分写入的版本保持未完成；外部原件丢失后，索引与旧标注保留，实时严格读取拒绝。在旧路径放入同名不同内容也不能通过校验，已就绪冻结版本仍可独立校验。密钥缺失或错误时无法通过解密验证。

旧 Redis 队列不恢复，也不自动重新执行未完成作业。演练报告将它们列为待核对；本工具不开放恢复应用流量。生产恢复上线前仍需独立确认所有异步 owner、外部根映射、旧物理 locator、任务处理方式和密钥/令牌处置。

## 故障演练

以下命令只破坏本次合成备份或在指定阶段退出，预期退出码为 `1`、清理状态为 `verified`；不得据此将失败当作成功恢复。

```sh
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault object
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault dump
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault key
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fail-after restore-db
```

真实部署还需确定备份目标、保留时间、外部原件保护责任和维护窗口。生产停写必须覆盖 API、所有 Worker/Beat、清理和外部写入；单个进程锁或数据库 dump 事务不能替代这个门禁。生产删除保护、在线/PITR、调度和上线切换须有各自验收证据。
