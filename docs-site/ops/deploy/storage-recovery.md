# 一致备份与隔离恢复演练

数据库记录和对象文件属于同一个恢复点。独立完成一次 `pg_dump` 和一次对象镜像，仍需核对二者是否对应：冻结版本可能尚未发布，文件可能正在删除，数据库中也可能保留旧桶绑定。

仓库提供本地离线演练，使用两套全新随机资源验证备份代次、恢复映射和业务完整性。它复用本机 PostgreSQL/MinIO 服务，各自拥有独立数据库、Redis 和九用途桶。演练不接收既有源或目标参数，不读取人工或生产业务数据；只写入合成夹具，不启动 API、Web、Worker 或 Beat。

## 执行演练

先完成[独立工作树环境](/dev/how-to/worktree-environments)的本机依赖和凭据配置。使用当前 checkout 的 API 虚拟环境；数据库迁移账号须能创建并删除自己的演练库，已有运行账号保持原权限。`pg_dump/pg_restore` 优先使用宿主机工具，缺少时使用当前本机 PostgreSQL 容器内的工具。

```sh
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py

# 可选：保存不含凭据的私有报告
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --report /tmp/recovery-report.json
```

退出码 `0` 表示本次演练和清理均通过。报告含统一 `backup_generation`、迁移头、对象与字节数、阶段用时、应用对账及清理状态。它说明本次合成规模和已知停写窗口，不代表生产 RPO、RTO 或性能承诺。报告用完后自行删除。

源、目标都有数据库 comment、桶 tag 和 Redis label。脚本拒绝既有资源、错误归属、未知数据库客户端和非空恢复目标；不强断连接，不创建或修改共享 PostgreSQL roles。正常结束和注入失败均校验并销毁本次随机资源。清理失败时退出码为 `1`，报告保留私有恢复目录与准确 owner；先核对归属再处理，不能通过删清单或强断连接绕过保护。

## 备份代次保存什么

备份使用私有目录和文件，最后原子发布完成标记。没有有效完成标记的目录不可用于恢复。

| 内容                   | 校验与用途                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| PostgreSQL custom dump | 保存完整 schema 与数据，记录 SHA-256；不恢复源角色所有权或全局授权。                     |
| 九用途映射             | 保留全部用途，按物理桶去重；空桶也是明确范围。                                           |
| 逐对象清单与内容       | 分页列举、流式完整 SHA、字节数和必要 metadata，包含冻结媒体与 ZIP。ETag 仅检查读中变化。 |
| 配置与迁移身份         | 保存代码提交、迁移头和非敏感物理映射，不复制真实 `.env`。                                |
| 数据库对账证据         | 保存表行数及内容指纹，明确冻结版本和未完成作业。                                         |
| 外部原件责任           | 记录未备份的外部来源及责任，不把引用索引当作原图备份。                                   |
| 独立密钥材料           | 仅生成演练专用 Fernet key，独立受限保存；公共清单只含其校验身份。                        |

默认预算为一万对象、单对象64 MiB、对象合计512 MiB、dump128 MiB。读前后复核对象集合、大小及 ETag，发布前再次核对数据库指纹和零客户端。遇版本化桶、历史版本、删除标记、未完成分片、超预算、缺对象或读中变化会拒绝发布。当前范围是离线的当前对象，不包含供应商副本、文件系统快照或 PITR。

## 训练版本存储归属的部署顺序

训练数据版本将 ZIP、保留图片和掩码的整个前缀固定到内部 `storage_ref`。升级使用 additive 迁移 0220；迁移只增列和约束，不从当前环境变量补写旧版本归属。

1. 暂停新版本创建、重试及相关自动触发，盘点归属为空的旧构建。对仍在排队或运行的旧版本先取消，等待所属 export Worker 实际退出该构建；不能以 API 已返回取消或账本暂时为空替代收尾证据。
2. 先应用增量迁移，再更新所属 API 和全部可能构建训练版本的 Worker，确认旧进程已退出。Celery 不会热加载源码；本机挂载代码的刷新不需要重建镜像。不同部署若使用烘焙代码，仍须按其部署方式更新运行代码，不能将未刷新 Worker 当作新协议消费者。
3. 新版本在创建事务固定归属后才派发。旧 `ready`、`failed`、`cancelled` 版本由有项目管理权限的人员显式调用[storage-pin 接口](/api/guides/training-datasets#固定存储归属与历史版本核验)；普通读取、重试和升级脚本都不能默默接管。候选来自已持久登记的平台 training 绑定，先核对其配置与实际保留副本，不用改当前桶来绕过检查。
4. 确认固定成功或明确记录无法核实的历史项后，再恢复相关入口。旧部分版本若没有独立输入 SHA，即使对象元信息摘要与当前字节相符也会拒绝；保留原记录与对象，不能直接 SQL 填入当前桶后继续重试或删除。

显式核验只读当前副本，最多盘点 100000 对象、实际读取 64 GiB、协作截止 600 秒；每个 API 进程一个核验名额，多进程需累计评估。核验可能完整读取 ZIP 和独立媒体/掩码，须安排相应 I/O 窗口；超时或取消仍要等实际关闭，收尾不确定时保留访问责任和占位。成功只保存归属与观察证据，不改冻结 snapshot、manifest、包内容或摘要。

已有 pin 不能通过普通更新改写；代码回退应保留新列和固定事实。存在任一固定版本或固定清理意图时，迁移拒绝破坏性降级。当前用途桶变化不会影响旧 pin 的位置，实际端点改变则明确阻断；此能力不允许直接切换整个 training 用途，也不替代真实后端迁移、独占权限或执行器最终输入集合对账。

## 恢复顺序与物理映射

脚本先验证完整备份和独立密钥，再销毁演练源库、源桶与外部合成原件，随后恢复到另一组空资源，证明目标不借读源数据。

目标库先创建为空库，再执行 full restore；恢复前不会运行迁移覆盖已有 schema。实际迁移头匹配后才授予已有运行账号权限。对象先完整验证备份，再检查所有目标桶为空，逐项复制并回读完整 SHA 和 metadata。目标桶保留自己的归属标签。

数据库内有持久物理引用，改环境变量不足以完成恢复。本演练只在恢复目标库显式映射平台桶绑定、平台 Asset 副本、来源预览、完整原图缓存、临时输入租约、训练版本归属及删除账本和托管原件保留账本，并记录变换账本。旧存储身份或未知映射会拒绝通过，不会静默“修复”为当前位置。原始 dump、业务ID、内容身份、采纳修订、冻结 snapshot、manifest 和 ZIP 均不改写；容量观测仍属于原位置和原采集时间。

训练版本及其删除意图的固定归属先核对源 endpoint、bucket、精确前缀和物理身份。恢复工具须具有表 owner 权限，在显式 `aap.restore_training_storage=on` 事务标记下，仅映射嵌套 `storage_ref.bucket/storage_identity`；删除意图自身的 bucket 同步映射，并记录变换账本。前缀、端点、绑定与配置代次、接管来源及核验证据均保持，不能把源证据改成目标现场新核验。已保存但身份无法核实的归属拒绝映射；归属仍为空的旧版本不因恢复而自动接管，其旧数据版本清理意图保持待核对。

托管原件保留记录只在初始平台位置/绑定及保存的存储身份与演练源一致时映射bucket/storage_identity；未知身份需要独立恢复合同，不能静默采用目标配置。原始assertion_digest、历史Dataset/Item/Asset及保留策略保持不变，恢复后回读原件摘要验证。该映射仍不授予物理回收权限，也不代表生产恢复点已成为在线保留锁。

声明保留要求不保存第二份locator，以RESTRICT关联稳定退休锚点。有效及已解除hold的ID、锚点、类别/编号、原因、历史操作者、时间和修订均逐字段对账；它们没有允许映射的列。相同locator的多条断言与不同期限一并恢复，恢复后的预演仍须看到相关记录的无限期和有效备份/迁移要求。不能丢弃已解除历史，或因换桶就将声明改成已验证恢复证明。

核验历史不加入物理映射白名单：期望内容、原定位/配置指纹、对象观测和未完成责任均完整保留。目标恢复导致锚点定位变化后，旧匹配只作历史，context不再匹配；不自动重派未完成核验。确认执行端与未收尾责任后再对目标显式创建新核验，不能通过改写历史指纹制造目标已验证的结论。

原件创建账本也不映射任何列：源最终键、配置、预算、真实成功响应、版本观察和完整回读事实全部保持。AssetLocation 与退休断言保留原 creation_id；该关联表达历史来源，不把目标桶恢复写入冒充源回执。目标物理定位按既有白名单变换并另记账，新配置下不能继续旧创建或将旧回执重新关联为当前创建。未完成创建保持待核对，不自动重放。

恢复验证调用既有业务校验器，核对标注—样本—Asset/修订、所有保留冻结图片和标签、清单及包 SHA、来源证据和 Native Executor 输入。部分写入的版本保持未完成；外部原件丢失后，索引与旧标注保留，实时严格读取拒绝。在旧路径放入同名不同内容也不能通过校验，已就绪冻结版本仍可独立校验。密钥缺失或错误时无法通过解密验证。

旧 Redis 队列不恢复，也不自动重新执行未完成作业。演练报告将它们列为待核对；本工具不开放恢复应用流量。生产恢复上线前仍需独立确认所有异步 owner、外部根映射、旧物理 locator、任务处理方式和密钥/令牌处置。

## 故障演练

以下命令只破坏本次合成备份或在指定阶段退出，预期退出码为 `1`、清理状态为 `verified`；不得据此将失败当作成功恢复。

```sh
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault object
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault dump
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fault key
apps/api/.venv/bin/python scripts/verify_worktree_recovery.py --fail-after restore-db
```

真实部署还需确定备份目标、保留时间、外部原件保护责任和维护窗口。生产停写必须覆盖 API、所有 Worker/Beat、清理和外部写入；单个进程锁或数据库 dump 事务不能替代这个门禁。生产删除保护、在线/PITR、调度和上线切换须有各自验收证据。
