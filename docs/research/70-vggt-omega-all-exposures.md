# VGGT-Ω 全曝光重叠窗口与动态补偿

> 归档状态：独立预览和离线试验入口已退役，大体积派生产物已清理。下文保留当时的方法与验收结果，旧地址和命令不再是运行入口。冻结协议、指标、失败记录、评分目标及源码快照保留；完整产物审计需重新生成缺失文件。清理范围见[研究索引](README.md#试验归档与清理)。

## 目的与范围

用 scene-0061 的全部 1,318 张独立 RGB 曝光丰富静态点云，同时验证动态目标如何减少跨时刻叠加产生的重影。当时的独立离线预览及上一组关键帧预览现已退役。

这组使用真实传感器标定与真实实例标注辅助实验。窗口重建会受到上下文、遮挡、深度误差和输入运动模糊影响，不能保证动态目标完全不糊，也不能把额外点数直接视为额外准确表面。

全部 RGB 按真实曝光时间排序，覆盖 19.192579 秒。六路相机异步且存在采集缺口，不能每六张强行视为同步帧，也不能将其描述成均匀帧率。LiDAR 共 382 次采集，包含 39 次关键扫描和 343 次 sweep。

采用官方 512 实用权重、balanced 480 预处理，实际网格为 640×352。共享源码固定在 `48b23c8ce72c9a8fcf987f0d7f43d8e4870759f6`，模型 Hub revision 固定为 `1041e80fc0e911235d3426b0a3d9a81075111a53`，权重 SHA256 为 `c02da418b18bb01d0392598d3f6147366bcde1bb70fd08a5e3bf7925b0667934`。GPU 仅使用物理 GPU1。

18 个窗口各包含 144 张独立曝光，通常步长 72，最后一个窗口从第 1,175 张开始，完整对齐末张图。尾部最多被三个窗口看见，但每张图预先固定唯一输出窗口：距离窗口边缘最远者优先，相同则取更早窗口。重复曝光只充当上下文，不重复算作独立时间支持。

原生预测几何逐窗用已知相机中心拟合一个正 Sim3。校准分支逐窗使用真实 LiDAR 独立拟合深度尺度，再用真实内外参映射至统一世界坐标；没有把不同窗口的原始深度直接混在一起拟合单一尺度。

## 静态对照与留出

分别比较关键扫描和全部扫描两条分支。两者均取距离曝光最近、最多四次、一秒内的允许扫描，采用相同局部校正与筛选规则。关键分支仅允许 36 次关键扫描；全部分支允许 371 次扫描。

三次评测关键扫描为旧组第 8、19、30 个零起始时刻。其前后 100ms 范围内的扫描一起全局排除，共 11 次，禁止用于尺度拟合、局部校正、自由空间筛选、对象校准和实测融合。静态评测复用旧组冻结的 38,461 个唯一真实回波目标及 1.5px 查询足迹。

静态候选排除曝光时刻所有可能 actor 的保守射线体积，再检查相邻真实曝光与邻方向相机的一致性、直接 LiDAR 支持和可见冲突。使用 0.1m 体素选取真实来源样本，颜色和坐标不跨物体平均；融合中实测点优先。

与旧组比较同时改变了 RGB 数量和全局/局部上下文。关键/全部扫描分支能观察更多真实锚点的收益，但不能将整组变化全部归因于 RGB 数量。

## 动态物体的三组对照

先按 `instance_token` 建立轨迹，仅在双端标注包围且时间间隔不超过 0.75s 时做位姿插值。单标注、端点外推和重叠盒归属歧义不参与多帧运动融合。每个曝光的对象深度只能使用同一实例、距离不超过 150ms 的允许 LiDAR，经源扫描时刻到 RGB 时刻的刚体变换后校准；至少八个唯一锚点、有限尺度调整和颜色/深度门控，并要求生成点位于曝光时刻的唯一实例盒内。

三种模式统一在同一真实参考时间展示：

- **单曝光对齐**：每实例取最近一个有效曝光，移到参考时刻。
- **未补偿叠加**：车辆使用前后 100ms 的同一批来源点，保留各曝光的原世界坐标。
- **刚体补偿**：车辆使用完全相同的预筛选来源，将每个点按源时刻与目标时刻的实例位姿变换；使用米制局部坐标，不按盒尺寸缩放。

行人、自行车、摩托车及铰接车三种模式均退回单曝光对齐。单曝光的根位姿对齐仍是刚体近似，不意味着恢复了人体或关节真实形变。

源曝光内跨实例共用同一像素时取最近深度，避免颜色重复归属。融合后的遮挡检查使用六路最近曝光，把候选几何从参考时间变换至各相机真实曝光时间，三组使用相同算子和门限；至少有一个方向的有效深度支持可见。该规则在构建前以 `sweeps-build-protocol.json` amendment 明确替代推理协议初稿的单前视检查，未根据评测输出选择。

默认展示单曝光对齐，可切到未补偿和刚体补偿。预览时间轴包含全部 224 个前视曝光，其他方向显示最近曝光及真实时间差，超过 125ms 标为缺失。右侧 RGB 点渲染固定为参考时刻的前视，使用完整校准静态模型和选定动态层；白色表示缺少几何，没有补画。上方显示点数不参与评分。

### 动态验证口径

三个留出扫描按实际采集时间选择唯一实例扩展盒内的原始回波，用同实例生成点的三维最近距离报告 0.1/0.2/0.5m 支持。盒边界扩展 0.3m，可能混入背景回波，归属并非逐点人工表面真值。另报实例×扫描分组、运动刚体分组、补偿新增/损失支持，以及相同预筛选来源下的对象局部 90% 范围散布。

这些都是稀疏支持或散布代理。更多点或更厚的表面也可能覆盖更多稀疏回波；局部范围更小也不能独立证明表面正确。没有把真实盒中心/轨迹吻合当成表面精度，没有将生成点到稀疏 LiDAR 的距离当作稠密精度。

在推理前仅按真实运动、持续时间和已知相机可投影范围冻结三个诊断实例：持续车辆 `c1958768d48640948f6053d04cffd35b`、较快车辆 `bc38961ca0ac4b14ab90e547ba79fbb6`、行人 `e59d97d4403a48b88fbb6a58fc9959e6`。不依据模型效果换样本；可投影范围不证明无遮挡。

## 实测结果

### 资源与覆盖

18 次窗口推理全部完成，纯前向合计 456.11 秒，包含加载与预测落盘的监测阶段为 967.12 秒。Torch 峰值分配 15,607.64MiB，NVML 观测到本进程峰值 17,130MiB；后者约 16.73GiB。重复窗口上下文有 1,274 次，输出所有权仍对应 1,318 个唯一曝光。全部图像均参与前向，两条分支各有 1,298 个曝光在筛选后留下静态候选，另 20 个没有通过筛选。校准、评分、动态时间轴和 RGB 渲染的 CPU 构建合计 1,735.19 秒。

| 静态分支       |   关键扫描 | 全部允许扫描 |
| -------------- | ---------: | -----------: |
| 实测 LiDAR     |    396,661 |    1,677,518 |
| 校准模型       | 14,591,661 |   14,745,908 |
| 实测与模型融合 | 14,686,630 |   15,279,859 |

未校准原生预测有 22,770,167 点。全部扫描的校准模型约为旧 234 图组的 3.54 倍；全部实测扫描本身也带来约 4.23 倍的静态点数。这些是采样数量，不是已证明准确的表面数量。

### 静态：更密，固定投影正确支持反而下降

同一批 38,461 个目标、同一投影查询下，误差不超过 0.5m 的正确支持率：

| 方法           | 关键扫描 | 全部允许扫描 |
| -------------- | -------: | -----------: |
| 实测 LiDAR     |   36.35% |   **50.65%** |
| 校准模型       |   37.51% |       38.58% |
| 实测与模型融合 |   37.93% |       38.56% |

原生预测为 22.60%，说明真实 LiDAR 校准改善了模型几何；但直接融合没有保住全部实测扫描的优势。全部扫描分支新增正确支持 2,496 个，损失 7,146 个，净减 4,650 个，即下降 12.09 个百分点，三个留出扫描均下降。共同有支持的 32,564 个目标中，平均绝对深度误差从 2.807m 增至 3.305m，中位数从 0.331m 增至 0.668m。

关键扫描分支净增 611 个正确支持，但共同目标中位误差从 0.337m 增至 0.733m，不能仅用平均误差略降宣称普遍改善。上一组 234 图融合的正确支持率为 45.35%；本轮同时改变窗口上下文和扫描来源，不能把下降单独归因于更多图像。

这里衡量的是固定相机投影查询的正确支持，不能当作整个稠密表面的精度。融合原样保留实测点，但新增模型点可能改变深度筛选及最近像素查询的赢家；原始实测坐标没有被移动或平均。独立来源审计检查实测属性完整保留。在三次留出的前视子集中，失去正确支持的 694 个目标中有 682 个改由模型点赢得投影查询，另 12 个由实测点赢得查询；保存的部分样例存在米级几何偏差。这项诊断仅覆盖前视子集，没有用这些目标调参。

同一曝光在重叠窗口中的校准深度仍有差异：全部扫描分支各窗口中位差的中位数为 0.213m，P90 差的中位数为 1.981m，最差窗口的中位差为 0.450m。这是上下文一致性诊断，不是相对真实表面的误差；统一坐标并不能保证各窗表面重合。

### 动态：部分车辆对齐改善，尚不能保证清晰

移动刚体只有 756 个留出回波、7 个实例×扫描组；其中 695 个回波来自同一辆持续车辆。按回波加权的稀疏表面支持为：

| 指标                         | 单曝光对齐 | 未补偿叠加 |   刚体补偿 |
| ---------------------------- | ---------: | ---------: | ---------: |
| 距离 ≤0.1m                   |     90.34% |     87.43% | **95.90%** |
| 距离 ≤0.2m                   |     95.50% |     97.35% |     97.49% |
| 以 1m 截断的平均距离         |     6.22cm |     6.87cm | **4.67cm** |
| 各实例×扫描等权的 ≤0.2m 支持 |     64.90% |     81.11% |     68.36% |

补偿在 0.1m 门限净增 64 个命中，但 0.2m 仅新增 3 个、损失 2 个。等权分组结果下降，说明改善没有覆盖所有实例和时刻。较快车辆只有 45 个回波，其中一个扫描只有一个回波，补偿后该回波由命中变为未命中；这样的小组会显著影响等权平均。

冻结行人实例的 62 个回波在三组中均为 56.45% 的 0.2m 支持，扫描 8 没有保留生成点。三组相同来自非刚体只用单曝光的规则，不能据此宣称行人运动补偿有效。全部 actor 的 7,710 个回波中，未补偿与补偿的 0.2m 支持分别为 85.10% 与 85.11%，几乎不变；等权分组为 45.49% 与 45.16%。

因此，这组支持“部分刚体在厘米级对齐上改善”，没有证明稠密表面准确、视觉锐度提升或动态目标完全不糊。真实实例轨迹仍是研究辅助条件；输入 RGB 的运动模糊、非刚体形变、遮挡与扫描内部时间差均未解决。

### 对标注平台的含义

当前最可靠的增密收益来自更多真实 LiDAR 扫描。模型结果保留为可切换的辅助审阅层，不能用更多模型点替代真实测量。后续需要让模型只补有独立一致性支持的缺口，并在投影冲突时明确优先实测几何，再用固定留出数据验证，而不是继续无条件累加模型点。

### 浏览器与本地检查

22 项独立 CPU 测试通过，覆盖窗口所有权、体素来源保留、严格时间插值、实例身份、米制刚体变换、扫描隔离、非刚体单曝光和后向可见性。Ruff、CSS token 检查及文档构建通过。

独立产物审计通过：检查 98,000 个静态来源样本、94,920 个动态来源样本，重新投影 1,680 个静态评分样本，重算全部 825 个动态实例×扫描×模式分数。最大来源坐标差为 0.000063m，最大动态源像素差为 0.0145px；这些只验证保存几何与其来源/变换一致，不表示预测表面达到同样的真实精度。11 次扫描全局隔离、两分支实测点属性完整保留、关键扫描几何与旧组逐值相同、上一轮 17 个运行文件保护均通过。

真实浏览器完成 24 项状态检查和 10 项交互检查，覆盖七种静态方法、三档显示预算、动态三组、快速切换、一次故障注入后的清空与恢复、六路相机、原生鼠标旋转/重置及全部 224 个参考时刻播放至末尾。桌面为 1440×1100，手机为 390×844；截图均已检查，手机无横向溢出。无故障注入的最终页面错误列表为空。

浏览器实际为 Linux HeadlessChrome 150、DPR 1、Canvas2D CPU 兼容绘制，WebGPU adapter 为 null。这些是独立离线预览的功能结果，不能当作生产 WebGPU 资格或硬件性能验收。一次 2× 全序列播放检查耗时 12.63 秒，包含等待末帧数据对齐，不是稳定帧率基准。

## 运行与证据

输入提取仅从已有数据包取出本 scene 缺失的 RGB/LiDAR sweeps，写到实验目录的 `source-inputs/`，保留原始数据。产物根目录为 `.artifacts/model-review/vggt-omega-lidar-densification/sweeps-sequence/`。

当时在独立 Python 环境中使用 Torch 2.6.0/cu124、NumPy 1.26.4、SciPy、Pillow、Numba、einops、safetensors 和 opencv-python-headless，具体版本随 `sweeps-environment.json` 保存。离线入口现已移出运行目录，清理前源码位于本地产物根目录的 `retired-runtime-source/apps/api/scripts/`。

协议、输入摘要、逐窗尺度、评分目标、指标、失败记录、阶段源码及浏览器证据保留。逐窗预测、局部终点、融合/动态点云、显示索引、源数据副本和渲染已清理。正式标注平台接入仍需用实际跟踪器替代真实实例标注，并验证非刚体、遮挡和失跟场景。

主要结果为 `static-validation.json`、`dynamic-validation.json`、`dynamic-derived-summary.json`、`overlap-validation.json` 和 `fusion-projection-loss-audit.json`。来源审计为 `sweeps-artifact-audit.json`；两组浏览器检查为 `browser-behavior.json` 与 `browser-interaction.json`。`sweeps-manifest.json` 保存清理前正式产物及共享渲染依赖的 SHA256，`cleanup.json` 记录本轮临时环境和测试中间产物的清理。未运行远程 CI。
