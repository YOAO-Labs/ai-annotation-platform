# VGGT-Ω 与 LiDAR 约束点云增密试验

本轮的目标是增加有几何依据的点云覆盖。RGB 清晰度、高斯数量和总点数都不能单独证明达标。

## 数据隔离与几何处理

1. **整次扫描留出**：中心 LiDAR 的所有原始回波均不进入尺度拟合、局部校正和实测基线。单帧基线用最近前一帧；多帧基线用窗口内其他两次或四次扫描。保留扫描 token 与原始行号，同一回波在多个相机中出现只计一个主评分目标。
2. **真实相机约束**：使用每个传感器曝光自己的外参、ego pose 和标定内参。图像与投影统一整数数组中心；缩放内参使用 `cx'=(cx+0.5)*sx-0.5`。模型预测位姿只归档，不作为最终点坐标来源。
3. **先校正再融合**：允许的静态 LiDAR 投影作为锚点，以每个独立回波等权的鲁棒 log 比例中位数校尺度。局部 log 残差由半径 24px 内的 8 个近邻传播，至少两个通过颜色/深度门槛，调整上限为 ±log(1.3)。没有局部锚点支持的区域保留全局尺度。端点门控不能保证在同色或预测深度相近的两个物面之间完全阻断传播。
4. **保守时间筛选**：静态点需要至少一个同相机、不同采集时刻的重投影支持，深度容差为 max(0.4m, 3%Z)，循环误差不超过 2px。直接与真实锚点一致可作为例外。可见模型冲突和 LiDAR 已观测自由空间冲突都能否决。来自同一模型窗口的时间支持是相关的一致性证据。
5. **动态分开处理**：利用 nuScenes 真值框遮挡全部车辆、行人及可动物类别，包含停放车辆，属于 oracle 诊断条件。动态候选只取中心六路相机曝光，没有跨时间累积或物体运动补偿；各路 RGB 与中心 LiDAR 的时差单列。
6. **保留来源**：每种点云按 0.1m 体素选择原始样本代表，不跨边缘平均位置。融合优先保留实测静态点，生成层保留相机索引、图像像素、置信值和时间支持数。

## 评分方法

比较前一帧 LiDAR、多帧实测、仅全局尺度模型、局部校正模型、时间筛选模型，以及实测与筛选模型融合。
每种方法均对**实际落盘点云**进行重投影，统一 1.5px 有限查询半径。可见静态目标按最大图像边距分配到一个固定中心相机，避免六路重复统计。

主指标是固定目标分母下，camera-Z 深度误差在 0.2/0.5/1m 内的正确支持率。缺失预测计为未命中。另报有支持目标的 MAE、P50、P90、有符号偏差、全部方法共同支持及与多帧 LiDAR 的共同支持误差，并区分新增正确目标和损失的原正确目标。
深度误差并非 3D 欧氏距离。另有固定回波对候选云的稀疏 3D proximity proxy；它也不能证明未观测区域整体精确率或完整度。距离和 RGB 边缘分层均保留，三/五帧使用同一 RGB 边缘定义。

## 结果

**12 个窗口均完成。校正与融合明显增加固定回波附近的正确深度支持，但不能据此将整个生成层认定为可靠测量。**

每种窗口有相同的 87,065 个唯一静态目标，来自六次中心扫描。三帧与五帧分别汇总，避免把同一批回波当作两份独立观测。

| 窗口 | 新增 ≤0.5m 正确目标 | 丢失原正确目标 | 净增加                  | 融合静态点中位数：实测 / 生成 |

分母仍为各自固定的 87,065 个静态回波。三帧和五帧新增静态体素的中位数分别为 300,702 和 483,656.5；这些数值仅描述密度，未被稀疏回波检验的体素不能直接称作正确新增表面。

在与多帧 LiDAR 的共同支持集上，三帧融合 MAE 从 1.067m 变为 1.237m（27,706 个共同目标）；五帧从 1.327m 变为 1.491m（38,656 个共同目标）。纯筛选模型的共同支持也没有优于实测：三帧 0.813m → 1.106m，五帧 1.186m → 1.479m。因此本轮证明的是更多回波附近获得容差内支持，尚未证明对原有实测附近的平均误差改善。

融合按体素优先保留实测样本，但生成点仍可能在投影查询时成为离目标像素更近的候选，所以保留原点本身不保证其原正确命中不会丢失。后续需要更严格的实测可见性、物面边界与离群点控制。

### 场景与分层

| 场景            | 三帧实测 → 融合 ≤0.5m | 五帧实测 → 融合 ≤0.5m |
| --------------- | --------------------- | --------------------- |
| 开发 scene-0061 | 22.72% → 49.41%       | 32.33% → 50.95%       |
| 验证 scene-0103 | 28.48% → 48.72%       | 36.37% → 49.54%       |

12 个窗口的融合正确覆盖均高于各自实测基线，但五帧不是每个中心都优于三帧：scene-0061 中心 30、scene-0103 中心 8 出现下降。汇总五帧比三帧仅增加约 1.15 个百分点的 0.5m 正确覆盖，前向时间、后处理和点数成本更高。本轮优先保留三帧方案作为下一轮候选起点。

三帧近处 <20m 正确覆盖 23.45% → 49.73%；20–40m 为 35.51% → 47.69%；40–80m camera-Z 为 33.14% → 42.89%。RGB 边缘目标为 24.19% → 43.43%，仍低于内部目标的融合 49.61%。各层完整 MAE/P90 与偏差在每窗 `metrics.json` 中。

还核对了一处边界口径：实测云以参考 LiDAR 原点 80m 球界裁切，模型按 camera-Z ≤80m 筛选。固定目标中有 219 个静态回波在球界外，占 0.25%。额外在相同球界内的 86,846 个目标上复核，三帧正确覆盖为 **25.825% → 49.065%**，五帧为 **34.552% → 50.207%**，主要结论不依赖这些边界外回波；不能据此声称已建立统一远距离输入预算的严格基准。

动态层有 13,603 个独立回波诊断目标，三帧融合的 0.5m 正确支持为 31.07%，五帧为 28.52%；前一帧未经运动补偿的动态实测为 14.81%。中心六路 RGB 与评分 LiDAR 时差为 −44.025ms 至 +0.271ms，且输入包含中心图像。该对照不能单独证明动态重建算法更优，也没有完成轨迹或场景流验证。来源审计确认生成动态样本全部来自中心曝光，未跨时刻拼接。

## RGB 纹理网格扩展

在上述 12 个固定窗口上接入真实三角网格渲染。VGGT-Ω 提供几何先验，RGB 来自各顶点所属曝光的原始 1600×900 图像；没有新增 RGB 预测头，也没有进行会移动几何的 RGB 优化。所有网格顶点严格复用已保存的 `filtered_model.bin`，包括 0.1m 体素筛选留下的原样代表。网格是在既有点之间连面，并未产生新的独立测量。

### 连面与渲染合同

- 同一曝光、同一静态/动态种类单独进行图像域 Delaunay 连面。源像素边长不超过 6px；三维边长不超过 max(0.35m, 3%Z)；深度跳变不超过 max(0.3m, 3%Z)。静态层保留整个三/五帧窗口，动态层只保留中心六路曝光。
- 原接受掩码先腐蚀 1px，再检查每个三角覆盖的整数像素和顶点，禁止跨越原来被否决的孔洞。保留缺口和断面，不以完整画面为目标补造背景。
- 使用原始 RGB 纹理和带像素中心仿射的 UV。双面绘制，按相机 Z 做遮挡；RGB 与深度使用 `1/Z` 透视插值。来源相机使用完整非中心 K、各自曝光位姿及 CV 到 Three 坐标转换。
- 六路分别保存 560×320 评分深度和 800×450 RGB 图；静态、动态诊断、全部图层有各自的渲染文件。另保存前视相机右移 0.5m 的静态网格 RGB 图，该位置没有独立图像真值，只用于观察视差与缺口。

网格仍使用原来固定的中心留出扫描。**静态目标用静态网格单独评分，动态诊断目标用动态网格单独评分**；全部图层的 RGB 图保留真实前后遮挡。初次实现混用了全层深度，审计后已在固定几何和阈值下完整重算 12 个窗口。初始 `mesh-protocol.json`、源码和初版指标均保留，修复前冻结 `mesh-layer-scoring-amendment.json`，并核对修复后顶点、UV、三角索引和目标文件摘要不变。

网格评分使用实际三角面覆盖的像素，缺口计为没有支持；点云原评分则允许 1.5px 查询半径，两种足迹不同。因此不能把网格数字与前文点云覆盖直接排名，也不能把源视角 RGB 回投看作新视角画质验证。

12 个窗口逐面检查共 5,525,647 个三角面，核对 180 张不同来源纹理；单窗口包含约 29.5万–72.4万面。这是不同窗口的保存总量，包含重复观测，不能当作一份场景的独立表面数量。最大来源像素重投影残差为 0.01020px。

| 3帧  | 29.17%         | 22.86%         | 0.712 / 1.697m |

动态层仍只作诊断，在相同 13,603 个回波上的 0.5m 正确覆盖分别为 26.87% / 23.71%，有支持目标 MAE 为 2.011m / 1.926m。连面本身没有解决跨曝光运动或局部错深度。

### 使用与浏览器验证

在 `http://localhost:8780/` 选择「RGB 纹理网格」，可切换六路贴近相机视角或重置为自由视角，拖动旋转、滚轮缩放；「生成静态」「动态诊断层」控制对应网格及六路 RGB 图。默认打开两类网格以查看 RGB 场景，评分卡始终明确报告固定静态目标。「按来源着色」可查看几何范围，取消后恢复 RGB。点击六路图像可打开原尺寸 PNG，下方链接打开静态网格相机右移 0.5m 的渲染。

本机 Chrome 150 无法建立 WebGL 上下文，实际验证使用 Canvas2D CPU 三角形栅格化，渲染的是可旋转的真实网格。来源相机的 450 个射线投影检查同时注入旧旋转/平移惯性，确认切换相机会清除惯性，避免偏离标定位姿。加载新窗口期间隐藏旧三维画面，防止与新窗口分数混合显示。

浏览器 CPU 与离线 Numba 渲染在同一窗口的 560×320 前视来源相机上逐像素核对，包含全层遮挡：覆盖像素 IoU 为 99.628%，共同覆盖 RGB 平均绝对误差为 0.00339（0–255）；边界少量像素的最大色差为 52，不能称作逐值完全相同。六路射线投影最大误差为 2.39×10⁻¹²px。具体记录在 `browser-mesh-probe.json`。

另有 4 个 CPU 合同测试覆盖纹理方向、像素中心、透视深度、遮挡、孔洞与深度断面；产物审计逐面核对来源种类、边长和保存的重建接受掩码，并验证保存的分层深度与评分取样一致。这不等于独立重建掩码或重栅格化全部评分深度。延迟请求、快速切换、注入加载失败和视角重置的浏览器验证通过，零尺寸画布也不会中断绘制。WebGL 路径没有实机成功证据；其近裁面会裁剪三角形，而 CPU 路径保守丢弃跨近裁面的整面，贴近物面时两者孔洞可能不同。

当前 RGB 网格仍然有明显空洞和局部错面。高分辨率原图纹理改善已支持表面的颜色细节，不能恢复未通过几何筛选的区域，也不能证明任意新视角达到照片质量。点云增密与几何误差仍是后续优化的主要依据。
