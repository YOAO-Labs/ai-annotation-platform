# VGGT-Ω 整场景联合重建

> 归档状态：独立预览和离线试验入口已退役，大体积派生产物已清理。下文保留当时的方法与验收结果，旧地址和命令不再是运行入口。冻结协议、指标、失败记录、评分目标及源码快照保留；完整产物审计需重新生成缺失文件。清理范围见[研究索引](README.md#试验归档与清理)。

## 范围与输入

本轮按用户提供的[项目主页](https://vggt-omega.github.io/)展示方式，新增一个可旋转的整场景彩色点云预览，配有前视相机轨迹、当前时刻六路相机视锥、39 帧时间轴，以及输入 RGB 和实际点云投影渲染对照。

试验使用 `scene-0061` 的全部 **39 个标注关键时刻 × 六路相机 = 234 张 RGB**，跨度约 19.15 秒。所有输入在同一次模型前向中联合参与，没有按短窗口分开推理后拼接。原始 nuScenes 压缩包还包含该场景 1,084 张非关键帧 RGB 和 343 个额外 LiDAR sweep；它们没有解压、没有参与本轮，页面明确标注全部可用关键帧范围。

本轮独立保存在 `.artifacts/model-review/vggt-omega-lidar-densification/full-sequence/`，没有修改上一轮三/五帧预测、评分、纹理网格和源码快照。当时页面地址为 `http://localhost:8780/full-sequence/`；独立预览现已退役。

## 模型与显存尝试

采用官方[源码](https://github.com/facebookresearch/vggt-omega)的固定提交 `48b23c8ce72c9a8fcf987f0d7f43d8e4870759f6`，以及 `facebook/VGGT-Omega` 在 revision `1041e80fc0e911235d3426b0a3d9a81075111a53` 的 `vggt_omega_1b_512.pt` 实用版权重。权重 SHA256 为 `c02da418b18bb01d0392598d3f6147366bcde1bb70fd08a5e3bf7925b0667934`。

官方将该权重用于实际场景展示；它与上一轮用于比较的 416 复现权重不同。场景长度、权重和输入分辨率同时变化，因此不能将两轮的结果差异单独归因于长上下文。

| 尝试         | 输入网格 | 分配方式            | 实测结果                            |
| ------------ | -------- | ------------------- | ----------------------------------- |
| 512 balanced | 688×384  | 默认                | 后续编码层显存不足；记录保留        |
| 512 balanced | 688×384  | expandable segments | 仍显存不足；记录保留                |
| 480 balanced | 640×352  | expandable segments | 234 张图单次联合前向成功，59.993 秒 |

最终仍使用 512 权重，只调整官方预处理函数的输入尺寸。物理 GPU 1 为 RTX 3090；PyTorch 峰值 allocated 为 21,574 MiB，reserved 为 22,152 MiB。网络显式限制使用 Flash 或 efficient SDPA，禁止回退到会物化巨大注意力矩阵的 math 路径。`use_checkpoint` 在上游 eval 路径不起作用，没有把它当作推理省显存手段。

原来的失败记录保留在根目录和 `attempts/512-expandable/`。成功记录、源码快照与原始深度、置信度、相机预测保留在 `attempts/480-balanced/`；`sequence-attempts.json` 指明选中的尝试，`sequence-selected-protocol.json` 对应页面的完整输入清单。

## 三维几何与校准

- **原始预测几何**：使用模型预测的相机和深度，按全部已知相机中心拟合一个全局 Sim(3)，同步变换朝向、相机位置和深度。没有逐相机形变。页面的相机残差属于这同一组相机的对齐拟合残差。
- **校准模型**：使用真实相机标定和逐曝光 ego pose，将原始模型深度做稳健全局尺度拟合及有界局部 LiDAR 校正。原始回波身份去重；局部锚点仅来自曝光前后两个关键帧以内。
- **时间一致性筛选**：对同相机前后关键帧、同关键帧两侧相机进行深度和两像素循环一致性检查；真实回波处的自由空间冲突不能被模型支持覆盖。静态表面排除所有车辆、行人和可移动物体的 oracle 框投影区域。
- **实测与融合**：单列多帧实测 LiDAR，融合时在 0.1m 体素中优先保留原始实测样本，不平均坐标。完整点云与 source/pixel/kind 来源一起保存；浏览器 12/35/120 万点的显示预算仅采样显示，不改变完整资产和评分。
- **逐帧目标候选**：只显示当前关键时刻的六路 RGB 候选，并要求反投影点落在该曝光时刻的 oracle 三维框内。六路曝光并不同步；没有估计实例运动、场景流或做运动补偿。原始模型和纯实测视图不混入这个校准模型候选层。

已知 K 采用 PIL 缩放的半像素仿射，反投影使用数组整数中心。模型预测 K 的主点减去 0.5，与上游训练的像素中心一致。世界到浏览器的坐标变换保持右手系，相机采用 OpenCV 到 Three 的轴转换；跟随视角使用完整 K 的投影矩阵与 letterbox。

## 留出验证

全场景统一留出零起始编号 **8、19、30 的三整次 LiDAR 扫描**。这三次扫描在每一个曝光的全局尺度、局部校正、冲突否决、静态融合和实测基线中都不出现；RGB 仍参与联合推理。由此避免先按每个窗口排除自己的扫描，再全场景合并造成的回流。

从留出扫描的唯一可见静态回波固定目标，六路只分配一次；对完整落盘体素点云统一使用 1.5px 有限足迹，报告 camera-Z 正确覆盖、已有支持上的误差、共同支持误差和融合新增/丢失正确目标。浏览器显示的 LOD 不参与评分。

稀疏 LiDAR 目标只能验证其附近的支持；新增点数、图像色彩和更连续的道路外观均不能证明未观测表面准确。右侧 RGB 是完整校准静态点云与当前帧目标候选的真实有遮挡投影，颜色来自输入图像，白色缺口保留，没有图像生成或补画。它也不是独立留出 RGB 的新视角指标。

## 实测结果

| 输出                 | 体素前静态来源点         | 保存的完整静态点 |
| -------------------- | ------------------------ | ---------------- |
| 原始预测几何         | 27,924,751               | 6,536,293        |
| 校准及一致性筛选模型 | 17,207,372               | 4,168,067        |
| 多帧实测 LiDAR       | 1,113,772                | 396,661          |
| 实测优先融合         | 实测与校准模型的已去重点 | 4,333,428        |

完整校准点数约为实测体素点数的 10.5 倍，这描述密度，不代表 10.5 倍的正确测量。
234 路输入都有预测和保留几何；其中 231 路保留静态点，另外三路（输入编号 22、23、28）
被近处目标的 oracle 投影覆盖，只有逐帧目标候选，未为满足计数而放宽静态筛选。
39 个逐帧候选层合计 896,989 点，不当作一个时刻的唯一动态点数。
CPU 校准、筛选、体素化、完整评分与 234 张相机 RGB 渲染合计约 430.1 秒。

三个全局留出扫描共形成 **38,461 个唯一静态目标**：

| 方法            | 有限足迹支持率 | ≤0.2m 正确支持 | ≤0.5m 正确支持 | ≤1m 正确支持 | 有支持时 MAE / P90 |
| --------------- | -------------- | -------------- | -------------- | ------------ | ------------------ |
| 原始预测几何    | 88.88%         | 12.91%         | 28.35%         | 46.71%       | 3.603 / 9.183m     |
| 校准模型        | 82.73%         | 25.27%         | 44.41%         | 56.71%       | 2.940 / 7.426m     |
| 多帧实测 LiDAR  | 62.60%         | 25.04%         | 36.35%         | 43.52%       | 3.561 / 9.729m     |
| 实测 + 校准模型 | 84.10%         | 26.57%         | 45.35%         | 57.65%       | 2.975 / 7.602m     |

融合相对实测新增 7,162 个 ≤0.5m 正确目标，同时损失 3,698 个，净增加 3,464 个，
即 **9.01 个百分点**。共同有支持的 24,052 个目标上，MAE 从 3.561m 降到 3.029m，
但 ≤0.5m 命中比例从 58.04% 降到 52.30%，说明误差尾部改善没有保证原有精确命中。
完整相机中心的全局 Sim(3) 拟合残差 RMSE 为 0.837m、中位数 0.534m、P90 为 1.253m；
朝向残差中位数 2.27°。这些数据支持全场景辅助显示，尚不足以将生成点当作标注测量真值，
也没有改变三帧增密作为既定默认路线的选择。

### 验证证据

- 13 项新几何及增密合同检查通过，涵盖全局扫描排除、Sim(3)、相机坐标和实际点的深度缓冲。
- 独立产物审计核对全部输入与预测摘要，抽查 91,800 个静态来源点，并独立重投影 480 个评分样本；
  最大来源坐标差 0.0000649m，最大来源重投影差 0.01090px。所有 LOD 点直接对应完整资产原样本，
  融合保存的实测坐标与来源逐值保持。旧短窗口/网格源码保护仍通过。
- 实际 Chrome 的 23 项交互检查通过，包括四方法、三显示预算、前中后关键帧、慢请求与快速切换、
  图像代次、两类失败恢复及播放末帧。六路相机共 210 条投影射线，最大矩阵误差约 1.21×10⁻¹²px。
- 实际鼠标拖动能改变视角，重置后的惯性漂移约 2.84×10⁻¹⁴m。390px 移动视口没有横向溢出。
- 本机 Chrome 无法创建 WebGL context，实际采用 Canvas2D CPU 绘制；网页提供相同几何的兼容交互。
  GPU 点颜色做 sRGB 到线性空间转换，但本轮没有获得 WebGL 硬件渲染验收。应用内浏览器未连接，
  页面在独立测试浏览器验证，当时保留了本地服务，现已停止；没有声称已替用户切换其应用内标签。

原始记录位于 `sequence-artifact-audit.json`、`browser-sequence-behavior.json`、
`browser-sequence-projection.json` 及各推理尝试目录，实际页面截图与环境记录一并保留。
