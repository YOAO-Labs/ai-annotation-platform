# VGGT-Ω 当前帧增密对照

> 归档状态：独立预览和离线试验入口已退役，大体积派生产物已清理。下文保留当时的方法与验收结果，旧地址和命令不再是运行入口。冻结协议、指标、失败记录、评分目标及源码快照保留；完整产物审计需重新生成缺失文件。清理范围见[研究索引](README.md#试验归档与清理)。

## 目的与结论

针对整场景重叠窗口预览中的目标缺失和残影，把实验改为当前标注时刻独立输出。独立预览已退役。同一 scene 的 39 个标注时刻、六相机共 234 张图全部完成，两组模型都不使用其他时刻的图像，也不累加其他时刻的模型几何。

当前证据支持继续验证“当前真实 LiDAR + 可关闭的当前相机模型辅助层”。最终筛选点云的运动目标分组中单图较好，全部目标则六相机略好；过滤前的模型深度也没有显示单图普遍更准。尚不能保证动态物体清晰或完整，不能将模型点直接作为标注真值。

## 四组与输入合同

| 方法         | 输入与输出                                                                    |
| ------------ | ----------------------------------------------------------------------------- |
| 当前帧 LiDAR | 当前完整原始扫描，独立保留全部点和原始五列数据                                |
| 传统叠帧     | 当前扫描加前后各一个关键扫描，用真实 ego/sensor pose 对齐；不做逐目标运动补偿 |
| Ω 单图       | `B=6,S=1` 六个独立单图序列；只显示所选相机的输出                              |
| Ω 六相机     | `B=1,S=6` 当前标注时刻的六路实际曝光联合推理；同样只显示所选相机的输出        |

这样能区分联合推理上下文与几何累积的影响。六相机输入仍然异步；全部曝光相对对应 LiDAR 的时间差为 −47.757～+1.072ms。未做逐回波 LiDAR 去畸变，也没有使用真实实例轨迹搬运模型点。

复用上一轮固定的官方源码提交 `48b23c8ce72c9a8fcf987f0d7f43d8e4870759f6`、512 实用权重和 Hub revision `1041e80fc0e911235d3426b0a3d9a81075111a53`。权重 SHA256 为 `c02da418b18bb01d0392598d3f6147366bcde1bb70fd08a5e3bf7925b0667934`，balanced 480 预处理产生 640×352 网格。模型推理只使用物理 GPU1。

两组均用同一当前扫描训练分区，采用相同逐相机 robust scale 和有界局部校正。没有局部支持的像素保留尺度校准深度；不足 32 个唯一尺度锚点会显式失败，不借用留出点或其他时刻。置信度采用逐图 20% 分位数，深度范围 1～80m，移除底部 5%；生成点使用真实 K 和每次曝光实际位姿反投影。

候选不使用 GT 目标框或每实例八锚点门槛，不因没有实例校准而整目标删除。新增点在六个当前相机中均避开训练实测射线周围 3px，随后每相机按 0.1m 体素保留真实来源样本；当前实测点不参与体素抽稀。射线保护会留下扫描线附近的空带，预览保留这种现象，没有补画。

## 留出与解释边界

推理前按扫描 token、原始行号固定约 80%/20% 互补分区，使用 SHA 种子和整数混合，避免周期抽样与 LiDAR 环线排序耦合。第 8、19、30 个零起始时刻继续作为评分时刻；完整扫描只在评分侧确定最近可见层，再选出留出回波，每个原始回波只选一个方向。最终固定 **11,514 个唯一可见回波**。

模型尺度、局部校正、射线保护及评分底云仅用当前扫描的训练分区。传统组额外使用不同采集的真实邻帧。展示侧追加完整当前扫描，评分侧绝不追加留出点。因此，预览包含完整真实点，评分回答的是“其余 80% 输入能否补出缺失回波位置”。这不是整扫描留出，也不是整个稠密表面的精度，不能与上一轮百分比直接比较。

相机投影查询采用连续 UV 的 1.5px 足迹。这个足迹小于许多同扫描回波的间距，输入 80% 的原始组对留出位置只有 1.02% 覆盖、0.37% 的 ≤0.5m 支持。**这不表示原始 LiDAR 只有 0.37% 准确率**；完整扫描仍是标注基准。

GT 扩展框只用于评分分组和预览定位，边界扩展 0.3m，可能混入背景。“框外”不能等同于所有真实静态点，“框内”也包含静止车辆。运动组由 GT 轨迹在评分时间前后 100ms 的水平速度至少 0.5m/s 定义，共 216 个目标回波。三次时刻与三个诊断实例均沿用前组，没有按新结果换样本。

## 实测结果

### 固定投影回波补全

下表分母是留出的回波，包含未覆盖位置，不是生成点精度：

| 方法                 | 全部 11,514 个 ≤0.5m 支持 | 框内 1,451 个 ≤0.5m 支持 | 运动 216 个 ≤0.5m 支持 | 全部 >1m 错误支持 |
| -------------------- | ------------------------: | -----------------------: | ---------------------: | ----------------: |
| 当前输入 80%，不补点 |                     0.37% |                    0.00% |                  0.00% |             0.64% |
| 传统前后各一帧       |                    28.37% |                   34.94% |                  5.09% |             6.26% |
| Ω 单图辅助           |                    45.69% |                   44.52% |             **52.78%** |            12.67% |
| Ω 六相机辅助         |                **46.39%** |                   44.45% |                 47.22% |            11.86% |

相比当前 80% 输入，传统叠帧新增 3,224 个正确支持，单图新增 5,218 个，六相机新增 5,298 个；三组均没有损失已有的 43 个正确支持。这个零损失只针对本次固定投影目标，不能推广到任意视角或整个表面。

3px 保护和 1.5px 查询的影响单独分层。距训练实测射线超过 3px 的 **8,428 个**空缺目标中，≤0.5m 支持分别为传统 27.04%、单图 54.03%、六相机 55.09%。1.5～3px 保护带有 2,969 个目标，单图和六相机分别为 22.36% 与 22.06%；保护点以外的候选仍可能落入目标的 1.5px 查询足迹。

### 单图优势还不能归因于模型本身

在相同尺度和局部校正之后、置信度/保护/体素筛选之前，直接查询预测深度：

| 范围         | 单图 ≤0.5m | 六相机 ≤0.5m |
| ------------ | ---------: | -----------: |
| 全部留出回波 |     72.19% |       72.89% |
| 运动回波     |     74.07% |       74.54% |

过滤前两组接近且六相机略高，最终运动组反而单图更高，说明点选择、置信度和采样也影响结果。不能把最终点云的分组差直接解释成单图深度普遍更准。

### 动态目标仍有局限

持续车辆在时刻 19 的所选方向中，训练实测扩展框内有 168 点，单图增加 2,549 点、六相机增加 2,485 点；40 个留出回波的同实例三维近邻 ≤0.2m 支持从 62.5% 提高至两组的 100%。这是稀疏近邻支持，厚表面也可能提高该指标。

行人在时刻 8 只有三个训练实测点，没有可评分的留出回波；单图和六相机分别只增加六点与十一点，仍然稀疏。在时刻 30，单图局部 90% 高度散布达到 2.109m，超过参考盒高度 1.856m；这可能包含框边背景或几何误差，不能宣称人体表面已恢复。较快车辆在时刻 19 仅一个留出回波，单图未命中、六相机命中，不能据此推广。

不累加跨时刻模型输出去掉了这一类残影来源；输入模糊、曝光异步、深度误差和薄小目标仍存在。未进行人工标注耗时、框尺寸准确度或多 scene 统计验收。

## 资源与验证

单图常规前向合计 13.27 秒，六相机常规前向 14.09 秒；包含加载、数值检查及落盘的推理阶段为 132.55 秒。Torch 峰值分配 6,485.52MiB，NVML 本进程观测峰值 6,894MiB。CPU 构建用时 359.11 秒，生成 936 张同方向 RGB 点渲染。

39 个当前扫描的 **1,354,112 个原始点**及五列传感器字节全部保留。两个模型组跨所有时刻/方向分别保存 10,256,858 与 10,309,700 个辅助点；界面每次仅加载当前时刻、当前方向的点，不把总点数当作同时可见或已证明准确的表面数量。

首次数值检查在评分前停止：`B=6,S=1` 与单独 `B=1,S=1` 的 BF16 运算形状不同，首个方向 P99 相对差为 3.445%，超过初始 2% 阈值。失败协议、源码与日志保留于 `current-frame-attempts/batch-numerics/`。随后固定批次形状，只替换其他五张图；首时刻前两个方向的深度输出均逐值不变。此检查证明这些输出不受其他图片影响，不证明 B1 数值等价，也没有单独实测 confidence 的独立性。

构建前的 `protocol-amendments.json` 修正了继承协议中旧的“全部图片单次联合”说明及旧整扫描留出标记的含义，保留已执行推理的冻结文件。

六项新增 CPU 检查通过。独立产物审计通过：核对全部 20,566,558 个生成点的源像素/深度/RGB、59,904 个测量射线保护样本，重新投影和评分全部 11,514 个目标；所有原始属性副本、分区、逐相机标定、邻帧范围、点云二进制和 936 张渲染尺寸通过。最大来源反投影舍入差 0.000063m 仅证明保存变换一致，不是模型真实精度。

真实浏览器完成 34 项功能检查，包含四组切换、六个相机按钮、首尾与固定时刻、原始层独立显示、来源分色、三个参考目标定位、评分分组、快速切换、一次 503 清空与恢复、相机投影、原生旋转/重置、39 时刻播放至末尾，以及 390px 手机宽度无页面溢出。最终正常页面错误列表为空；故障注入的预期错误单独保存。桌面、手机和同目标三组局部截图均已目视检查，模型仍有表面散布与扫描保护空带，没有将视觉结果描述为无残影。

实际浏览器为 Linux HeadlessChrome 150、DPR 1，桌面 1440×1100、手机 390×844。绘制采用 WebGL2，但实际 renderer 为 ANGLE / Vulkan SwiftShader 软件设备，WebGPU adapter 为 null；不代表 RTX 3090 的浏览器渲染性能。完整后端与最终文字检查见 `browser-final-smoke.json`，未做生产工作台 GPU 资格或远程 CI 验收。
