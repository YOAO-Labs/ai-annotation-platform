# ADR-0155：持久推理执行权与后端排空确认

状态：实施中，尚未完成独立部署与故障验收。

## 问题

原路由先读取 PostgreSQL 候选，再由 Redis 接受租约。排空和项目禁用若发生在两步之间，
暂停的旧候选仍可能获准。Redis 租约被取消、过期或丢失，也无法证明后端工作已经结束。

修改前在隔离 PostgreSQL、Redis 和真实 HTTP 后端上记录了四项实际行为：排空后旧候选
获准、项目禁用后旧候选获准、客户端超时后后端仍活动但 Redis 在途数为零，以及删除
本次测试独占 namespace 后已有租约不再计数。基线固定旧源文件指纹，不覆盖已有冻结夹具。
16 次、并发 4 的本地 CPU fixture 请求另保存原始耗时，不能据此声明生产容量。

## 决策

PostgreSQL 持有执行 scope、实际 HTTP attempt、管理占用、代次、物理实例连续性和最小命令
回执。两项固定 Native 能力提供封闭动作；提供方持有完整准入策略和命令协调。Redis 保留
非权威诊断用途，零计数不参与排空证明。

执行权使用独立短事务，不提交调用方的 Task、Prediction、Audit 或 Learning 事务。普通
调用按请求取得 scope，视频跟踪在整作业内固定实例并心跳。第一次实际发送前复核当前
成员、项目、配置与代次；已接受且活动的视频 scope 可在排空、项目禁用后继续，解绑、
配置变更和显式关闭另受围栏约束。

HTTPX 保留原传输、代理和连接配置。请求 hook 在实际发送前登记 attempt，响应流耗尽后
才报告完整响应；超时、取消、早关闭和传输错误保留未决状态。登记失败禁止发送；结算
回执丢失不重发推理，也不丢弃已经收到的成功结果。scope 关闭根据实际 attempt 账本
推导状态，不能提交“在途数为零”的断言。活动和未决工作不会因 TTL 消失。

卸载、重载在网络调用前取得持久管理占用，既有调用方在 I/O 前释放连接的边界保留。
管理占用在实际完整响应结算后解除；未知结果继续阻止恢复接流和新准入。Registry、Pool、
Member 的相关管理写入使用共同围栏，锁序沿用 Registry → Pool → Member。

空账本不能把旧实例认定为空闲。受认证的实际后端 drain/bind 交换关闭旧准入，等待真实
工作归零，再绑定新 epoch、进程 incarnation 和签名密钥。后端启动时默认未绑定，拒绝
旧 epoch 与重复 attempt；已开始的任务、响应流和延迟 future 保持计数直到实际完成。
配置管理凭据的后端每次启动都关闭旧请求，不提供旧流量绕过开关。未配置凭据的普通
旧推理无法建立管理连续性，且拒绝忽略传入的托管准入 header。

## 通信与凭据

公开 owner wire 只携带封闭命令和不透明 capability/subject，不携带后端凭据、推理 payload、
签名密钥或调用方提交的排空回执。subject 由短事务密封实际已构造传输配置的摘要，绑定
数据库 realm、原签发事务、scope/control 与 attempt；签发事务在 owner 接受 begin 后、
实际 HTTP 前关闭。恢复副本不能使用来源数据库的旧能力。

命令不自动重提。丢回包或不确定提交最多查询一次状态；回执明确区分已提交、待提交与
未知。长排空的后续查询使用新的 request ID 和相同 control ID，旧命令回执保持不变。

## 当前验证边界

已记录修改前的实际竞态基线，通信、协调、ASGI 控制器、HTTPX 完成跟踪和 API 端口的
局部测试正在逐层执行。首批两项 Native 检查通过完整迁移往返、受限函数权限、未决请求
保留和配置写入围栏；路径正则和测试事务构造的首次失败记录继续保留。
局部测试不能替代完整 Native 并发、非空恢复、
独立安装与镜像、实际入口、停止／重启／交接和跨语言消费者资格。

复核发现已绑定实例重启后允许旧流量会使数据库保留的 ready 状态失真。因此移除了
新引入的旧流量启动选项；进程始终从关闭准入开始，旧 token、无 token 和重复请求分别
验证。原有环境残留的绕过配置直接拒绝启动。托管 Registry 的部署必须保持该控制器和
凭据约束，一个物理端点对应一个控制器实例；不能由多个未共享状态的进程共同冒充一个实例。

完整 Registry／Pool 控制面、健康远程协调、Stats／GPU 消费者及十模块／七门槛仍继续
推进。本决策不声明完整 Inference 已独立部署，不上线真实环境，不扩展 Go 实验。
