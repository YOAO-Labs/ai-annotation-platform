# ADR-0155：持久推理执行权与后端排空确认

状态：实施中，尚未完成独立部署与故障验收。

## 问题

原路由先读取 PostgreSQL 候选，再由 Redis 接受租约。排空和项目禁用若发生在两步之间，
暂停的旧候选仍可能获准。Redis 租约被取消、过期或丢失，也无法证明后端工作已经结束。

修改前在隔离 PostgreSQL、Redis 和真实 HTTP 后端上记录了四项实际行为：排空后旧候选
获准、项目禁用后旧候选获准、客户端超时后后端仍活动但 Redis 在途数为零，以及删除
本次测试独占 namespace 后已有租约不再计数。基线固定旧源文件指纹，不覆盖已有冻结夹具。
16 次、并发 4 的本地 CPU fixture 请求另保存原始耗时，不能据此声明生产容量。

## 决策

PostgreSQL 持有执行 scope、实际 HTTP attempt、管理占用、代次、物理实例连续性和最小命令
回执。两项固定 Native 能力提供封闭动作；提供方持有完整准入策略和命令协调。Redis 保留
非权威诊断用途，零计数不参与排空证明。

执行权使用独立短事务，不提交调用方的 Task、Prediction、Audit 或 Learning 事务。普通
调用按请求取得 scope，视频跟踪在整作业内固定实例并心跳。第一次实际发送前复核当前
成员、项目、配置与代次；已接受且活动的视频 scope 可在排空、项目禁用后继续，解绑、
配置变更和显式关闭另受围栏约束。

HTTPX 保留原传输、代理和连接配置。请求 hook 在实际发送前登记 attempt，响应流耗尽后
才报告完整响应；超时、取消、早关闭和传输错误保留未决状态。登记失败禁止发送；结算
回执丢失不重发推理，也不丢弃已经收到的成功结果。scope 关闭根据实际 attempt 账本
推导状态，不能提交“在途数为零”的断言。活动和未决工作不会因 TTL 消失。

卸载、重载在网络调用前取得持久管理占用，既有调用方在 I/O 前释放连接的边界保留。
管理占用在实际完整响应结算后解除；未知结果继续阻止恢复接流和新准入。Registry、Pool、
Member 的相关管理写入使用共同围栏，锁序沿用 Registry → Pool → Member。
尚未签发任何 attempt 的管理占用可安全关闭；与 begin 竞争时使用同一控制行锁，关闭后
不能再签发旧控制请求。普通 scope 不能使用 `control:` 操作冒充管理占用。

空账本不能把旧实例认定为空闲。受认证的实际后端 drain/bind 交换关闭旧准入，等待真实
工作归零，再绑定新 epoch、进程 incarnation 和签名密钥。后端启动时默认未绑定，拒绝
旧 epoch 与重复 attempt；已开始的任务、响应流和延迟 future 保持计数直到实际完成。
配置管理凭据的后端每次启动都关闭旧请求，不提供旧流量绕过开关。未配置凭据的普通
旧推理无法建立管理连续性，且拒绝忽略传入的托管准入 header。

## 通信与凭据

公开 owner wire 只携带封闭命令和不透明 capability/subject，不携带后端凭据、推理 payload、
签名密钥或调用方提交的排空回执。subject 由短事务密封实际已构造传输配置的摘要，绑定
数据库 realm、原签发事务、scope/control 与 attempt；签发事务在 owner 接受 begin 后、
实际 HTTP 前关闭。恢复副本不能使用来源数据库的旧能力。

命令不自动重提。丢回包或不确定提交最多查询一次状态；回执明确区分已提交、待提交与
未知。长排空的后续查询使用新的 request ID 和相同 control ID，旧命令回执保持不变。

## 当前验证边界

已记录修改前的实际竞态基线，通信、协调、ASGI 控制器、HTTPX 完成跟踪和 API 端口的
局部测试正在逐层执行。四项 Native 检查通过完整迁移往返、受限函数权限、未决请求
保留、配置写入围栏和只读运行计数。一项真实 HTTP 组合场景使用实际受限 LOGIN、
独立 owner 与后端控制器完成 drain/bind、准入、推理和结算；丢失准入回包后只查一次
状态，调用方业务事务仍可回滚。路径正则、协议字段和测试构造的失败记录继续保留。
实际未提交 Prediction 的 Registry／Pool 外键锁不会再与短准入事务自我争用，engine 和
connection 绑定两条路径均保留外层回滚。实际控制 HTTP 超时后，同一 control ID 在
后台工作结束前继续排空，结束后才能绑定新代次，旧 token 和 capability 随即失效。
局部测试不能替代完整 Native 并发、
独立安装与镜像、实际入口、停止／重启／交接和跨语言消费者资格。

已知且明确发生在准入前的短事务锁竞争最多重试五次，每次先退出事务再等待。
提交结果未知时不重试；实际推理 HTTP 不会自动重发。只读运行观测使用独立封闭查询，
不写命令回执。回执按数据库 realm 隔离，恢复副本不能返回来源实例的旧准入 header；
真实非空恢复已验证原权限、记录及来源数据库不变，副本处于隔离状态且旧回执不可用；
恢复后安全重新绑定仍待实施。三种模式的运行状态端点通过实际数据库验证，清空 Redis
或电路提示故障不会清除未决计数，owner 不可用时保持未知；它不能授权卸载。

复核发现已绑定实例重启后允许旧流量会使数据库保留的 ready 状态失真。因此移除了
新引入的旧流量启动选项；进程始终从关闭准入开始，旧 token、无 token 和重复请求分别
验证。原有环境残留的绕过配置直接拒绝启动。托管 Registry 的部署必须保持该控制器和
凭据约束，一个物理端点对应一个控制器实例；不能由多个未共享状态的进程共同冒充一个实例。

完整 Registry／Pool 控制面、健康远程协调、Stats／GPU 消费者及十模块／七门槛仍继续
推进。本决策不声明完整 Inference 已独立部署，不上线真实环境，不扩展 Go 实验。

GPU 自动驱逐通过普通执行 scope 的 `gpu:unload` 操作组合两项权威：路由控制器只接受
`POST /unload` 的该操作，要求严格成对的 GPU 代次与凭据 header 并排除其他活动请求；
实际 GPU 生命周期入口继续验证签名、资源／进程身份、代次、操作 owner 与排空状态。
这不取得要求手动停流服务池的管理占用，普通推理 scope 不能借此替代 GPU 授权。

HTTPX 最后一个请求 hook 在准入失败时才报告 `not_sent`，保留原公开异常；hook 通过后
记录请求可能已发送，不能再降级成未发送，也不能重用已使用或结算的 grant。重定向
后续准入失败不能抹去先前发送事实。未发送的 resident 租约按精确 owner／代次释放，
冷加载按同一预留租约与 owner 撤回；已发送后超时、取消或缺少结算继续保守处理。
有字节上限的批量／交互预测在响应体完整读取后才报告 GPU 响应，响应头、超限或中断
都不能作为请求完成证明；读取完成后 JSON 解析失败仍是已完成的传输响应。
GPU 驱逐、取消排空、成员激活及 rollout 控制显式传递当前会话来源，不借用主环境连接。
卸载回包丢失后仍获取新鲜 challenge 健康证据，由既有精确身份／代次／状态校验决定
是否完成卸载；健康不可用或证据不匹配时保持 Unknown 与预算，不能从通信失败推断成功。

明确剩余边界：驱逐开始后数据库代次已经前进，不能仅凭未发送在本地回退代次或清除
预算。持续路由拒绝直到驱逐 deadline 后，完整的持久恢复／repair 仍需实施；现有路径
保留预算和围栏，不能把状态保守阻塞称作完成恢复。视频 scope 和 capability
目前只在 worker 内存中，崩溃交接还需 Jobs 持久执行代次、scope 关联和窗口结果检查点。
已有活动或未决 scope 不会因 worker 心跳过期而释放，不能把这一保守阻塞称作可恢复交接。

独立安装检查发现共享协议的本地 wheel 缓存未跟踪源码，新文件在 editable 环境可导入，
旧缓存构建却缺少路由模块。共享协议现与其他独立包一致，将源码和协议文件纳入构建
缓存键；安装资格必须核对文件指纹，不能只看依赖同步退出码。

非 editable 安装通过351项检查，72个包文件与源码指纹一致，不依赖 API／ORM／Celery。
实际独立入口经过停止、重启、回执重放和 API 显式选择后不回退验证。16次、并发4的
准入／关闭命令最初耗尽 NOWAIT 重试；普通服务池准入现通过私有辅助函数排队取得
`NO KEY UPDATE` 锁，每次等待上限250ms，仍保持 Registry → Pool → Member 锁序，
其他管理围栏不变。独立进程、Native、未提交 Prediction 与等待上限共9项检查通过；
超时后原事务仍可重试，调用方的 `lock_timeout` 保持原值。该16次本地控制命令样本的
p50约223ms、p95约252ms，不能与推理请求基线作性能对比，也不证明模型／GPU容量。

独立的视频链路检查使用真实 FFmpeg 视频、受限 Media 进程、版本化 S3 原片、实际
health/setup、认证 drain/bind 与 HTTP `/predict`。两个窗口共用一个执行 scope，第一
个窗口等待期间验证持久心跳续期，第二个请求运行时提交取消；返回后作业停止，没有
第三次请求，两个实际响应完成后 scope 关闭为 cancelled。后端使用确定性的 CPU 夹具，
这验证调用、输入、心跳和取消边界，不验证模型精度、GPU容量或崩溃交接。

GPU 路由组合已通过实际 TCP、受限 Native 路由账号和 YOLO 生命周期代码的联合检查：
错误 GPU 签名不能卸载，有效签名完成驱逐，服务池成员保持 active，没有伪造服务管理
占用。模型与内存回收是无 GPU 的夹具，GPU 凭据由测试签发；该检查不证明真实硬件、
GPU 仲裁 owner 的完整独立部署或生产容量。实际 Redis 的精确预留／代次 CAS 另行验证。
