# 0099 — SFTP 持续引用要求部署核验的只读 jail

- **Status:** Accepted
- **Date:** 2026-10-23
- **Deciders:** 用户授权推进完整 E03；实现与只读复核
- **Supersedes:** —

## 背景

普通 SFTP 的路径 open 无法原子保证不跟随链接，协议也不能证明服务端 chroot 或只读账号。把连接 base_path 当安全根、仅做前后 lstat 或允许 UI 自报隔离都会造成错误保证。旧连接器复制导入的规范化路径和系统 known_hosts 不能直接充当持续引用合同。

## 决策

复用 Source、ScanEntry、Registration、Reference、快照、预览与 Task 门禁，新增独立 SftpAccess。部署者维护 `STORAGE_SFTP_ROOTS`：句柄映射精确 host/port/username/完整主机公钥。连接 base_path 必须为 `/`，整个账号可读命名空间都是位置授权范围，Source 子目录仅作筛选。声明前须实际核验服务器只读 jail、无 shell/转发；协议探测不能授予此资格。

客户端使用独立 HostKeys 和 RejectPolicy，在认证前核验公钥；不加载系统 known_hosts 或自动接受未知公钥。白名单解析后固定 socket 地址，凭据在线程中解密，设置连接、认证和通道超时。保留旧复制导入适配器与调用者。

目录有界逐项枚举，复用 BFS 检查点、租约、取消恢复和末次清单核对；不虚构跨连接目录游标。路径链 lstat、句柄 stat、读取前后观测与完整 SHA 负责内容一致性，不宣称 SFTP inode、不可变版本、条件读取或原子 nofollow。真正的根边界由服务器 jail 提供。

资格摘要成为扫描及内容绑定锚点，新 API 节点也须匹配原扫描锚点。变更或撤回资格先禁用位置并提交修订、停止旧 worker 发布，再协调 API/worker 部署；单个环境变量变更不是集群撤权。新服务器或新资格另建位置，旧引用不自动重绑。

## 后果与边界

- API 与各扫描/读取 worker 必须同步部署资格，并分别通过节点探测；未获资格时失败关闭。
- 原地登记不写平台原图，预览独立计量；每次原图使用仍有完整校验 I/O。托管复制可复用同一严格快照，但之后不依赖外部来源。
- 整体故障停止尝试，保留候选与业务数据；文件错误独立记录。源离线时预览不能替代原图继续标注。
- 服务器只读 jail 是部署信任前提，无法由客户端校验弥补。目录每次清单最多5000项，使用逻辑路径身份而非物理 inode。
- 回退禁用新资格，保留旧引用和明确不可用状态。周期同步、Agent 与训练冻结属于其他 Epic。
