# 0104 — 来源内移动通过明确接纳的新定位保留原业务身份

- **Status:** Accepted
- **Date:** 2026-10-23
- **Deciders:** 用户要求完整完成 E04 并实际浏览器验收
- **Supersedes:** —

## Context

同内容移动会表现为旧路径未见与新路径新增。自动按摘要合并会把复制件误判为移动；修改原 Reference 会丢失凭据。路径内修订号无法表达不同路径的先后顺序。

## Decision

完整预检只提供同 SHA 新增候选，用户明确配对旧未见项与目标。固定 generation、旧头前驱、候选 SHA，严格读取并沿用当前权限、原 Key proof、策略与资格屏障。事务内追加同业务 Item/Asset 的跨路径修订，退役旧头、建立新头并消费目标登记条目；不改变外部文件、原始绑定、任务或标注。

路径内编号继续独立；数据库单调 acceptance_order 决定同来源/Item/Asset 最新接纳定位。原引用起点仍校验，读取只用最新明确接纳定位，失败不回退。数据库保护跨路径前驱的永久身份、内容和所有权一致性。两端差异保持冻结，共享接纳结果。

## Consequences

同来源内可继续原任务，目标不重复创建业务样本。多摘要相同候选由人选择；未见不证明删除。旧路径回归成为新增，不能抢回已移动样本。仅清理退役路径的准确预览键，托管原图和业务历史保持。

0204回填既有账本的排序字段，不虚构接纳时间；含跨路径前驱时拒绝降级。应用回退需保留新版读取，不能删账本或把旧路径伪装成最新定位。跨来源、根和资格迁移不在本合同内。
