# 0086 — 任务名称共享并与格式、媒体及冻结身份分离

- **Status**: Accepted
- **Date**: 2026-10-16
- **Deciders**: Project maintainers
- **Supersedes**: None

## Context

训练、推理能力、流水线和导出使用不同名称表达同一视觉操作，且历史 `task_type` 同时指视觉任务、提示模式或媒体池。混合标注项目需要针对一个任务抽取数据；视频派生图片还需保留原项目参数。直接改写已有字典会破坏参数、数据和模型回执的摘要。

## Decision

由无第三方依赖、兼容 Python 3.10 的 `aap-task-contract` 提供规范任务、历史别名、冲突检测和显式历史序列化。训练与协议分别依赖该包；API registry 继续拥有能力说明并生成前端词表。任务、格式、输出媒体分别写 `task`、`format`、`media_type`；提示保留 `context.type`，媒体池使用 `modality`。

新参数定义和数据契约产生新身份。历史定义按完整 ID/摘要解析，历史字节、检查点和哈希不回写。公开视图派生规范任务，外部旧 backend 的适配只发生在传输层。混合项目的数据版本固定单一工具/类别范围，其他标注排除计数，不能成为隐式负样本。

视频导出共用原始来源及绝对帧网格元数据；未来图片物化应冻结采样/协作参数、逐帧来源和标注版本，并按视频内容/场景分组。当前训练物化仍只接受图片项目。

## Consequences

增加一个小型共享包和构建输入，以避免训练包引入 API/Pydantic 依赖。旧命名保留于兼容读写路径和不可变证据；新生产者只写规范名称。跨镜像续训仍须通过原生检查点恢复验证后配置精确允许项，不能因名称相同放宽身份检查。
