# 0080 — 模型谱系按需读取，候选决策独立追加

- **Status**: Accepted
- **Date**: 2026-10-15
- **Deciders**: Project maintainers
- **Supersedes**: None

## Context

训练数据、实验、执行尝试、候选模型、部署和项目发布已有各自的权威身份。管理员需要沿来源检查历史证据、记录候选处置，并在归档后仍找到当前发布。完整递归图会增加查询开销，也容易把配置克隆、断点恢复和基础权重名称混为同一操作。独立外键只能证明目标存在，不能保证项目与父子归属相同。

## Decision

使用现有 PostgreSQL 表的显式字段投影提供单跳读取。根节点受项目管理权限约束；直接来源逐条验证父子关系，缺失、无效、跨项目或自环返回 gap。后续关系按需选择，每页最多 20 条，用绑定项目、节点和关系的时间／ID 游标读取；索引覆盖过滤与排序列。页面标记重复访问的路径，不预加载祖先，也不引入图存储或图形依赖。

投影不读取完整配置、执行凭据、运行时、部署收据或评估 spec，也不调用执行器检查、训练状态同步或存储签名。JSON 身份字段只接受字符串；部署节点明确表示最近一次检查，历史发布展示冻结身份。配置克隆、checkpoint 恢复、配方修订使用各自明确的来源边。

`ModelDecision` 保存追加序号、处置、说明、作者显示名和请求幂等摘要。写入与人工发布共用项目 advisory 锁，重新核对管理权限并锁定模型行；相同 UUID 与内容重放已有记录，变更内容返回冲突。API 不提供修改或删除决策记录的操作。最新序号控制候选的列表处置，既有说明保留。归档候选仍可直接打开，当前发布动态保留在默认列表；决策不更新发布代次、项目选择、权重或类别身份。

预测计数只读取当前保留、匹配完整候选 SHA、类别与绑定摘要的受控记录，并同时连接预测 ID 和分区时间。每次最多读取 1,001 条并报告上限；旧记录、删除历史和不可归属记录不在范围内。候选身份不足时不返回伪造的零值。此计数不是累计使用量、标注采纳率或模型质量指标。

项目和训练实验删除在对象存储操作之前检查引用。实验既检查模型的 run 引用，也检查其任一尝试被模型引用的情况，保护不一致的旧来源。新决策没有可变评估引用，不增加评估删除／purge 竞态。

## Consequences

### 正向

- 历史身份可以逐层核对，深历史不会导致递归加载或执行器副作用。
- 候选处置与 serving 状态保持独立，并发说明不会覆盖已有记录。
- 精确执行、数据版本及评估详情的链接可刷新和返回，候选列表保留归档与页码上下文。
- 不一致的历史来源显式缺失，删除保护先于存储删除。

### 负向

- 管理员需要逐层浏览，当前不提供整图导出或全祖先查询。
- 每个反向关系需要维护对应索引；可归属预测计数有读取上限和明确覆盖范围。
- 决策历史需要保留，不能通过归档释放来源模型或训练数据存储。

## Alternatives Considered

- 递归查询或独立图数据库：没有足够的查询需求支持第二套关系权威与运维成本。
- 只保存模型当前备注：会覆盖决策历史，无法正确区分并发说明和重试。
- 归档时清除发布：把列表整理误当成 serving 变更，破坏人工发布合同。
