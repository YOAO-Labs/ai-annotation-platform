# 0102 — 内容修订追加业务身份并推进来源路径头

- **Status:** Accepted
- **Date:** 2026-10-23
- **Deciders:** 用户授权继续推进 E04；实现与只读复核
- **Supersedes:** —

## Context

同路径图片被覆盖后，旧任务仍必须绑定旧内容和标注。直接改 SourceItem 会丢失历史，复用按摘要去重的托管 Item 则可能把新内容连到别人的任务。仅比较 SHA 还不能识别 A→B→A 的前驱变化。

## Decision

SourceRevision 保存不可变的接纳身份、观测、SHA、顺序号、前驱、确认预检和操作者；SourceItem 只保存当前路径头。Change 固定前驱 revision ID。单项确认要求已完成的完整预检及 content_changed，携带 generation、前驱 ID 和候选 SHA。独立入口不扩大 additions_only 或普通重试的范围；开始正式登记后需重扫才能接纳尚未处理的变化。

沿用严格读取与 Location→Source→Dataset 锁，在 I/O 后和提交前复核原账号、Key proof、来源/位置/策略与前驱。新 Item/Asset、空白 Task、修订、路径头和审计原子提交。托管复制绕过业务 SHA 去重；引用保留各自 ScanEntry。重复确认返回原结果，并发相同确认重新读取已提交结果；过期前驱不前进。

旧业务对象不改写、不复制标注。历史修订继续参与目录媒体所有权和来源影响统计；预览缓存只关联当前 Asset，不代替旧任务原图。数据库触发器保护历史事实和头与修订的一致性。业务删除清空活动 FK，保留原 Item/Asset UUID；迁移回填不虚构接纳人或时间。

## Consequences

新旧样本同时可见，后续关联项目沿用追加语义。可变目录中旧字节被覆盖后仍不可读；本方案不备份外部原图。单项确认同步读取受限图片并复用现有传输预算，逐项操作不自动放开周期门禁。

0203迁移需要回填现有路径头并调整引用唯一性；有修订账本时拒绝破坏性降级。应用回退保留账本和旧读取保护，仅关闭新入口。移动、未见裁决、同摘要观测变化和标注迁移另行推进。
