# 0184 — 独立服务、原生能力与客户端按实际边界取证

- **Status:** Accepted（回填既有约定）
- **Date:** 2026-11-21
- **Deciders:** Core team；API、各独立服务、Python SDK 维护者负责各自边界
- **Supersedes:** —

## Context

同一操作可以跨 API、独立服务、调用方事务、存储提供方和 worker。公开协议兼容、当前权限、持久提交、物理工作结算是四个不同的判断。一次 HTTP 200、一个 ORM 对象、一次成功的 JSON 往返或一个进程退出，不能同时证明这四件事。这个记录保存从源码说明中回收的决策，尤其保存可执行夹具中不由断言本身说明的前提和反例；不宣布新的运行拓扑、部署资格或生产容量。领域政策仍由各自已有的 ADR 持有。

## Decision

[按源码路径查阅局部决策与理由](../evidence/0184-decisions.tsv)。编号对应原始实现位置，相关 ADR 仍拥有其领域合同。

### 所有者、事务与验收证据

- **Core 与独立服务：** 按[同库事务数据能力](../0092-transactional-module-data-capabilities.md)划分边界。Native 端口借用原连接时，不接管提交、回滚、锁或 ORM 状态；按 owner 约定使用保存点，保留 flush 顺序和 dirty/expired 行语义。回复的类型、操作、目标、scope/echo 以及承诺的收据必须在事务可提交之前验证。单独的 HTTP 进程则自持提交：Body/命令已经完成、确认阶段才失联时，状态是未知，不等于回滚；用相同操作 ID 和摘要查回执，不重投物理请求或换本地实现。清理失败不掩盖初始错误，连接关闭失败不把已确认提交报成失败。Workspace 所有权转移在所执行的同一事务检查就绪；独立 asyncpg 分支回滚自有事务，借用连接的分支按协议 rollback 位保留调用方语义（[所有权转移](../0134-workspace-project-owner-transfer.md)）。
- **验证者：** 权限验收须用实际受限 `LOGIN` 验证既允许的函数又拒绝私表、无关函数及 owner 凭据；`SET ROLE`、超级用户、只核 schema 或误撤无关消费者权限都不充分。原生函数仅有 `EXECUTE` 的测试按目录 OID 检查，不假定调用者可解析私有 schema。另一个进程或连接须看到已提交的准入、锁、变更或拒绝；SAVEPOINT 内的 fake 可以测语义，不能证明持久收据或跨连接可见性。进程验收绑定已安装 wheel/SQL 和镜像摘要、实际启动进程、最小角色及精确输入；本地源文件、挂载替换、假 provider、已构建镜像分别只有自己的证据范围。Docker 重启可能重分配短暂端口，探针须重新解析 origin。破坏性验收在实际操作前复验 verifier 所有的资源 ID 与 acceptance label，恢复测试不用全局清理掩盖泄漏。
- **历史代码和可执行兼容基线：** 捕获前核对实际旧实现及依赖，冻结响应字节、有关头、状态与 SQL 相位；回放不重新捕获。`test_workspace_project_access_read_phases.py:37` 从冻结 commit 取源码验 hash，仅在临时可执行副本中转换到字节相同的 policy import；这不授权修改原件。跨语言 peer 传递 receipt JSON 文本，不经过 JavaScript `Number`，以保留 PostgreSQL 精确 `int64` 审计 ID。旧迁移描述符的命名按当时 wire/SQL spelling 保留，当前命名只在确有必要的重放适配中替换。只跑一条目标迁移或用 `LIKE` 克隆表，不能宣称当前 ORM 已接好或按原名的索引、外键动作也被验证。`bo0453` 从 Assets Source wheel 读取的 `0453_import_original_verification.sql` 是历史迁移工件，仍冻结；`-- aap-statement-break` 是分句输入。
- **Jobs、Audit 与包边界：** Job 先持久交接再联系 broker；timeout 可能已经投递，补偿读真实 Job 状态，不能用缓存的 `pending` 覆盖 worker 已领取或终态。Broker 确认、业务收据和连接关闭分开证明；无 Celery ID 的信号不可查库，通知计数不能证明这一点。`test_jobs_lifecycle_refresh_loader.py:52` 使用 SQLAlchemy 2.0.49 的实际 refresh 构形，核定替换走 Jobs 受限读取且不变更 projection、参数和 dirty 列；有锁、附加 criteria 或非 PostgreSQL 不重写。该依赖的升级债见 [#162](https://github.com/YOAO-Labs/ai-annotation-platform/issues/162)。普通域的 import 图同时检查 `from` 路径和候选子模块，第一方走规范路径；兼容门面只由专门契约验证。审计 archive 流只负责自己的 portal，独立 cursor 仍须可读；同长度、同行数的输入仍验完整 SHA，合法 gzip 包装不豁免未请求页里的坏内容。分区首次创建数量随已安装对象变化，第二次须为零；`relkind` 的 `p` 表示分区表，asyncpg 可能以 `bytes` 返回。
- **本地对照夹具还需保留能排除替代解释的条件。** WebSocket relay 的 fake 不触碰 Redis；运行时延迟构造连接池，但一个只 `yield` 的 fixture 不能证明导入没有副作用。测试归档 teardown 仅清理自己持有的句柄与可证明属于本次插入的行；留下的不可变审计与 actor 由专属测试库销毁。由 `LIKE` 克隆时需显式恢复验证所需的 FK 动作，不能为模拟历史损坏弱化 production guard。

### Identity、Workspace、Notifications 与 Labeling

- **权限错误须定位到正确相位。** [平台身份与项目职责](../0075-platform-identity-vs-project-authority.md)分离，平台 `employee` 或历史全局 `annotator`/`reviewer` 不证明 membership。项目赋值也不自动增加 membership；项目管理员能执行某些账号运维操作，不代表可以改平台角色。[平台角色 owner](../0125-independent-identity-platform-role-commands.md)的 GET preview/PATCH 公共入口先要求 `super_admin`。一个已认证的 `project_admin` 无论目标是否在其项目，均应首先收到 **403**；通过权限门后，PATCH 无效角色是 400，通过角色校验后的无效 UUID、缺失或停用目标是 404。旧 `test_users_role_matrix.py:136` 接受 `(403, 404)` 只证明未成功，不能证明目标隐藏或鉴权相位；`test_users_visibility_scope.py:310`、`:386` 分别用未指派/外项目目标钉住严格的 403，不能把旧夹具的宽断言解释成兼容政策。最后超管按全库计数，排除已保留自停用者；夹具暂时在自身保存点隔离外来超管，不删其他用例数据，也不等于实际部署单租户。
- **当前事实与历史收据独立。** Identity 重新验证当前角色、凭据 generation、原 API Key verifier/scopes 与锁后过期时间；事务级 `now()` 不能代替跨锁等待的时钟。角色 no-op 可有回执但不写 Audit、不拿项目所有权锁；实际变更不级联成员、工作与凭据。离职变更先检查 actor/target scope，再查 CAS，私有成功须含正的 `int64` `audit_id`，不因旧公共字段可空而放宽。头像上传用上传前捕获的期望引用，显式无头像不等于缺省；只有清除/预设命令可用当下引用作缺省。非空 Identity owner URL 选择 HTTP，失败不回退直读私表。密码重置、邀请和通知分别见[密码重置](../0124-independent-identity-admin-password-reset.md)、[邀请与 MailV2](../0122-independent-identity-invitations-and-mail-v2.md)、[独立撤权](../0115-identity-admission-and-durable-revocation.md)；SMTP 处于 DATA、已接受但没收到 `250` 时，不能假定未发，接管沿用 outbox 行和 `Message-ID`，不在持有用户锁时发送。
- **Workspace 保留鉴权、投影与写入相位。** [项目 access](../0141-workspace-project-access-query.md)初次可见性与端点锁后授权不可并为一次缓存判断；相容的 `KEY SHARE` 后若整行 temporal 解码失败，应先于独占升级冲突。目录先解码全部相关列，再调用 Identity、过滤 inactive 或按 UUID 去重；PostgreSQL 的无穷日期/时间与有限但 Python 年份越界不是同一值。列表和总数使用同一可见范围，成员仅承诺 `assigned_at` 的既有顺序；并发同版本一方成功，另一方 busy 或 stale，删除再添加不复用 membership ID。[配置写入](../0136-workspace-configuration-command-owner.md)在 `begin` 读取资源/权限后才判不透明配置和 selector；视频批次若任意成员缺来源，优先于另一个成员未就绪。项目创建的阈值 `null` 走数据库缺省值，不普遍转换 PATCH 的 `null`。Guide Asset 字节归存储，发布/CAS 归 Workspace，owner 故障不回退 ORM（[Guide Assets](../0144-workspace-guide-assets-owner.md)）。
- **偏好数据允许修复而不扩大坏状态。** 快捷键按 command entry 合并，只验证触及的非空覆盖与所属域；`null` 重置可用于未知 ID，读取保留损坏或较新子树。浏览器回传的不透明数字可按 binary64 等价判定未变化，布尔值不能当数字；最终恢复原存储值而不是写入舍入值。命名布局预设是独立的原子 CAS map，整图替换所以省略条目是删除；省略整个字段才不改。`"0"` 是首次写入前虚拟版本；仅无已存 revision 时兼容旧写入方。既有超限或重名允许删减修复，但不扩大；只改预设不能顺便把外层布局引擎降级。`test_me_preferences.py` 的原文 JSON／`1e309` 用例须在 HTTP 层拒绝且不写，不能先由客户端正规化为另一个输入。
- **通知接受不等于订阅者已收到。** [通知所有权](../0121-identity-self-deactivation-and-notification-delivery.md)内保留 member 后 reviewer 的读取顺序及每次 ORM autoflush。读删与偏好同步只在事务提交且有变更后发布，旧显式即时通道仍保留旧编码器。Redis `PUBLISH(0)` 已接受；取消或 finish 不可用发生在发布后时依靠租约、稳定 notification ID 和持久 inbox，不凭错误重复声称未送达。`test_notifications_publisher_image_live.py:644` 的停止点在租约提交、握手字节已到达但还不能 PUBLISH，只证明发送前接管，不能外推为发送后去重的证据。Node 通过只传字节的网络桥验证公开线形，不导入 owner SDK。
- **Labeling：** 流转由当前项目职责、有效指派及锁后事实裁决；显式 Task 指派优先于批次继承。标注轮次提交冻结此前贡献者和提交人，后续 accumulator 增长不改本轮证据；历史 `NULL` 表示未知，不补造贡献者，不能借此批准自审（[审核与任务锁](0005-task-lock-and-review-matrix.md)）。交接只改目标项目与仍可编辑的工作；Batch reset 清掉已离组人员从旧默认物化且非 override 的任务指派，使其恢复继承，同时保留真实手工覆盖，不清除批次默认指派。`test_batch_delete_reset.py:168` 中恒真的默认值断言不能证明最后一点，已在 [#178](https://github.com/YOAO-Labs/ai-annotation-platform/issues/178)跟踪。导入 overwrite 只替换 `_imported` 的行；多摄像头先建主 3D `SceneTrack`，不信 payload 顺序。派发场景偏好只重排已有资格，首选被领取要回退；跨帧身份是 `track_id`，3D 插值先到世界空间再投到目标帧。[原生视频 writer](../0159-independent-labeling-video-writer.md)消费已封存的连续窗，缺口后的成果不能作为取消前缀；candidate identity 规范化不重排前后向分支，回执哈希取 canonical 输入而非会合并 `-0.0` 的 JSONB 回读。

### Assets、原生媒体、存储与退役

- **身份、地址、权限各有来源。** [Assets Catalog](../0097-independent-assets-catalog.md)的原件用业务入口鉴权，缩略图才是签名存储 URL；同 SHA 的独立副本不自动授予可见性。直接 Item 与 `primary_lidar` 的来源冲突不任选其一。存储地址用记录下来的所有者、版本、精确 key 与 allocation revision，发起 I/O 的凭据再取当前 revision；切换 purpose bucket 只影响新分配。`"null"` 是 S3 版本字符串，不等于省略；Copy 请求中的 VersionId 不能当返回的 `CopySourceVersionId`，未观测到的 HEAD 不能说成 current。呈示可规范化 ETag，回执保存提供方原样。签名时绑定最终 origin 的 `Host`，不可事后改写；签名本身不证实读通。空间 `FramePose` 是 ego-to-global，四元数维持 nuScenes 的 `[w,x,y,z]`，平移向量 `[x,y,z]`；空间页 scope/snapshot/cursor 漂移拒绝整批，不返回第一页前缀（[空间 owner](../0102-assets-spatial-state.md)）。
- **Source 入站验证由 Source 结算。** 原生写允许复用调用方冻结的 publication 身份，不重读其未提交 intent；独立持久 receipt/fence 在新事务。物理读取前的私有 nonce 仅用于消解尚未启动的准入；物理读已排空但结算锁争用时查 `/v1/import/verify-status`，不再发读取。提交给 provider 的 completion 意图最多一次，即使回包丢了也保留既有尝试。固定版本读取、条件写、ETag、HEAD 或成功枚举都不是等价的 SHA 证据；文件暂存须等源上下文退出时完整检查原文件和父目录后才能交付。ZIP 中央目录在 `ZipInfo` 分配前按实际 entry 数限制，不能以报表里的 count 代替；偏移匹配 CPython `_RealGetContents` 的 ZIP64 规范化，升级解释器须保留有界读取和 ZIP64/前缀布局 oracle。线格式 manifest 的 16 MiB 与 50,000 文件预算彼此独立；文件名和对象键的 UTF-8 字节数也不等于字符数。相关 owner 见[持久导入](../0100-durable-connector-import.md)、[同步 ZIP 和扫描](../0101-assets-synchronous-zip-and-scan.md)、[目录引用核验](0094-verified-request-content-snapshots.md)。
- **图像／视频零件有各自的持久责任。** [图像 owner](../0106-independent-image-media-owner.md)的 Native 金字塔用 generation 和保存的输出引用分配、签名、退役；不走旧 ready manifest 或普通 thumbnail 指针。精确、已排空的 PUT receipt 先持久写再精确回读；心跳随后丢失仍以该 attempt ID 结算 `written`，不能抛成 abandoned；若请求或关闭未结算就没有 `not_written` 证明。旧 `ready` 缺 saved-output 所有权时，GET 是 `200`/`missing`/`retryable=true`，不是源漂移；重试不移动 active pointer。旧扫描不能删 Native 成员。视频 workflow version 仅记录溯源，不能替代 source identity；tracker claim scope 归 canonical ledger，Assets receipt 不复制。源签名 GET 不携带控制面凭据或 caller cookie；解码只取保留的字节，不打开外部协议；错误不回显签名 URL。分段只用实测 packet/PTS 与保留的 input（[Media owner](../0105-independent-video-media-owner.md)、[保留输入与帧计划](../0109-retained-video-inputs-and-frame-plans.md)、[Tracker 输入](../0110-retained-tracker-video-inputs.md)）。
- **取消与退役不能替代物理结算。** 客户端 timeout、失租、关闭信号、响应头到达、逻辑取消/退役均不能证明底层流、线程或子进程已经退出。资源许可保留至实际结束及收据提交；未知结果不丢失 durable 责任。Storage Agent 先原样重放已完成结果而不是领新工作；ACK 证明已接纳结果却不能证明未关闭的 I/O 完结，收据先持久再删除本地暂存；验证 stage 和待发文件可共存，磁盘预算须计两份。普通存储读对 scope/owner 漂移整体失败；受限 reference mutation 仍保留调用方原事务，不能用通用“读时先释放所有锁”破坏它。原件和缩略图 I/O 的竞态夹具分别卡在精确 GET 阶段而非所有网络读，才可证明锁窗口。
- **视频夹具套件的封存顺序：** 先在父、子运行均开放时核实每个子运行已受理的视频请求，持有各自的请求准入锁直到提交；再独占套件行，重查子运行集合及未发布输出，最后封存。若先独占父行，发布者不能取得必需的共享锁；若先封存，合法的发布证据也变得不可见。在截止期间新加入子运行或仍缺发布证据时，整次截止不提交，不把工作进程退出视为发布。
- **删除权不来自遍历游标或同内容。** [Mask 字节](../0111-independent-mask-content.md)校验 canonical 未压缩 RLE 字节，gzip 只作传输包装，digest/size 和压缩输入/展开预算分别检验；PUT/GET 进入 S3 前重新验证普通值，不因对象已是 Pydantic model 就豁免。扫到旧名、外来名只推进进度；marker 条件写丢回包保留 fence，不重发 Delete，只有精确已退役 owner/prefix/version 授权。S3 multipart 的 `Prefix` 支持不一致，可有界增大扫描范围但不能扩大 abort 权；abort 后重列第一页，版本删除走支持对应 IAM 条件的逐版本命令。精确 LIST 身份才是 GC fixture 对账依据，不用可能只有秒精度的 HEAD 瞬时值。Labeling GC 的 `not_found` 表示 journal claim 不可见，不表示字节不存在；库存失败不前移持久 cursor，仍可协调既有删除，finish 丢确认继续用同 operation ID，而非发第二次物理删除（[Mask GC fences](../0112-durable-mask-gc-fences.md)、[Assets cleanup](../0096-assets-source-deletion-and-cleanup.md)）。
- **媒体夹具须让错误实现得出不同结果。** PCD 压缩体按 field-major 排列但不重排点；记录 1 的 NaN 仍占 label 槽 1（`<3I` 是 `(0,1,2)`）；故意把 `FIELDS` 改成 `intensity z x y` 以防误按列位置定 XYZ。nuScenes 修改第四个 little-endian float 使原件证明变而 XYZ PCD 不变。LZF 的 >5 MiB 展开、<1 MiB traced peak 是 Python 分配证据，不是 RSS。Frame sampling 就近取整且半数取偶，Node peer 不用 JavaScript `Math.round` 替代。MOT 的 `outside` 留空、不重编号；COCO 要显式查所有引用并实际解 mask，`createIndex()` 无异常不够，重复 `json.dumps` 相等只证明同运行时稳定。WebCodecs fixture 的 B 帧用于证明 packet 解码序不同于呈现序；损坏的 sample offset 不改时间表，错误 codec 的夹具仍用有效 `avcC`。例见 `apps/api/tests/test_lidar_pcd_contract.py:88`、`test_export_video.py:693`、`test_seed_webcodecs.py:236`。

### Inference 与 Training

- **预标注的两类授权和数据流不能合并。** [分阶段预标注](0043-staged-preannotation-pipeline.md)的 root 由无 `parent_stage` 决定，不假定 ID 为 0；父 stage 先于子 stage 且须产出几何。Workbench 看当前 actor 编辑资格，bulk 看有效的 pending/批次准入；被冻结的 scope 可作执行上下文，不能绕过当前源、成员、Task 和终态锁后复核。下游输入只可 `crop` / `geometry`，拒绝 `full_image`，否则旧启发式会静默改投。子 crop ID 是上游原始位置，不在过滤后重编号；三级中的 `"0"` 可能指中间候选，故非根父级拒 `drop_box`。类别过滤不计 `skipped_geometry`，不可裁或过小才计；`intermediate` 供下游不持久，属性冲突按最终（可能带 `label_` 前缀）的 root key 判定。二次推理无几何在 I/O 前 400，合法但过小走 422；没有逐键证据的现存属性视为人工。夹具里相同父级/padding 只上传一次，不等同只编码一次，JPEG SOI 不等同已成功解码。单 mask 的 256×256 feedback 是不透明 base64，魔数 `m1`；只剥前导 singleton 轴，多候选省略，浮点往返精确基线是经 `float16` 量化后的值。
- **发送、健康与路由由不同 owner 保证。** transport 使用 API 已捕获的地址和凭据，禁用环境代理/重定向，旧 `type` 兼容仅在 transport 转换；发送 admission 绑定最终 method/path，后续重定向失败不表示原请求未发。先将上游原始状态和发送结果交给 grant，再映射公开错误；拒绝未知执行证明、不泄漏 provider 细节。ASGI 最后一段非空 body 可延迟到工作实际结算，不能因 `Content-Length` 让客户端提前观察完成。健康的 `/health`+`/setup` 是同一观测窗口；旧重叠探针不能靠较晚完成覆盖新快照。要保留原始 observation 的空白、末尾换行及 `NaN`/`Infinity`，避免改变 decoder 的失败相位。池可互换性来自规范化模型身份/兼容性而非 runtime 展示项，部分声明不隐式升级 managed capability。`off/observe` 保留旧成员；`enforce` 用精确目标 lease，目标饱和不借用兄弟。进程内 per-backend 信号量默认 4，按 backend ID 在活 event loop 缓存，配置调整按现行运行手册重启；不可用它代替跨进程上限。详见[路由权威](../0155-durable-inference-routing-authority.md)、[健康观测 owner](../0152-credential-owning-health-observations.md)、[GPU 资源准入](0049-cross-backend-gpu-memory-arbitration.md)。
- **恢复不再获权或重做已完成工作。** 退役与准入用相同排斥栅栏，失真的计数、到期 lease、部分签发的 bearer 都不能证明静默。Topology hold 在 Native 同一 XID 复核并持久化；远端不确定不丢 hold，按原 control ID 读状态。恢复 finish 重新查每个 controller；prepared restore 继续作写屏障，成功 receipt 重放不再开启执行。视频成功回执也先校验 claim；仅有被退役 acquisition 的历史绑定意图不授予新权。[视频执行绑定](../0157-video-execution-claims-and-route-binding.md)与[窗口账本](../0158-video-window-journals-and-replay.md)分别管 scope 与续接；空窗口也要结算，首窗空／outside 时保持已准入 seed，原始点只用于 seed window。文本续窗按边界 IoU 对齐而非 backend-local ID；接受按捕获源绑定而非幸存 slice 写回，保留手工关键帧，任一源软删／版本漂移或缺冻结证据则整笔拒绝。真实 prefork child 的退出只证明交付丢失；独立 owner 重跑必须证明不二次推理、不换 writer 回执。成功、保留部分结果的取消以及 `async_jobs` 镜像终态是三个可区分的断言。
- **训练以冻结任务和执行资格取证。** 训练由 native executor 持有，数据集构建仍走自己的 worker。必须以新 attempt、实际子进程组退出和继承 `flock` 证明接管；杀 supervisor 或观察到 heartbeat 消失不够。原生推理扣账先独立提交，timeout 不冲销，重试同一冻结输入但重新扣实际派发；发生物理 I/O 后以原 JWT/Key、当前 revision 和存储身份复核。业务关系的同内容成员不折叠；split 按内容/scene 连接分组，历史 digest 黄金值来自 canonical task 元数据前的 `770fb03be`。旧版本可使用当前获授权的定位符读固定内容，不改写历史标签/来源；覆盖 provider 的 current key 并不使旧 VersionId 不可读，需对确切版本造反例。日志关闭未知不开始上传、不假记账；脱敏写入用例与逐行脱敏正确性分开。从输入过关不能推导模型回流资格；权重初始化不继承优化器/EMA/epoch，Ultralytics 的 `device` 文本整数兼容只用于该比较。见[预览资源归属](0077-native-augmentation-preview-cpu-ownership.md)、[脱敏日志](0078-attempt-observability-and-redacted-logs.md)、[冻结逐样本评估](0079-frozen-sample-evaluation.md)、[训练初始化](0081-controlled-training-initialization.md)与[版本化 YOLO 身份](0090-versioned-yolo-identities-and-content-assets.md)。

### Python SDK、CLI／TUI 与公开合同材料

- **SDK 维护者：** OpenAPI 快照、`api-coverage.toml` 与实际调用点共同划定可用合同。离线 catalog 从 AST、声明和快照抽取，不消费 Python 普通注释；`scene_tracks.py:81` 的字面占位符 `track_id` 仍必须保留。文档代码块的 `compile()` 验语法，不证明方法可用；目录 fixture 应先验证文档存在以免参数化静默变零例。独立 SDK 版本和目标平台版本不联动。core-only 可导入和使用 HTTP；WebSocket/TUI extras 保持可选。
- **调用方意图不得静默改变。** 先校父/子资源确实关联再写；destructive CLI 被拒绝或取消时零 mutation 请求。来源 DELETE 返回空 `204`，失联可由调用方用同一 UUID `Idempotency-Key` 重放，SDK/CLI 不自动重试。排队取任务的 `200` + JSON `null` 是空队列；分派预览须显式发送两个可空目标，`null` 清该角色；评论 `null` 不改，留附件或绘图时 `""` 才能清正文。较新反馈 anchor 原样保留；导出判别键 `kind` 即使是默认值也要发。用户从 TUI 列表或详情启动导出都先配置；关闭无作业，VOC 同步不进入该作业型入口，LiDAR 用轴选项而非帧模式选项。终态作业不发取消请求；没有 `download_url` 不造下载动作。
- **凭据与机器输出各走自己的通道。** 登录用提交的凭据先做轻量 GET，失败不落盘；每项读取优先级均为显式参数、环境、配置文件。对新文件原子使用 0600，不把写后 chmod 误说成覆盖既有文件也无泄露窗口；手写 TOML 插值与覆盖权限债见 [#177](https://github.com/YOAO-Labs/ai-annotation-platform/issues/177)。预签名 PUT 和绝对 URL 下载都不附平台 Authorization。JSON 模式 stdout 由机器整体解析，进度和错误不得混入，日志不输出 token 或回显只写凭据的诊断。窄终端会折断 `config.toml`，夹具去空白只为验证路径提示，不约束 Rich 的排版。统计流只把 `1008` 当鉴权终止，不无穷重连；坏记录不拖垮同帧其余记录；无 Key 或 stream 不可用时保留 REST 静态区。
- **运维与构建：** 插件部署须在 Docker 可能启动前持久化 `launch_attempted`，不能把已可能启动的部署当成可取消预留；旧回执缺 `started_at` 先核证实际进程，quiet 证明仍绑定原 activation boot。历史 CPU LibreYOLO 配置的等价识别只供旧记录恢复，不豁免新部署的 GPU 隔离约束（[安装式推理插件](../0180-installable-inference-plugins.md)）。[Go 审计月报](../0090-module-languages-and-audit-summary-process.md)是无生产依赖的只读实验；`//go:embed openapi.json` 是编译器输入，公开 schema 从内嵌字节交付，不是 `godoc` 注释。两槽、每请求 64 MiB 是故意的内存围栏；已有容器峰值是约 7.28 MB 输入的负载，不证明两个最满请求可用。改变实验容量先量实峰值与过载失败，不以 RSS 样本替代。Node 审计 peer 对齐时区偏移时保留 PostgreSQL 亚毫秒小数，并把 OID 1082 的 `DATE` 保留为日历文本，不转 JavaScript 时刻。该切片没有已跟踪的独立 C/C++ 源或 cgo 前导注释；Python 的工具指令、解释器指令、docstrings 与持久工件仍不参与解释性注释删除。

## Consequences

- 每个 owner 仍可独立演进实现，但须保留所属授权相位、冻结事实、精确 wire 表示和失败结算；不为减少文档重复而合并这些防线。可执行夹具继续区分源码、Native、提交、真实进程和运行环境，不随源码注释移动而升级验收声明。
- 双连接、冷镜像、真正受限角色、精确对象版本与不确定关闭比纯内存测试成本高；只在相应边界运行，不把一条成功路径或不相干的广泛套件当替代。历史与新部署可使用不同表示，变动标准库／ORM／provider 时需按相应边界重建证据。跟踪的问题并未随退役注释而修复。
