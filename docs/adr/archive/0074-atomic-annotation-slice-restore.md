# 0074 — 切割使用受限操作账本与原子恢复

- **Status:** Accepted
- **Date:** 2026-09-08
- **Deciders:** 图片与视频工作台交互 Epic 的已授权实施
- **Supersedes:** —

## Context

把一个已保存对象切成两个对象需要同时更新来源、创建另一块，并支持一次撤销恢复原状。现有历史的 create / delete 叶命令会更换 ID，批量命令允许部分失败，无法保证两块结果的原子性。直接回传客户端保存的旧 geometry 也可能覆盖其他会话的后续编辑。

## Decision

图片简单 Polygon 使用 `polygon-slices:commit`，服务端只接收来源 ID、来源版本、幂等键与 2–256 个归一化切线点。切线必须简单、与来源有且仅有两个穿越点，其间各段在内部，其余段在外部。允许端点在边界上以支持覆盖整张图片的 Polygon；相切、沿边重叠、孔洞、多外环和零面积拒绝。

前端用边界两条互补弧与内部切线构造预览，并复用 `polygon-clipping` 检验交集和对称差的面积。服务端独立构造同样的平面分割：验证来源、切线与两块结果的简单性、边界穿越与区间位置、结果方向和面积守恒。这些条件保证内部不重叠且并集为来源；面积误差最多 `max(1e-10, source_area * 1e-8)`。服务端不引入生产几何依赖，测试使用 GEOS 作独立对照。自交检查采用 x 区间剪枝，候选边对检查和切线交点检查各设固定百万步预算。

面积较大的结果保留源 ID，相等时按质心 x / y 排序。来源身份和属性保留；新对象复制类别、工具单元、业务属性、属性来源、层级与原父对象，使用操作者和 manual 来源，不复用预测身份与置信度。沿用 Task → 编辑锁 → Annotation 的写入顺序，在一个事务内写入两个对象、任务统计、`slice_polygon` 账本、split lineage 与审计。创建子对象也先锁定 Task，再读取父对象活动状态，避免恢复停用对象期间产生迟到子对象。

`slices/{operation_id}:restore` 只接受目标 `before / after`、完整的两个结果版本和幂等键。几何与活动状态来自原切割账本的受限前后快照。每次成功恢复同时记录新版本与当前侧；下一次请求必须携带这份已记录版本集，不能通过重新读取任意当前版本绕过冲突。任一结果变化、被锁定、缺失或出现活动子对象时，整批拒绝。两个 ID 保留，版本递增，inactive 对象也进入响应版本集。

恢复期限固定为原切割提交后 30 天，撤销与重做不续期。恢复到当前侧不修改对象版本；同键同请求回放首次响应，同键异参冲突。`restore_slice` 账本和 `slice_restored` lineage 保留每次实际恢复的来源。

画布只拥有未保存切线与预览。切割提交与 history 不进入离线叶操作队列。提交失败保留不可变请求以便重试；同一次恢复也持久保存原幂等键。收到恢复结果即结算原任务历史，再异步刷新对应缓存；刷新不能延迟历史结算，切换任务也不能把迟到结果放入新任务。恢复失败保持栈位置并提示。

Mask 切割沿现有 `mask-mutations:commit` 增加 `slice_mask`，不改变 `split_components` 必须返回完整原连通分量的含义。来源是图片中已保存、未锁定、无活动子对象的 Raster Mask。两个有序端点定义直线，按像素中心叉积 `>= 0` 分到左侧；不使用 epsilon，不擦除边界像素。服务端在原 RLE 列区间内二分分界，按现有累计代数预算独立验证两个结果。较多像素保留源 ID，相等时左侧保留，沿用相同属性与 provenance 合同。

Mask 使用恢复快照格式 2：原账本只存前后版本、geometry 摘要与活动状态。内容从当前对象或既有 `MaskAnnotationRevision` 读取，不复制 RLE 正文。恢复先按 Task → 内容引用 / upload → revision → Annotation 的顺序校验并加锁，再修改对象。捕获触发器保存旧版本后，对所有引用 revision 使用非缩短的 `GREATEST(expires_at, original_deadline)`；无限期限保留。缺失、过期或摘要不匹配时整次拒绝。现有 GC 的 revision 引用扫描继续保护 undo 后停用的新对象，不增加扫描来源或配置。

## Consequences

- 切割、撤销和重做各为一个数据库事务；失败不会留下半个对象或半段历史。客户端仍沿用任务历史的会话存储与 5 分钟恢复窗口，服务端 30 天期限独立于该窗口。
- Polygon 几何快照保存在现有操作账本，Mask 只记录受保护版本引用；无新增业务表、部署服务或环境变量。
- Alembic `0161` 扩展操作和 lineage 的 CHECK，`0162` 仅增加 `slice_mask` 操作类型。已有切割数据时降级明确拒绝收窄约束；撤销上线应关闭入口并保留兼容 schema 与审计数据。

## Alternatives Considered

- **批量 create / delete / update**：不能保留 ID，也不能在任一叶操作失败时恢复整批状态。
- **客户端上传两块结果或任意旧快照**：无法建立来源守恒和后续编辑保护。
- **通用 mutation 框架或新的生产几何库**：当前范围是简单环的一条内部切线，受限服务与平面分割校验足够支持该合同。
