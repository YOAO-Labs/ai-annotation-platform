# 0076 — 受控训练模型身份与发布

- Status: Accepted
- Date: 2026-10-14
- Deciders: 项目维护者（委托实施代理确认阶段范围）
- Supersedes: None

## Context

已有推理 registry 和服务池表示部署资源，不能唯一标识可变的权重与类别。训练产物进入预标注后，发布切换、队列延迟和故障重试都可能让同一请求使用不同模型。类别名称猜测也会破坏项目标注语义。

## Decision

独立保存不可变模型版本、实例部署回执、追加发布历史和带 generation 的项目选择。模型从同项目成功执行的已验证产物注册，完整绑定原生类别，保护来源实验及存储。先完成认证安装、原生合同检查、固定样本推理和负责人确认，再原子发布；首轮仅开放单阶段整图图片检测。

预测创建时冻结权重、类别、绑定、来源和部署，并持久保存到 AsyncJob。幂等重试读取原冻结身份，发布切换只影响新任务。路由精确限定已安装实例，不以其他成员或内置权重替代。YOLO 模型池与类别缓存使用版本及 SHA-256；响应实际身份和原生索引通过验证后才映射为项目类别，Prediction 显式保存来源。

## Consequences

正向：发布、回退和重试具有可追溯身份；历史预测不受新发布影响；借用与资源准入沿用现有实现；损坏本地副本可按原摘要恢复。

负向：单实例故障会让该版本请求失败；权重与历史长期保留，需要明确的后续生命周期管理；跨框架回流必须独立验证，不能仅因训练成功而开放。

## Alternatives Considered

- 修改 registry 的权重地址：无法保留历史任务身份，也无法安全共享类别缓存。
- 请求中传任意权重 URL：绕过受控来源、授权和兼容检查。
- 发布时更新全部待执行任务：破坏幂等和可复现性，也难以回滚。
