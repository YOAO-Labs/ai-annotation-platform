# 0084 — LibreYOLO 回流复用受控模型并独立核验原生推理

- **Status**: Accepted
- **Date**: 2026-10-16
- **Deciders**: Project maintainers
- **Supersedes**: None

## Context

LibreYOLO 已能在固定数据与执行器中训练、续训和下载原生最佳权重，但训练成功不能证明推理加载兼容。原生 YOLO9 loader 会容忍缺失张量并补齐类别名称，单图预测也返回一个 Results 对象；直接复用 Ultralytics 加载和结果索引会隐藏部分加载或丢掉多框结果。

实际保留权重在既有受控推理镜像的隔离环境通过 CPU 加载、全部主张量比较及非方形图片输出检查。额外依赖与现有 Torch、torchvision、Ultralytics 和图像库可共存，无需新增常驻服务。

## Decision

在既有 YOLO backend 内新增独立原生适配器。共享纯 Python helper 固定 LibreYOLO、框架版本、YOLO9 t/s/m/c 家族规格、原生 state-dict 格式和 CPU 运行时资格，供 API 与推理端共同核验。冻结实验详情单独报告注册资格，注册时重新计算；既有 config 和摘要保持不变。

安装按 SHA256 与字节数验证唯一最佳权重，先以 weights-only 方式读取并检查未经原生修补的完整元数据与类别顺序。原生构造后比较全部主模型键、shape 和实际 tensor 值，只允许独立验证过的辅助训练头作为额外键。规格 E、其他家族／任务、量化和未经验证的格式明确拒绝。

原生单图 Results 不做检测索引切片。检查原图尺寸、完整对齐的检测数组、有限坐标与置信度、整数类别及过滤／数量上限；保留 checkpoint 的输入尺寸和 letterbox 约定，再复用既有输出几何转换。CPU 推理对象继续由原模型池借用者和阻塞执行所有者管理。

LibreYOLO 收据固定家族、规格、格式、字节数与运行时资格。池键纳入已核验收据摘要，从而包含框架、版本、类别和运行时；旧 Ultralytics 收据与三字段推理 wire 身份保持兼容。模型、部署、发布和项目选择继续分离，复用确切实例路由、权限、健康、绑定检查、试用、人工发布、回滚和预测来源。

原生最终评估经既有 reader 验证，保持真实零、负哨兵和不可用的逐类别／precision／recall 信息。共享样本评估与主动学习排名另有资格，API 和推理端在请求收据绑定前拒绝尚未通过该资格的 LibreYOLO；不能将原生别名包装为可比指标。

## Consequences

负责人可以在既有模型面板完成 LibreYOLO 回流，历史下载与实验继续可用。无需数据库迁移、新部署变量或第二个服务；代价是共享镜像增加锁定原生依赖，必须重建并复验部署身份。推理资格不证明模型质量或人工效率，GPU、其他任务和格式需独立资格验证。

回退先停止新注册／安装，显式将有效发布回滚到已核验部署，再停止不再承载绑定的运行时。历史权重、收据、模型、发布、预测及训练来源均须保留。不能重写旧收据或配置来伪造新资格。

## Alternatives Considered

- 保留仅下载：继续可用，但无法满足同一平台中的人工发布和来源追踪。
- 将 LibreYOLO 权重送入 Ultralytics loader：模型格式和输出语义不同，无法证明完整加载。
- 新建常驻 LibreYOLO 服务：增加部署、路由和资源所有者；已验证的依赖共存不需要此复杂度。
- 自动开放共享评估：受控推理兼容不证明跨框架评估语义，继续保留独立资格门。
