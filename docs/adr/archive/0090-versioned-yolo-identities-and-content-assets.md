# 0090 — YOLO 家族按冻结运行时核验，权重按内容寻址并独立准备节点

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** 项目维护者（本次实施授权）
- **Supersedes:** —

## Context

在线学习从单一 YOLO11 受控路径扩展到 YOLOv8、YOLO11、YOLO26 的检测与实例分割，以及 LibreYOLO9 检测。只有文件名白名单无法证明原生模型头、实际规格、训练损失或回流推理分支正确。框架升级还会改变源码哈希和参数定义身份，直接替换版本常量会破坏历史实验与安装收据。

基础权重过去分别放在训练器与推理服务的本地目录。同机可以避免重复保存，不同机器则需要可靠的本地副本。相同桶名只表明对象存储中的命名约定，不能证明连接到同一环境，也不能证明另一节点已有可用文件。

## Decision

采用离线共享模型登记表，显式列举 Ultralytics 三个家族的 n/s/m/l/x 检测、实例分割，以及 LibreYOLO9 t/s/m/c 检测，共 34 个组合。E 没有当前原生实现，因此只保留历史读取，不允许新建实验。框架、版本、任务、家族和规格共同约束参数定义、初始化、执行与回流；不根据扩展名推导受控资格。

历史参数定义、初始化策略和收据保持原字节身份。新 Ultralytics 参数定义使用独立修订与原生清单；旧冻结实验继续要求原合格运行时，未获验证的跨版本续训与初始化明确失败。新部署的服务身份不能覆盖旧 UUID 的收据。

YOLO26 使用精确原生端到端分支，固定 `nms=false`，区分真实 L1 损失与不适用的 DFL 项。实例分割为原生语义辅助目标生成确定性标签，保留各实例原始掩码，按 batch、类别数和输入面积限制辅助目标预算。架构验证同时核对 YAML 拓扑、原生模块和张量形状，兼容已确认的官方旧格式及原生类别迁移图，拒绝跨规格冒用。

公共基础权重保存在当前环境既有训练桶的 `model-assets/sha256/<sha256>/weights.pt`，同时固定字节数。管理员准备工具校验上传及下载的真实字节；运行容器读取只读节点缓存，不持有对象存储管理凭据。节点心跳声明本地已校验摘要，创建与领取再次核对。对象存在或另一节点就绪不替代本节点准备。

同机训练器和 YOLO Backend 可挂载同一实际宿主目录；不同宿主机各自准备缓存，无共享文件系统前提。受控回流权重在服务保护目录按 SHA 去重，版本目录通过硬链接复用文件，安装收据仍按版本独立保存。每次新安装都检查任务、类别与原生环境；并发及取消通过进程内锁、文件锁和原子替换处理。损坏修复不得原地改写其他版本仍引用的 inode，身份冲突不得重绑定 UUID。

资格证据按具体模型、运行时与操作记录。CPU 小输入原生训练、续训和安装可证明功能链路，不能替代目标设备容量、GPU 生命周期／故障或两台真实主机验收。

## Consequences

正向：

- API、界面和两个原生消费者共享明确型号身份，历史实验不随当前目录移动。
- 同机基础权重可物理复用，跨机部署保持可用，不要求网络共享盘。
- 冷缓存、损坏文件和错规格在执行前明确失败，成功安装仍有独立可追溯收据。

负向：

- 保留版本化契约和精确结构验证需要持续维护，新家族不能只增加名称。
- 节点必须显式准备权重并发布实际就绪状态，统一桶无法消除本地磁盘需求。
- 升级期间可能短暂保留新旧实例，须等冻结请求结束后再退役；目标硬件验收仍由部署方完成。
- 暂不自动回收共享 blob；删除与引用清理由后续独立策略负责。

## Alternatives Considered

**只扩展文件名白名单**：不能为 YOLO26 生成语义目标，也不能验证真实模型头和回流运行时。

**所有机器挂载同一共享卷**：引入额外文件系统可用性和锁语义依赖，且不能替代对象身份与每节点设备验证。

**所有模型原地升级到最新版本**：改变冻结身份，旧实验与安装收据将失去原证据，不能作为默认升级路径。
