# 0081 — 项目权重初始化保留固定来源并创建全新训练状态

- **Status**: Accepted
- **Date**: 2026-10-16
- **Deciders**: Project maintainers
- **Supersedes**: None

## Context

训练实验已有受控基础模型、完整参数、不可变数据与自己的恢复检查点。候选模型保留成功执行的确切权重、原生类别、绑定及评估证据。用户需要在新数据或参数下以项目模型初始化新实验；把候选塞入 `base_model` 会破坏参数定义，把它当作 `resume` 会继承不属于新实验的训练状态。配方、克隆和自动策略还需要一致保留来源，旧执行器不能静默忽略新增字段。

## Decision

保留 `base_model` 的结构及参数定义职责，新增独立 `initialization` pin。初始资格限定锁定的 Ultralytics YOLO11 检测栈、相同规格、完全相同的原生类别顺序以及全部状态张量转移。项目管理权限、成功来源 attempt、唯一权重、注册 provenance、运行时和评估证据共同决定资格；候选归档、部署和发布状态相互独立。

pin 包含模型／实验／尝试／数据身份、受控对象 key／SHA／大小、类别与绑定、来源配置／数据／验证摘要、运行时、评估证据及共享资格策略摘要。请求选择固定摘要，不选择可变的最新模型。预检、创建和首次领取独立完整校验对象，大小上限 2 GiB；错误明确拒绝，不回退目录权重。

实验、配方修订和策略增加 nullable RESTRICT 模型外键；旧行不回填。来源模型 KEY SHARE 锁串行接受与删除，不改变资源／实验的 claim 锁顺序。省略或显式目录初始化移除新增默认字段，保留历史请求和配置摘要。

独立执行器声明初始化策略能力，下载分离的权重文件并在反序列化前验证摘要。原生训练创建新 trainer，首批次前核对实际模型、全部状态张量指纹、epoch 零，以及新 optimizer／scheduler／scaler／EMA／best 状态。`native-config.json` 保存独立证据，服务端成功提交再次核验。后续恢复使用本实验自己的检查点，保留原 pin 和恢复模式回执。

配置来源 `origin`、初始化权重和 checkpoint 恢复保持独立。配方、克隆、策略固定同一 pin；解除配置来源不清除初始化，也不隐式选择被克隆实验的新产物。前端用会话单调代次、草稿修订、URL 意图和查询作用域拒绝 ABA 结果，未确认创建只重试原始 body。YAML 格式 2 携带来源 ID／摘要，旧格式仅替换参数。增强预览只验证数据变换。

## Consequences

正向：用户可审计新实验的精确权重来源，保留原生训练与自身恢复语义；来源失效在 GPU 训练前明确失败；旧配置和请求不被改写。谱系读取增加独立来源与反向关系，不需要流式读取权重。

负向：首次资格较窄，不支持类别重映射、其他原生族、外部任意权重或训练器跨版本转移。预检与首次领取的完整校验增加对象读取；被引用候选和其来源产物必须保留。镜像部署需同步实际目录并刷新拥有的执行器和相关 API／worker。

## Alternatives Considered

- 只保留管理员目录权重：无法满足项目模型初始化。
- 把候选当作基础模型名称：混淆结构／参数定义与权重来源。
- 使用断点续训：会继承源优化器、轮次和输出上下文，不能代表全新实验。
- 仅前端选择或仅传下载 URL：旧执行器可能忽略字段，且缺少持久完整身份与原生回执。

## Notes

资格依据锁定的 [Ultralytics model](https://github.com/ultralytics/ultralytics/blob/v8.4.177/ultralytics/engine/model.py) 与 [trainer](https://github.com/ultralytics/ultralytics/blob/v8.4.177/ultralytics/engine/trainer.py)，结合实际保留产物和当前原生执行验证。来源加载成功不表示模型质量改善；同基准评估仍是独立工作。
