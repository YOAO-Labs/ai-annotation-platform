# 0101 — 周期来源协调沿用领域运行和人工接纳

- **Status:** Accepted
- **Date:** 2026-10-23
- **Deciders:** 用户授权继续推进 E04；实现与只读复核
- **Supersedes:** —

## Context

手动增量差异已有冻结基线、独立扫描与两阶段登记。需要周期检查目录，同时避免重复 beat、进程中断或凭据轮换造成重复建运行和权限接续；内容差异仍需人工接纳。

## Decision

每来源保存固定间隔计划，沿用单个现有 beat 和精确 worker 队列。数据库拥有到期时间、修订、短期派发令牌和持久运行指针；消息只是唤醒。按 Location → Source → Schedule 串行推进，在 I/O 后复查，沿用领域账本、租约、任务中心和正式登记恢复 owner。暂态故障按间隔重试，不补跑历史周期。

计划固定启用人的账号和 API Key 原证明，逐次校验当前权限、双 scope、配置及根资格。创建或恢复后的领域运行仍需匹配固定证明，不能由嵌套入口重新捕获新凭据。活动扫描或预检不能更换计划执行身份，完成或取消后可重新授权；已完成的差异仍保留核对门禁。人工扫描和预检不被接管，人工正式登记只观察，不能用计划身份重写它的授权。

后台指定 worker 真实刷新自己的探测，然后扫描和预检，不伪装 API 节点。人工确认仍由 API 当前节点复读。除全部相同以外，完整差异暂停后续周期，等待人工登记或带修订和扫描 ID 的显式跳过。跳过不创建业务样本、不改写差异。暂停周期不撤销已建业务运行；取消任务不自动恢复。

## Consequences

不增加服务、依赖、环境变量或镜像构建，复用现有读写限制、幂等与审计。固定间隔15–10080分钟，不支持日历、时区和追赶。逐分钟协调意味着阶段推进可能延后；全量预检仍需读完整字节，差异账本持续增长。权限/配置/根变化停用计划后需人工核对再启用。

0202只新增计划表，历史任务清理保留运行与周期指针；有计划时拒绝破坏性降级。回退仅暂停计划并保留已提交业务历史。
