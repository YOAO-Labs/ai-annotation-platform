# 0183 — API 装配保留调用方事务、当前权威与物理责任

- **Status:** Accepted
- **Date:** 2026-11-21（回填 `e8a4f595` 与同期注释迁移前的既有实现）
- **Deciders:** API、Identity、Jobs、Notifications、Assets、Workspace、Labeling 与 Learning 维护者
- **Supersedes:** —

## Context

FastAPI、Celery 和运维入口复用同库 owner 能力，也调用独立进程与对象存储。有些容易误改的约束只记在适配器旁：使用同一个 Session 不表示可以多 flush 或 commit；发布成功不表示回执已持久化；用户请求、远端执行及对象句柄各有独立生命周期。这里移交仍适用的 API 装配理由；既有领域 ADR 继续定义其协议。本记录不回写冻结的迁移历史，也不表示部署切换、合并事务或修复所列技术债。

## Decision

### 调用方事务、ORM 与迁移

- **调用方决定提交。** [同库事务数据能力](0092-transactional-module-data-capabilities.md)持有固定函数和私表权限；`apps/api/app/application/` 组合 owner，HTTP 或 worker 保留事务。`services/identity_account_lock_data.py`、`services/identity_read_relations.py` 等以条件 flush 补足 text/Core SQL 不做 ORM autoflush 的差异；不在 `no_autoflush` 中引入全量 flush。Identity 运维 provisioning 刻意保留原有无条件 flush，令种子、账号与审计仍在一个调用方事务中可见。仅需隔离 `NOWAIT` 的读锁则用 **连接** savepoint：`Session.begin_nested()` 在进入保存点前会 flush，即便调用方关闭 autoflush。参见 `services/original_sources.py:148` 和[运维账号与权限读取](0132-identity-operational-provisioning-and-authority-reads.md)。
- **数据库事实与 Session 投影不是同一层。** Jobs 生命周期 mapper 只提交确实赋值的字段掩码，保持原 `UPDATE OF` 触发时机、部分 flush、转换异常前的赋值和时间戳过期。`db/models/async_job.py:74` 的创建关系不含执行快照与存储进度字段：不得连显式 `None` 都交给创建；快照仅由 Jobs 的专门绑定能力改写。`db/jobs_lifecycle.py:176` 仅改写受支持的 PostgreSQL 单行主键列 refresh；锁定查询、有 loader criteria 的查询、其他 mapper 或 dialect 不动。原投影、绑定参数与刷新选项保留；普通行、snapshot、progress 由三个 Jobs 固定能力在同一语句补齐，不回读私表。批量生命周期命令使用 owner 返回的精确命中 ID 做 ORM fetch 同步，合成的 ORM DML 只作缓存输入；过期后找不到行时按原 `Session.get` 语义移除身份。批次预测先取消活动行、同步，再删除，尊重原 autoflush。见 `services/jobs_lifecycle_data.py:101`、`:169` 与 Jobs 生命周期[部署契约](../../docs-site/dev/concepts/module-deployment.md#jobs-lifecycle-queue)。
- **Notifications 的判断与 Jobs fetch 不可合并。** `services/notification.py:449` 的已读／删除由 Notifications SQL 命令处理；API 使用 SQLAlchemy 2.0.49 的 evaluate 语义同步现有身份，即使数据库更新零行，`no_autoflush` 下也可能有内存命中；不能用受影响 ID 交集或全量 expire 替换。保留谓词顺序、过期／脏字段、删除与保存点回滚登记；本地编译不执行二次 UPDATE/DELETE。Jobs 与 Notifications 的活动私有 ORM 依赖（包括部分列刷新）由 [#162](https://github.com/YOAO-Labs/ai-annotation-platform/issues/162)跟踪；回归以 `test_jobs_lifecycle_refresh_loader.py`、`test_jobs_lifecycle_native.py`、`test_notifications.py`、`test_notification_read_state_cache.py`、`test_notifications_delete_baseline.py` 为准。Project、AI Mask 的 owner 查询保留已缓存但未完全过期的同一实例，不追加读取或 flush；过期缺行不可留下陈旧身份，参见 [Workspace 项目事实](0175-workspace-project-fact-relations.md)和[推理公开权威](0155-durable-inference-routing-authority.md)。
- **Alembic 和普通服务分权。** `apps/api/alembic/env.py:10` 在读 `Base.metadata` 前导入模型以完成注册，保留调用者显式注入的连接地址，只在未配置时使用设置；避免测试误迁移开发库。PostgreSQL 在线迁移以会话 advisory lock `727274` 串行执行；取锁引起的外层事务须显式 commit 持久化 DDL 和 revision，而非提交即解会话锁；失败先 rollback 再解锁，避免遮盖原错误。`app/config.py:93` 的 migration DSN 由迁移 launcher／专用维护 worker 使用，普通 API 和普通 worker 仍持运行身份。`scripts/configure_gpu_collector_role.sql` 只给独立 `gpu.control` collector 预置登录角色所需授权，应由 schema owner 在迁移之后运行。冻结 SQL、迁移 byte 与 lint 解释是不同对象。

### 身份、连接与签发边界

- **准入不是未来授权。** `apps/api/app/deps.py:255` 的 scope 依赖中，`None` 是 JWT 线路，API key 的 `*` 跳过该 scope 守卫，空集合不是全权；项目角色仍由 Workspace、任务或批次可见性由 Labeling 判断。在 Job 受理、原件打开、长连接、上传发布、模型结果落库之间，按操作持同事务当前账号／项目／成员／credential 围栏；原 key 的 owner、撤销、有效期和 scope 收紧不得用新 JWT、当前通用凭据或冻结 scope 替代。有些 accepted-key 能力只核验持久身份，不重新证明明文持有；完整 receipt 需核对自身绑定的原始证明，不能混用两种合同。等待锁后的过期按实际时钟复查。见[准入与撤销](0115-identity-admission-and-durable-revocation.md)、[已接受 key 的当前围栏](0161-identity-current-authority-consumers.md)、[Workspace 锁定快照](0166-workspace-locked-authority-snapshots.md)。
- **独立 Identity 持签发与派生密钥。** 远程 API 消费经过 transport 鉴权的固定响应，而非使用 API `SECRET_KEY` 重新签发或验证 Identity 产物；当前账号状态与会话撤销仍以 Identity 提供的事实为准。旧部署的签名密钥不得无计划轮换，因其也绑定持久指纹与派生凭据。Transport 中的认证信息不得随重定向转发或进入握手日志（`services/notification_socket_bridge.py:16`）。嵌入式钥匙用量提交只在实际有用量变更时发生；先释放已验证 key 的锁，再进行 bcrypt、账号命令或独立 Identity 发布，不能引入 key→User 逆序。账号／恢复策略拒绝在变更前返回；会话本地失败可提交旧登录审计。原有账号偏好响应没有 64 KiB 总量限制，分块读取大小不是 admission 限额。见[Identity owner](0118-independent-identity-account-commands.md)、[恢复与邮件](0119-independent-identity-recovery-and-mail.md)、[签发边界](0161-identity-current-authority-consumers.md#identity-signer-boundary)。
- **服务器身份和业务权限各自验证。** Assets Source 持有 connector Fernet key，与 JWT key 分离；未配置时拒绝凭据操作，不以零值或当前 API secret 代替。`config.py:62` 的 SFTP 持续引用资格是部署证据：按精确 host/port/username 和完整主机公钥验证，在用户认证前核对公钥，不自动接受未知 key；客户端检查不证明服务端 jail、只读或无 shell。S3 路由限定保存的 endpoint、完整 opaque key 和版本，LIST/DNS 指向不能签发内容凭证。Site Agent 的退役凭据只可报告已受理命令的确切结果（`api/v1/site_agent_transport.py:130`），不能领取命令或上送字节；心跳也不证明命令已关闭。Relay 在短事务里保存命令身份、截止时间及总 bytes 约束，Redis bytes 先于 DB 进度，允许相同 offset/相同内容重放，拒绝不同 bytes。参见[连接管理](0103-assets-connection-administration.md)、[严格 S3 引用](0098-strict-external-s3-references.md)、[合格 SFTP](0099-qualified-sftp-references.md)。
- **通知、邀请及上传用原身份，不偷换请求主体。** 已受理的连接器取消返回的是原作业 owner，不是当前合法取消者；核对 Job ID，不能要求两 actor 相等。项目邀请的历史目标不是外键：删项目不能把邀请变成账号邀请。签发邀请邮件轮询在 owner commit 后退避，不占 SQL 锁或 sender lease，远程模式由远程 owner 独占。Avatar 先释放 accepted-key 围栏做像素处理，分配与发布重新比较原 credential、旧 avatar 及确切 pending receipt，Identity 原子绑定新的和退役旧的；附件／引导图以期限、父对象及原 Comment 重新授权，不从 Feedback 镜像推导。已退役 owner 的清理独立于业务事务，固定错误投影不得泄漏 provider 请求。见[邀请 owner](0122-independent-identity-invitations-and-mail-v2.md)、[Guide Assets](0144-workspace-guide-assets-owner.md)及 `services/avatar_uploads.py:252`、`services/comment_attachment_authority.py:165`。

### 队列、通知与 worker 执行围栏

- **Jobs 持有可重放的派发内容。** `apps/api/app/services/jobs_dispatch.py:74` 冻结执行 ID、队列／options 与完整消息（逐帧还冻结 canvas），在已受理操作同事务保存，提交后发；5 秒有界的独立 ACK 不能把 broker 接受变成执行完成。ACK 丢失等待 lease 后重投相同信封，不能重构成另一条业务请求。普通 worker 订阅 `default`，未路由消息不能落到 Celery 默认名 `celery`；Beat 必须独立运行，worker 心跳在同名 `celery:hb:{worker}` 写 Unix 时间，缺失是未知而非 0。跨帧、数据集链接、旧导入等调用仍按各自持久合同推进；例如链接分块留有已接受代次和游标，直接 `delay` 必须等 link/Job 可见，重复链接可找回同一活跃作业，不能据此声称每条派发都有 outbox。见[持久建题](0093-durable-task-creation-authority.md)、[持久连接器导入](0100-durable-connector-import.md)、[失败预测重试](0114-durable-prediction-retries.md)。
- **回调不持有新 Job 代次。** `application/job_terminal.py:29` 显式分发类型 owner，取消是协调请求，不是进程已停；通用 broker 中断不能写入带独立执行围栏的视频、也不能替有已受理摘要的预测重试失败分支结算。域账本按 Job/执行 ID、generation、token、当前状态及业务权限核验，旧信号不能清除新 claim 或重置已完成业务。去掉外部 FK 的历史 scope 仍给授权与回执使用，不能把项目删除后的 Job 当全局 Job。训练 native attempt、库存、导出与清理的 timeout 只证明观测中断；不能据此认定 SDK/子进程已经关闭。见[视频执行 claims](0157-video-execution-claims-and-route-binding.md)、[窗口与重放](0158-video-window-journals-and-replay.md)、[独立写入 owner](0159-independent-labeling-video-writer.md)和[恢复屏障](0160-coordinated-video-restore.md)。
- **实时消息只是可见性提示。** 普通 HTTP 已读／删除与多数延期发送先 commit，再通知；WS 对每条受限消息重验 Identity、Workspace 与目标权限，重连也重新认证，30 秒 JSON ping 是保活而非 ACK。终态 worker 路径的通知去重、静音和 append 在调用方事务内，以 savepoint 隔离自身失败；仍在 commit 前即时发，另一 Session 最多等 150 ms 再失败关闭，慢提交可能只留下可读取的行而无实时推送，见 [#184](https://github.com/YOAO-Labs/ai-annotation-platform/issues/184)。不要通过放宽可见性或把 Redis publish 当作事务证明来补偿。库 owner 和旧消息语义分别见[Notifications 投递](0121-identity-self-deactivation-and-notification-delivery.md)及[WebSocket 重新认证](archive/0011-websocket-token-reauth.md)。
- **订阅需求不是 backend 健康。** `api/v1/ws.py:524` 的 ML 统计订阅只允许当前运维角色，订阅者为零时 Beat 不轮询 GPU backend。计数复用是为减少健康探测，并非后端可用性的证据；当前非原子负数修正不能保证故障或进程退出后准确收敛（[#185](https://github.com/YOAO-Labs/ai-annotation-platform/issues/185)）。
- **逐帧运行使用保留输入与已提交游标。** `workers/frame_preannotate.py:270` 要求 actor、sealed manifest 与选择摘要，按原视频帧序号分段；原 retained-input Job 和当前执行 Job 不得合一。空预测的已提交帧也是完成，重投不能重新推理；Labeling 在最终 Task 锁下再次检查该帧的回执、取消、权限。写锁延期重试要保留已完成兄弟段，现由 worker 延长 Redis chord 键与应用进度 TTL（[#182](https://github.com/YOAO-Labs/ai-annotation-platform/issues/182)）；旧抽帧 stage 消息仅失败关闭，不启动旧 pipeline。派发 ACK、worker RETRY、对象 close 三者不能相互代替。批量预标与工作台规则分别由 `application/preannotation_execution.py` 的准入及最终化持有，不能用已冻结上下文跳过当前 edit lock、批次指派、权限或临终 Job 检查。链接[保留视频输入](0109-retained-video-inputs-and-frame-plans.md)、[持久预标结果](0113-durable-preannotation-results.md)与[退役围栏](0178-video-retirement-deletion-fences.md)。

### 规范原件、物理责任与存储变更

- **区分来源、内容、业务关系和物理位置。** `apps/api/app/services/original_sources.py` 以规范 owner 解析 Task：没有直接 DatasetItem 仍可有 `primary_lidar`；即便非 primary link 也与独立 TaskOriginal 冲突。读只采集标量 DTO，不触发 DNS、凭据解密或存储 client 构造。保存的 `storage_ref` 记录分配时 owner；purpose 变更只给新分配。旧对象、缓存 C 的权威与 quota、A→B 的已验证读取路由、创建时 receipt 是不同事实（`services/original_cache.py:882`）；不能试遍当前桶、把 source ETag 当目标 HEAD 条件、或凭 MD5/HEAD/LIST 当完整内容 SHA。精确 S3 key 不做文件路径归一化。见[内容与位置标识](archive/0091-dataset-content-and-location-identity.md)、[受控存储](archive/0092-controlled-storage-registry.md)、[核验快照](archive/0094-verified-request-content-snapshots.md)。
- **外部 I/O 前释放业务锁，发布前重取权威；例外跟具体 owner。** 常规原件、目录注册、扫描、附件、导出与媒体 owner 先冻结事实结束业务事务，物理阶段有独立 permit，再比较当前源／配置与权限。持久重放只比较本次提交固定的 receipt；replacement 不能继承旧资产、配置 revision 或 actor。用稳定锁序（例如 Connection→Location，Dataset `NO KEY UPDATE`→Item，按 UUID 排序的多目标）；源和 goal 各自有 Gate，已发布的 B 不以 A 的 stop 代替 B 准入，物理同别名也要在 permit 提交之后重查共享 GC claim。取消要取消并 drain 物理线程、decoder、response body、client 与临时 stage，有句柄不明即不释放责任或 quota；`StorageOperation` 不是 worker 状态，也不受业务 FK cascade。目的地 probe、List/HEAD、resume/重放只按声明读或写，GET 不能临时调 allocation 或补账。见[不可变目录引用](0095-immutable-directory-reference-tasks.md)、[定向登记](0096-durable-directory-registration.md)、[来源变更](0102-explicit-directory-content-revisions.md)、[同内容再校验](0103-explicit-same-content-revalidation.md)。
- **先记录所有权，再做物理变更。** `services/managed_original_creation.py`、`services/task_originals.py`：至少先创建独立、精确 key 的 intent，尝试以 SHA/size 和上传时的不可变版本证明；创建、写后、完成 ACK 不明分别处理。已写／不明 receipt 占用 `(storage_identity,bucket,key)`，不能由 TTL、后来的 404/412、相同 bytes 或旧无 intent 记录转成可重写/可删除。独立事务的 receipt 必须活过业务 rollback 与删除，不能依赖未提交父行；原件发布按唯一 Creation 收敛到同一 row。`managed_original_reclaim.py` 先持久提交 `delete_started` 再调 SDK；对已绑定的精确版本证明不存在且物理结算后才能完成，进程信号或 delete marker 不足。Retirement assertion 记录删除时所知事实（unknown 不阻断业务删除），记录数不是可回收副本数，`retain_until=NULL` 无期限；不以当前绑定重写历史。见[来源删除与清理](0096-assets-source-deletion-and-cleanup.md)、[Workspace 解绑事务](0177-workspace-caller-transaction-dataset-unlink.md)与[受控存储](archive/0092-controlled-storage-registry.md)。
- **迁移与用量账本有独立证据和撤回顺序。** `services/storage_migration_copy.py` 的 history identity 分离内容、physical intent、验证状态和时间；target 写入意图/ACK 先落独立数据库账本，再提交本地检查点，取消和权限变化不应抹掉晚到的物理 ACK。当前 key 空不能证明曾未写入（delete marker 可遮挡版本），重试 conditional PUT 需要完整确切版本历史为空。Finalization、read publication 按原 Gate/revision/receipt 锁序判断，不以进度字段授权；轻量读 DTO 不开启 admission savepoint 或创建 Gate。`services/storage_usage*` 分页只发已完成 generation，旧 Celery ID 不得推进新代次；不明结果保留未知，不把后来的存在观测当上次写入成功。只有 exact bucket/key 和所有者证据一起证明分类，MD5 只是索引入口；多 owner 冲突保留未分类，不用桶前缀猜测。`storage_fault_events.py` 另开短事务记录 allowlist 故障，不输出 DSN、对象地址、provider 异常；不反向改变业务 commit/rollback。
- **回收执行与公开预览复用事实，不共享权威。** `services/managed_original_reclamation.py:566` 的 GET 只有只读投影并再次核对账号/key 和配置摘要；执行以同一个 SQL 快照的 raw facts 检查保护记录。未知的历史来源形状仍是全局 blocker，不能因筛选某一个 retirement 就漏掉；当前文本拼接耦合由 [#186](https://github.com/YOAO-Labs/ai-annotation-platform/issues/186) 跟踪。迁移复制重放有稳定的证据优先级：已保存 receipt 优先于不明 ACK 的意图，同级按目标键字典序，不假定可推断哪条映射最早。
- **派生物也有各自 owner，且不是原件许可。** Images 的 generation、源 SHA/尺寸和输出令牌必须匹配，原生 job ID 不证明 manifest/overview 已写入，不能退回 legacy client。Video 段与 tracker 使用原帧和原时间表，从实际输入提取 decoder config；WebCodecs 必须区分 B 帧 preroll 的 DTS 与展示帧身份。Worker 在完整共享 capture、所有 decoder/输出/client 真实 close 后才发布任何 ready；部分验证与聊天浏览不授予输出写权。`services/storage.py:36` 的签名默认按 600 秒边界对齐以复用 URL/cache key，严格短 TTL 使用 `align=False`；媒体生命周期只针对 `videos/` 前缀的缓存类目标，不是整桶。已引用的 playback proxy、poster、审计归档、avatar 不靠任意过期后懒重建。详见[视频媒体](0105-independent-video-media-owner.md)、[图像媒体](0106-independent-image-media-owner.md)、[发布时冻结输入](0107-versioned-accepted-media-inputs.md)、[图像批量清单](0108-bulk-image-input-manifests.md)及[帧服务分层](archive/0018-video-frame-service-segments-and-tracker-boundary.md)。

### HTTP、序列化与调用边缘

- **中间件与状态码是线上合同。** `apps/api/app/main.py:271` 最后注册的 middleware 在最外层；上传流的 ASGI 包络上限必须早于 multipart/JSON 解析，CORS 的 preflight 不进入内层 Audit。生产 headers 的 CSP 假定 API 不返回需 inline script/style 的 HTML；上线认证式 CORS 不可误用开发 localhost regex。生产“显式配置来源”的断言目前只拒绝空有效列表，遗漏会用非空开发默认值（[#183](https://github.com/YOAO-Labs/ai-annotation-platform/issues/183)），不要把它写成已落实。ZIP 预算另留 64 KiB multipart 边界，一个文件、零普通字段，解析异常包括取消要关闭所有已创建 spool 且保留原错误，与上传内容限额分层（[#181](https://github.com/YOAO-Labs/ai-annotation-platform/issues/181)）。API 链路用 ContextVar 关联审计、按路由模板记指标而非 UUID 原始 URL；Sentry 脱敏区分大小写无关的 Authorization，不能宣称是全事件脱敏。见[安全 headers](archive/0010-security-headers-middleware.md)。
- **播放和输入路径拒绝旧权威。** `api/v1/original_playback.py:49` 在浏览器请求优先使用 Fetch Metadata；开发反向代理可能改 Host，fallback 才比较 Origin。即使命中缓存也可能等待无关退役 close，签发 cookie 前再验源与 lease。`services/original_playback_response.py:52` 的 HEAD 忽略 Range；`If-Range` 不匹配时忽略整个字段（包括语法错误），有效多区间回完整内容，空文件的正 suffix 没有合法 206。超长范围在整数转换前受限，给 `pread` 的偏移按真实长度夹紧。显示用 URL 不可作为 worker/出口的可移植 URL。读者遵从原线上错误映射；无对象、真正 source drift、失效 authority、未结算 I/O 不可统一当不存在。
- **请求是否给出值、来源和顺序都可有意义。** 数据集 `axis_convention` 更新缺省保留、显式 null 移除、值写入；新建缺省不写历史 `metadata` 项，显示按 ISO 8855。Server `updated_at` 已被 flush/commit 置过期时显式 refresh，避免 async 序列化发出隐式读取。仅删除整个数据集且明确给出 `Idempotency-Key` 时，才允许在 Dataset 行已消失后进 owner 校验确切回执；普通 GET 或其他删除不放开。系统设置的 `false`/`0`/`""` 不是便于回退的空值，发生版本冲突先 rollback 解锁再读已赢者的有效配置。字面路由（如管理 CSV `export`、connector `allowlist`）须早于 UUID 参数路由。封闭协议由 owner 发布；路由/模型 docstring 可进入 OpenAPI，不属于待移除的源码注释。参见[OpenAPI 客户端合同](archive/0003-openapi-client-codegen.md)、[LiDAR 坐标约定](0034-lidar-axis-convention.md)及[素材目录协议](0097-independent-assets-catalog.md)。
- **运维输入和种子不能发明成功。** `scripts/seed_pointcloud.py:325` 的幂等重跑只应认可批次 owner 证明的“无未分包任务”；现有 `except HTTPException` 范围更广，可能吞掉批次写入 503/409（[#163](https://github.com/YOAO-Labs/ai-annotation-platform/issues/163)）。nuScenes 导入使 Scene、Task、pose、标定 flush 到入口 Session，关闭普通点云路径的中间 commit；旧 seed 对象仅在最终 SQL commit 后删除，上传本身不受数据库 rollback，未知/失败只保留物理责任。开发 seeds 不能跑 production；namespace 用有宽度上限的确定性 ID 匹配测试 fixture，清理先收停新 admission、drain 已受理工作再做物理删除，不能假设关页面终结服务请求；新抢占、删除范围、锁序按实际 Job/项目/Item 度量。`scripts/audit_project_roles.py` 用 PostgreSQL `REPEATABLE READ, READ ONLY` 统一统计和抽样，保留 legacy 角色作迁移证据、task assignment 优先于 batch、异常 JSON 类型不直接强转。见[空间素材状态](0102-assets-spatial-state.md)、[场景帧](archive/0035-scene-and-frame-foundation.md)与[平台角色和职责](0075-platform-identity-vs-project-authority.md)。
- **审计归档按物理分区而不是当前名称删除。** `services/audit_archive_partitions.py:61` 在 `SHARE NOWAIT` 后复查分区 OID，防止同名替换。校验逐行读独立命名的 SQL cursor，并明确关闭服务端 portal 后才尝试 DROP；只关 asyncpg 的 Python 结果不足。校验读全 gzip 和尾部以拒绝额外 member／padding，读 API 分页只限制保留输出、不缩小证据范围。归档候选若 commit 回包不明，按已保存归档的确切 locator 查询，不从暂存成败推断。见[Audit 分区](archive/0007-audit-log-partitioning.md)。

### Workspace、Labeling、Inference 与 Learning 的本地组合

- **项目和批次权限在写入时再次建立。** 任务分派必须在当前项目成员角色和兼容的活跃账号上成立，而非旧全局 annotator/reviewer；可用任务先按 canonical visibility 过滤再分页。账号→项目→成员→批次→Task 的实际写入顺序隔离停用／转移。未分类 split 范围是 `batch_id IS NULL` 和旧 `B-DEFAULT`；scene 模式只能按 scene 强制同序分包，而非把连续帧按随机策略分给不同人。删批若有非 pending 或 AI 工作默认拒绝（单次 409、批量逐项失败）；force 先用旧 batch ID 重置状态与清 AI、保留人工标注，再重新归类，同事务维护计数，即使没有 `B-DEFAULT` 也不能跳过项目计数。draft 没有负责人/审核员才可批量预标，指派改变要刷新资格即便状态不变。见[锁定与审核](archive/0005-task-lock-and-review-matrix.md)、[admin lock](archive/0008-batch-admin-locked-status.md)、[集合锁与计数](0172-project-set-locks-and-labeling-counters.md)、[同事务计数](0176-labeling-lifecycle-counter-deltas.md)。
- **写入保留原始标注证据。** 单题与批量共享生命周期用例；批量保留每块 commit、随后质检派发，最终批次投影与审计另提交，不保证所有事件都是提交后发布。已知无 contributor 的 `[]`、未知的 `NULL`、真正首次审核的冻结证据不能互换。讨论中原生 task root 必须匹配真实 Task 项目、anchor 和空 parent；旧标注评论镜像不是 Issue thread，软删标注仍可留历史评论。历史写入、撤销、修复按稳定 track/annotation 版本与顺序加锁；只变帧属性不能覆盖轨迹默认。Mask refs 区分 legacy `coco_rle_ref` 与 gzip marker，最终引用与 RLE/Task 锁在原事务；只有确知不变且已链接的历史帧引用才可省略。压缩 transport 的 4 MiB 解压上限独立于压缩、像素与 AI payload 限制；`test_mask_gzip_transport.py` 防止与 RLE 对象限额漂移。见[标注切片原子恢复](archive/0074-atomic-annotation-slice-restore.md)、[Mask 内容](0111-independent-mask-content.md)、[GC 围栏](0112-durable-mask-gc-fences.md)、[次级质检派发](archive/0089-injected-quality-job-dispatch.md)。
- **推理输入、路由与结果分开。** `application/preannotation_execution.py` 及 `services/prediction.py` 识别没有 `parent_stage` 的根，不假定 ID 为零；沿父索引和几何 lineage 派生下游，保留 LS 形状的原索引给接受／拒绝而非列表位置。交互接受的 prediction 是追溯记录，不回到 pending 候选。AI Mask `_prediction_out` 此处只接一条 owner 回执的 mask 结果，不等同一般几何重建；实际拓扑事实来自 Inference owner，不得因缓存复用绕开后续权威和最终标注锁。推理路由不能用请求 backend 名代替实际实例、服务池、冻结 release 或已绑定 execution，健康观测不授予拓扑修改；外部试探前释放可阻塞独立健康 owner 的 Registry 锁。安装先持久保存 inspected launch 再探测，安全停机仍比较 container/boot/revision。见[编排链路](archive/0043-staged-preannotation-pipeline.md)、[Mask 候选](archive/0053-native-mask-ai-candidate-lifecycle-and-video-correction.md)、[拓扑锁](0151-inference-topology-locking.md)、[持久路由](0155-durable-inference-routing-authority.md)与[插件安装](0180-installable-inference-plugins.md)。
- **导出不能由单一序列化惯例替多种 wire。** Scope、选中 Task 集和已封存内容/选项决定任务，同一幂等重试可以复用，命中仍复查权限；没有完整 selection revision 就不能跨独立作业扩缓存。COCO 类别键是 `(tool_unit_id,class_name)`，类别 ID 跨 unit 唯一；YOLO OBB 先在像素空间旋转再归一，否则非正方形变形。损失可接受的 bbox 投影与 lossless 几何合同分别判断，视频稀疏采样用原始 frame ordinal 不重编号；KITTI 无角色的预检可计算供选择和诊断的路径事实，执行仍要求 camera role。冻结 ZIP/媒体的 waiter 错误不能处置可能已发布的对象；要重验 lease 和 owner receipt。见[原生交换格式](archive/0024-aap-json-format.md)、[场景帧](archive/0035-scene-and-frame-foundation.md)及[模块数据能力](0092-transactional-module-data-capabilities.md)。
- **Learning 依赖冻结媒体与真实执行终止。** `services/training_datasets.py` 在同一 PostgreSQL 语句快照冻结 Task、标签与原件，I/O 后重新取得 project advisory lock，比对权限和版本；追回旧 dataset 或 assessment 时沿保存的 version/attempt target，不用今天的 training bucket。用共同内容、Scene 和祖先维持 train/val 隔离，合并证据不丢成员关系。训练由 native executor 持物理资源，Celery 构建版本的专用连接持会话 advisory lock 跨 commit；丢 commit ACK 后先重读该版本 `package_key` 是否等于 exact attempt 成品，再决定清理。预览、训练和评估不借同一合同宣称资格；停止确认可成立而报告未发布，不能用 UI 终态、超时或空 GPU 健康代替真实 process exit。训练部署必须复核被选择的安装与检查 ID，较新的 release 不覆盖队列中的冻结模型。见[数据冻结与任务流](archive/0087-project-task-dataset-streams.md)、[预览 CPU owner](archive/0077-native-augmentation-preview-cpu-ownership.md)、[评估](archive/0079-frozen-sample-evaluation.md)、[人工审核的主动学习](archive/0083-human-reviewed-active-learning.md)及[模型回传](archive/0084-qualified-libreyolo-model-return.md)。

## Consequences

**正向：** API 继续持原请求与调用方事务；能从明确 owner 判断何时复查当前权限、哪一次提交赋予释放物理责任的条件，以及何种 DTO 只是一份历史观测。进程、消息、对象存储故障不会仅因调用方事务结束而被归为成功或已停止。

**负向：** 兼容 ORM、retained 输入和短事务边界仍约束升级。验收必须包括真实受限登录、晚到结果、取消时物理关闭、提交回包丢失与 replay，不是只比较 HTTP 200 或测试超级用户。问题单中的绕路保持未修复；管理看板固定活跃分已由 [#158](https://github.com/YOAO-Labs/ai-annotation-platform/issues/158)跟踪，本次不重复建单。

## Alternatives Considered

- **用普通 HTTP 统一替代借用连接的能力：** 无法继承 Session 的脏对象、保存点、行锁和外层 rollback；异步工作须使用已接受的持久命令，不从跨库调用猜测提交。
- **把权限、业务和物理状态压成一个标志：** 既无法阻止撤权后发布，也无法证明旧执行、对象句柄或不明的 PUT 已关闭；会造成迟到写入、静默掉消息或删除已发布的 bytes。
- **用全量 refresh/expire 或扩大数据库授权隐藏物化差异：** 破坏原缓存与部分 flush，可能多读私表、错误合并行或跳过限制；需要修复的兼容缝以问题单和对照矩阵收口。
