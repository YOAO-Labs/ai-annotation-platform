# 在线学习闭环多阶段计划草案

> 用户已委托实施代理逐阶段确认与验收。阶段 A–E 的首批范围已完成，验收记录见 [A 数据版本](../archive/1791972267_online-learning-phase-a.md)、[B 平台训练](../archive/1791975133_online-learning-phase-b.md)、[C 模型回流](../archive/1791979058_online-learning-phase-c.md)、[D 自动触发](../archive/1791982370_online-learning-phase-d.md)、[E LibreYOLO](../archive/1791983290_online-learning-phase-e.md)。

后续训练参数、配置体验、实验分析与能力扩展的交付记录见 [已归档的训练体验总览](../archive/1792035920_online-learning-experience-roadmap.md)。T01–T14 已完成各自范围的验收；本文保留初始规划与尚未完成资格验证的任务边界，不将首批 A–E 的授权扩展至新增能力。

在线学习围绕“标注完成 → 数据版本 → 训练 → 模型评估 → 回流预标注 → 人工修正”展开。采用按批次迭代的训练方式，每轮固定数据、参数和模型来源，先支持人工触发与人工发布，再扩展自动触发和其他训练框架。

保留草图中的项目层、训练层、导出层、模型回流层。最小闭环覆盖阶段 A、B、C，首个训练器选择 Ultralytics，首个任务类型选择图片目标检测。第二训练器已由需求方确定为 [LibreYOLO](https://github.com/LibreYOLO/libreyolo)，在阶段 E 核验其检测训练与推理合同。

首批交付支持两种训练器的图片检测训练、续训和产物下载，以及 Ultralytics 模型注册、人工发布、回流修正和默认关闭的自动训练策略。LibreYOLO 平台模型回流及其他任务类型仍为后续范围，不从训练成功推断精度提升。

## 目标与边界

用户能够在项目内选择合格标注生成训练数据版本，启动训练、查看过程、下载模型，并将选定模型版本用于后续预标注。每条预标注结果可以追溯到模型版本、训练实验和数据版本。

首轮覆盖单项目、图片检测、单任务单 GPU、人工启动、人工发布。保留原有离线导出入口，新增训练数据版本入口。第一轮训练使用基础权重，后续可选择兼容的自训练模型初始化。

首轮不包含逐样本实时更新参数、未经审核的预测自动充当真值、跨项目训练集合并、多机分布式训练、任意上传脚本执行或自动替换线上模型。主动学习选样属于后续单独规划，不作为阶段 D 自动触发的隐含范围。

最小替代方案是离线下载数据包、手工训练和手工部署。阶段 A 保留这个独立可用的结果；继续建设 B、C 的收益是统一执行状态、模型身份、类别映射及回退，减少数据与模型来源丢失。

## 总体流程与对象关系

```text
项目标注与审核
    ├── 原有离线导出 → 下载
    └── 冻结训练数据版本
             │
             ▼
       Bridge 格式转换 → 可下载训练包
             │
             ▼
       训练队列与 GPU 分配
             │
       ┌─────┴──────┐
       ▼            ▼
 Ultralytics 容器  其他训练器容器
       └─────┬──────┘
             ▼
       指标、日志、模型产物 → 下载
             │
             ▼
       评估与模型版本注册
             │
             ▼
       加载检查与人工发布
             │
             ▼
       预标注 → 人工修正与审核
                         │
                         └── 下一轮数据版本
```

反馈形成业务闭环，每次运行内部的数据依赖为有向无环关系。新版本只能引用既有数据或模型版本，不能覆盖其父版本。

| 对象         | 核心信息                                                         | 生命周期约束                                   |
| ------------ | ---------------------------------------------------------------- | ---------------------------------------------- |
| 训练数据版本 | 项目、来源范围、冻结标注、类别映射、素材摘要、划分清单、内容摘要 | 就绪后不可变；被实验引用时禁止直接删除         |
| 训练配置快照 | 训练器及镜像摘要、基础权重摘要、参数、随机种子、Bridge 版本      | 实验创建时冻结；不追随模板后续修改             |
| 训练实验     | 数据版本、配置快照、父模型、执行尝试、当前状态                   | 独立保存长期来源；统一异步任务承接运行展示     |
| 执行尝试     | 任务标识、运行节点、GPU、进程身份、心跳、日志、结束原因          | 重试生成新尝试；迟到消息不能改写后续尝试       |
| 训练产物     | 权重、配置、指标、日志、大小和校验值                             | 上传完成并校验后才可见；不复用临时导出生命周期 |
| 模型版本     | 来源实验、权重、任务类型、类别定义、评估记录                     | 不可变身份；注册不自动启用                     |
| 发布记录     | 项目、模型版本、类别绑定、推理目标、操作者、前一发布             | 并发更新受版本校验保护；支持切回上一发布       |

上述是领域对象，最终建表与复用关系在各阶段实施计划中明确，不要求每个对象独立建表。

## 阶段划分

| 阶段               | 独立交付结果                             | 依赖               | 工作量判断                     |
| ------------------ | ---------------------------------------- | ------------------ | ------------------------------ |
| A 数据版本与训练包 | 用户可下载固定、完整、可直接训练的数据包 | 现有项目与导出能力 | 中，重点是一致性和素材保全     |
| B 平台内训练       | 用户可在平台训练并下载产物               | A                  | 大，新增执行服务和任务协调     |
| C 模型回流         | 自训练模型参与预标注并能回退             | B                  | 大，涉及模型身份、协议和路由   |
| D 自动触发         | 合格数据变化后自动生成候选模型           | C                  | 中，重点是幂等、权限和资源约束 |
| E 多训练器扩展     | 第二类训练器拥有完整训练与产物流程       | B；回流依赖 C      | 由目标框架与素材合同决定       |

A → B → C → D 为主线；E 在训练与回流合同稳定后启动，不阻塞 D。每一阶段都必须在后一阶段不交付的情况下保持可用。表中的工作量用于拆分，不承诺工期；实施排期由维护者在精确范围和运行环境核实后确定，不预设发布版本号。

## 阶段 A 数据版本与训练包

### 交付范围

项目内新增“在线学习 / 数据版本”。用户选择项目或批次范围，查看纳入和排除统计，创建固定版本并下载 Ultralytics 检测训练包。采用项目既有审核语义识别合格标注；无审核流程的项目需由项目负责人显式确认本轮数据，快照记录该确认，不能仅凭“有标注”视为合格。

数据版本冻结标注内容、类别表、样本身份、原始素材摘要和数据划分。复制素材到独立训练存储中的项目与版本前缀，避免源素材删除或下载签名过期破坏训练。首版优先完整复制，去重在存储成本成为瓶颈后再优化；数据版本就绪前必须完成素材校验。

冻结以一致的数据库读取结果为基准，再物化素材；数据库事务不贯穿整个素材复制过程。复制时校验读取到的对象版本或摘要，发现素材变化则失败，不生成混合时点的就绪版本。标注快照必须保存内容，单独保存活记录 ID 不足以冻结。

Bridge 只负责转换冻结快照、校验与生成报告。Ultralytics 产物包含图像、标签、`data.yaml`、平台到训练类别的映射和来源清单。首版仅接收图片矩形框；包含不支持几何时预检阻止，用户修改范围后重新创建，禁止静默丢弃。

### 数据划分与质量规则

- 建议首次划分为训练 80%、验证 20%，按素材来源组和重复内容分组，保存实际划分清单和随机种子。这是草案建议值，不是现有配置。
- 后续版本继承已存在样本的分区，新样本才参与分配；同一来源组不得横跨分区。未来支持视频时按视频或场景分组。
- 以验证集选择 checkpoint；独立测试集供发布评估使用，不参与训练调参。没有独立测试集时页面明确显示评估范围，仅支持人工试用判断，不宣称泛化提升。
- 验证集内容变化即生成新的评估基准标识；不同基准上的分数不直接显示为新旧提升。
- 类别编号在版本内冻结，类别新增、删除、重命名产生新版本，并重新校验基础模型兼容性。
- 空白待标样本不得当作负样本；只有明确确认无目标的合格样本才可进入负样本集合。
- 空训练集、空验证集、缺失素材、非法框、缺失类别映射均阻止生成就绪版本。样本不足以完成分组划分时展示原因，不自动混用样本。

### 验收与回退

在独立测试项目中验证：创建期间编辑标注不会改变快照；源素材变化能够被发现；下载包经训练器数据加载器读取成功；负样本和类别编号正确；重复图片不跨分区；越权读写被拒绝；失败重试不留下可见半成品。

关闭新建入口即可停止该功能，原有导出继续工作。已就绪快照保持可下载；无引用的失败暂存对象可清理，不能因回退功能自动删除已完成的数据版本。

## 阶段 B 平台内训练

### 交付范围

项目内新增“训练实验”，流程为选择数据版本、训练器和基础权重、配置参数、检查并启动。基础模型从核实兼容的受控目录选择；本阶段支持下载 `best.pt`、用于断点恢复的 checkpoint、配置、指标及日志。

训练执行器从平台领取任务，在受控容器内调用框架原生训练接口。Celery 承担准备和协调工作，GPU 训练放在独立执行单元，避免长训练占用普通业务 worker。首版只运行管理员配置的镜像与参数白名单，不接受用户脚本或任意容器镜像。

实验状态为“排队 → 准备数据 → 训练 → 评估 → 上传产物 → 成功”，并有“取消中、已取消、失败、执行失联”分支。以实验及其执行尝试作为领域状态来源，后台任务状态由同一服务同步，不能维护两个独立推进的状态机。

单任务独占一个已分配 GPU。训练与在线推理使用明确分开的资源分配，资源不足时排队。当前主机拥有两张 RTX 3090。用户已确认现阶段推理不在使用，并同意训练限用其中一张；训练执行器固定暴露第二张卡，单卡同时只运行一个训练任务。部署和验收记录实际物理 UUID、设备可见性与执行环境，不能仅靠逻辑 cuda:0 判断卡身份。

### 故障处理

| 故障                  | 行为                                                             |
| --------------------- | ---------------------------------------------------------------- |
| 重复投递或重复点击    | 创建请求幂等；执行尝试通过租约领取，已有活进程时不得重复启动     |
| worker 重启或心跳丢失 | 先根据容器身份核实存活；确认停止并回收租约后才允许新尝试         |
| GPU OOM 或非法参数    | 记录错误并结束尝试；用户调整参数后创建新实验，不静默改变训练配置 |
| 用户取消              | 发出停止请求，确认进程退出才标记已取消并释放 GPU                 |
| 上传失败              | 保留受控暂存产物并重试上传；不因上传失败重跑完整训练             |
| 存储空间不足          | 预检拒绝或明确失败；清理本次未完成暂存，不删除其他实验产物       |

恢复同一中断训练必须使用原数据、配置及兼容运行环境；如果数据或参数变化，创建新实验并记录父模型，不能伪装成原任务恢复。

### 验收与回退

先做 CPU 数据加载测试，再在隔离 GPU 资源上完成小规模真实训练。检查日志、指标、产物、取消、失联协调、重复投递和断点恢复；测试中确认旧尝试的迟到回报不能覆盖新尝试。产物校验失败不得呈现为训练成功。

回退时停止领取新任务，完成或明确取消运行中的任务，保留实验和产物，平台仍可使用阶段 A 的离线训练包。执行器不可用不应阻断标注、导出和现有推理。

## 阶段 C 模型注册与回流

### 交付范围

项目内新增“模型版本”，支持从本平台训练产物注册候选模型、查看指标与来源、试用、发布和回退。首版只允许注册本平台受控训练得到的权重；外部权重导入另行评估，不与已有预测文件导入混用。

注册表单显示名称、任务类型、来源实验、数据版本、基础模型、权重摘要、评估报告以及模型输出类别到项目类别的绑定。先完成类别绑定和推理兼容检查，再创建发布记录。未经完整映射的类别不得默默按名称猜测。

模型版本、后端物理实例、服务池保持不同身份。扩展 YOLO 自定义权重加载能力，模型池键和类别缓存包含模型版本身份及权重摘要；兼容旧预训练模型的选择方式。缓存淘汰不能卸载仍被请求使用的模型。

推理任务在创建时固定模型版本及类别绑定版本。发布仅改变新任务的选择，不改变运行中任务及历史预测；预标注结果记录模型版本、实验与数据版本来源。

### 发布与评估

发布顺序为产物校验、受控加载、类别与输出检查、小样本推理、项目负责人确认、原子更新项目发布选择。目标服务池中只有确认能够提供同一模型版本的实例可以接收该版本请求，禁止失败后悄悄切换模型。

比较新旧模型时使用同一固定评估清单，展示 mAP、Precision、Recall、分类别结果及推理耗时。框架与评估配置不同、类别范围不同或基准不同的报告分开展示。精度分数只作为依据，发布还需抽样确认误检、漏检和人工修正成本。

本方案假设自训练模型可以改善目标项目的标注效率。若同一基准或试用任务上没有改善，则保留旧发布，候选模型仍可下载和研究；训练成功不等于必须发布。

### 验收与回退

完成真实闭环：阶段 B 模型注册 → 加载检查 → 项目预标注 → 人工修正与确认 → 下一数据版本。并验证同一任务类型的两个模型不会串用类别、跨项目模型不能越权使用、损坏权重不能发布、并发发布不会互相覆盖、服务池缺少权重的实例不会接流。

发布前记录上一个可用发布。回退时先验证旧模型在目标推理资源上可用，再原子切换项目选择；当前运行任务继续使用其固定版本。候选、历史模型和结果不随回退删除。

## 阶段 D 自动触发训练

### 启动条件与交付范围

阶段 C 的人工闭环已通过真实验收，取消、失联协调和资源排队可靠，且项目负责人明确启用策略后，才开放自动触发。默认关闭，不自动发布模型。

支持按新增或修正的合格训练样本数量触发，以及定时检查触发。策略保存项目范围、训练模板、变化门槛、冷却时间和资源限制；启用时要求填写并校验必要参数，不凭草案猜测适用于所有项目的数量阈值。

只统计训练分区内的有效内容变化，同一素材的重复事件合并；验证集变化产生新基准，不作为训练样本数量增长。每个项目首版最多一个自动实验处于活跃状态，其间新增变化合并为后续待处理版本。

以策略版本和数据内容摘要生成触发身份，并通过数据库唯一约束及事务协调防止重复。记录已排入的候选摘要与最近成功训练摘要，失败不得吞掉尚未学习的数据变化；同一失败候选等待人工处理或策略重新启用，避免无限重试消耗 GPU。

策略执行采用可审计的项目授权，每次冻结数据和启动训练前重新检查权限。负责人失权、项目停用或策略关闭后停止后续自动入队；已运行任务遵循显式取消流程。

### 验收与回退

模拟事件重复、定时任务重叠、训练期间新增样本、训练失败、权限撤销和策略关闭，保证同一候选不会重复启动，数据变化不会因失败丢失，训练产物不会自动替换线上模型。

关闭策略即停止新触发，保留手工训练、数据版本、运行记录和当前发布。对于关闭时已排队的自动任务，取消尚未启动的任务；已经运行的任务在界面提供继续或取消操作。

## 阶段 E 多训练器与任务类型扩展

### 启动条件与合同

第二训练器已确定为 LibreYOLO，首轮沿用图片检测任务。阶段 E 仍需核对官方固定版本的输入样例、检查点、指标和推理产物合同；不得直接套用 Ultralytics 的同名参数或权重加载器。

训练器适配分为两部分：Bridge 转换冻结数据；Runner 运行训练、上报状态并整理指标和产物。共同合同包括能力声明、配置校验、输入准备、启动与取消、状态与日志、评估报告和产物清单。指标保留任务类型和语义，不把所有框架强行映射为 mAP。

新增训练器先完成可下载产物的独立路径；具备对应推理后端后，再接入模型注册与回流。Ultralytics 的分割、旋转框、关键点也逐项通过数据、指标和输出协议验证，不因框架支持就直接开放全部项目类型。

### 验收与回退

每个适配器通过同一组状态、取消、幂等、错误、产物摘要和来源追溯验收，再运行该任务类型的真实数据测试。支持回流的适配器额外完成小样本推理和旧发布回退。

禁用单个适配器的新建能力，不影响其他训练器。既有数据、实验、模型及已运行部署保留；下线推理能力需先迁移或回退其项目绑定。

## 页面与接口草案

页面采用项目内“在线学习”入口，包含概览、数据版本、训练实验、模型版本。模型市场继续承接推理能力与部署状态，两处用来源链接互相跳转。管理员配置训练执行资源，项目负责人操作数据、训练与发布；其他成员的查看权限沿用项目可见性，不默认开放下载或 GPU 操作权限。

以下路径表达拟新增接口边界，尚未实现；实施时统一加现有 `/api/v1` 前缀，并核对当前路由、权限及 OpenAPI 约定。

| 阶段 | 接口族草案                         | 行为                                                   |
| ---- | ---------------------------------- | ------------------------------------------------------ |
| A    | `/projects/{id}/training-datasets` | 预检、创建、列表、详情、受权下载                       |
| B    | `/projects/{id}/training-runs`     | 创建实验、列表、详情、日志、指标、取消、恢复、下载产物 |
| C    | `/projects/{id}/trained-models`    | 从受控产物注册、查看版本、加载检查、评估               |
| C    | `/projects/{id}/model-releases`    | 发布历史、创建发布和回退；原子更新项目选择             |
| D    | `/projects/{id}/learning-policies` | 配置、启停、触发记录                                   |
| E    | `/training-backends`               | 查询管理员配置的训练能力；不暴露任意远程地址或脚本执行 |

创建异步操作返回任务标识，详情查询返回领域对象与当前执行状态。变更请求支持幂等或版本校验，列表分页，日志有界读取；对下载签名重新鉴权，不能将签名 URL 当永久对象身份。

## 存储与运行边界

- 训练数据与模型产物使用持久对象空间，临时目录使用尝试标识隔离。可重建的格式转换缓存以数据摘要、Bridge 版本和配置作为身份。
- 被实验、模型或发布引用的产物禁止直接删除。用户主动删除项目或需要清除数据时，必须展示依赖并执行统一生命周期流程；不得因源项目级联删除导致模型来源记录悬空。
- 完成、失败和取消后清理执行器工作目录；已经验证并持久化的日志与产物保留。异常清理只处理本次拥有的对象，不能按宽泛目录或桶名删除。
- 首版不要求第三方账号或云训练 API Key。部署需要管理员配置限定范围的对象存储访问和平台到执行器的认证，训练容器只获得本次输入与输出范围，不携带平台管理员令牌。
- 不新增用户必须设置的环境变量；服务端部署配置在实施 B 时根据现有环境配置机制明确，并同步 `.env.example`、生成的环境变量文档与 `DEV.md`。
- 数据量扩大十倍时优先流式复制与校验、复用已完成版本、限制执行并发；避免一次把全部图像或标注载入内存。存储容量和作业耗时依据真实样本测量后设置边界。

## 验证与文档交付

| 验证层     | 重点                                                               |
| ---------- | ------------------------------------------------------------------ |
| 数据与转换 | 快照一致性、类别映射、分组划分、负样本、非法几何、缺失素材         |
| API 与权限 | 项目隔离、撤权、下载权限、幂等、并发更新、非法状态迁移             |
| 执行器     | 真实小规模训练、OOM、取消、失联、重复投递、产物上传和恢复          |
| 推理回流   | 自定义模型加载、模型与类别缓存隔离、服务池版本一致、来源记录与回退 |
| 浏览器     | 完整创建流程、刷新后状态恢复、失败信息、日志、下载、发布与回退     |
| 自动策略   | 重复事件、重叠调度、失败后的变化保留、关闭与权限撤销               |

每个实施阶段只运行与本次变更相关的验证。数据库测试使用已验证归属的可丢弃数据库，Python 优先使用当前 checkout 的虚拟环境。浏览器验收使用独立项目和素材；结束后清理测试项目、存储对象、容器、GPU 进程及临时报告，保留的验收证据明确登记。

阶段实施后按影响执行现有检查：`pnpm lint:python`、`pnpm --filter @anno/web lint`、`pnpm --filter @anno/web typecheck`；样式涉及语义 token 时执行 `pnpm --filter @anno/web lint:css-tokens`；API 变更同步生成物并运行 `pnpm openapi:check`。具体测试文件和执行命令在阶段转为实施计划时确定。文档草案本身仅需格式、链接及 `git diff --check` 检查，不启动应用或训练任务。

实现时同步交付用户指南、API 文档、在线学习架构说明、训练执行器运维说明与 `CHANGELOG.md` Unreleased 条目。涉及权重托管和模型身份的架构决策记录到 ADR。当前草案不修改用户指南来宣称尚未存在的功能，也不调整应用版本。

## 转为实施计划的条件

每个阶段开始前重新核对当前代码、活动计划和迁移状态，列出该阶段的精确文件清单、数据迁移及兼容策略、运行环境、测试命令和人工验收步骤；按照 [promotion gate](README.md#promotion-gate) 将相应计划转到活动目录。

阶段 A 前需要确认真实审核语义、首批图片检测样本和素材保留策略；阶段 B 前需要核实独立 GPU 资源、容器启动与认证方式；阶段 C 前需要核实当前模型选择协议、服务池路由和项目类别绑定；阶段 D 前需要项目负责人明确自动触发参数；阶段 E 前需要确认第二训练器及输入输出合同。各条件有明确负责方和所影响阶段，不阻塞已满足条件的独立交付。
