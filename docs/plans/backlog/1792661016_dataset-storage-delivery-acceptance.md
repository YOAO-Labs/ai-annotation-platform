# 实施路线、依赖与跨 Epic 验收

> 状态：research-draft；未排期，未批准实施，未分配发布版本。
> 转入日期：2026-10-22；本地核验基线：`e169d9ef53a9eda60abd4e67bf553ab4e6ab618e`。
> 实施前须通过 [backlog promotion gate](README.md#promotion-gate)。[草案总览](1792661016_dataset-storage-roadmap.md)、[架构契约](1792661016_dataset-storage-architecture.md)和[交付验收](1792661016_dataset-storage-delivery-acceptance.md)共同约束本系列。

> 阶段是能力门槛，不是固定日历承诺。Epic 的基础切片可以先交付，不要求同一 Epic 的全部增强项一起上线。

## 1. 实施原则

首期交付“已有图片目录 → 可用数据集 → 标注”的完整业务链。对象存储选型试验可以并行，但替换 MinIO 的生产切换单独进行。跨站点 Agent 只有在共享挂载或直接连接无法满足部署条件时才进入实施。

底层抽象、权限保护、内容一致性和已有训练冻结能力的兼容属于首期必要条件。它们不能以“治理属于后续 Epic”为由推迟。

## 4. 推荐实施批次

### 批次 A：先解除身份与名称耦合

- 盘点所有通过数据集名称推导路径的读取/写入/扫描入口。
- 引入位置和业务用途绑定的兼容层；历史对象按现存键解析。
- 新写入用稳定 ID；历史 checksum 标记算法和可信来源，ETag 独立。
- 回填保持 DatasetItem、任务、Scene 和版本 ID 不变。
- 用当前上传、扫描、标注、视频及训练链路证明兼容层不改变既有结果。

建议作为可独立上线的基础批次，避免与生产对象存储切换一起排障。

### 批次 B：打通一个受控目录

- 只读挂载一个试点图片根，指定可访问的 reader/worker。
- 支持受控路径选择、异步预检、原地登记、有限并发校验和统一读取。
- 把未校验、不可读、内容变化与仅预览状态贯穿 API 和 UI。
- 完成一条真实标注的读取/提交、历史数据集回归；选择该数据集已关联项目，通过现有训练版本流程完成单目录最小冻结。

### 批次 C：替换页面重复入口

- 数据集独立详情，存储位置独立详情。
- 数据连接器配置并入存储位置；旧入口兼容跳转。
- 清理错误容量命名、硬编码供应商/协议、重复的数据集列表。
- 使用同一可用性和权限契约；原有后台任务入口按上下文过滤。

### 批次 D：将目录变化纳入日常操作

- 定时扫描、完整扫描世代、增删改差异确认、按文件重试与任务恢复。
- 质量筛选、保存视图、来源筛选、项目上下文统计。
- 外部原图变化与冻结训练版本的冲突和失效路径验证。

### 批次 E：对象存储生产迁移

- 候选通过应用兼容性测试，完成全用途对象清单与内容校验。
- 先演练迁移和恢复，再冻结写入、最终增量、切换、观察。
- 单独设置迁移完成和旧后端退役门槛，保留可核验的回滚资料。

### 批次 F：按真实需要扩大到跨站点

- 根据真实机器/网络清单决定哪些位置需要 Agent，哪些直接挂载即可。
- 演练断连恢复、凭据吊销、任务幂等与带宽控制。
- 扩展近端缓存和训练清单消费，不要求所有站点完整复制所有数据。

## 5. 验收数据与环境

建立可重复的测试集：

- 基本图片目录：多层子目录、中文/空格/长文件名、同名不同内容、同内容不同路径、空目录、损坏图片、非图片文件。
- 变化目录：扫描中追加/覆盖/改名/移动/删除，权限变化，保留大小/时间戳但改变字节的对照项。
- 访问边界：正常子目录、`..` 越界、绝对路径、越界符号链接、目录挂载消失或被替换。
- 项目样本：同一数据集关联两个项目，分别具有不同任务/标注状态；已有 Scene 和训练冻结版本。
- 兼容样本：现有托管图片、视频播放/抽帧、已导入 S3/SFTP 数据、导出包和训练包。
- 运维样本：来源离线、对象存储失败、worker 重启、任务重复投递、缓存满和数据库暂时故障。

性能验证采用实际规模加一个放大档位。可建议 1 万和 10 万图片作为参考档位，但必须在经配置允许的文件/字节预算内运行；不绕过现有导入上限。记录机器、磁盘、网络、格式分布、平均/最大文件大小和并发，不能只记录“支持十万张”。

## 7. 性能与可观测性目标

以下是验证方法与工程目标，**没有任何数值被声明为当前项目实测**。

| 项目       | 必须采集                                   | 放行依据                                                     |
| ---------- | ------------------------------------------ | ------------------------------------------------------------ |
| 数据集列表 | p50/p95响应、DB查询量、分页大小            | 随样本规模增长仍使用分页；无每请求全桶扫描                   |
| 首次扫描   | 枚举/校验速率、RSS峰值、错误率、队列长度   | 内存与并发有界；进度真实；达到经代表环境校准的目标           |
| 增量扫描   | 新/变/缺失计数、实际读取字节、耗时         | 无变化目录避免无意义重复物化；严格校验边界不能被性能优化绕过 |
| 原图/预览  | 首字节与完整响应延迟、缓存命中、失败码     | 离线/变更不返回错误内容；大图读取有取消与超时                |
| 冻结版本   | 源校验耗时、冻结占用、失败样本报告         | 已 ready 版本内容固定，失败不产生伪 ready 状态               |
| 统计面板   | 统计耗时、`measured_at`、来源、误差/未知项 | 页面使用快照或聚合，不触发全存储遍历                         |
| 迁移/恢复  | 字节数、差异数、抽检/全检范围、RPO/RTO实测 | 能解释检查覆盖率，关键引用完整，无静默数据丢失               |

各阶段记录同一批代表数据的基线和改造后结果。阈值由 M0 的实际环境确定；不能以“体感快”或未经来源支撑的供应商吞吐量替代。

## 8. 上线与回滚

### 功能上线

建议按位置/数据集启用：内部样本 → 一个真实试点目录 → 扩大用户。每步保留源清单、作业报告、读取错误率与回滚条件。权限失败、内容错配、历史版本不可读是停止扩量条件。

### 应用层回退

本系列采用保留schema的受控应用回退：停止旧写入方，以独立数据库和对象存储只读权限启动维护入口；旧托管数据按已核验内容读取，已有reference索引保留且不被旧代码误写误删，外部原件仍由当前兼容应用读取。旧版本的具体页面可用范围按实际演练记录，不以应用启动成功代替。独立读取开关、双路径回退及回退计数已由用户明确删除；不在紧急回退中删除身份映射或改写历史对象键。操作和已知限制见[受控只读应用回退](../../../docs-site/ops/upgrade-guide.md#数据集存储的受控只读应用回退)。

### 存储层回退

以 E07 的执行手册为准。切换后旧后端的副本可能已经过时，必须核对新写入、删除标记、元数据与用途绑定。回退前再次冻结写入并反向同步/验证；不能仅修改 endpoint。

## 10. 统一完成定义

- 需求、数据/接口、UI 和异常行为与共同契约一致。
- 必须验收通过，包含内容错配、越权、离线和重复执行等负例。
- 旧流程兼容与历史数据迁移有证据；未完成项明确标记，而非隐含跳过。
- 操作有日志/任务记录，指标有时间和来源；敏感信息不进入普通响应。
- 配置、部署、故障定位、回滚和恢复文档随功能交付。
- 性能结论附环境和数据，不把估算当实测。
- 完成评审的待决策项落到记录；未启用能力明确停留在后续阶段。
