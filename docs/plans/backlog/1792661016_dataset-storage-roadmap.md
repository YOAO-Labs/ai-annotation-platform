## 1. 这轮升级要实现什么

让已有图片目录直接成为平台中的数据集：图片可以留在服务器磁盘、NAS 或其他允许访问的位置；平台建立目录索引和业务关系，用户能够预览、关联项目并开始标注。平台继续支持上传文件、复制托管和对象存储，但创建数据集不再必然意味着把原图复制到一个统一的桶里。

同时重新划清两处界面的职责。**数据集管理负责“有哪些数据、如何使用这些数据”**；**存储管理负责“数据在哪里、连接是否可用、平台占用了多少空间”**。两页共享同一套状态与统计定义，用上下文链接连接操作，避免重复维护列表、指标和配置表单。

已有目录接入是本次主线。MinIO 替换是独立的基础设施改造线：可以并行试验，生产切换以兼容性与回滚演练通过为条件，不阻塞首期目录接入。

## 3. 已确认方向与草案默认

### 3.1 来源材料明确的产品目标

- 已有图片目录可以原地注册；不会要求用户先整理成 MinIO 桶。
- 数据集管理与存储管理需要消除重复信息和操作。
- 需要支持数据不集中存放，以及多机器部署的后续演进。

### 3.2 为便于推进采用的草案默认

- 首期面向服务端或受控 worker 可访问的只读图片目录；NAS 通过受控挂载进入同一模型。
- 浏览器用户选择自己电脑的目录属于上传流程；无法凭浏览器路径持续访问另一台电脑的磁盘。不可直连的站点在 E06 接入 Agent。
- 原图策略为“原地引用”或“复制托管”；是否生成预览、按需缓存单独设置。
- 外部源只读，移除数据集不删除其原图。源内容变化生成待处理差异，不静默替换已有任务的图片。
- 首期重用现有 Celery/AsyncJob、全局后台任务入口、项目关联和训练版本体系。
- SeaweedFS 与 RustFS 进入候选验证；最终生产后端由测试结果与实际运维约束决定。
- 首期新任务和冻结版本必须执行内容一致性校验；目录数据集在选定项目标注上下文后可进入现有最小冻结流程。仅文件名、大小和修改时间不足以证明内容未变。

这些默认已经足够产出可评审的方案，不需要为了每个实现细节暂停推进。需要产品/技术正式决策的条目集中于[架构与决策](1792661016_dataset-storage-architecture.md)。

## 6. 首期最小闭环

首期不是只做一个“扫描目录”按钮。一次验收应完整走通以下过程：

1. 管理员把已有图片目录作为只读受控根暴露给读取 worker，注册存储位置并验证可达性。
2. 数据集管理员从允许范围内选择子目录，预检文件数量、格式、不可读项与可能的缓存占用。
3. 选择“原地引用”后建立数据集索引；原目录没有新增、修改、移动或删除，平台未自动生成整份原图副本。
4. 用户浏览样本，看到内容校验进度以及“原图可读 / 仅预览可用 / 暂不可用”的实际状态。
5. 有权限的用户关联项目，在内容一致的图片上完成一条标注；项目页面仍是任务和标注进度的权威入口。
6. 数据集改名后样本仍可读；重复扫描不产生重复样本或重复任务。
7. 源目录短暂离线时，不把整个目录误判为文件被删除；预览缓存与原图可用性分别显示。
8. 从已关联项目为该目录生成最小冻结训练版本；随后源文件被覆盖时，旧任务不显示新字节，已冻结版本继续读取原有内容。
9. 移除数据集前展示业务影响；外部原图不被删除。

详见[跨 Epic 验收矩阵](1792661016_dataset-storage-delivery-acceptance.md)。

## 7. 这轮继续沿用的能力

当前项目已经具备外部 S3/SFTP 导入、连接凭据加密、异步任务与取消、数据集多项目关联、时序 Scene 和训练冻结版本。现有训练能力还包含分组切分、重复图冲突检查和版本分析。因此本方案围绕扩展这些能力编排工作，不把它们重复列为从零建设。事实与代码入口见[基线文档](1792661016_dataset-storage-baseline.md)。

## 8. 完成评审的判定

- 产品评审确认目录接入、页面边界、原图变化与删除行为。
- 技术评审确认样本/内容/位置模型、旧接口兼容策略和授权边界。
- 运维评审确认首期可达目录、挂载方式、候选对象存储试验环境及恢复要求。
- 测试评审确认正常、重复、离线、变更、越权、回滚和恢复场景。
- 根据真实数据规模和团队投入对 Epic 拆任务及估时；本草案不虚构交付日期或吞吐量。
