## 1. 核心用户结果

用户已经有一个图片目录，例如服务器上的 `/data/traffic/camera-a/2026-10/`。管理员把它作为受控只读位置开放后，用户选择该目录并注册，平台即建立可浏览、可关联项目、可用于标注的数据集。首次注册不要求把目录里的原图复制进对象存储。

“原地”不代表没有元数据或派生文件。数据库索引、缩略图、按需缓存和训练版本冻结副本分别产生并分别计量；原图所有权仍在来源目录。

## 2. 当前基础与缺口

现有导入向导支持本地文件、压缩包和外部连接来源；后端导入 worker 通过 source adapter 读取内容，再调用 `ingest_one` 存入统一 datasets 桶。该能力适合“复制导入”，需要新增“只注册引用”路径。[代码依据：导入向导](../../../apps/web/src/components/datasets/ImportDatasetWizard.tsx)、[导入 worker](../../../apps/api/app/workers/dataset_import.py)、[数据集服务](../../../apps/api/app/services/dataset.py)

当前 Docker 部署已经支持自定义 MinIO 数据目录，但更换 MinIO 挂载磁盘不会让已有业务目录自动成为数据集。本 Epic 解决的是注册与访问语义。[代码依据：部署配置](../../../docker-compose.yml)

## 3. 范围

### M1 必须实现

- 管理员配置的服务器目录或已挂载 NAS，共享给指定扫描/读取 worker。
- 在受控根内浏览、选择相对目录、按扩展名/规则过滤、递归与非递归扫描。
- 预扫描、显示影响、确认注册、查看任务进度与部分失败。
- `reference` 与既有 `managed_copy` 两种原图策略；选择与缓存策略相互独立。
- 逐批登记样本，分离“已索引”“可用”“待校验”“异常”计数。
- 已注册样本通过统一文件访问链路进入项目和标注流程。
- 源目录只读；删除数据集或解除关联不删除外部原图。

### 后续切片

- 外部 S3/SFTP 的持续原地引用，通过同一来源模型扩展。
- 远端不可直连机器上的目录，通过 E06 Agent 接入。
- 自动监听、周期同步、来源变化裁决，归 E04。

### 暂不做

- 直接让网页通过任意本机绝对路径读取用户电脑文件。
- 把浏览器“选择文件夹上传”描述为原地注册。
- 自动修改源目录、整理文件名、移动图片或删除重复文件。

## 5. 建议交互流程

1. 从数据集列表点击“创建数据集 / 接入已有数据”。
2. 选择“已有服务器目录”；仅列出用户有权使用的位置。
3. 选择位置和根内相对目录，设置递归、图片类型和排除规则。
4. 原图策略默认“保留在原位置”；单独设置预览缓存。界面列出托管复制作为另一个明确选择；复制可以从只读来源读取，但目标必须是另一个允许写入的位置。
5. 运行预扫描；展示可接入数、预计原图体量、被排除数、不可读/损坏数、同路径已登记数。
6. 显示影响：“原图复制量 0；将新增元数据；若启用预览将产生派生文件”。预览大小不能精确预测时标注估算。
7. 确认后创建数据集和 DatasetSource，启动注册任务；关闭页面后可在现有全局任务入口继续查看。
8. 数据集详情显示逐批可用样本、来源摘要、最后扫描时间和异常处理入口。

预扫描与正式注册之间文件可能变化，因此预扫描只是带时间戳的计划；正式执行必须重新核验条目，不承诺数字完全一致。

## 6. 后端行为与失败语义

### 受控目录

- 客户端提交 `location_id + relative_root`，不提交任意宿主机绝对路径。
- 浏览、扫描和读取全部校验根目录边界；仅检查前端输入不够。
- 默认不跟随符号链接；确需支持时必须解析后仍在允许根内，且检测循环。
- 目录由操作系统只读挂载或最小权限账号保护；应用层也不提供源目录写入操作。
- worker 启动时报告位置可达性；路径在 API 容器中存在不代表扫描 worker 可访问。

### 登记与可用性

- 枚举按页或流输出，逐批事务提交；不把十万条文件记录攒到单个事务。
- 同一来源同一路径重复注册保持幂等；跨路径相同内容形成重复候选，不自动合并业务身份。
- 上述重复候选规则针对新原地来源；现有复制导入的重复跳过策略首期保持兼容，统一策略如需调整另行评审。
- 允许先登记元信息，随后流式读取并校验内容、提取尺寸；逐个样本变为可用。
- “待校验”样本不直接用于标注或冻结；首次使用可触发优先校验，不要求等待整个目录全部完成。
- 可读文件可生成缩略图；生成失败不把原图判定为丢失。
- 正在被采集程序写入的文件，可依据稳定窗口延后处理；窗口只能减少竞争，不能取代摘要校验。

### 异常分类

| 情况                         | 行为                                               |
| ---------------------------- | -------------------------------------------------- |
| 根目录不可达 / 无权限        | 停止该来源任务，保留已登记样本，不标记全目录已删除 |
| 单文件不可读 / 损坏          | 记录条目错误，继续其余文件；可单独重试             |
| 已存在相同来源路径且内容未变 | 跳过或刷新观测状态，不新增任务                     |
| 同一路径内容变化             | 标记 changed，交 E04 处理；不覆盖旧样本            |
| 扫描中来源断开               | 保存检查点和不完整扫描状态，重试时恢复             |
| 用户取消                     | 停止领取新批次；保留已提交部分，清楚显示实际结果   |

## 7. 数据与 API 草案

| 操作示例                                  | 关键输入 / 输出                                                                                       |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `GET /storage/locations/{id}/directories` | relative_path、cursor；返回授权范围内目录与可读性                                                     |
| `POST /dataset-source-plans`              | location_id、relative_root、filters、ownership_mode、cache_policy；返回 plan_id、观测时间、统计和异常 |
| `POST /datasets/{id}/sources`             | plan_id、配置版本、幂等键；返回 source_id、job_id                                                     |
| `POST /dataset-sources/{id}/register`     | 执行或继续登记；复用 AsyncJob 展示                                                                    |

这些是接口划分建议，最终可并入现有 datasets/storage API。路径浏览不能返回凭据、根外路径或其他未授权位置。

配置建议记录扫描规则版本、源路径、原图策略、缓存策略和首次计划快照。更改来源根与更改过滤条件均需重新预览影响；不能隐式解除全部旧样本。

## 8. UI 边界

数据集向导负责选择来源并解释数据结果。位置的主机、凭据、根授权由存储页面维护；缺少位置时可通过“申请/配置存储位置”深链进入，并返回原向导。普通标注员不必理解 NAS 协议、容器路径或 S3 endpoint。

来源详情只显示逻辑名称、相对目录、策略、样本数和最近状态。绝对路径与排障信息按权限显示。

## 9. 验收标准

| 编号     | 可执行验收                                                                                                                                      |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| E03-AC01 | 对含图片的受控目录选择 reference 注册，平台托管原件写入字节为 0（可选预览派生物另计）；源文件内容、名称和目录结构不变，元数据与派生文件单独记录 |
| E03-AC02 | 已校验样本可在数据集预览、关联项目并完成一次标注保存，无需再次上传该图片                                                                        |
| E03-AC03 | API 与 worker 路径映射不同或目录不可达时，预检返回具体位置错误，不能显示注册成功后空数据集                                                      |
| E03-AC04 | `../`、绝对路径注入、越界符号链接和循环链接均不能读取允许根以外内容                                                                             |
| E03-AC05 | 注册取消后再次执行，相同来源路径只产生一个有效登记关系，不重复创建关联项目任务                                                                  |
| E03-AC06 | 目录中部分图片损坏或仍在写入，其余稳定图片可用；错误明细可导出或分页查看并单项重试                                                              |
| E03-AC07 | 源目录离线时，已有索引与标注保留，明确显示原图不可用；可用缩略图不能被误标为原图在线                                                            |
| E03-AC08 | 删除数据集或解除来源时，按照 E11 处理引用；外部原图未被删除、改名或移动                                                                         |
| E03-AC09 | 预扫描后替换某张图片，正式登记重新检查，不能以旧扫描摘要登记新字节                                                                              |
| E03-AC10 | 用户选择本机文件夹时界面明确这是上传；不会承诺网页能持续读取未接入 Agent 的本机目录                                                             |

## 10. 测试与上线

测试数据包括空目录、深层目录、中文与空格文件名、大小写冲突、重复内容、只读图片、损坏图片、正在写入图片、挂载中断、权限收回。建议增加十万图片档位验证内存、数据库查询和任务恢复，数值目标在 M0 环境中校准。

先对测试目录和少量真实数据集开放入口；新来源默认只读。保持上传/压缩包/复制导入入口，以独立选项解释各自用途。

回滚关闭“新建原地来源”能力，但已经注册的数据仍通过兼容读取服务提供；若读取服务也需回滚，必须将对应数据集置为受控不可用，不能把相对路径交给旧 S3 逻辑处理。

## 11. 待评审与风险

- 支持的图片格式由现有解码链路验证后列出，不按扩展名直接承诺可标注。
- 目录频繁写入时的稳定等待时间需结合采集流程设定；推荐采集端先写临时文件再原子改名，但平台仍要校验。
- 大文件校验会产生来源读取负载，提供并发/带宽限制，并与 E12 指标联动。
- 外部源用户自行删除图片时，平台无法保证原件持久存在；冻结版本通过 E10 单独确保可复现。
