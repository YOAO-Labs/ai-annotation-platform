## 1. 任务目标与背景

### 1.1 要做什么

模型市场（`ModelMarket`）现在的观测**只覆盖图像类推理**（GPU / 图片变体池 / cache 命中按 `prompt_type=point/bbox/text`）。v0.10.35 已让 gsam2 把 **video 独立池**暴露进 `/health`，本版本补两件事：

- **A. 模型市场 image/video 标题分类**：观测面板按「图像推理 / 视频追踪」分组展示，显存 / cache / 延迟按模态拆分。
- **B. 视频追踪任务聚合监控**：`video_tracker_jobs` 当前只在工作台单 job badge 显示、**无聚合视图**；新增聚合端点 + 监控页（active/running/completed/failed），形态对齐图片侧 preannotate jobs 监控。

### 1.2 为什么做

- 有了真实 video tracker（v0.10.35）后，运维需要在一个地方看到：哪台 backend 在跑视频、video 池占了多少显存、有多少追踪任务在排队/失败——目前这些信息**散落且无聚合**。
- 模型市场的观测信息架构**无任何模态维度**，image 与 video 混在一起读不清。

### 1.3 关键现状（务必先理解）

## 2. 实现方案

### 2.A 模型市场 image/video 标题分类 + 预热控件按模态拆分

> **2026-05-22 设计修正（用户在 RegisteredBackendsTab 实测发现）**：原计划只想「并排展示 video 池信息」，但实测暴露更根本的问题——**预热控件本身对视频后端是错的**：
> - `VariantPanel` 的「预热」调 `/reload` → `_get_predictor(sv, dv)` → **图片池** `_pool`（[main.py:445](../../apps/grounded-sam2-backend/main.py)），加载的是 `grounded-sam2-dinoT-sam2.1tiny` 图片 predictor，**永远碰不到 video tracker**（video 用独立 `_video_pool`，首个 video_tracker 请求才冷启，[main.py:270](../../apps/grounded-sam2-backend/main.py)）。一个纯视频项目点预热 = 白占图片侧显存。
> - tracker（`sam2_video`）**不用 DINO**（DINO 只做图片侧 text→box grounding；视频直接拿 seed bbox 传播）。面板里的 DINO 下拉对视频追踪**完全无意义**。
> - `VariantPanel` 读的全是图片池字段（`health_meta.pool.loaded_variants` / `cache.buckets` / DINO enum），**无 video 池概念**。
>
> **决策（已拍板）：预热控件按模态拆成两套。**

**前置数据透传（两条链路都缺 video 字段，必须先补）**：
- `ml_client.health_meta()`（[ml_client.py:126](../../apps/api/app/services/ml_client.py)）白名单加 `"video_pool"`（现仅 `gpu_info/host/cache/model_version/pool`）→ 否则 `VariantPanel` 永远拿不到视频池。
- `ObserveTarget`（[admin_ml_integrations.py:297](../../apps/api/app/api/v1/admin_ml_integrations.py)）+ `_probe_one` 加 `video_pool` 透传 + `supported_trackers`（从 `/setup` 取，`_extract_variant_catalog` 旁边补一个 extractor）。

**后端新增 video 池预热入口（轻量，按模态拆分的应有之义）**：
- gsam2 `/reload`（[main.py:438](../../apps/grounded-sam2-backend/main.py)）`ReloadRequest` 加 `task_type: "image"|"video" = "image"`（默认 image，**向后兼容**）。`task_type="video"` 时走 `_video_pool.get(sv)`（**只认 sam_variant，不传 dino**），返回 `{ok, loaded, reloaded, sam_variant, task_type:"video"}`。
- 前端 `ml-backends.ts` 的 `reload(...)` 支持可选 `task_type`。

**前端 `VariantPanel.tsx` 拆两组**：
1. **图像推理变体**（现有内容归此组）：SAM+DINO 双下拉 → `/reload`（image）→ 图片池 `loaded_variants` / cache 命中 / LRU。仅在 `/setup.params` 有 image 变体 enum 时显示。
2. **视频追踪变体**（新）：仅 SAM 单下拉（无 DINO）→ `/reload`（video）→ `health_meta.video_pool.loaded_variants` / `active_sessions` / cap。
   - 若 `/setup.supported_trackers` 为空 → 整组显示「该后端不支持视频追踪」。
   - 文案标注「视频追踪池首次请求自动冷启，预热可提前载入到显存」。
3. `ObserveBackendsPanel.tsx`：同样按「图像推理 / 视频追踪」分组展示 `video_pool`（来自 `ObserveTarget.video_pool`）。
4. **空态 / 兼容**：旧 backend（无 `video_pool` 字段、`supported_trackers` 缺失）→ 视频组降级显示「该 backend 未上报 video 观测」，不报错。
5. **`PerfHud`（可选）**：维持现状，本版本不动。

### 2.B 视频追踪任务聚合监控（后端 + 前端）

1. **聚合查询端点**：[`video_tracker_jobs.py`](../../apps/api/app/api/v1/video_tracker_jobs.py) 新增 `GET /video-tracker-jobs`（管理员 / 按项目权限）：
   - query：`project_id?` / `status?` / `model_key?` / 分页；
   - 返回 job 列表（`status` / `model_key` / `from_frame`/`to_frame` / `direction` / `error_message` / `started_at`/`completed_at` / `created_by`）+ 聚合计数（按 status 分组）。
   - 复用 `VideoTrackerJob` 模型（[video_tracker_job.py](../../apps/api/app/db/models/video_tracker_job.py)），**只加查询、不改写入链路**。
2. **监控页 / 区块**：在模型市场或仪表板新增「视频追踪任务」视图（参考图片侧 preannotate jobs 监控页的信息架构，照搬其列表 + 状态 chip + 分组形态，不自造）：
   - 计数卡：queued / running / completed / failed / cancelled。
   - 列表：可按 status / model_key / project 过滤；failed 行展开 `error_message`。
   - running 行可选接 `/ws/video-tracker-jobs/{jobId}` 实时进度（现有 [`useVideoTrackerJobs.ts`](../../apps/web/src/hooks/useVideoTrackerJobs.ts) 已有单 job 订阅，复用）。

### 2.C video tracker 模型尺寸（sam_variant）选择 plumbing

> roadmap Phase 3.2 列入本版本。后端已就绪（`_video_pool` 按 `sam_variant` 分桶、`/predict` video_tracker 分支已读 `ctx.get("sam_variant")`，[main.py:665](../../apps/grounded-sam2-backend/main.py)）；缺的是请求链路从对话框传到 adapter context。

链路（每层加一个字段，纯 plumbing）：
1. `VideoTrackerPropagateRequest`（[video_tracker_job.py schema](../../apps/api/app/schemas/video_tracker_job.py)）加 `sam_variant: str | None = None`。
2. `create_tracker_job`（`../../apps/api/app/services/video_tracker_job_service.py`）把 `payload.sam_variant` 存进 `job.prompt["sam_variant"]`（**无需 DB 迁移**——prompt 已是自由 JSONB；不新增列）。
3. `video_tracker_runner.py` 构建 `TrackerContext`（runner:282）时从 `job.prompt.get("sam_variant")` 取出 → `TrackerContext` 加 `sam_variant: str | None`。
4. `MLBackendVideoTrackerAdapter.propagate`（`../../apps/api/app/services/video_tracker_adapters.py`）在 context 里发 `"sam_variant": ctx.sam_variant`（仅非空时发，缺省让后端回退默认 tiny）。
5. 前端 `videoTracker.ts` 的 `VideoTrackerPropagatePayload` 加 `sam_variant?`；`VideoTrackerPropagateDialog.tsx` 加 SAM 变体下拉（变体目录来自项目 backend `/setup.params.sam_variant.enum`，复用图片侧 `aiVariant` 取数模式；后端不支持变体时不显示下拉）。

### 2.3 不做（边界）

- 不改 backend 推理 / 显存池 / 协议（那是 v0.10.35）。
- 不做协议统一 / 模态校验 / 注册流程优化（那是 Phase 3.3 / v0.11.0）。
- 不做跨 backend 全局指标大盘（Prometheus/Grafana 侧，另议）；本版本聚焦平台内可见性。

## 3. 验收口径

1. 模型市场观测面板：支持 video 的 backend 显示「图像推理 / 视频追踪」两组，video 池显存 / 会话数正确（与 backend `/health` 一致）；不支持 video 的 backend 视频组显示「不支持」，不报错。
2. 旧 backend（无 `video_pool` 字段）观测面板不崩、降级显示。
3. `GET /video-tracker-jobs` 返回聚合计数 + 列表，过滤 / 分页正确；权限正确（非授权用户拿不到他项目外的 job）。
4. 监控页计数与 DB 实际 job 状态一致；failed 行可见 `error_message`；running 行进度实时更新。
5. 暗色模式 `pnpm lint:css-tokens` 通过。
