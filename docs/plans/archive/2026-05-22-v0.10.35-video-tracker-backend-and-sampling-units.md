# §A · 采样下 propagate「N 帧」单位对齐导航网格（前端）

## A.1 要做什么

采样开启（`step > 1`）时，把"按 N 帧传播"的 **N 改用网格格子为单位**，与 `←/→` 导航统一；range 提示同时显示网格序号；底层喂给后端/写回的仍是源帧。

涉及两个对话框：
- **AI 传播** [`VideoTrackerPropagateDialog.tsx`](../../apps/web/src/pages/Workbench/stage/VideoTrackerPropagateDialog.tsx)：预设 `10/30/60 帧`，`range.to = frameIndex + span`（源帧）。
- **手动铺帧** [`VideoKeyframesPropagateDialog.tsx`](../../apps/web/src/pages/Workbench/stage/VideoKeyframesPropagateDialog.tsx)：`count`，`target = frameIndex + step * count`（源帧；注意此处 `step` 是方向 ±1，非采样步长，命名巧合勿混）。

## A.2 为什么做

`←/→` 在采样开启时一下跳一个网格格子（step=10 时跳 10 源帧），但对话框「30 帧」是 30 **源帧** = 仅 3 个格子。用户心智里的"帧"= 能落脚的网格格子，两套单位混在同一工作台，采样率越高越割裂；AI 传播还会把 keyframe 写在用户**导航不到**的 off-grid 源帧上（只能靠 `Shift+←/→` 逃生口够到）。

## A.3 实现方案

**核心原则（D2）**：源帧空间是底层唯一真相，只在**对话框的输入/展示层**做"网格格子 ↔ 源帧"换算。

1. **取采样步长**：复用 [`videoSamplingGrid.ts`](../../apps/web/src/pages/Workbench/stage/videoSamplingGrid.ts) 的 `deriveSamplingStep(samplingConfig, sourceFps)`（`none→1`）。两个对话框需新增 prop 拿到当前 `step`（从 `VideoStage`/`useWorkbenchState` 的 `videoSampling` 透传，参考 `VideoStage.tsx` 已有的 `videoSampling` 链路）。

2. **AI 传播对话框**：
   - 预设语义改为"**N 个网格点**"：`step>1` 时标签显示 `10 格 (≈100 帧)` 之类；`range.to = frameIndex + span * step`（向后），`bidirectional` / `backward` 同理乘 `step`。
   - `step===1`（不采样）时**完全保持现状**，标签仍是「N 帧」。
   - range 提示：`step>1` 显示 `G{from/step} → G{to/step}`（网格序号）+ 括号标源帧 `F{from}→F{to}`；`step===1` 维持 `F{from}→F{to}`。
   - `到下一关键帧` / `到结尾` 预设不变（它们本就是按已有 keyframe / maxFrame 算，与单位无关）。

3. **手动铺帧对话框**：`count` 改为"网格格子数"，`step>1` 时 `target = frameIndex + dir * count * samplingStep`；标签与 range 同上处理。

4. **（可选，建议做）keyframe 吸附网格**：采样开启时，propagate 写回 / AI 传播写回的 keyframe `frame_index` 吸附到最近网格点（`Math.round(f / step) * step`），让用户能导航到每个生成的关键帧。**若实现，必须保留"手动 keyframe 不被吸附覆盖"**（manual source 优先，见后端 `apply_tracker_results` 的 manual_frames 逻辑，前端写回同理）。**若本版本不做吸附**，至少在 UI 注明"AI 传播可能在网格外生成帧，用 `Shift+←/→` 微调可达"。

> ⚠️ **不要动**：tracker 后端按源帧逐帧跑、`geometry.frame_index` 存源帧、导出按网格重编号——这些全不变。§A 是纯前端表现层。

## A.4 验收（§A）

1. `step===1`（采样关闭）：两个对话框行为/文案与 v0.10.34 完全一致（回归红线）。
2. `step=10`：AI 传播选「10 格」→ 实际 from→to 跨 100 源帧；按 10 次 `→` 走过的距离 ≈ 选「10 格」。
3. range 提示在采样开启时同时给出网格序号与源帧号，无歧义。
4. （若做吸附）AI 传播后每个生成 keyframe 都能用 `←/→` 直接导航到；手动 keyframe 不被吸附改写。
5. 暗色模式 `pnpm lint:css-tokens` 通过。

## A.5 测试（§A，主进程跑）

- `VideoTrackerPropagateDialog.test.tsx` / `VideoKeyframesPropagateDialog.test.tsx`：补 `step>1` 用例（range 换算、标签、回归 `step===1`）。
- 浏览器自测（preview）：建采样项目，开两个对话框逐一核对 range 与导航一致。

# §B · gsam2 真实 video tracker backend

> 目录：[`apps/grounded-sam2-backend/`](../../apps/grounded-sam2-backend/)。本节只动该容器，**不碰 sam3-backend、不碰 apps/api 的协议/runner（除 §B.4 跨窗 seed 一处）**。

## B.1 现状（已就位 vs 缺口）

**✅ 平台侧全就位，无需改**（除 §B.4）：
- 协议桥 `../../apps/api/app/services/video_tracker_adapters.py`：`MLBackendVideoTrackerAdapter("sam2_video")` 已把请求打到 `/predict`，`context.type="video_tracker"`，带 `from_frame/to_frame/direction/prompt/source_geometry`。
- 调度 `../../apps/api/app/services/video_tracker_runner.py`：`_tracker_windows` 按 `settings.video_tracker_window_size_frames` 分窗、逐窗调 adapter、Redis 推 `frame_result`/`job_progress`、低置信度自动 `outside`（`_frame_result_from_payload`）、cancel/失败处理。
- 响应契约：backend 返 `{"result": [{frame_index, geometry, confidence, outside}, ...]}`，frame_index 为**源帧号**（D2）。

**❌ gsam2 backend 缺口**：
- [`main.py`](../../apps/grounded-sam2-backend/main.py) 的 `/predict` 只认 `point/bbox/text`，收到 `video_tracker` 直接 422。
- 只加载了图片栈：[`predictor.py`](../../apps/grounded-sam2-backend/predictor.py) `build_sam2` + `SAM2ImagePredictor`（`:94-100`）+ GroundingDINO。无 video predictor。
- [`model_pool.py`](../../apps/grounded-sam2-backend/model_pool.py) 的 `ModelPool` 按 `(sam_variant, dino_variant)` 分桶，**只管图片 predictor**，video predictor 塞不进（无 dino 维度、有视频会话状态）。

## B.2 设计：video predictor 用独立池 / 独立显存预算（同容器）

**决策（已拍板）**：gsam2 同一容器内，video 与图片**模型权重独立、显存预算独立、互不驱逐**。理由见 [roadmap 3.1](../../ROADMAP/2026-05-21-video-workbench-roadmap.md)（长任务不饿死交互、video OOM 隔离、清理时机不同）。

新增 `video_predictor.py` + `video_pool.py`（与图片 `predictor.py`/`model_pool.py` 平行，**不复用、不改它们**）：

1. **`VideoPredictor`**（`video_predictor.py`）：
   - 用 `from sam2.build_sam import build_sam2_video_predictor` 构建（注意：与图片的 `build_sam2` 不同入口，**另一份权重**；可共用同一 checkpoint 文件路径，见 `SAM2_CONFIGS`）。
   - `propagate(video_path, from_frame, to_frame, direction, seed_bbox, *, frame_index_offset)`：
     - `init_state(video_path=...)` 加载该窗帧（**显存随窗帧数线性涨**——这是 video 的大头）；
     - `add_new_points_or_box(...)` 用 seed_bbox 在窗首帧加 prompt；
     - `propagate_in_video(...)` 逐帧拿 mask → 转 bbox（外接框，与现 image 路径的归一化坐标约定一致）；
     - yield/return `[{frame_index(源帧号), geometry:{type:"bbox",x,y,w,h}, confidence, outside}]`；
     - **坐标归一化**：复用 `predictor.py` 既有的"像素 → 0-1 归一化"约定（照搬，勿自造）。
   - **会话状态按窗结束即释放**：`init_state` 的反向清理 + `torch.cuda.empty_cache()`（复用 main.py 的 `_free_gpu_memory`，但走 video 自己的预算计数）。

2. **`VideoModelPool`**（`video_pool.py`）：
   - key = `sam_variant`（video 无 dino 维度）；cap 用**新 env** `VIDEO_MODEL_POOL_CAP`（默认 1）。
   - 独立 `build_timeout`、独立 idle/卸载（**不挂图片的 idle watcher `clear_all`**；video 按 job 释放会话，模型权重可保留供下个 job 复用，再加自己的 idle 卸载）。
   - 与图片池**并存**：两池各自驱逐，互不影响。显存吃紧时（后续版本）再考虑合并预算，本版本不做。

3. **新增 env（同步 `.env.example` + `pnpm docs:gen-env-vars`，CLAUDE.md §5）**：
   - `VIDEO_MODEL_POOL_CAP`（默认 `1`）
   - `VIDEO_TRACKER_MAX_WINDOW_FRAMES`（backend 侧单次 `init_state` 安全上限，超出在 backend 内再切；与 api 侧 `video_tracker_window_size_frames` 协同，**取两者较小**作实际窗）
   - `VIDEO_IDLE_UNLOAD_SECONDS`（video 池独立 idle，默认沿用图片同值或单独配）

## B.3 `/predict` 增 video_tracker 分支

改 [`main.py`](../../apps/grounded-sam2-backend/main.py) `/predict`：

1. `ctx.type == "video_tracker"` 分支（在现 point/bbox/text 422 之前拦截）：
   - 解析 `from_frame/to_frame/direction/prompt/source_geometry/sam_variant`；
   - 视频 URL：`task.file_path` 是签名 URL / 路径——backend 需能读取（按现 image 路径的取流方式扩展到视频；若需 ffmpeg/pyav 解码，加进 `pyproject.toml` 并 **rebuild**，CLAUDE.md §8）；
   - 从 `VideoModelPool.get(sam_variant)` 拿 `VideoPredictor`，调 `propagate(...)`；
   - 返回 `{"result": [...]}`（多条，frame_index 源帧号）。
2. **能力声明**：`GET /setup` 增 `"supported_trackers": ["sam2_video"]`（为 Phase 3.3 协议统一铺路；前端/平台暂可不消费，先声明）。
3. **可观测（含 `/health` 暴露 video 池，必做）**：
   - 既然 video 用独立池（§B.2），`GET /health` **必须**新增 video 池区块，否则模型市场（`ObserveBackendsPanel`）只看到显存被占却不知是谁占——这是独立池的应有之义，不是额外工作：
     ```
     /health 返回新增:
       "video_pool": { "cap", "loaded_variants", "active_sessions", "idle_seconds" },
       "gpu_info": { ... 含 video 池占用，与图片池分列 }
     ```
   - `observability.py` 指标加 `task_type="image|video"` 维度（或新增 `video_tracker_frames_processed_total{sam_variant}` / `video_tracker_latency_seconds`），让 `/metrics` 能按模态拆分。
   - `OOM / timeout → 抛错让 api 侧落到 `video_tracker_jobs.error_message`（ADR-0012 故障域隔离，别吞）。
   - **前端（可选，本版本可做可不做）**：`ObserveBackendsPanel.tsx` 消费 `video_pool` 字段，按「图像推理 / 视频追踪」加标题分组展示。完整的任务聚合监控页留 [v0.10.36](2026-05-22-v0.10.36-model-market-tracker-observability.md)。

## B.4 跨窗续追（api 侧，唯一改的平台代码）

**问题**：现 `../../apps/api/app/services/video_tracker_runner.py`（`:259-273`）每个窗都用**原始** `source_geometry=annotation.geometry` 起追。mock 无所谓，但真实 SAM2 video 会让窗 2..N 全从**首帧框**起追 → 错位。

**本版本方案（无状态近似）**：runner 在窗循环里维护 `last_geometry`，把上一窗最后一帧（非 outside）的 geometry 作为下一窗 `ctx.source_geometry` 的 seed：
- 窗 1：`source_geometry = annotation.geometry`（原始）；
- 窗 k+1：`source_geometry = 上一窗末帧 result.geometry`（续追）；
- `backward` 方向：窗序已 `reverse()`，seed 取上一窗"时间上更早"的边界帧，注意方向。
- 优点：实现小、容错好、backend 保持无状态、符合 ADR-0012；缺点：窗边界可能轻微漂移（可接受，后续 session-token 优化再消除）。

> ⚠️ 只动 `run_tracker_job` 窗循环里传给 `TrackerContext` 的 `source_geometry`，**不改协议字段、不改 mock adapter 行为**（mock 仍按原 source 填，测试不受影响）。

## B.5 验收（§B）

1. 项目绑定 gsam2 backend，选 `sam2_video` 发起传播（30s@30fps 短视频）→ 逐帧 bbox 跟随目标、`job_completed`、keyframe 落 `geometry.keyframes`（源帧号）。
2. **跨窗**：窗大小设小（如 10 帧）跑 50 帧 → 目标连续跟随、无窗边界跳回首帧框（验证 §B.4）。
3. **显存独立 + 可观测**：video job 跑的同时发图片 `bbox` 交互请求 → 图片变体**不被驱逐**、交互不卡（验证独立池）；`GET /health` 能看到 `video_pool` 区块（已加载/会话数/显存），与图片池分列；video job 结束后会话显存释放（`/health` 可见）。
4. OOM / 超长视频 / backend 5xx → `video_tracker_jobs.error_message` 可诊断，平台不崩。
5. `mock_bbox` 路径完全不受影响（回归）。
6. `sam3_video` 仍走 `MLBackendVideoTrackerAdapter`，本版本不实现其 backend 端（选它会因 sam3-backend 返 422 而失败，符合预期；UI note 已标"需 backend 支持"）。

## B.6 测试（§B）

- backend 单测：`video_predictor` 坐标归一化 / outside 判定 / 窗内传播（可用极短 fixture 视频或 mock SAM2 video predictor）。
- api 单测：`video_tracker_runner` 跨窗 seed 续追逻辑（`from_frame`/`backward` 两方向，断言窗 k+1 的 `source_geometry` = 窗 k 末帧）；用 `MockBboxTrackerAdapter` 不触真实模型即可验证 seed 传递。
- **真实模型验证在主进程 / 有 GPU 环境手动跑**（CI 无 GPU）。
