# v0.10.43 · 导出能力重整：多目标格式 + 多几何 + 友好命名（图像）

> **来源**：v0.10.42 导出 Modal 容器之上的能力填充。用户实测发现现状导出"残"——COCO/YOLO 只导矩形框、下载名是 UUID。**本版即 `ROADMAP.md` §A 第 61-64 行 P2「v0.10.28 新几何导出/导入/预测支持」的落地**（export.py/export_packaging.py 当前只导 bbox/polygon/mask，rotated_bbox/polyline/keypoint 无 COCO/YOLO/VOC 映射）。
> **性质**：后端为主（`ExportService` / `export_packaging` / `export.py` worker / API query）+ 前端导出选择器（落在 v0.10.42 的 Modal 内）。
> **前置**：[v0.10.42 导出 Modal 悬浮页](2026-05-23-v0.10.42-export-modal.md) 提供承载容器。
> **后续**：视频逐帧 YOLO（单帧 video_bbox + 轨迹摊平）已拆到 [v0.10.44](2026-05-23-v0.10.44-video-frame-yolo-export.md)，本版不含。

## 0. 一句话目标

把图像项目导出从"单格式 / 仅 bbox"升级为：**可多选导出目标**（一个 job → 一个 zip，多目标分子目录）、**按几何映射正确格式**（YOLO 变体手选 det/obb/seg、COCO 同文件承载多几何），并给出**人类可读的下载名**。

## 1. 现状事实（已读码确认）

### 1.1 关键缺陷 —— COCO / YOLO 只导矩形框，其它几何被静默丢弃
- `_bbox_geometry()`（`../../apps/api/app/services/export.py`）只放行 `geometry.type ∈ {bbox, None}`。
- COCO annotation 组装（`export.py:396-419`）与 YOLO 行生成（`../../apps/api/app/services/export_packaging.py`）都过它。
- 结果：`polygon / multi_polygon / mask / rotated_bbox / keypoint / polyline` 标注导出 COCO/YOLO 时**全部被吞**，无任何提示。

### 1.2 平台几何类型（`_jsonb_types.py` discriminated union，已确认字段）
| type | 字段 | 归属 tool_unit |
|---|---|---|
| `bbox` | x,y,w,h（归一化） | bbox |
| `rotated_bbox` | cx,cy,w,h,angle(度,[0,360)) | rotated_bbox |
| `polygon` | points: list[[x,y]] ≥3 | region |
| `multi_polygon` / `mask` | 多连通域 / 掩膜 | region |
| `polyline` | points: list[[x,y]] ≥2 | polyline |
| `keypoint` | list[Keypoint] | keypoint |
| `video_bbox` | frame_index + x,y,w,h（单帧框） | — |
| `video_track` | track_id + keyframes[] + outside[] | — |

### 1.3 单格式假设贯穿全链路（多选格式的冲突点，见 §1.5）
- API：`format: str = Query("coco", pattern="^(coco|voc|yolo|aap_json|video_json|mot|kitti)$")`（[`projects.py:775-786`](../../apps/api/app/api/v1/projects.py)）—— **单值**。
- worker：`run_export(format: str, ...)`；`compute_cache_key(scope_id, format, ...)`；object key `image/{project_id}/{job_id}.zip`（`../../apps/api/app/workers/export.py`）—— **单格式单 zip**。
- 缓存表 `export_cache` 按单 format 记录命中。

### 1.4 命名 / 桶路径现状
- 桶 key 写死 `image/{project_id}/{job_id}.zip` —— **视频项目也塞 `image/` 前缀**（瑕疵）；叶子 = UUID `job_id` → 用户下到 `8f3a….zip`，不可读。
- 异步预签名下载**未设** `response-content-disposition`，故下载名 = 丑 UUID。仅已下线的 VOC 同步路径给过 `{display_id}_voc.zip`。
- zip **内部**结构良好且保留：
  - 图像 YOLO：`{project_id}/{dataset_id}/labels/{rel}.txt` + `classes.txt`/`data.yaml`/`images_manifest.json`/`fetch_images.py`
  - 图像 COCO/AAP：根 `annotations.json`
  - 视频 MOT：`{seq}/gt/gt.txt` + `seqinfo.ini`；KITTI：`labels/{seq}.txt`；JSON/AAP：根 `annotations.json`

### 1.5 视频项目被禁止图像格式
- `_assert_image_export_supported`（`export.py:48-58`）显式禁止 video-track 项目导 coco/yolo/voc。
- 视频导出（`_build_video_export_zip`）只认 `video_track` 几何；`video_bbox`（单帧框）仅在 `video_json` 的 `legacy_video_bbox` 数组露面，无 YOLO/COCO 路径。
- **但抽帧基建已齐**：`derive_sampled_frames`（采样网格帧号）、`derive_step`、`fetch_frames.py`（ffmpeg `select` 就地抽帧）、`resolved_track_frames`（轨迹插值摊平到逐帧）。

## 1.5 「导出格式多选」与现仓库的冲突分析（用户明确要求评估）

**结论：多选格式与现仓库的单格式假设冲突，但冲突点有限且可控。** 推荐 **方案 B（后端接收目标列表 → 一个 job 产一个 zip，多目标分子目录）**，理由是"一次导出、一个友好命名的 zip"符合用户对承载更复杂能力的预期。

| 冲突点 | 现状 | 方案 B 改动 |
|---|---|---|
| API query | `format: str` 单值带 pattern | 改 `targets: list[str]`（重复 query 或逗号分隔），逐项校验 |
| worker 签名 | `run_export(format: str)` | `run_export(targets: list[str])`，内部 for 循环逐目标写 zip |
| 缓存键 | `compute_cache_key(..., format, ...)` | key 纳入**排序后的目标集合**（`",".join(sorted(targets))`），保证集合稳定命中 |
| zip 布局 | 单格式文件落包根 | **>1 目标时**每目标落 `{target}/` 子目录；**=1 目标时保持现有根布局**（零行为变更，向后兼容） |
| object key | `image/{project_id}/{job_id}.zip` | `{media}/{project_id}/{job_id}.zip`（`media` 按 data_type 取 image/video） |

**备选方案 A（前端并发 N 个单格式 job）**：零后端 job 模型改动、各自独立缓存，但产出 N 个 zip / N 条任务铃，不是"一个包"。列为低成本回退，不作首选。

## 2. 已定决策（用户确认）

1. **YOLO 变体手选**，不自动推断。
2. **导出目标多选**，一次导出产一个 zip（**方案 B**，见 §1.5）。
3. **取消 COCO 内独立的"标注类型多选"**——COCO 目标即"把它能承载的几何全装进去"；多选粒度只在"导出目标"这一层（要分就勾 coco + yolo-seg）。
4. **内部 `labels/` 路径不变**（保留 `dataset_id`，避免同名数据集冲突）。
5. **下载名 = `{job_id 前几位} + 数据集名`**（见 §4 阶段 4 的精确格式）。
6. **格式边界（datumaro 底线，`ROADMAP.md` 决策表第 227 行）**：本版只**补全既有 COCO/YOLO 三件套对新几何的覆盖**，不新增小众格式族。客户要 KITTI/DAVIS/Cityscapes/LabelMe 等走"导 COCO/AAP JSON → datumaro CLI 转"，不手写——见 [取经合集 §3.3](../../ROADMAP/2026-05-18-cvat-labelstudio-inspiration.md)。
7. **视频逐帧 YOLO 移出本版**，见 [v0.10.44](2026-05-23-v0.10.44-video-frame-yolo-export.md)。

## 3. 导出目标模型（geometry ⇒ format，统一抽象）

导出选择器列出**导出目标**（多选），每个目标隐含其消费的几何；非法组合不暴露给用户：

**图像项目**
| 目标 | 消费几何 | 落包 |
|---|---|---|
| `coco` | bbox + polygon/multi_polygon(segmentation) + keypoint(keypoints+skeleton) + group_id(`__group_id`)（COCO 单文件可同时承载） | `annotations.json` |
| `yolo-det` | bbox | `labels/*.txt`(cls cx cy w h) |
| `yolo-obb` | rotated_bbox | `labels/*.txt`(cls x1..y4 四角) |
| `yolo-seg` | polygon/mask | `labels/*.txt`(cls 归一化多边形) |
| `aap_json` | 全部（无损） | `annotations.json` |

**视频项目**（现有目标，本版仅纳入多目标 zip 框架，不改其内容）
| 目标 | 来源几何 | 落包 |
|---|---|---|
| `video_json` / `aap_json` | video_track(+video_bbox) | `annotations.json` |
| `mot` / `kitti` | video_track | 现有 seq 结构 |

> 视频逐帧 YOLO（`yolo-frames-det`，单帧 + 轨迹摊平）见 [v0.10.44](2026-05-23-v0.10.44-video-frame-yolo-export.md)。
>
> COCO 不再单设"标注类型多选"——COCO 目标即"把所有它能承载的几何都写进去"。多选粒度交给"导出目标"这一层（如同时勾 coco + yolo-seg）。

## 4. 实施步骤（带验收，分阶段）

### 阶段 1 · 后端几何写入器补全（修 §1.1 缺陷，最高价值）
- 新增按 `geometry.type → 各格式` 的写入器：
  - COCO `segmentation`(polygon/multi_polygon)；
  - **COCO `keypoints`（做全）**：骨架拓扑直接读现成 `ToolBinding.keypoint_schema`（`_jsonb_types.py:219` 的 `nodes`/`edges`，v0.10.28 已落）→ `categories[].keypoints`(节点名) + `categories[].skeleton`(edges，COCO 1-indexed)；实例 `KeypointGeometry.points` → `keypoints:[x,y,v,…]`(去归一化到像素) + `num_keypoints`。**无需新设计配置 schema**。
  - rotated_bbox → `yolo-obb` 四角；polygon/multi_polygon → `yolo-seg` 归一化多边形。
- **I12 同期项（ROADMAP 第 173 行）**：COCO 导出时把 `Annotation.group_id`（`annotation.py:52`）映射到 `annotation.attributes.__group_id`，零额外结构成本，随 COCO 写入器一并落。
- `_bbox_geometry()` 不再做全局闸门；各目标按自己消费的几何过滤。
- **verify**：构造含 polygon+rotated+keypoint+bbox 的项目 → 导 coco 含 segmentation + keypoints(skeleton 与 keypoint_schema.edges 一致) + 同组框带 `__group_id`；导 yolo-seg 仅含多边形行；导 yolo-obb 仅含旋转框四角；不匹配几何被跳过且 job 结果里报"跳过 N 条"。

### 阶段 2 · 多目标导出（方案 B，照 §1.5 改 5 处）
- API query `format` → `targets`（保留单值兼容：单元素列表）；worker 循环；缓存键纳入排序目标集；zip >1 目标分子目录、=1 目标保持根布局；object key `{media}/...`。
- **verify**：勾 coco+yolo-det → 一个 zip 内 `coco/` `yolo-det/` 并存；只勾 coco → 根布局不变（旧行为）；重复导相同目标集命中缓存。

### 阶段 3 · 友好下载名
- 预签名 URL 加 `response-content-disposition`，下载名 = `{project_display_id}_{dataset_name}_{job_id[:8]}.zip`；项目跨多数据集时省略 `dataset_name` → `{project_display_id}_{job_id[:8]}.zip`；批次级再缀 `{batch_display_id}`。
- 桶 object key 仍用全 `job_id` 保唯一 + 缓存稳定（不动）。
- **verify**：下载得到的文件名形如 `P-12_animals_8f3a1c2d.zip`，可读且唯一。

### 阶段 4 · 前端导出选择器（落在 v0.10.42 Modal 内）
- Modal 内渲染"导出目标"多选（按项目 data_type 给图像/视频两套目标集）；保留 includeAttributes / videoFrameMode。
- 提交时传 `targets[]`；轮询 async-job 结果展示生成进度 + 跳过提示。
- **verify**：图像项目见 coco/yolo-det/obb/seg/aap 多选；视频项目见 video_json/aap/mot/kitti；多选触发单 job 单 zip。

### 阶段 5 · 文档收尾
- `CHANGELOG.md` v0.10.43；`docs-site/dev/reference/` 导出格式规格补多目标 + 几何映射；用户手册导出章节更新。
- **README.md 无导入导出/格式章节可改**（已确认仅含文档/快速开始/测试/目录结构/License），格式文档真值在 `docs-site/dev/reference/` 与用户手册 —— 文档同步指向这两处即可。
- **ROADMAP 收尾**：本版落地后删 `ROADMAP.md` §A 第 61-64 行 P2「v0.10.28 新几何导出/导入/预测支持」中"导出协议覆盖新几何"一条 + 优先级表第 209 行对应行（按记忆约定，完成项直接删，CHANGELOG 已记录）。

## 6. 风险 / 注意
- 后端改 `ExportService`/`export_packaging`/worker 属业务代码，dev 下 worker 需 `docker restart`（CLAUDE.md §8，Celery 无 reload）；API 走 `--reload` 自动生效。
- 缓存键纳入目标集后，**旧缓存自然失效**（key 变），无需手动清；注意别让 key 顺序不稳定（必须 `sorted`）。
- 多目标 zip 体积与生成时长上升，`update_progress` 分段需按目标数细分，避免长时间停在某百分比。
- COCO `categories[].keypoints`/`skeleton` 直接派生自 `keypoint_schema`——若某 keypoint 类未配 schema(nodes 空)则该类 keypoints 段留空/跳过，不要写半截 categories 让下游解析器报错。
- ROADMAP §A 第 61-64 行 P2 含导出/导入/ML 三条；本版只落"导出协议覆盖新几何"一条（+ I12 group_id），收尾删该条时**勿误删** import/ML 两条（仍 open）。
