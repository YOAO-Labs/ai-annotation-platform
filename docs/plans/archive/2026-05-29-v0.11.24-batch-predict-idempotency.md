# v0.11.24 · 批量预标幂等：跳过已预标 / 覆盖历史预标

> Epic 切片 2/3 · 批次解绑状态修复
> 依赖：[v0.11.23](2026-05-29-v0.11.23-batch-delete-reset-cascade.md)（复用其预测清理 helper）· 用户可见：是（预标对话框新增模式）
> 背景：[ROADMAP §A AI 预标重复叠加](../../ROADMAP.md)

## 目标

根治「同一 task 被重复预标 → 重复/重叠标注」的**根因**：`_run_batch`（`apps/api/app/workers/tasks.py`）选 task 时只按 `status=='pending'` 过滤、不查"是否已预标"，`create_from_ml_result`（`prediction.py:267-316`）无条件 INSERT，`predictions`/`annotations` 均无 `(task_id, source)` 唯一约束 → 第二次预标直接叠加。

v0.11.23 只堵了「删批次触发的重复」一条路径；本版让 `batch_predict` **本身幂等**，覆盖所有触发路径（重复点预标、解绑重分包后再预标、task_ids 直接指定等）。

## 决策

给预标加 `predict_mode`（三选一）：

| mode | 语义 | 实现 |
|---|---|---|
| `skip_predicted`（**默认**） | 跳过已预标过的 task，只预标"干净"的 | 选 task 时排除 `total_predictions > 0`（或有存活 `prediction_based` annotation）的 task |
| `overwrite` | 覆盖：先清旧预测再重新预标 | 预标前对选中 task 跑预测清理（复用 v0.11.23 helper 的清理部分），再正常 INSERT |
| `append` | 保留旧行为（无脑追加） | 当前行为；仅为兼容/特殊场景保留，UI 不默认暴露 |

> 默认选 `skip_predicted` 而非 `overwrite`：避免"再点一次预标"误删用户已采纳/微调的 AI 标注。`overwrite` 是显式破坏性操作。

## 任务

### A. schema 加 predict_mode

文件：`apps/api/app/schemas/preannotate.py` · `PreannotateRequest`

```python
predict_mode: Literal["skip_predicted", "overwrite", "append"] = "skip_predicted"
```

### B. 透传到 worker

文件：`apps/api/app/api/v1/projects.py` · `trigger_preannotation`（`batch_predict.delay(...)` 调用，约 1043-1051）；`apps/api/app/workers/tasks.py` · `batch_predict` 签名 + `_run_batch`。

- `batch_predict.delay(... , predict_mode=body.predict_mode)`
- `batch_predict(self, ..., predict_mode: str = "skip_predicted")` → 透传给 `_run_batch(..., predict_mode=predict_mode)`
- `total_tasks_hint`（trigger 里预估计数，约 1029-1041）也要按 mode 调整：`skip_predicted` 时 hint 应排除已预标 task，否则进度条分母虚高。

### C. _run_batch 按 mode 选 task / 清理

文件：`apps/api/app/workers/tasks.py` · `_run_batch`（task 选取约 128-145）

三处选 task 分支（task_ids / batch_id / project）统一加 mode 处理：

```python
# skip_predicted: 在现有 where 上追加排除已预标
#   .where(Task.total_predictions == 0)   # 或 NOT EXISTS prediction_based annotation
# overwrite: 先正常选出 task，再对这批 task_id 调清理（见 D），然后照常预标
# append: 现状不变
```

- `task_ids` 分支当前**无 status 过滤**（按指定 id 全跑）；`skip_predicted` 下也应排除其中已预标的，并 log 跳过数量（避免"静默少跑"误解）。

### D. overwrite 清理复用 v0.11.23 helper

v0.11.23 的 `_reset_and_clean_batch_tasks` 是按 `batch_id` 定位的；本版 overwrite 需按 **task_ids** 清理。两种做法（动手时择一）：

- **优先**：把 v0.11.23 helper 的「预测清理」内核再抽一层 `_clean_task_predictions(task_ids: list[UUID])`（按 task_id 定位：软删 prediction_based annotation、NULL parent_prediction_id、删 prediction_metas/predictions/failed_predictions、归零 total_predictions、重算 total_annotations/is_labeled），`_reset_and_clean_batch_tasks` 与本版 overwrite 都调它。worker 侧注意：清理是 service 层逻辑，worker 内已有 db session，直接调 `BatchService(db)._clean_task_predictions(...)` 或独立函数。
- 次选：worker 内就地写清理 SQL（与 helper 逻辑一致），但有重复，不推荐。

> overwrite **不重置 task.status**（与删批次不同）——预标不改流程状态，只换预测内容。

### E. 前端预标对话框加模式选择

文件：AI 预标触发入口（`apps/web/src/pages/AIPreAnnotate/components/ProjectDetailPanel.tsx` 为主，动手时确认实际提交 `/preannotate` 的组件；批次页 `BatchesSection.tsx` / `BatchesKanbanView.tsx` 若也有预标入口需同步）。

- 预标参数区加一组单选：「跳过已预标任务（默认）/ 覆盖已有预标 / 追加」。
- `overwrite` 给二次确认或醒目提示（会删除已有 AI 标注）。
- API 客户端类型（`apps/web/src/api/` 下预标相关 payload）加 `predict_mode`。

### F. 测试

文件：`apps/api/tests/test_batch_predict_idempotency.py`（新增，mock ML backend `/predict`）

1. **skip 默认**：对已预标 task（`total_predictions>0`）再次预标，断言不新增 prediction、不重复 annotation、worker 报告"跳过 N"。
2. **overwrite**：再次预标，断言旧 prediction/prediction_based annotation 被清、只剩新一份、`total_predictions` 反映新结果、manual annotation 保留。
3. **append**：行为同旧（追加）——锁定回归基线。
4. **task_ids 直接指定** + skip：已预标的被排除。
5. **hint 计数**：skip 模式下 `total_tasks_hint` 排除已预标。

## 验证

1. `uv run pytest tests/test_batch_predict_idempotency.py -q` 全绿。
2. 手动：对一个批次跑预标 → 再点一次预标（默认 skip）→ 工作台确认无重复框；切 overwrite 再跑 → 旧 AI 框被换成新的、手工标注还在。
3. 与 v0.11.23 联动：删批次（已清预标）→ 重分包 → 再预标，全程无重复。

## 风险 / 决策点

- **"已预标"判定口径**：用 `total_predictions > 0` 最简单，但该字段被 v0.11.23 清理归零——两版需对齐口径。也可用「存在存活 prediction 行 / prediction_based annotation」更精确。动手时统一到一个判定函数。
- **task_ids 分支静默跳过**：skip 模式排除已预标 task 时必须 `log` 跳过数，否则用户以为全跑了。
- **overwrite 删的是 AI 标注**：用户可能已对 AI 框做过微调（但仍是 prediction_based？需确认微调后 annotation 的 source 是否转 manual）——若微调后仍算 prediction_based，overwrite 会误删微调。动手时确认"采纳/编辑 AI 标注后 source 字段的变化"，必要时 overwrite 只清未被人工动过的预测。
- **worker 调 service 层清理**：确认 worker 的 db session 与 `BatchService` 兼容（async session），避免事务边界问题。
