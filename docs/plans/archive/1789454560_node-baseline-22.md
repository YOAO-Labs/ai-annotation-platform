# Node.js 基线从 20 升级到 22

> Status: 已实施（本 PR）；Node 24 后续项见 Remaining work。

## 1. 背景与证据

仓库长期处于「半迁移」状态，文档声明的基线（Node 20）与实际运行环境不一致：

| 事实                                                     | 值                              |
| -------------------------------------------------------- | ------------------------------- |
| 生产 Web 构建镜像 `infra/docker/Dockerfile.web`          | `node:22-alpine`（固定 digest） |
| `origin/main` lockfile 中声明 `engines.node >=22` 的依赖 | 21 个（`@scalar/*` 等）         |
| 本机开发运行时                                           | Node 22.23.1                    |
| CI（12 处）/ `DEV.md` / `README.md` / `docs-site` 声明   | Node 20                         |
| 根 `package.json` `engines`                              | 未声明                          |

Node 20（Iron）已于 **2026-04-30 EOL**，不再接收安全补丁。仓库默认未开 `engine-strict`，
因此 `>=22` 依赖只打印告警、不拦截，问题被静默掩盖；同时为维持「Node 20 兼容」会被迫
钉旧依赖（头像功能里 DiceBear v10 → v9 就是第一个实例）。

## 2. 目标版本：22（不是 24）

本计划最初评估 Node 24（Active LTS，EOL 2028-04），但在 Node 24.21.0 上跑全量单测时发现
一个**与本次配置改动无关、但会阻断 Node 24** 的既有不兼容：

```
TypeError: RequestInit: Expected signal ("AbortSignal {}") to be an instance of AbortSignal.
  at node:internal/deps/undici/undici (Request/RequestInit webidl 校验)
  at @mswjs/interceptors ClientRequest
  at @remix-run/router createClientSideRequest
```

根因：Node 24 内置 undici v7 对 `AbortSignal` 做严格 instanceof 校验；而 Vitest 2 的 jsdom
环境用 jsdom 的 `AbortController`/`AbortSignal` 覆盖全局，却保留 Node 的 `fetch`/`Request`，
两个 realm 不匹配。该问题在 Vitest 4（`vitest-dev/vitest#8390`）中被修复。

因此本次取 **Node 22（Maintenance LTS，EOL 2027-04）**：

- 与生产镜像 `node:22-alpine` 完全一致，**无需改 Dockerfile**；
- 满足全部现有 `>=22` 依赖，解除 DiceBear 等「为旧运行时钉版本」的倒逼；
- 不触碰 Vitest，风险最小。

## 3. 改动

- `.github/workflows/*.yml`（12 处）：`node-version` 20 → 22。
- 根 `package.json`：新增 `"engines": { "node": ">=22.0.0" }`。
- 新增 `.nvmrc`（`22`）与 `.npmrc`（`engine-strict=true`）：低于基线时 `pnpm install` 直接失败。
- 文档前置要求：`DEV.md`、`README.md`、`docs-site/dev/tutorials/local-dev.md`、
  `docs-site/dev/tutorials/first-contribution.md` 的 `>= 20`/`≥20` 改为 `>= 22`/`≥22`。

## 4. 验证（Node 22.23.1，本机）

- `pnpm install`（`engine-strict=true`）通过；无 engine 报错。
- `pnpm codegen`、`pnpm typecheck` 通过。
- `pnpm test`：523 文件 / 5250 用例全部通过。
- `pnpm lint`（含 CSS token）、`pnpm format:check` 通过。
- `pnpm docs:build`、`pnpm --filter @anno/web build`、`pnpm size` 通过。
- Node 24.21.0 上的调查记录见 §2；未把 24 纳入本次改动。
