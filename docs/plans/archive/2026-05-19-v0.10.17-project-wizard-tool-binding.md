# v0.10.17 · 项目向导通用化 + 工具维度类别属性 + Magic Box + 模板编辑器

> 日期: 2026-05-19 · 版本: v0.10.17
> 落地后请重命名为 `2026-05-19-v0.10.17-project-wizard-tool-binding.md`(plan 模式仅允许此默认路径)

## Context

ROADMAP 反馈四件相关事一起做:

1. **新建项目向导过窄**: 当前 `CreateProjectWizard` 把"项目类型"枚举死 7 种(image-det / image-seg / image-kp / lidar / video-mm / video-track / mm),其实只有 image / video / lidar 三种**数据载体**,具体能做什么由"工具集"决定。强行用 `type_key` 区分让 UI 死板、客户场景只要不是平台预设的组合就要再加 type_key。
2. **类别和属性与工具脱钩**: 现在 `classes_config` 是项目级扁平 dict,所有工具共享一份。客户提的是"bbox 工具标行人车辆,polygon 工具标可行驶区/天空,AI 交互工具又有自己的类",一张大表混着塞强行兼容不了。需要把绑定颗粒度提到"工具单位"。
3. **Magic Box (粗框 → SAM 收紧到对象紧凑外接矩形)**: SmartBoxTool + sam3-backend 的 bbox→mask 链路已就绪,只差最后一步从 mask 取紧凑 bbox 回写。同窗口落地零额外后端。
4. **TemplateEditModal 复杂字段 UI**: 后端 `ProjectTemplate` schema 已完整支持 `classes_config / attribute_schema / rendering_config`,只是前端 Modal 没暴露,被迫"先从已有项目导出再做模板"。本次工具维度改造完成后,这三个字段必须按新结构暴露,顺手补齐。

**已对齐的关键决策**(由用户在 plan 阶段确认):

- **类别绑定颗粒度 = 工具独占**(强隔离)。每个工具单位独立持有 classes + attribute_schema,可同名不同色。
- **工具集呈现 = 三组**:基础几何 (bbox + polyline) / 区域 (polygon + mask 打包) / AI 交互 (smart-point + smart-box + text-prompt + exemplar 打包)。其中 polyline 当前还没有,本版 v0.10.17 **不实现** polyline 工具,但 schema 留好位置。
- **Magic Box 仅复用 SAM 链路**,不引入 Canny/Sobel snap-to-edge(留 v0.11+)。
- **后端 schema 重写为嵌套结构 + alembic backfill**,旧扁平 `classes_config` 按 `type_key` 推断映射到对应 tool_unit。

## 核心数据模型变更

### tool_unit 枚举(后端 + 前端共享)

新增"工具单位"概念,作为类别/属性绑定的 key:

| tool_unit_id | 包含工具 | type 限制 |
|---|---|---|
| `bbox` | BboxTool | image, video |
| `polyline` | (本版无实现) | image, video (留位) |
| `region` | PolygonTool + MaskTool(打包) | image |
| `ai_interactive` | SmartPointTool + SmartBoxTool + TextPromptTool + ExemplarTool + MagicBoxTool(打包) | image |
| `lidar_box_3d` | (本版无实现) | lidar (留位) |

### Project 模型新字段

新增 `tool_bindings: JSONB`,形状:

```json
{
  "bbox": {
    "enabled": true,
    "classes": [{ "name": "person", "color": "#f00", "alias": "人", "order": 0 }],
    "attribute_schema": { "fields": [...] }
  },
  "region": {
    "enabled": true,
    "classes": [...],
    "attribute_schema": {...}
  },
  "ai_interactive": {
    "enabled": false,
    "classes": [],
    "attribute_schema": { "fields": [] }
  }
}
```

**新 schema 是唯一真相**。alembic 迁移把旧 `classes_config` + `attribute_schema` backfill 到对应 tool_unit:
- `type_key in (image-det, video-track, video-mm, mm)` → 写到 `bbox`
- `type_key = image-seg` → 写到 `region`
- 其它(image-kp / lidar) → 写到 `bbox`(占位,后续手工调)

旧字段 `projects.classes_config` 与 `projects.attribute_schema` **保留作 v0.10.17 的过渡视图**:运行期由 trigger 或 service 层从 `tool_bindings` 派生(union 合并),供未迁移的导出/聚合查询继续读;v0.10.18 起删除。

### Annotation 关联工具单位

`annotations` 表加 `tool_unit_id: String(30) NOT NULL DEFAULT 'bbox'`。alembic backfill 按 `annotation_type` 反推:
- `bbox` → `bbox`
- `polygon` / `mask` → `region`
- `point` / `line` → (留待 v0.10.18 加 polyline/keypoint 时填,本版统一记 `bbox`)

`predictions` 表同样加 `tool_unit_id`。

`class_name` 字段保留,但语义改为"在 `tool_bindings[tool_unit_id].classes` 内"。新增标注/预测时,服务层校验 `class_name ∈ tool_bindings[tool_unit_id].classes`(空白单位放行,兼容历史);校验失败 422。

## 风险与不做的事

- **不做** polyline / keypoint / lidar 工具实现(留 Slice schema 位但置灰)。
- **不做** snap-to-edge(Canny/Sobel),Magic Box 仅 SAM bbox→mask→紧凑外接矩形。
- **不做** 跨 tool_unit 类别"软关联"(同名映射 / 别名复用)。强隔离意味着 bbox 的"人"和 region 的"人"是两条独立记录,导出 COCO 时通过 `supercategory` 区分。如果客户后续反馈"想共享",再加可选 alias_to(tool_unit, class_name)。
- **不做** v0.10.18+ 计划的:删除派生 `classes_config / attribute_schema` 字段、加 polyline 工具、AAP JSON 1.1 importer 完整支持 video_track tool_unit。
- **迁移风险**: alembic backfill 默认把所有 image-det 项目类塞 bbox unit;若客户实际混用 polygon 工具,需要事后到 ProjectSettings 把类**复制**到 region unit(强隔离,不能共享)。这条要在 CHANGELOG 与 docs-site 标注。
