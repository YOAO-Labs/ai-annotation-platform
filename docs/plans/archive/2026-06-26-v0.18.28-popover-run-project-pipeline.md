# v0.18.28 · 「当前题 AI」popover 新增「运行当前题（按项目编排）」

> 草案 (2026-06-26). **交互工具栏重设计 epic 第 3/3 版**。让 popover 读项目已存编排（v0.18.27），对当前题跑完整流水线。**依赖 [v0.18.27](2026-06-26-v0.18.27-project-pipeline-persistence.md)**。
>
> Epic 总览见 [v0.18.25](2026-06-26-v0.18.25-interactive-ai-toolbar-redesign.md)。上游 [多阶段预标注编排 epic](../../ROADMAP/2026-06-23-staged-preannotation-pipeline-roadmap.md)（§5 工作台衔接红线）。

## 1. 背景

popover「当前题 AI」现在只能跑**单阶段·本次临时配置**（`handleRunAi`，`useWorkbenchShellModel.tsx:1103-1138`，`buildArgs` 单阶段、无 `pipeline_stages`）。v0.18.27 让项目能存一条编排后，popover 应能**把那条编排只跑当前图**——它从「单阶段执行器」升为「双模式执行器」，但**仍是执行器、不是编排编辑器**（编排在 `/ai-pre` 定义保存）。

## 2. 目标 / 非目标

**目标**
- popover 读 `project.preannotate_pipeline`；非空时显示「运行当前题（按项目编排）」入口。
- 点击 → `preannotate` with `task_ids=[当前题]` + `pipeline_stages=项目编排`，`predict_mode="overwrite"`。
- 项目无编排 → 退化为现状单阶段运行（完全向后兼容）。

**非目标**
- popover **不 host 阶段卡列表、不变成编排编辑器**（路径 B epic §5 红线）。
- 不改 `/ai-pre`、不改 worker（执行链 + payload 已就绪）。
- 候选属性审阅/采纳**不重做**（v0.18.0/0.18.3 已支持，多阶段产出的带属性候选直接复用）。

## 4. 设计与改动

### 4.1 popover 组件（`AIInspectorPanel.tsx` `AIPredictionPopover`）

- props 加：`hasProjectPipeline?: boolean`、`projectPipelineStageCount?: number`、`onRunPipeline?: () => void`。
- 运行按钮区（`:530-544`）：`hasProjectPipeline` 为 true 时，在「运行当前题」旁/下增第二个按钮「运行当前题（按项目编排 · N 阶段）」→ `onRunPipeline`。两按钮共用 `aiRunning` 禁用态。
- 无项目编排 → 不渲染第二按钮，头部布局与现状一致（向后兼容）。
- header 已偏挤（两按钮 + badge），实装目视确认；必要时第二按钮放阈值区上方独立一行。

### 4.2 运行链（`useWorkbenchShellModel.tsx`）

- 读 `currentProject.preannotate_pipeline`（v0.18.27 已扩字段）→ 派生 `hasProjectPipeline` / `projectPipelineStageCount`。
- 新增 `handleRunAiPipeline`（仿 `handleRunAi` `:1103`）：
  ```ts
  const stages = currentProject?.preannotate_pipeline;
  if (!stages?.length || !taskId) return;
  triggerPreannotation.mutate({
    ml_backend_id: stages[0].ml_backend_id,   // 顶层 backend = 源阶段 backend
    task_ids: [taskId],
    pipeline_stages: stages,
    predict_mode: "overwrite",
    on_key_conflict: "last_wins",             // 与 /ai-pre 默认对齐 (实装核对)
  }, { onSuccess: () => preCfg.markHot(), onError: … });
  ```
- 把 `hasProjectPipeline` / `projectPipelineStageCount` / `onRunPipeline=handleRunAiPipeline` 接到 popover props 组装处（与 `onRunAi`/`aiModel` 同处下发）。

## 5. 测试

- 项目无编排 → popover 仅「运行当前题」（第二按钮不渲染）。
- 项目有编排 → 第二按钮渲染、显示阶段数；点击以 `task_ids=[当前]` + `pipeline_stages=项目编排` + `overwrite` 调 mutation。
- `handleRunAiPipeline`：空编排 / 无 taskId → 不发请求。
- 回归：现状单阶段「运行当前题」不变。

## 6. 验收

- 项目在 `/ai-pre` 存了 detect→classify 编排 → 工作台打开某题 → popover 出现「运行当前题（按项目编排 · 2 阶段）」→ 点击对当前图跑完整链 → 候选带属性（`vehicle_type`/`color`…）→ 右栏审阅/分步采纳正常（复用 v0.18.3）。
- 未配编排的项目 → popover 仅单阶段运行，无第二按钮。

## 7. 风险

- **顶层 `ml_backend_id` 必填性**：`apps/api/app/schemas/preannotate.py::PreannotateRequest` 带 `pipeline_stages` 时顶层 `ml_backend_id` 是否仍必填、是否被源阶段覆盖——实装核对 `trigger_preannotation`（`projects.py:1385-1505`），本 plan 暂取「顶层 = stage0.ml_backend_id」。
- **`predict_mode` / `on_key_conflict` 默认**：与 `/ai-pre` 跑编排时一致（核对 `ProjectDetailPanel.onRun` `:499-508`）。
- **popover header 拥挤**：§4.1 两按钮布局，目视确认。
- **版本号收尾**：CLAUDE.md §10 → 0.18.28。新增功能 → 记 CHANGELOG；同步 popover 相关用户手册（`docs-site/user-guide` 工作台 AI 章节）。
