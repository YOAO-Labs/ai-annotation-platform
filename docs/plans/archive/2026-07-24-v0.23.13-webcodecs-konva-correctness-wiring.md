## 1. 本版目标

本版把已经存在但生产不可达的 WebCodecs decoder 恢复为可用的 Konva 暂停帧来源，并先建立可证明的
正确性与降级合同。

成功后：

- 设置中开启“WebCodecs 精确解码”并刷新，会真实请求当前帧所属 chunk；
- 前端用后端 sample manifest 构造 `EncodedVideoChunk[]`；
- decoder 按目标 timestamp 选择 `VideoFrame`；
- precise bitmap 在暂停态优先进入 `VideoKonvaMediaLayer`；
- 当前帧 JPEG 与画布读取同一个 bitmap；
- pending、缺 samples、unsupported codec、CORS 和 decode failure 都回退；
- 播放态完全保留 `<video>`；
- 快速 seek 不显示旧帧；
- 当前明显死代码和误导注释得到收口。

本版本不实现持久 GOP decoder session；同一帧请求 single-flight，但随机目标仍可从关键帧重新建立一次
无状态 decode。性能复用在 v0.23.14 单独完成。

### 2.3 已确认的错误

`decodeChunkToBitmap(config, chunks, targetFrameIndex)` 当前使用：

```ts
const wanted = frames[targetFrameIndex] ?? frames[frames.length - 1];
```

这里的 `targetFrameIndex` 是视频全局帧号，而 `frames` 只包含局部 GOP decoder output。即使把它改成
局部 index，B 帧也会让 decode order 与 presentation order 不同。唯一可靠选择键是输入 chunk 的
timestamp 与 output `VideoFrame.timestamp`。

### 4.3 新增 `videoChunkDemux.ts`

文件：

```text
apps/web/src/pages/Workbench/stage/videoChunkDemux.ts
apps/web/src/pages/Workbench/stage/videoChunkDemux.test.ts
```

导出：

```ts
export interface EncodedVideoDecodePlan {
  config: VideoDecoderConfig;
  chunks: EncodedVideoChunk[];
  targetFrameIndex: number;
  targetTimestampUs: number;
  chunkId: number;
  gopStartDecodeIndex: number;
  targetDecodeIndex: number;
}

export function buildEncodedVideoDecodePlan(
  chunkBytes: ArrayBuffer,
  samples: VideoChunkSamplesResponse,
  targetFrameIndex: number,
): EncodedVideoDecodePlan | null;
```

算法：

1. 验证 `codec_string`、width、height 和 `samples`。
2. 在保持后端 packet decode order 的 `samples` 数组中查找
   `sample.frame_index === targetFrameIndex`。
3. 从 target decode index 向前找最近 `is_keyframe=true`。
4. 若未找到 key sample，返回 null；不能把数组第 0 项强行标记为 key。
5. 验证 `[gopStartDecodeIndex, targetDecodeIndex]` 每个 sample：
   - `offset_in_chunk`、`size_bytes` 为安全整数；
   - offset ≥ 0、size > 0；
   - `offset + size <= chunkBytes.byteLength`；
   - `pts_ms`、`duration_ms` 为有限数。
6. 对每个 sample 用 `Uint8Array(chunkBytes, offset, size)` 构造
   `EncodedVideoChunk`，避免先 `slice()` 产生一次不必要副本；由原生 constructor 决定是否复制。
7. `type` 只读 sample key flag。
8. `timestamp = Math.round(pts_ms * 1000)`。
9. `duration_ms > 0` 时设置 `duration = Math.round(duration_ms * 1000)`。
10. base64 description 解成 `Uint8Array`，填入 `VideoDecoderConfig.description`。
11. config 使用 `codec/codedWidth/codedHeight`。
12. 返回目标 sample 的 timestamp，不把 target frameIndex 传作 output 下标。

注意：

- `atob` 失败或 description 空时返回 null，并记录 `description_unavailable`；
- 当前 chunk 是 MP4 AVCC/HVCC sample，缺 description 不尝试 Annex-B 猜测；
- 本版不在前端转换 NALU 格式；
- B 帧测试必须使用类似 decode order `[frame 10, frame 12, frame 11]` 的 fixture。

### 4.4 修正 decoder 核心

重构 `decodeChunkToBitmap`：

```ts
export async function decodePlanToBitmap(
  plan: EncodedVideoDecodePlan,
): Promise<DecodedVideoFrameBitmap | null>;
```

能力探测：

```ts
VideoDecoder;
EncodedVideoChunk;
createImageBitmap;
```

config 支持：

```ts
const support = await VideoDecoder.isConfigSupported(plan.config);
if (!support.supported) return null;
decoder.configure(support.config);
```

兼容边界：

- 如果实现提供 `VideoDecoder` 但缺少 `isConfigSupported`，本版允许走 configure try/catch；
- 该降级要进入诊断，不能假设 supported；
- `isSecureContext` 只作为诊断字段，不单独阻断，因为某些本地环境可能有实现差异。

output 策略：

```ts
let wanted: VideoFrame | null = null;

output(frame) {
  if (frame.timestamp === plan.targetTimestampUs && wanted === null) {
    wanted = frame;
  } else {
    frame.close();
  }
}
```

flush 后：

- 没有 wanted → null；
- `createImageBitmap(wanted)`；
- 返回 entry 的 `frameIndex = plan.targetFrameIndex`；
- finally 关闭 wanted 与 decoder；
- bitmap 成功交付后不在 finally 关闭，由缓存接管。

error callback：

- 保存首个 error；
- flush 后即使 promise 异常行为因浏览器不同，也按 error 状态返回 null；
- 不向 console 打完整 chunk、description 或二进制。

### 4.5 hook 缓存与 single-flight

### 4.6 新增 `useVideoPreciseFrame`

文件：

```text
apps/web/src/pages/Workbench/stage/useVideoPreciseFrame.ts
apps/web/src/pages/Workbench/stage/useVideoPreciseFrame.test.ts
```

输入：

```ts
interface UseVideoPreciseFrameArgs {
  taskId: string | null | undefined;
  frameIndex: number;
  enabled: boolean; // paused && !frameClock.isSeeking
  maxItems: number;
}
```

输出：

```ts
interface UseVideoPreciseFrameResult {
  active: boolean;
  bitmap: CachedVideoBitmap | null;
  sourceState:
    | "disabled"
    | "idle"
    | "chunk-pending"
    | "loading"
    | "decoding"
    | "ready"
    | "fallback";
  fallbackReason: PreciseFrameFallbackReason | null;
  diagnostics: VideoPreciseFrameDiagnostics;
}
```

query 流：

1. `useVideoChunkDecoder({ taskId, maxItems })` 先解析 flag 和浏览器能力。
2. decoder inactive 时所有后续 query `enabled=false`。
3. active 时请求 task manifest v2。
4. `targetChunkId = floor(frameIndex / chunk_size_frames)`。
5. `getChunk(datasetItemId, targetChunkId)`：
   - pending：按响应 `retry_after`，clamp 到 1–10 秒轮询；
   - ready：停止轮询；
   - failed：停止并 fallback；
   - query 不使用 `staleTime=Infinity` 持有 signed URL；
   - URL 过期导致 bytes 403 时 invalidate 后只重取一次 metadata。
6. ready 后请求 samples：
   - query key 为 dataset + chunk；
   - `staleTime=Infinity`；
   - 404 不重试，fallback `samples_unavailable`。
7. ready URL + samples 后请求 chunk bytes：
   - raw `fetch(url, { signal })`；
   - 检查 `response.ok`；
   - query key 使用 dataset + chunk，不使用带签名 URL；
   - `gcTime` 设短值，例如 60 秒；
   - v0.23.14 再升级为显式 byte LRU。
8. bytes + samples 就绪时 build plan 并 decode。
9. decode 完成后，仅当最新 ref 仍匹配 taskId + frameIndex 且 pipeline enabled，调用
   `decoder.showFrame(frameIndex)`。
10. 返回 bitmap 时再次验证 `bitmap.frameIndex === frameIndex`。

播放/seek 门：

- `enabled=false` 时不发新的 metadata/chunk/sample/bytes/decode；
- 已有 bitmap 可以留在 cache，但媒体层播放时不会使用；
- `frameClock.isSeeking=true` 时等待原生 seek 稳定，避免 scrub 每个中间值都启动 pipeline；
- 稳定后 effect 会因 `isSeeking` 变 false 自动启动当前目标。

### 4.7 接入播放控制器

在 `useVideoPlaybackController`：

1. 保留 `useVideoBitmapCache` 作为即时显示与 fallback。
2. 在 `frameClock` 和 `performanceConfig` 可用后调用：

   ```ts

     taskId: manifest?.task_id,
     frameIndex,
     enabled: !isPlaybackActive && !frameClock.isSeeking,
   ```

3. 选择：

5. `captureCurrentFrameJpeg` 先读 `displayBitmapRef.current`，再回退 `<video>`。
6. 返回 `frameSource`：


7. 删除未使用的 `showCachedBitmap` result 字段。
8. 删除顶部未迁移 TODO。

native bitmap 仍在 seek 后捕获，不因 precise active 而关闭。这样精确帧冷启动期间仍能立即显示 fallback。

### 7.1 `videoChunkDemux.test.ts`

| 场景                           | 断言                                                      |
| ------------------------------ | --------------------------------------------------------- |
| 普通 I/P GOP                   | 从最近 key 到 target；timestamp/duration 为微秒           |

| GOP 前无 key                   | null，不伪造 key                                          |
| offset 负数/小数/越界          | null                                                      |
| size 0/越界                    | null                                                      |
| description base64             | config.description 字节一致                               |
| description 非法/缺失          | null                                                      |
| duration 0                     | chunk init 不带 duration                                  |
| coded size 非正数              | null                                                      |

### 7.2 decoder 单测

- output 顺序与输入 timestamp 顺序不同，仍命中 target timestamp；
- target 为第二个 output，非目标 frame 立即 close；
- 没有 target timestamp → null；
- `isConfigSupported=false` 不 configure/decode；
- configure/decode/flush/error callback/createImageBitmap 各自失败；
- wanted frame、其它 frame、decoder 各 close 一次；
- 成功 bitmap 不被 decoder finally close；
- 相同 frame 并发只调用一次底层 decode；
- task 切换后旧 bitmap close 且不入新缓存。

### 7.3 precise hook

MSW / mock fetch 覆盖：

- flag off：manifest/chunk/samples/bytes 全部 0 请求；
- manifest v2 缺 dataset / chunk size 非法；
- chunk pending 两次后 ready；
- pending polling 使用 retry_after；
- chunk failed；
- samples 404 不重试；
- bytes CORS/network/500；
- signed URL 403 → metadata refresh 一次 → 成功；
- unsupported config fallback；
- frame 5 慢、frame 6 快：只 frame 6 激活；
- frame 5 → 6 → 5，同 key single-flight 最终可命中 frame 5；
- `enabled=false`（playing/seeking）停止新请求；
- 卸载 abort fetch；
- maxItems 透传。

### 7.4 controller / Konva

- paused + precise frame match：`displayBitmap=precise`、source=webcodecs；
- precise frame 不匹配：使用 native bitmap；
- precise null：使用 native；
- 两者 null：media layer 使用 video element；
- playing：即使 bitmap 存在，`pickMediaImageSource` 选 video；
- `captureCurrentFrameJpeg` 使用 precise bitmap；
- Stage 传 `displayBitmap` 而不是 native `activeBitmap`；
- `data-video-frame-source` 跟随 source。

### 7.5 后端 API

补当前缺口：

- ready chunk samples 200，字段含 description；
- diagnostics 无 samples → 404；
- 不可见 dataset item → 404；
- response samples 保持存储顺序。

## 11. 风险与回滚

- 最小回滚是关闭 localStorage flag；native 路径保持原状。
- 本版不改变 annotation 或持久数据，回滚无数据迁移。
- 若 manifest v2 query 出现权限或兼容问题，precise hook fallback；不能切换主工作台 manifest。
- 若某 codec `isConfigSupported=true` 但 decode 失败，记录 `decode_failed`，不重复无限重试。
- 若 ImageBitmap 创建造成资源压力，本版由现有 item LRU 止损，v0.23.14 必须完成 byte budget。
- 若本版发现 sample timestamp / frame_index 后端合同错误，暂停 UI 接线，先用最小后端测试复现；
  不在前端猜测纠正。
