## 工作包 A：账号恢复可完成

4. 重置成功后检查旧会话失效、当前重新登录及管理员临时密码后的改密引导；复用现有 token generation 和密码重置标记，按真实调用补接。

涉及：上述 auth、password_reset、email、me schema，以及登录/忘记密码/重置页面、SettingsPage、现有认证 hooks。

## 工作包 B：停用、恢复和交接分清楚

### 产品行为

- 人员列表提供启用、停用、全部筛选。停用保留历史记录；删除继续保留现有独立语义，不能把删除按钮改名后作为可逆停用。
- 正常离职采用“查看待交接事项 → 按职责选择接收人 → 确认交接并停用”。紧急停用可以立即阻止使用，并保留管理员可查询的待交接清单。
- 待交接清单覆盖项目 owner、批次标注员/审核员、待标注/审核/退回任务及编辑锁；展示个人 API Key 的用途或名称，提示集成负责人另行换发，不转交旧明文密钥。
- 按项目分别选择合格的标注接收人、审核接收人和项目负责人；不强迫单一接收者承担所有角色。接收人必须启用且具备目标项目实际权限。
- 恢复账号只恢复允许恢复的停用状态；不抢回已交接任务、不恢复已撤销密钥、不承诺还原已脱敏历史。
- 保留最后一名超管、自身停用及项目管理员管理范围的现有限制。

### 接口、数据与一致性

- 现有 `GET /api/v1/users` 增加可选账号状态过滤，缺省仍为启用，保持现有返回数组契约。列表分页属于第二批的兼容扩展。
- 新增 `GET /api/v1/users/{id}/offboarding-preview`，按项目返回当前职责、数量、可选接收人和阻断原因；预览不修改数据。
- 新增 `POST /api/v1/users/{id}/offboarding`，接收逐项目的接收者映射、预览版本和原因；执行时重新核对职责、权限与锁，状态已变化则返回 409 并要求刷新预览。
- 新增 `POST /api/v1/users/{id}/reactivate`，只允许明确可恢复的停用账号。
- 在 User 上补充明确的停用类型、时间、操作者、原因；继续以 `is_active` 承担现有认证检查，不挪用表示在线状态的 `status`。所有停用/删除/自助注销写入路径同步维护生命周期信息。
- 历史 `is_active=false` 不能一律视作可恢复。可可靠判定来源的记录按既有操作归类；无法判定的归入历史未知状态，不自动开启恢复，也不反向重建被脱敏的审计信息。
- 用户停用、任务和批次归属、项目负责人、锁释放及审计在同一事务内完成。复用现有批次级联和项目转让规则，并处理所有仍可继续流转的任务状态，包括退回任务。
- 迁移采用可兼容的新增字段，按实施当天 Alembic head 生成迁移，不在本文预分配迁移编号。不得通过批量重建用户完成迁移。

```text
成员管理页 → 交接预览 API → 项目 / 批次 / Task / 锁
           → 确认 API → 重新校验 → 单事务更新归属与账号状态
                                     └→ 审计 → 接收者继续工作
```

验收：分别使用跨两个项目的标注员、审核员和项目 owner 验证交接，标注员场景包括退回任务；交接后各职责的接收者都能继续工作。历史混合职责作为异常数据单列，不要求第一批先支持同账号跨项目不同角色。并发领取、接收者被停用、权限不足时不出现部分转交；紧急停用立即阻止新业务操作，旧会话和 API Key 也不能继续以该账号工作。

## 工作包 C：查询失败与任务后页可处理

1. 标注/审核首页和任务列表分别处理加载、空数据、失败、权限变化；失败提供重试，不把失败转成空任务列表。
2. 标注任务列表接入既有分页能力，提供加载更多或可持续滚动入口，保留筛选条件与当前选择。
3. 在旧数据已加载后的刷新失败中保留旧内容并说明更新失败；请求切换后迟到响应不能覆盖当前项目或筛选。
4. 保留可重试错误的必要上下文，并复用 BUG 反馈采集入口；不在员工页面堆放后端堆栈。

验收：250 条任务的批次可访问第一条和最后一条；断网、403、500、空队列四种场景可区分；筛选切换和返回后没有重复或丢失列表项。

## 工作包 D：让用户确认保存与提交结果

1. 固定显示保存中、已保存、仅保存在本机、同步失败；实时进度连接状态不再代表标注已经保存。
2. 提交前使用既有持久化/离线队列 owner 判定，只有服务端确认后才显示送审成功并自动下一题；不得另建一份保存状态或任务选择状态。
3. 必填校验失败定位具体对象及字段；保留已编辑内容。提交成功、退回、撤回都给出明确结果。
4. 按现有工作台状态约束验证切任务、切项目、退出账号和旧请求晚到；不允许旧账号/旧任务的队列写入新上下文。

实施时遵循 `.agents/skills/aap-workbench-state/SKILL.md`；重点扩展真实行为验收，不重写已存在的离线机制。
