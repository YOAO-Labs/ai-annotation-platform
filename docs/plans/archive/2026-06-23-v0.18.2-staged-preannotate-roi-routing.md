# v0.18.2 — M2 · ROI 配置、类别路由与降级策略

> 状态：**待实施 plan**（不开干）。创建于 2026-06-23。
>
> 定位：路径 B（[ROADMAP](../../ROADMAP/2026-06-23-staged-preannotation-pipeline-roadmap.md)）第二里程碑。M1 打穿了「单 detect→单 classify」顺序通路；本期把通路变**可控**：ROI 可配、**按类别路由（`parent_class_filter`）**、**并行扇出（同父多分类）**、阶段级失败/降级策略、**按阶段进度上报**。仍是后端 + 数据层为主，完整阶段卡 UI 的产品化留 M3（本期 UI 只补「并行添加同级阶段」与逐阶段进度的最小呈现）。

## 1. 目标 / 非目标

**目标**
1. `roi.mode` / `roi.pad` 可配（M1 固定值升为请求可调）。
2. `parent_class_filter`：本阶段只对指定父框类别启动（ROADMAP §3.1 的「按类别路由」声明式过滤）。
3. **单层并行扇出**：多个阶段共享同一 `parent_stage` → 各对同父框跑、各写不同属性键，结果 union 合并进同一父框。
4. **并行兄弟键冲突检测**：每阶段 `write.keys` 显式声明；编排校验期对「多阶段写同键」给告警（默认拒绝，末位覆盖留开关）。
5. 阶段级失败策略可选：下游失败 → ①保留上游框、属性留空（默认）vs ②整框丢弃。
6. 进度 / 成功率**按阶段上报**：每阶段独立进度与统计（为 M3 逐阶段进度条供数据）。
7. UI 最小补：`ProjectDetailPanel` 支持「并行添加同级阶段」+ 每阶段类别过滤器/ROI pad 字段 + 逐阶段状态徽标（完整可视化留 M3）。

**非目标**
- 不做 `chord` 真并行（同步顺序跑并行兄弟，ROADMAP §7.1；真并行留 M3）。
- 不做 `write=new_shape`、正式表字段（留 M3）。
- 不做「一键采纳整条 pipeline」、工作台候选属性审阅泛化（留 M3 / v0.18.3）。
- 不做完整阶段卡列表产品化 UI（增删排序、成功率图表，留 M3）。

## 2. 详细设计

### 2.1 ROI 可配（升级 M1 的 `build_roi_inputs`）

- `roi: { "mode": "crop", "pad": 0.05 }`：`mode` 本期仍只实装 `crop`（结构留扩展位，如未来 `mask`/`context`）；`pad` 从 M1 固定值改为请求传入，缺省 0.05。
- `build_roi_inputs` 读 `stage.roi.pad` 做 bbox 外扩；越界 clamp 到图边界。
- 校验：`pad ∈ [0, 0.5]`，`mode ∈ {"crop"}`。

### 2.2 类别路由 `parent_class_filter`（ROADMAP §3.1 / §4）

- worker 取父框时按 `class_name ∈ parent_class_filter` 过滤（沿用 ROADMAP §3.2 伪码）：
  ```python
  boxes = [b for b in parents if not stage.parent_class_filter
           or b.class_name in stage.parent_class_filter]
  if not boxes: continue          # 该框无符合类别的父 → 跳过本阶段
  ```
- **语义即声明式路由**：不相交类别集 = 不同类走不同下游模型；重叠 = 同类喂多模型（配合 2.3 扇出）；命中零阶段 = 保持纯检测框（降级）。**无 if/else 分支节点**。
- 过滤维度对齐：父框 `class_name` 是检测类（detect 粗类），`parent_class_filter` 用同一类名集合。

### 2.3 单层并行扇出（同父多子）

- 数据模型已就绪：多个 stage 设同一 `parent_stage`（如 stage 1、2 同 `parent_stage=0`）即并行兄弟（ROADMAP §1 深度 2 扇出树）。
- worker 顺序跑各兄弟（M2 仍同步，§7.1）：每个兄弟对同一批父框各跑一遍、各 merge 自己的 `write.keys` 进父框 `attributes` → **union 合并**。
- `PredictionMeta.extra.enriched_by_stage` 累加多个阶段 index，`stage_attr_keys` 累加各阶段写的键。
- 校验：并行兄弟的 `parent_stage` 必须指向同一已存在源阶段。

### 2.4 键冲突检测（ROADMAP §7.6）

- 编排归一化阶段：收集所有阶段 `write.keys`，若两阶段写同一键 → **默认拒绝该配置**（422 + 结构化 detail 指明冲突键），提供 `on_key_conflict: "last_wins"` 显式开关时改为末位覆盖。
- 不同键 union 是常态，无需告警。
- 前端：配置时即时校验，冲突键标红（最小提示，完整 UI 留 M3）。

### 2.5 阶段级失败 / 降级策略

- 请求体阶段可选 `on_failure: "keep_parent" | "drop_box"`（缺省 `keep_parent`）：
  - `keep_parent`（默认）：下游对某父框失败 → 保留上游框、该属性键留空，记软告警（沿用 `failed_predictions`）。
  - `drop_box`：下游失败 → 连同上游框一并丢弃（适合「无属性则该框无意义」场景）。
- 「前驱无（符合过滤的）框」是正常降级（跳过），不计失败。

### 2.6 按阶段进度上报

- 现进度发布是 batch 级单进度。改为**每阶段一条进度通道**：阶段 index + `{detected, enriched_ok, enriched_failed}` 统计。
- 复用现有 async_jobs / 进度发布机制，payload 增 `stages: [{stage, status, stats}]`（ROADMAP §4 运行态数据来源）。
- 前端本期最小消费：每阶段卡显 pending/running/done/failed 徽标 + 计数；完整进度条/成功率图表留 M3。

### 2.7 UI 最小补（`ProjectDetailPanel`）

- 「并行添加同级阶段」：在某父阶段下加一组同级卡（容器持多份共享表单实例，红线同 M1——不改共享表单）。
- 每阶段卡补字段：`parent_class_filter`（类别多选）、`roi.pad`（数字）、`write.keys`（来自协议③导入字段，多选/只读）。
- 逐阶段状态徽标 + 计数（消费 2.6 数据）。
- 仍是卡片列表，非画布（ROADMAP §4 决议）。

## 3. 实施步骤（每步带 verify）

1. `roi.pad`/`mode` 可配 + 校验 → verify：同图不同 pad 裁出不同外扩 crop；非法 pad 422。
2. `parent_class_filter` → verify：detect 出 car+person 混合框，classify 阶段设 `[car]` 只对 car 跑、person 框保持纯检测。
3. 并行扇出 union → verify：同 `parent_stage=0` 配 color + vehicle_type 两阶段，同一车框得 `{color, vehicle_type}` 两键。
4. 键冲突检测 → verify：两阶段都写 `color` → 默认 422；带 `last_wins` 开关 → 末位覆盖入库。
5. 阶段级失败策略 → verify：构造下游必失败场景，`keep_parent` 保框留空、`drop_box` 丢框，各符合预期。
6. 按阶段进度上报 → verify：跑多阶段批，async_jobs payload 出现逐阶段 `stats`，前端徽标随之更新。
7. UI 最小补 → verify：界面能并行加同级阶段、配类别过滤/pad、看到逐阶段徽标。
8. 版本收尾（CLAUDE.md §10）：bump 四处 + `uv lock` + openapi 快照；`curl localhost:8000/health` 验证 0.18.2。

## 4. 验收标准

- detect 出多类框，classify 阶段按 `parent_class_filter` 只对指定类启动，其余类降级为纯检测框。
- 同父并行两分类阶段，目标框 union 得多属性键；写同键时按冲突策略处理。
- 下游失败按 `keep_parent`/`drop_box` 表现正确，不导致整批崩。
- 多阶段批量预标的进度/成功率按阶段可见。

## 5. 风险 / 开放问题

- **顺序跑并行兄弟的耗时**：N 个分类器对同批框顺序跑，wall-clock = ΣN；规模化前可接受，`chord` 真并行留 M3（§7.1）。
- **类别名对齐**：`parent_class_filter` 用 detect 类名，需与项目 classes / detect `/setup` 类名一致，否则静默过滤为空。校验期可给「该过滤器不匹配任何已知检测类」告警。
- **键冲突默认策略**：拒绝 vs 末位覆盖的最终缺省，按实测使用习惯再定（§7.6 留口）。
- **进度通道改造面**：从单进度改逐阶段，触及 async_jobs payload 结构，注意前端老消费方兼容。
