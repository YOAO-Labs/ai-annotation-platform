# E2E CI 鲁棒性与反馈速度优化

> 状态：已实施并完成本地验证；提交与远程验证结果以关联 PR 的检查记录为准。范围为测试、CI 与开发文档，不修改产品行为或发布版本。

## 背景与证据

- 运行 `34304471704` 的第四分片耗时 59.7 分钟。布局矩阵覆盖 2 种模式 × 3 种媒体，每例执行 54 次重排、限时 180 秒；旧配置重试两次，六例全部超时可耗时 54 分钟。
- 当前主分支已提供四个默认分片、三个 Mask 套件、单次重试、首例最终失败早退，以及 15/20/30 分钟的进程/步骤/job 限时。保留这些保护。
- 运行 `34315896922` 的 CI 约 10 分 51 秒通过，第四分片仍有一个重试后通过的用例。该数据是既有基线，不是本次优化结果。
- 普通 E2E 混有工作区与画布截图比较；`annotation.spec.ts` 的画框用例在未保存时调用测试接口推进状态，仅检查 URL，存在漏报。

## 目标与边界

1. 普通 PR 保留全部现有功能回归，以及六种布局上下文的真实拖动、跨视口、紧凑模式、持久化和刷新恢复检查。
2. 普通布局场景执行 14 次重排（10 次面板动作 + 4 次任务队列动作）；完整 54 次压力场景保持独立，相关 PR、主分支、每晚和手动运行。
3. 截图差异在独立套件中报告，保留既有基线、容差和审核流程，不自动更新基线或忽略视觉失败。
4. 画框检查必须经过真实 UI 选类与保存，验证请求、API 读回和刷新恢复；补充保存失败场景，确认不会产生已保存标注。
5. 每个失败尝试保留 trace，CI 汇总每个套件的耗时、失败、重试后通过和跳过数量。

不扩大同一数据库的 worker 数，不改共享开发环境，不引入新的测试框架，不削弱权限、写入保护、画布生命周期和持久化断言。其余固定等待、全量 seed 成本及历史跳过用例属于后续逐项优化，不在本次批量改写。

## 实施方案

### 测试分类

- 在现有测试上添加 Playwright `@visual` / `@stress` 标签，保留截图测试标题与文件位置。
- 默认配置排除两个标签；新增扩展配置复用默认配置，清除排除规则、只选择扩展标签，禁用整例重试。
- 新增 `test:e2e:visual`、`test:e2e:stress` 命令；保留现有功能与 Mask 命令。
- 布局矩阵共享场景实现，短流程与压力流程均动态计算视口切换位置和最后浮动动作，避免缩短循环后丢失断言前提。

### CI 调度与报告

- 提取现有 E2E runner job 为可复用 workflow，保留独立 runner 的 Postgres、Redis、MinIO、构建与超时边界。
- CI 计划 job 为每个 PR 保留原七套件。前后端应用、共享依赖、Playwright 和相关 workflow 变更追加视觉与压力套件；路径删除与重命名均按变更路径判断。主分支总是包含扩展套件。初始分类保守覆盖整个应用目录，不在本轮进一步收紧路径。
- 路径分析失败时使计划 job 失败，不能静默跳过扩展检查。所有已选择套件继续进入原 `Frontend E2E` 必需汇总门禁。
- 新增每晚与手动扩展 workflow，复用相同 runner 与套件定义。
- 输出机器可读 Playwright 报告并生成 Actions 摘要；保留 HTML、失败截图及 trace。报告缺失时明确标记测试未完成。

资源取舍：相关 PR 增加两个独立 runner，以分别报告视觉和压力结果；实际排队时间和 runner 总用量需要后续远程 CI 观察。维持现有数据库隔离，不以在同一数据库增加 worker 来节省服务启动成本。

### 业务断言

- 画框用例显式指定任务并等待图片就绪；用已有媒体位置/尺寸属性计算坐标，验证指针落在画布上。
- 使用真实类别选择完成创建；监听该任务的 POST，成功响应后验证 annotation ID、类别、几何及 API 列表；刷新后再次核对渲染与持久化内容。
- 保存失败用例仅模拟 annotation POST 的服务端错误，其余链路真实运行；确认请求确实发生、没有已保存标注、刷新后仍为空。

## 验证

- Node 测试验证路径分类：无关文档、工作台/共享样式、依赖、测试夹具、CI、删除/重命名与主分支/定时事件；验证必需套件没有被过滤掉。
- Playwright `--list` 检查普通、视觉、压力与 Mask 命令的实际选例和互斥性，不启动数据库。
- 在当前 checkout 的 Python 虚拟环境中使用新建的 `_e2e` 数据库、专用服务端口与独立对象存储桶；不得连接日常开发数据库或清理共享桶。
- 浏览器执行画框成功/失败、完整布局短流程与压力流程、视觉套件。对成功保存检查注入临时故障，确认断言会红，再恢复并验证通过。
- 执行受影响 TypeScript/ESLint 检查、格式检查、workflow 命名检查和 `git diff --check`。
- 测试结束清理数据库、对象桶、报告、临时日志、浏览器输出及自有进程。记录本地实测与远程 CI 尚未验证的边界。

## 成功标准

- 短流程每种上下文的重排数从 54 降到 14，同时保留所有末态与恢复断言。
- 默认命令不执行截图和压力用例；扩展命令无静默漏选。相关 PR 与夜间会执行完整检查，扩展失败能够阻止相关 PR 的 E2E 门禁通过。
- 正常尺寸变化不会使纯功能用例因截图尺寸不同而失败；视觉差异仍由独立套件发现。
- 真实保存被破坏时，成功链路测试必须失败；保存失败场景不得通过 seed 伪造业务成功。
- 时间收益以相同场景的本地短流程/压力流程实测和后续远程 CI 为准，不承诺尚未测得的总耗时。

## 回滚

调度与测试改动可通过撤销相应提交恢复，无产品数据迁移。后续 flaky 排查中的视频状态修复独立提交，可单独回滚。保留已有截图位置和分支保护汇总名称。

### 验证边界与后续观察

首轮 PR 远程运行定位到两处既有测试问题，均在本地隔离栈复现后修正：中心绘框的选中对象浮窗遮挡下一次边缘拖拽，改为通过真实 UI 收起浮窗，并在绘制前验证起点命中画布；点云连续建框的全页类别文本查询同时匹配面板和详情下拉框，改为限定到类别面板。几何、保存与连续创建状态断言保持不变。修复后的远程结果及重试记录以关联 PR 为准。

第二轮上述两个分片通过，视频 Issue 分片暴露会话统计上报在刷新时取消的误报，以及 180 帧夹具与正式 manifest 分片大小不一致的问题。补齐明确端点的生命周期取消规则，保留业务写入与 HTTP 错误检查；Issue 夹具按 API 配置生成真实完整分片，浏览器前置检查正式 manifest 与分片范围和就绪状态。复用生产转码及样本探测，Python 测试逐帧验证真实分片的像素身份，并覆盖自定义分片大小；不改变应用导航超时或放宽像素断言。

后续对已通过 CI 中的九项 flaky 逐项读取首次失败 trace，收敛为四类问题：

- 五项 Mask 交互竞态：展开动画改变快捷区滚动位置，造成更多按钮按下和抬起错位；虚拟列表自动滚动使悬停编辑入口失去命中。共享 helper 等待实际动画完成，高级编辑改用选中信息卡，并覆盖折叠后重新进入编辑。保存、像素、冲突和权限断言保持不变。
- 两项精确视频首帧等待：frame clock 更换任务或时间表时取消旧 seek，却未释放已发布的 seeking 状态；当新时间已经到达目标帧时不会再次 seek，精确解码持续等待。新 owner 显式释放旧状态，回归测试覆盖 A→B→A 与估算时间表切换到精确时间表，旧代码实际失败、修复后通过。
- 一项视频 Issue 误报：G1 与 G2 的取消判定重复且不一致。两套件共用明确端点的取消分类器，并通过前端单元测试验证业务写入、HTTP 错误和其他网络错误不会被忽略。
- 一项点云浏览器上下文创建超时：发生在测试主体之前。后续使用构建产物、Chromium 的 SwiftShader 软件渲染和四核 CPU 复现，定位到前置跨帧任务弹窗的背景模糊。其合成清理会阻塞后续上下文创建；仅正常卸载点云或每例重启浏览器未消除清理耗时。关闭模糊后恢复正常，再恢复模糊又出现约 25 秒的浏览器退出延迟。公共 Modal 增加默认开启的背景模糊选项，跨帧任务中心显式关闭，保留遮罩和 Radix 模态交互；不增加重试或放宽超时。

点云回归断言直接检查任务中心遮罩的计算样式：旧构建实际返回 `blur(2px)`，在预期 `none` 的断言处失败。修复后的原四例顺序与上下文创建耗时、完整远程矩阵结果记录在关联 PR 中。该验证使用软件渲染，不代表真实 GPU 资格验证。范围检查另发现快捷键、删除确认、跳过任务、审核退回原因及窄屏提示也可能在点云上覆盖模糊层；尚未复现同样超时，保留为候选，不宣称本次消除了所有弹窗的同类风险。

本地验证：58 项视频状态单元测试、4 项取消分类测试通过；20 个可执行 Mask 场景逐项通过。最终组合运行的 14 项浏览器场景全部无重试通过，覆盖折叠卡片再编辑、G1/G2 跨任务与故障恢复，以及完整精确帧套件的真实像素和回退检查。类型、ESLint、格式和差异检查通过；测试用户及项目均清零，自有容器、报告和临时配置已清理。后续远程结果以关联 PR 的验证记录为准；不以一次全绿运行证明历史 flaky 已永久消失。
