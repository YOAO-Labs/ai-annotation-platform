## 3. T4 实测暴露并顺手闭环的 5 项真实生产缺陷

1. **检查点在取消/失败尝试中未纳入监督器上传清单**（`apps/training-executor/training_executor/worker.py`）：`worker.py` 在处理插件 `cancelled` / `failed` 终态时仅登记 `result.json` 与 `train.log`，未把训练器已原子落盘并 `fsync` 的 `checkpoint.json` / `checkpoint-NNNN.pt` 纳入待上传产物，导致 `POST /resume` 无法找到可续训检查点。已新增 `_stage_committed_checkpoint()`（严格校验非符号链接、目录 containment、文件名正则、精确 SHA-256 与字节数），经 `apps/training-executor` 125 项测试与场景 9 真实 LibreYOLO GPU 续训验证。
2. **模型回流旧版兼容路径漏检 `runtime_qualification` 漂移**（`apps/api/app/services/trained_models.py` `check_trial_runtime`）：当推理试跑携带 `runtime_qualification` 时，若旧回退分支未比较 `dict(live_qual) == dict(expected_qual)`，可能放行运行时资格漂移。已补齐精确字典比对。
3. **新安装缺失 `inference_runtime` 仅按特定框架名拦截**（`apps/api/app/services/trained_models.py` `check_install_runtime`）：改为数据驱动，只要 `expected_receipt(version).get("artifact_format") is not None` 且安装回执缺少 `inference_runtime`，一律返回 `409` 拒绝。
4. **实例分割预检允许省略显式配置且空清单读取 `validation_digest` 存在空键风险**（`apps/api/app/services/training_runs.py` `_frozen_plugin_config`）：补齐分割任务必须提供显式 `configuration`（否则返回 `422`）及安全读取 `dataset.manifest.get("validation_digest")`。
5. **原生增强预览契约校验未在边界拒绝非检测任务**（`packages/python-sdk/src/training_contract/preview.py` `validate_request`）：显式拒绝非检测任务并返回统一错误提示。
