### A3. 页面行为

- 使用成员与邀请、邮件与访问地址、数据导入、视频体验四组表单；现有连接器白名单仍由专属组件管理，不复制一份通用文本框。
- 每项展示有效值、来源（部署默认或后台覆盖）、单位、作用范围、修改人/时间和生效时机；技术变量名可在说明中查看，主要标签使用业务名称。
- 支持搜索设置、按组保存、取消未保存修改和逐项恢复部署默认。保存前展示本组变更摘要，离开页面时处理未保存修改。
- 保存失败保留输入；后台刷新不覆盖正在编辑的表单；保存成功展示实际读回的有效值，不能只显示提交值。
- SMTP 密码始终只返回是否设置；“保留密码”“更换密码”“清除密码”含义明确，测试邮件明确使用已保存配置。修改未保存时先保存后测试。
- 恢复默认指删除 DB 覆盖并回到本部署环境值，不等于恢复开发机地址，也不等于清空字段。

### A4. API、类型和读写语义

- 保留 `GET/PATCH /api/v1/settings/system` 及已有字段；GET 增量返回新值、非敏感来源元数据和版本标识，兼容当前调用者。
- 增加 `POST /api/v1/settings/system/reset`，接收明确的 key 列表，在一笔事务内删除对应覆盖并记录审计。现有服务 `reset()` 可复用，当前 PATCH 的 `null` 忽略行为不能假装成重置。
- 新页面写入带读取时版本标识；服务端在事务内核对并串行化设置写入，冲突返回 409，页面保留草稿并展示最新值。旧 PATCH 调用保留只更新显式字段的兼容行为。
- 白名单字段定义集中维护类型、范围、单位和生效说明；API schema 与前端通过生成契约校对，避免只在表单里增加字段。
- 拒绝未知字段、非法类型、非整数计数和超范围值；不能用 `bool("false")` 一类强转接受错误输入。
- 读取合法的 `false`、`0`、空字符串时不使用 `value or default`。SMTP 的显式清除存为可辨别的空值；重置覆盖与清除邮件密码是不同操作。历史 NULL 覆盖维持继承环境值的兼容语义。
- 仅超管可读写全局设置。审计记录普通配置前后值、操作者及恢复默认操作；敏感字段只记录是否变更。

### A5. 真正生效的消费链路

DB 覆盖不会自动改变进程中的 `config.settings`。必须同时修改消费者，不能只增加输入框、schema 和白名单。

```text
超管设置页 → 系统设置 API → SystemSettingsService → system_settings + 审计
业务 API   → 有效配置读取 → 邀请判断 / 同步建任务 / 视频预热
导入 API   → 配额快照 → AsyncJob.payload → Celery → 同步枚举器
Beat       → presence worker → 有效配置读取 → 在线状态更新
```

1. 保留最多 30 秒的跨进程缓存传播合同。管理页面读回使用已提交数据；事务提交后再失效当前进程缓存，失败事务不能污染有效配置。
2. 需要一起使用的键以同一次查询形成快照，特别是两项导入预算，避免逐键缓存形成混合版本。
3. 新连接器导入在 API 受理时把有效文件数、字节数与配置版本写入 `AsyncJob.payload` 的有界配置快照；不接受客户端自行提供更宽松的预算。
4. Worker 将快照作为显式参数传入同步 `_collect_within_limits()`，不能在逐文件循环中查 DB。运行中和已经排队的任务继续使用自己的快照；修改全局配置只影响后来受理的任务。
5. 升级前已经排队且缺少快照的历史任务，在第一次执行前读取一次有效值并持久化，之后重试复用该值。同一任务重试不换预算；重新创建导入任务才使用新值。
6. 邀请创建、数据集关联和视频预热分别在其业务决策点读取配置；在线状态扫描在该轮执行时读取，维持原有扫描调度。
7. 初次上线代码需要刷新受影响 API/Worker，并确认实际运行的入口已更新；此后上述六项调参不要求重启进程。
8. 数据库读取失败不能悄悄退回更宽松配额。导入等预算操作使用同一操作已取得的快照，尚未取得快照时按已有请求/作业失败机制返回可重试错误。可选视频预热读取失败则本次不派额外块并记录诊断，保留主视频请求正常返回，不能把辅助预热变成播放成功的必要条件。

### A6. 本轮不开放的配置与后续边界

### A7. 系统设置验收

- 超管可读写；项目管理员及普通员工被服务端拒绝。直接构造非法 key、类型和越界值均被拒绝。
- API A 保存 → API B 在缓存合同内读取新值；重启后保持 DB 覆盖；恢复默认后回到当前部署环境值。
- 邀请按两位管理员分别计数，滚动 24 小时边界正确；在线阈值仅改在线状态，不能停用账号或改变登录会话。
- 连接器导入数量等于预算成功，超过一个文件或一个字节提前失败；失败不留下本次部分业务导入。
- 导入排队后修改设置，旧任务与重试保持原快照，新任务使用新快照；文件枚举循环不增加逐文件配置查询。
- 同步阈值两侧分支正确，0 不被回退值吞掉；预热为 0 时不派额外块，既有缓存及主视频请求正常。
- 两位超管并发修改、保存失败、恢复默认、SMTP 清除/保留/更换、表单脏值刷新均按约定工作。
- 验证实际行为而非仅 GET 回显；记录 API、worker 的有效值及非敏感版本，不记录秘密。

## 工作包 B：邀请直接进入目标项目

- 在现有邀请表单增加可选目标项目，复用已有用户组选择器与内置角色。项目成员角色遵守当前模型，不提前实现第三批的跨项目混合角色。
- 新用户接受邀请后建立账号、用户组与目标项目成员关系；已有账号先登录并确认加入项目，不重复注册、不按邮箱默默合并账号。
- 接受时重新校验邀请人仍有管理资格、项目仍存在、角色仍可分配；失败保持可解释状态，避免只建账号却留下不明原因的半完成入职。
- 复制邀请链接仍是完整可用路径；邮件作为已有 SMTP 能力上的可选发送方式，不要求公司先配置邮件系统。
- 接受后显示开始任务或等待分派及负责人；不承诺仅加入项目就已经有激活批次。
- 数据上为邀请增加可选项目关联，旧邀请继续有效；账号创建与正式成员写入使用一致事务。按现有邀请路由增量扩展，不另建第二套邀请系统。

## 回退、成本与完成条件

最小交付是工作包 A 的六项设置及真实消费者接线，其他工作包可独立排期；整体规模为较大范围，单个普通入口改善为小至中等范围。
设置扩展不新增部署服务、第三方账号或环境变量控制开关；邮件可继续使用已有公司 SMTP，未配置时保留复制链接。

- 恢复单项配置通过删除 DB 覆盖完成，不要求回滚整个应用或改写 `.env`。
- 代码回退前列出旧代码不识别的新设置键，恢复这些键的部署默认。先排空使用新快照的排队、运行及重试任务，或保留兼容 worker 处理完毕，再回退消费者代码；旧 worker 不识别新快照，不能仅恢复配置就承诺旧任务预算不变，也不能靠调低全局值中断它们。
- 邀请和派发已产生的成员/负责人变化需显式撤销或反向操作，不能用 UI 回滚替代业务回退。
- 最大风险是假热更新、多个消费者读到不同预算，以及低频部署参数被误做成日常设置。以实际 API/worker 行为、快照和作用范围说明验收。
- 完成每个工作包后更新正式文档；全部范围交付后追加 `## Outcome`，准确记录提交、验证和剩余范围。
